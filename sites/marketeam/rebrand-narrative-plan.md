# 官网品牌与叙事改版方案（2026-07-30）

状态：样张迭代中（2026-07-30 起，loop 模式）。用户指令：**多做几个变体，一轮 loop 产出一个，每轮先反思上一轮的不足再改进**。三次修订（2026-07-30 晚）：用户否决 G 水墨（太丑），并澄清目标用户——**全世界用 Codex/Claude 的人，享用 AI 提效的普通专业者，不是极客**。该定义成为评分主轴：普世可读、温暖精致（Slack/Notion 气质）加分，亚文化编码（水墨文创、NASA 怀旧、像素游戏）减分。广度撒点到 H 为止已足够定象限，此后转**深度**：主攻 E（微缩指挥室，普世情绪 + 精致质感），用「单工位特写」派生法补它的系统化短板（每位成员 = 一张亮着身份色的工位特写，可作头像、分区插图、OG 素材），D 作系统化备胎。

变体队列（2026-07-30 二次修订：用户指出不要在单一风格下探索，要在更广的风格空间撒点，方向间距离最大化）：E = 等距微缩指挥室（拟物立体，俯瞰六工位，直接画出「老板俯瞰团队」的权力感）；F = 复古任务控制中心（怀旧未来主义，把「指挥中心」按字面做）；G = 水墨东方（中文产品的文明身份，全行业空位）；H = 像素组队（八位机游戏文化，「你的队伍」）。几何小人（样张 D）只是其中一个点，不是母风格。每轮固定动作：反思 → 生成资产 → 独立样张 → 同视口截图 → 登记。候选 A `index-loop-narrative-be3c.html`、候选 B `index-loop-narrative-2e1d.html`，同视口截图见 `workdir/shots/`（不入库）。胜者经用户确认后才提升为 `index.html`。

## 一、诊断

对照三个参照站（openalice.ai、maka-agent.com、cindy.cn）逐个真实浏览后的结论：当前 `index.html` 的工艺水准不低（着色器边框、逐字进场、玻璃质感都很讲究），病灶不在工艺，在两层缺失：

**第一层：没有可占有的品牌资产。**

- 三个参照站各有一件「看一眼就知道是谁」的资产：OpenAlice 的奶油纸色 + 吉祥物 + 「ONE PERSON, ONE REPO, ONE AGENT」口号系统；Maka 的果冻立体字标 + 贴纸 + 瑞士网格反差；Cindy 的黑红斜杠系统 + 动漫角色 + 「想到，就能做到」。
- 我们的页面是深色底 + Inter + 紫色点缀 + 玻璃质感，属于当前 AI 创业公司的默认皮肤。换掉标志后可以属于任何一家同类产品。
- 名字资产在手里但没打出来：莫比乌斯环（一条带子首尾相接、只有一个面）天然映射「一条对话装下整个循环推进的团队」，首屏背景图甚至就是一条缎带（`manifesto-ribbon.jpg`），但被暗色渐变压到几乎不可见，全站没有一个字解释这个名字。

**第二层：没有情绪叙事。**

- 页面从头到尾在「介绍产品」（选团队 → 发指令 → 看分析），参照站在「讲用户的故事」。共鸣需要三个机制，当前一个都没有：
  1. **痛（旧世界对照）**：立一个用户认得出的旧世界再推翻它。OpenAlice 的写法是「过去一个交易台意味着一栋楼、一台彭博终端、十二个穿衬衫的人——现在它是你电脑上的一个文件夹」；Cindy 的写法是「传统协作是一条流水线：产品等设计、设计等研发」。**注意位置：两站都把对照放在页面后段、能力展示完之后，作为情绪高潮收束全页；没有任何一站用痛开场，开场全是欲望与自信。** 对照句的力量来自「刚看完全部能力再回望旧世界」的落差，放在开头只是没有支撑的大话。我们的问题是全页从头到尾没有这个对照。
  2. **爽（欲望画面）**：具象的、能在脑子里放映的场景。我们已有的爽点写出来了却放错位置——「你就像老板一样，只需要发号施令」埋在第二功能区正文；样机对话里「今天下班前我要看到」是全页最有戏剧张力的一句，被当界面填充文字用掉。
  3. **安（接住恐惧）**：把活交给一群智能体，用户的真实顾虑是「会不会乱改我的东西、跑偏了能不能兜住」。Cindy 为此开了一整节逐条拆解；我们只有副标题里半句「可见、可回退」。没有信任，兴奋不会转化成下载。

## 二、方向决策

### 2026-07-30 方向修订：团队群像（候选 C，现为主推）

用户评审样张 A/B 后判定：二者仍未解决「无可占有品牌资产」「无情绪叙事」两个核心目标，并明确方向决策可以变动。复盘：A 的色板纪律、B 的排印声部都是设计系统层面的安全动作，过不了「能否凭记忆复述/画出」的资产测试；叙事结构虽对，但全篇「团队」是抽象名词，情绪没有可共情的主语。

二次迭代（同日）：用户判定 v1 群像「六个小土豆」不够好——圆角色块只有颜色差异、没有剪影差异，缩小后不可辨认。v2 改为**颜色 × 形状双编码**：每个成员一个专属几何剪影（圆/方/三角/五边形/拱/六边形），Leader Agent 为戴领带的紫色五边形；形状系统同时溢出为界面标记语言（分节标、列表符、品牌标形状行）。样张 D（`index-loop-narrative-f593.html`）落地此版并把首屏重构为团队主场。

修订决策：**把六色身份色板人格化为六个极简几何成员（团队群像）**，身份紫者为 Leader Agent 站位居中。理由：参照站全是单主角人格化或纯字标，「群像」无人占用，且群像即产品本体（用户面对的是一支各有分工的队伍，不是一个助手）；色板从抽象点升格为「有脸的成员」，同时补齐资产与情绪主语。风格约束：极简几何、扁平、缩至头像尺寸成立，避开二次元（Cindy 已占用），不背叛产品克制。原候选 A/B 保留作对照；样张 C 在 A 的骨架上加角色资产与场景化首屏。角色资产用生成式图像产出，入库前须通过小尺寸检验。

采用**风格化不拟人**路线（Maka 式），吸收人格化路线的一小步：

- 不造角色、不给脸。与「像老板一样发号施令」的庄重叙事以及 console 端安静工作台的定位保持连续。
- 但把 **Leader Agent** 升格为全站反复出现的固定词：统一写法、固定的头像色标记，让用户记住「我只需要和一个对象说话」。
- 把「让团队自己推进」升格为战吼级口号。
- 名字故事只以文案存在（见叙事线第 5 节），**不做任何环形、缎带、∞ 图形**。理由：莫比乌斯环是三维物体，小尺寸退化成 ∞ 俗套符号，大尺寸三维渲染是通用抽象官网的头号套路，且本目录明令不做字面隐喻视觉。参照站的共同规律也是如此：视觉资产都是审美承诺，没有一个是名字的图解。
- 证据层（版本号、日期、真实截图）与品牌路线无关，无条件补齐。

### 视觉签名：候选方向与决策程序

视觉签名不由文字方案拍板，按目录最小闭环用样张对比决定：

- **候选 A（推荐首选）：角色色板系统。** 近单色深底上，全站唯一的彩色声部来自产品已有的六色粉彩身份色板（与 console 头像同源，见 brand-spec）。分节标记、要点符号、进度指示统一做成「一排成员色点」。产品原生、任意尺寸成立、营销页与产品视觉同一血统；表达的正是产品本体——一间安静的深色指挥室里坐着一排颜色各异的成员。
- 候选 B：中文排印声部。大字号中文标题排印与字重对比建立编辑感签名，区别于全行业英文优先的版式。
- 候选 C：延伸目录已收敛过的 Relay Atlas 语言（坐标、路线、责任领地）。
- **决策程序**：候选 A 必做样张，B 或 C 选一陪跑；同视口截图对比首屏、功能区、行动区，用「能否一眼复述签名」「去掉装饰后层级是否成立」评审，胜者进入正式收敛。
- 现有首屏缎带背景（`manifesto-ribbon.jpg`）属于行业默认皮肤的一部分，样张中倾向删除或大幅弱化，以实际对比为准。

三项取值：VARIANCE 中（保留深色工作台基底，不换暖色，避免与产品截图冲突；识别度靠色板纪律与叙事而非换肤）／ MOTION 低至中（保留现有动效预算，不再加）／ DENSITY 中（新增两节，删并一节，总长基本持平）。

## 三、页面叙事线重排

新顺序：**欲望（首屏）→ 立场（宣言区，保持短）→ 机制（三功能区，标题改收益句）→ 安（信任区，新增）→ 对照高潮 + 名字故事（新增，行动区之前）→ 战吼（下载行动区）**。

旧世界在全页只出现两次、各一句：宣言区隐含一次，高潮区完整画一次。不设独立的「痛点区」，不在页面前段铺陈痛苦——参照站的实证是：开场放欲望，对照放收尾。

### 1. 首屏——权力感提到第一位

- 主标题保留：「把整个开发团队，装进一次对话。」（价值主张成立，不动。）
- 副标题改写，把爽点从正文提上来，参考初稿：
  > 你只管发号施令。产品经理、开发、文案、测试在同一条会话里并行推进——你不在的时候，他们也在干活。
- 徽章区加真实版本号（现有的 GitHub Releases 请求逻辑已能拿到版本，顺手显示出来），替代空泛的「公测中」。

### 2. 宣言区——保持现位、保持短

「不要一个个管理 Agent，只需要和 Leader Agent 聊清楚」是全页最有品牌潜力的一句，位置也是对的（首屏之后、机制之前的立场宣言）。**不扩写成痛苦描写**——这句话本身已经隐含了旧世界（一个个管理的疲惫），一句带过的立场比铺陈痛点更有底气。只做两处微调：Leader Agent 加固定色标；「聊清楚」后半句与首屏副标题的措辞对齐。

### 3. 三个功能区——机制不动，标题改成用户视角的收益句

- 「从一个团队开始」→ 「一句话，配好一支团队」
- 「尽情表达需求，团队自己会推进」→ 保留方向，副文案把「今天下班前我要看到」从样机对话里呼应出来，例如区块引导句用「敢提要求，是因为有人兜底」。
- 「团队进程不满意？直接开始优化」→ 「哪里慢了，当面问」
- 每区正文保持现有信息量，只做语气统一：主语从「功能」换成「你」。

### 4. 信任区——新增

标题方向：「放心把活交出去」。逐条写产品真实具备的能力，每条都必须可验证，不写承诺式空话。候选条目（以产品实际能力为准，实施前逐条核对，砍掉不成立的）：

- 每一处改动进入审查视图，你逐条看、逐条批
- 不满意可以回到之前的检查点
- 需要拍板的决策会停下来问你，不擅自做不可逆的事
- 工程与对话记录留在你的电脑上

### 5. 对照高潮 + 名字故事——新增，放信任区之后、行动区之前

全页能力与信任都展示完之后，用一段对照收束情绪（模仿参照站的位置：能力展示完毕后的引文高潮，不是开场铺垫）。参考初稿：

> 过去，「有一支开发团队」意味着招聘、排期、开会、汇报。
> 现在，它是你桌面上的一个窗口。

同区结尾接名字故事两行：

> 莫比乌斯环只有一个面：沿着它走，会回到出发的地方。
> 一条对话也是——需求从你这里出发，穿过整个团队，带着成果回到你手上。

两段都只做文字与排版，不配任何环形图形（决策理由见「二、方向决策」）。对照句的主语用「老板视角」的旧世界（招聘、排期、开会），与首屏「发号施令」的叙事同一人称，不用「盯终端窗口」这类只有重度 AI 用户才有的痛。

### 6. 下载行动区——战吼升格

「让团队自己推进。」保留为行动区主标题，并在页脚以固定格式复现一次（参照站的口号都会在页脚回声一次），形成口号系统。

按目录惯例，不直接改正式页，先出候选副本：

## 五、验收

实施完成后由执行者自行跑一遍：

1. **叙事验收**：本地起静态服务，逐屏截图首屏 → 宣言 → 三功能区 → 信任区 → 对照高潮与名字故事 → 行动区，检查顺序与文案落位；用一句话复述视觉签名，能复述则通过。
2. **静态可读**：禁用脚本加载页面，正文、列表、关键结论全部可见（目录约束：静态阅读本身成立，进场动画只做增强）。
3. **降级与无障碍**：开启 reduced-motion 后无动画但内容完整；键盘逐个元素走查焦点可见。
4. **移动端**：390px 视口无横向滚动，单列阅读顺序与叙事线一致。
5. **证据层**：版本号从 GitHub Releases 正常显示；请求失败时降级为现有文案不报错。
6. **对照复盘**：候选页与现 `index.html` 同视口逐屏对比截图，确认信息量未丢失、动效未加量。
