# 苹果感动效

这份文档只收**默认判断会错的地方**。通用动效知识（时长要短、要有缓动、尊重 reduced-motion）到处都有，不在这里。下面每一条都是先按直觉做、被实测打脸之后才写下来的，附着当时的数字。

## 一、「苹果感 = 回弹」是错的

默认直觉：spring 就是弹，加点 bounce 才有味道。

事实：WWDC23《Animate with springs》给的默认建议是 **bounce = 0**——临界阻尼，数学上**永不过冲**。bounce ≈ 0.3 已经「noticeable bounciness, more playful」，bounce > 0.4 被明确点名 `exaggerated—avoid for UI elements`。

苹果用弹簧而不用贝塞尔，真实理由是两条，都跟弹无关：

1. **速度剖面**——贝塞尔的结束是硬停（"jerk to a halt"），弹簧起步有加速度、收尾像真实物体一样自然停住。
2. **速度保持**——被手势或另一次动画打断时，弹簧以当前速度为初速度奔向新目标。

**推论一**：项目红线里写着「禁止 bounce / elastic 曲线」时，**不要用它否定弹簧本身**。bounce = 0 的弹簧不过冲，不属于被禁的形态。把「弹簧」和「回弹」混为一谈会让你退回贝塞尔，而贝塞尔恰恰是苹果在避开的东西。

**推论二**：现成动效库的默认值往往比苹果自己更弹。Animate UI 的 popover 默认 `{ type: 'spring', stiffness: 300, damping: 25 }`，阻尼比 ζ = 25 / (2√300) ≈ 0.72，**是会过冲的**。照抄默认值 ≠ 苹果感。

## 二、要弹簧不等于要装动画库

默认直觉：spring 得上 framer-motion / motion。

临界阻尼弹簧有解析解，采样成 CSS `linear()` 就是精确的弹簧曲线，零运行时依赖：

```
x(t) = 1 − (1 + ωt)·e^(−ωt)        ω = 2π / duration
```

`duration` 用苹果的**感知时长**语义（≈ 无阻尼周期），不是沉降时间。25–30 个采样点足够，见 `scripts/spring-easing.py`。`linear()` 在 Chromium 113+ / Safari 17.2+ 可用，Electron 只要不是老版本都有。

**库真正不可替代的只有一件事**：打断时保留速度并重定向到新目标。那对拖拽、手势、滚动惯性有意义；对**离散开合的浮层/弹窗没有**——没人会在 popover 展开到一半时抓住它甩出去。为一个 popover 引入运行时依赖不划算。

先问「我需要的是曲线形状，还是速度保持」，再决定装不装。

## 三、别用 ease-out 贝塞尔冒充弹簧

`cubic-bezier(0.165, 0.84, 0.44, 1)` 这类 expo-out 看着「快进慢出」很像弹簧，实测完全不是：它在**前 18% 的时间里走完 60% 的位移**，剩下 82% 的时间在磨最后 40%。读起来就是「平 + 拖尾」——既没有起步的加速感，收尾还是硬停。用户对这种曲线的典型反馈就是「太平了」。

**判据**：把被驱动的量（scale / 尺寸 / clip 百分比）按时间采样打表，看形状。

```
弹簧（对）: 0.929 → 0.955 → 0.971 → 0.991 → 0.999 → 1.000   先慢后快，长尾收敛，不越界
expo-out（错）: 头几帧就跳到六成，然后一路磨
```

## 四、「面板长大」不能用 scale

默认直觉：`scale(.9) → 1`。

`scale` 会把**面板内容一起缩放**，读成「整体放大」（zoom），不是「容器长出来」。要的是容器变大、内容始终是最终尺寸——用 `clip-path: inset()`：

```css
/* 从被锚定的那个角展开 */
from { clip-path: inset(var(--clip-t) var(--clip-r) var(--clip-b) var(--clip-l) round 12px) }
to   { clip-path: inset(0 0 0 0 round 12px) }
```

顺带：最终态要写 `round <radius>`，否则 `inset(0)` 会把圆角裁成直角。

## 五、共享元素过渡看着最贴，但会毁掉触发器

默认直觉：「App 图标点开变详情」= 触发器和面板共用一个 `view-transition-name`，让浏览器把它们当同一个元素。

结果是错的：那等于**让触发器本身成为动画的「旧半」**。于是

- 触发器被拉伸放大（32px 的圆被拉到几百像素，在面板顶部撑出一个穹顶）；
- 变形组的起点是触发器**自己的方框**，长大的面板从它身上盖过去，把用户刚点的位置遮住。

**触发器不该参与动画。** 它是另一个元素，应当原地不动。要的是面板自己长大。

（如果确实要做共享元素——两侧是**同一张图**、且两边都该动，比如列表缩略图 → 详情大图——那 View Transitions 是对的工具。判据是：那个元素在动画结束后**还在**吗？触发器在，所以它不是共享元素。）

## 六、生长起点是「面板被锚定的那个角」，不是「触发器」

这两者不同，混淆会让动画从错误的位置长出来。

浮层的锚定角由**碰撞处理之后**的两个轴共同决定：`side` 定贴哪条边，`align` 定靠那条边的哪一端。Radix 会把结果写成 `data-side` / `data-align`（其他定位库有等价物）。

```css
[data-overlay-clip][data-side="bottom"] { --clip-t: 0; --clip-b: 100%; }
[data-overlay-clip][data-side="bottom"][data-align="start"] { --clip-l: 0; --clip-r: 100%; }
/* side=bottom + align=start → 面板左上角 ＝ 触发器左下角 */
```

写死一个角，贴边翻转时方向就反了。务必用定位库解析后的值，不要用作者传入的期望值。

## 七、退场不是入场的倒放

默认直觉：`playbackRate = -1` 既省事，位置连续还免费。

对弹簧来说这是错的：**临界阻尼弹簧的长尾倒过来播 = 起步几乎不动、末尾撞停**。实测倒放到 240ms 时才走了 7.7%，前半程看着像卡住了。

退场要自己的曲线和更短的时长：普通 ease-out + 约入场一半的时长，第一帧就动。位置连续性另想办法（见下条）。

## 八、可打断必须换掉 CSS keyframes

CSS 动画只能从**自己的首帧**重启，没有「从当前位置接着走」。实测：面板长到 39% 时点击关闭 → 关闭动画从 100% 开始 → 面板先弹到全尺寸再淡出，可见跳变。

正确做法：Web Animations API，**每次状态翻转都以元素当前计算值为起点新建动画**。

```js
const current = getComputedStyle(node).clipPath;   // 动画进行中读到的就是当前帧的值
animation.current?.cancel();
node.animate([{ clipPath: current }, { clipPath: target }], { duration, easing, fill: "both" });
```

这样入场/退场可以各有曲线，位置仍然连续。实测中断在 51.9% 时是往回缩到 84.5%，连续反转两次也不跳。

三个必须一并处理的代价：

1. **presence 要自己持有。** Radix 之类是靠 CSS `animationend` 决定何时卸载的，WAAPI 不触发它；要给 Portal 加 `forceMount`，把 `open` 用 context 传下去，自己决定何时 unmount。
2. **新挂载时计算值是 `none`**，兜底必须**跟方向走**：开 → 收起态，关 → 展开态。统一兜底成展开态会让入场「从展开动到展开」，等于没播——而且这个 bug 在测量里长得像「动画成功了」。
3. **jsdom 没有 WAAPI**，`prefers-reduced-motion` 也要落到终态；两者都走同一条 fallback。

## 九、同组切换不是「排队」

默认直觉（也是用户常提的）：B 等 A 退完再开。

排队是**纯延迟**，切换会变迟钝。正确的规则有三条：

- **只有被抢占的退场才快。** 无人接管的关闭走全程——那时它就是屏幕上的主体，值得被看完。
- **接管者的入场不压缩。** 它是新焦点。
- **已经在退场的用 `updatePlaybackRate` 原地提速，不重启**，否则又制造一次跳变。

「组」= 一个可能同时有多个实例的组件（每条消息一个的信息浮层），不是「所有浮层」。实测：让位方 126ms 退清（原 320ms+），接管方不受影响。

## 十、就地展开类组件不能用在浮层上

Family Button / Morph Surface / Dynamic Island 这类「点一下就地长开」的组件，前提是**触发器与面板同位、在文档流里展开**（或固定在屏幕角落）。

浮层不是：它要 portal 出去、贴边翻转、焦点回返。就地展开会顶开下方内容、靠近窗口底部直接出屏、被祖先的 `overflow` 裁掉。

挑组件时先问：**它假设触发器和面板在同一个位置吗？** 是的话，它不适合浮层，无论动效多好看。

## 十一、动效的测量方法（不测就是瞎调）

看截图判断动效是没用的，看视频也很难量化。三条硬经验：

- **后台标签页的动画被节流。** 采样出来会是同一帧重复、间隔从 45ms 变成 1000ms。测之前先把被测标签置前。
- **要冻帧就用 `getAnimations()`**：`a.pause(); a.currentTime = 130;` 然后截图。别靠「点开就赶紧截」碰运气。
- **交互事件要发全。** 测浮层关闭时只发 `click` 不发 `pointerdown` 会得出「关闭坏了」的错误结论——大量库的外部关闭是由 `pointerdown` 起头的。发 `pointerdown` + `pointerup` + `click`，并且**前后两版要用同一套事件序列**，否则对比无效。

采样打表的最小写法：

```js
const f = [];
for (let i = 0; i < 10; i++) {
  await new Promise(r => requestAnimationFrame(() => setTimeout(r, 45)));
  f.push(getComputedStyle(el).clipPath);
}
```

## 十二、别拿不相关的规范条款否定方案

这条不是动效知识，是读规范的方式，但在动效上最容易犯：设计规范里的禁令往往**绑着具体场景**。「目录轨不得使用居中膨胀」「侧栏信息面不得复制邻项缩放」约束的是列表/轨道里的 dock 式**邻项联动**变形——拿它去否定「弹窗里单个格子 hover 放大」是过度引申，会被一眼看穿。

引用禁令前先确认它约束的场景是不是当前场景。真要突破，走**登记例外**的正规路径（在规范里写清楚参数、理由和仍然禁止的部分），不要给单个组件偷偷开口子。
