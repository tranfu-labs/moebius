# 成套角色头像生成

一次要出 N 个头像、且它们必须像同一套的时候用这份流程。单张图不需要它。

**核心难点从来不是「能不能生成一张好看的头像」，而是「N 张放在一起像不像一套」。** 下面每一条都是为这个目标服务的。

## 零、跑起来需要什么

```bash
pip install openai pillow numpy
export IMG_API_KEY=...      # 必需
export IMG_BASE_URL=...     # 可选，走 OpenAI 兼容代理时才需要；不设就用官方端点
```

三个脚本按顺序用，每步的产物是下一步的输入：

```bash
python scripts/generate.py                      # → 一张 3×3 品红幕布网格图
python scripts/dekey.py sheet.png out/ a,b,c…   # → 按幕布色定位切分 + 去背，9 张透明图
python scripts/frame.py out/ final/             # → 按固定占比烘焙，得到可直接进产品的素材
```

`generate.py` 里的 `CAST` 和 STYLE 段落是本 skill 写作时用的**猫的示例**，换成自己的角色清单即可；STYLE 段落跨批必须逐字不变（见第二节）。

## 一、批内一致：网格法（最重要的一条）

**永远不要逐张生成。** 逐张调用 N 次，画风、构图、光照、色调必然漂移，拼在一列里一眼就散。

正确做法：**一次生成一张 3×3 网格图，再切片。** 同一张画布内模型会自动统一线条、上色、比例、眼睛画法。

```
A 3x3 grid of exactly 9 portraits on a flat #FF00FF background, evenly spaced, equal size.
SHARED STYLE — identical across all nine: ...
THE NINE, left to right, top to bottom:
1. ...
```

## 二、跨批一致：逐字相同的 STYLE 段落

超过 9 个就要多批。**批与批之间，STYLE 段落必须逐字不变，只换角色清单。**

实测：两批交错排列后无法分辨批次边界。所以扩容到 36、45 张是安全的。

**验证方法**：把两批交错拼成一张图（批1/批2/批1/批2…）看能否看出分界。分批各拼一行是无效验证——人眼对"整行 vs 整行"的差异不敏感，交错才暴露漂移。

## 三、幕布用品红，不要绿幕；而且必须满幅

生成时背景用**纯品红 `#FF00FF`**，事后用色度键抠掉，产品里的背景色由代码控制。

- **为什么不用绿幕**：很多角色有绿眼睛，绿幕会在眼睛上打洞。品红不会和毛色/瞳色/口鼻/皮肤冲突。
- **为什么不直接生成成品背景**：抠成透明后，背景色可以接到产品既有的身份色板上。**N 张脸 × M 种底色 = N×M 种组合**，撞脸概率大幅下降，且配色自动与产品统一。

**幕布必须铺满整个方形单元格，绝不能是个圆。** 只写"不要画圆"不够，模型仍会画圆形色块；要正面描述目标构图：

```
The magenta fills the ENTIRE SQUARE CELL, edge to edge. There is NO circle, NO disc,
NO round badge, NO vignette, NO frame of ANY kind.
The subject is BIG in the cell: head spans most of the width, ear tips near the top edge,
and the SHOULDERS RUN OFF THE BOTTOM EDGE and are cut by it.
```

**画成圆的后果**：抠出来的主体自带圆弧轮廓，放进圆形容器还看不出来，一放进圆角矩形就变成"圆形头像贴在方块上"，四角露出底色。等你发现时整套素材都要重做。

prompt 里还要写死：背景绝对平整、无渐变无阴影无暗角、主体上不能出现任何品红色。

色度键 + 去色溢出（scripts/dekey.py 是参考实现）：

```python
score = (R + B) / 2 - G          # 品红判据
alpha = clip((FULL_KEY - score) / (FULL_KEY - NO_KEY), 0, 1)
# despill：边缘吃到品红的像素，把 R/B 拉回 G
limit = min(clip(score - NO_KEY, 0, None) * alpha, max(min(R, B) - G, 0))
R -= limit; B -= limit
```

## 四、占比归代码，不归 prompt

**让模型做它擅长的事（画好一个角色），不要让它操心"在容器里占多大"。** 那是确定性问题，写进 prompt 只会得到不稳定的结果。

正确分工：模型输出满幅素材 → 代码测量主体 bbox → 按固定比例缩放定位 → 烘焙进资产。

实测下来的基准（先扫一遍再定，不同题材不同）：

| 主体宽度 | 顶部留白 | 效果 |
|---|---|---|
| 100% | 0% | 太满，耳朵被切、两颊贴边 |
| 92% | 4% | 偏满，配饰容易顶到边缘 |
| **86%** | **7%** | **最佳：轮廓完整、脸够大、圆与圆角矩形都成立** |
| 80% | 10% | 太空，四周死色太多 |

把占比烘焙进资产（透明 PNG 里主体已在正确位置），UI 层就只剩背景色和裁切形状两件事，无需逐图微调，圆形和圆角矩形共用同一份文件。

**合成时底和主体必须一起裁。** 只画好底再把主体叠上去，主体的肩膀会溢出容器变成方块。这个 bug 看单张素材发现不了，只在合成图里现形。

## 五、小尺寸是硬约束，先量再定

**列表头像通常只有 28–32px，很多风格在这个尺寸直接失效。** 定风格前先做尺寸梯度图（32/40/48/64px，放在真实底色上）。

实测结论：
- 写实人像插画在 32px 退化成"浅色脸+深色一坨"，**区分度还不如纯色首字块**
- 拟人动物在 32px 明显更强，因为**花色是大面积色块**（橘/黑/三花/暹罗/玳瑁），而人类发型是轮廓细节，缩下去就没了
- 分界线在 40–48px：48px 以上写实细节才成立

**小尺寸下有效的是大色块和剪影，不是细节。**

## 六、性格驱动，不要职业道具

让角色可辨的是**表情、姿势、视线、头部角度**，不是手里拿的东西。

- 用 MBTI（或任何性格框架）驱动每个角色的表情与姿态，写成具体的画面描述而不是标签："下巴微收、半闭眼直视、一只耳朵后转"，而不是"ENTJ"
- **职业只用衣领/头饰极轻地暗示**。真人头像不会举着放大镜，角色头像也不该
- 头饰要服务性格：沉思型的松垮毛线帽、观察型的兜帽拉起；而**最自持的类型什么都不戴——克制本身就是刻画**

## 七、摆拍 vs 抓拍

这是"好看但中规中矩"和"有生命力"的分水岭。

- **摆拍**：正面、居中、得体表情、统一机位 = 证件照，九张像一个模板换皮
- **抓拍**：捕捉一个"没打算被看到"的瞬间 = 有戏

抓拍的具体写法：眼球斜到眼角（side eye）、半闭眼、嘴张到一半（打哈欠/大笑/吐舌）、耳朵后转、头歪出垂直线、脸更靠近更占满画面、允许略微偏离中心。**prompt 里要明确写「把每个表情推得比得体更过一点」。**

额外收益：抓拍构图脸更大，**32px 下反而占用更多有效像素**，小尺寸识别度也更高。

## 八、模型不听话的地方（必须显式对抗）

- **道具**：写了 no props/no tools/no icons，仍可能画出符号。多写几遍，并给出理由式表述（"没有人会在头像里举着放大镜"）
- **性别刻板印象**：不提性别时，模型会自己按职业分配（经理=女装、开发=男帽衫）。**必须显式要求性别表现多样且与职业无关联**。换成拟人动物可以从根本上绕开这个问题
- **禁表情会导致死板**：不要写 no mouth / no expression。要明确要求画出眉毛和嘴、要有可读的表情

## 九、切图按幕布色定位，不按网格均分

**网格图的单元格之间有细白缝，按 `宽/3` 算术均分一定会把白缝切进来。** 白色不是幕布色，色度键留着它，于是每张素材外面套一圈浅色方框——缩到 80% 尺寸以下就看得一清二楚。

正确做法：**对幕布色做行/列投影**，白缝天然是分隔带，直接得到 3×3 的真实边界。

```python
magenta = (R + B) / 2 - G > 60
rows, cols = bands(magenta.any(axis=1)), bands(magenta.any(axis=0))
```

从成品背景（非色度键）切的历史方案，三种都失败过，记下来免得重走：
1. **均分格子 + 内切圆** → 边缘残留 50–85%（实测 418px 格子里圆只有 386px 且贴左边）
2. **按背景色投影找分隔带** → 相邻行的主体错位，没有一条扫描线是纯背景，行会粘连
3. **连通域标记** → 主体间隙只有 1–2px，闭运算直接把九个连成一块

用满幅色度键 + 幕布色投影就绕开了整类问题。

## 十、多批要串行

图像 API 有并发配额。三批并行提交会撞 `429 Slot reservation failed`，而且**只有部分批次失败**——很容易误以为全部成功。多批一律串行跑，或者跑完检查每批的产物目录是否都存在。

## 十一、产出规格

- 存 **192px WebP**（quality 88–90）：足够 64px 显示的 2–3 倍屏，单张约 8KB，36 张约 300KB
- 分配用 **slug 稳定哈希**，保证同一角色永远同一张脸
- 撞脸估算按生日问题算：池 N、同组 k 个，撞概率 ≈ 1 - N!/((N-k)!·N^k)。**同组撞脸是并排显示的，比跨组刺眼得多**，池子要按同组人数上限来定

## 十二、多维度分配：哈希必须真正独立

同一个 slug 要同时决定「哪张脸」和「哪个底色」时，**两个维度必须用不同算法的哈希，而不是同一个哈希取不同的模**。

池 36 张、色板 6 色，36 是 6 的倍数，于是 `hash % 36` 在数学上完全决定 `hash % 6`——每张脸永远绑同一个底色，标称的 6×36=216 种组合实际只有 36 种，同组撞脸概率是估算值的 6 倍。

这个 bug 不会报错、不会崩、界面看着也正常，只有算一遍才发现。判据很简单：**只要一个维度的基数是另一个的倍数，同源哈希就一定退化。** 用两个不同算法（例如一个 ×31、一个 djb2），别用同一个哈希加偏移。

## 十三、素材落地的三个非显然陷阱

- **`currentColor` 的 SVG 必须内联进 JSX**。用 `<img src="logo.svg">` 加载时，SVG 无法继承外部 CSS 的 `color`，`currentColor` 会退化成黑色，深色主题直接糊掉。内联才能一份素材通吃双主题。
- **装饰性图形不要给可访问名**。给 SVG 加 `aria-label` 会把它折进容器的可访问名（一个成员 tab 从「测试」变成「测试 Anthropic」）；SVG 的 `<title>` 元素更隐蔽，它会计入 `textContent`，让容器上的文本断言莫名其妙地挂掉。图形若总是伴随文字出现，就设 `aria-hidden`，精确信息交给文字。
- **有尺寸档位表就不要让调用方用 className 改尺寸**。档位一旦被绕过，所有依赖档位查表的东西（角标大小、偏移）都会停在原档：56px 的头像配着 16px 档的角标，看上去像忘了做。要新尺寸就加一档，别在调用点覆盖。

## 十四、验收看屏幕，不看代码路径

**「每个调用点都传了参数」和「屏幕上真的有东西」是两回事。**

机械审计（grep 每个调用点有没有传 `engine`）会给出全绿，但如果数据源里那个字段普遍是 `undefined`，代码路径完全正确，画面上一个图标都没有。

推论有两条：

- **每改一处都要看真实渲染**，别因为做了「全覆盖审计」就跳过看图。审计证明的是你写的代码，不是用户看到的结果。
- **story fixture 必须反映真实状态**。真实产品里每个 Agent 都绑定执行引擎，fixture 里却只有一个成员有——新功能就会看起来像没生效。缺省数据要按「真实世界里这个字段一般都有值」来填。

## 执行清单

1. 定角色清单：花色/外形 + 性格描述 + 衣领/头饰暗示
2. 写 STYLE 段落（共享，逐字固定）
3. 每批 9 个，品红幕布，`quality="high"`
4. 色度键去背 + despill
5. 用 frame.py 把占比烘焙进素材（主体宽 86%、顶部 7%）；UI 侧只负责底色与裁切形状
6. 出尺寸梯度图，按真实显示尺寸验收
7. 多批时出交错拼图验一致性
8. 存 192px WebP
9. 接进产品后**打开真实页面看一眼**，确认默认数据下就能看到效果
