> 范围：定义 Agent 需要用户拿主意时，在输入框上方出现的一份问答表单——它由哪些部分组成、一次问几题、用户如何前进回退和改答、答完发出去的是什么、以及用户不想用它时会怎样。表单出现的时机由 Agent 自己判断，不由产品预设；输入框本身、附件草稿、待发射区与时间线由[主页面会话区](./main-conversation.md)定义。

> 产品基线：[moebius 产品需求文档](../prd.md)

## 页面目标

Agent 经常需要用户拿主意——「要 A 还是 B」「这几件事做哪几件」「还有什么要交代的」。没有表单时，Agent 只能把问题写在正文里，用户读完还得把答案重新组织成一段话打进输入框：问题明明已经问清楚了，用户却要再抄一遍；问题一多，还容易漏答其中一条。

表单让用户点几下就能给出准确、无歧义的回答。

与它冲突时让位的是**表单的表达力**：宁可题型少、样子固定，也不要为了能表达更多情况，而让 Agent 有机会构造出用户看不懂的界面。

## 用户场景

- Agent 做完一段工作，需要用户在两三种收尾方式里选一种才能继续。
- Agent 一次要问好几件事，用户希望一件一件回答，而不是面对一大段问题自己数着答。
- 用户答到第三题才想起第一题选错了，想回去改。
- 用户答到一半去看别的对话，回来想接着答，而不是从头再来。
- 用户看到表单但决定放弃这次问答，想直接跳过整份表单。
- 用户暂时不想看表单内容，但还想保留答案和当前题目，想把它收起来。
- 用户看到表单但只想先追问一句别的，直接从正常输入框发送后，这份表单不再需要。
- 用户不用鼠标，全程用键盘答完并发送。

## 入口与去向

### 入口

表单只有一个来源：Agent 在自己的回复里发出它。产品不提供任何预置表单、配置文件或让用户手动召唤表单的入口。

### 去向

- 用户答完发送后，表单变成一条普通用户消息进入时间线，Agent 拿到的是正常上下文。
- 用户点击「跳过」后，当前整份表单和未发送的答案草稿被销毁，不产生用户消息。
- 用户点击收起后，表单仍是当前活动表单，只折叠成一行，答案草稿和当前题目都保留。
- 用户不理它，直接在正常输入框发送消息后，当前表单和未发送的答案草稿被销毁；这条独立消息照常进入时间线。
- Agent 发来新表单时，旧表单被替换。

## 页面结构

表单是主会话底部的一块区域，不是独立页面，也不是弹窗。它固定在输入框上方：

```text
│  … 时间线 …                                        │
├─────────────────────────────────────────────────────┤
│  ┌───────────────────────────────────────────────┐  │
│  │                 表单卡片                 [⌄]  │  │
│  └───────────────────────────────────────────────┘  │
│  [附件草稿 / 文本胶囊 / 待发射区（既有，在表单下方）]│
│  ┌───────────────────────────────────────────────┐  │
│  │  正常输入框                        ＋      ↑  │  │
│  └───────────────────────────────────────────────┘  │
```

越靠近输入框的越是用户自己的东西。表单是外来的，排在最上面，不把用户已经准备好的附件和草稿挤开。

右上角的 `[⌄]` 是一个小号、圆角、outline 风格的收起按钮。表单收起后只保留成员、活动状态和展开按钮，不删除表单；再次点击向上的箭头可以展开。

### 表单卡片 · 中间某一题

```text
┌─────────────────────────────────────────────────┐
│  成员                       ▬▬ ▬▬ ── ──  2/4 [⌄] │
│  当前问题标题                                   │
│                                                 │
│  作答区                                         │
│                                                 │
│  [跳过]                         [上一步] [下一步] │
└─────────────────────────────────────────────────┘
```

进度跟成员同处一行、靠右收成一排细格子，不单占一行。它是问题的索引，占满整行的进度条会读成页面在加载，也会比它索引的那道题还抢眼。

### 表单卡片 · 最后一题

```text
┌─────────────────────────────────────────────────┐
│  成员                       ▬▬ ▬▬ ▬▬ ──  4/4 [⌄] │
│  当前问题标题                                   │
│                                                 │
│  作答区                                         │
│                                                 │
│  [跳过]                           [上一步] [发送] │
└─────────────────────────────────────────────────┘
```

### 三种作答区

每题各自是其中一种，题与题互不相干：

```text
单选                     多选                     自由输入
( ) title                [ ] title                ┌──────────────┐
    description              description          │              │
( ) title                [ ] title                └──────────────┘
    description              description
( ) ┌───────────────┐    [ ] ┌───────────────┐
    │ 或者自己写…   │        │ 或者自己写…   │
    └───────────────┘        └───────────────┘
```

单选题和多选题的最后一项固定是一个「自己写」的输入项，由产品补在 Agent 写的预设选项后面。Agent 当场想出来的几个选项不可能穷尽用户的真实想法，逼他在几个都不对的选项里挑一个，比让他直接写一句更糟。这一项不由 Agent 声明，它连怎么写都不用知道，也就写不坏。

### 只有一题时

进度整体不显示，直接是问题加发送——不给用户一个只有一格的进度条看。

```text
┌─────────────────────────────────────────────────┐
│  成员                                      [⌄]  │
│  当前问题标题                                   │
│  作答区                                         │
│  [跳过]                                  [发送] │
└─────────────────────────────────────────────────┘
```

### 表单卡片 · 暂时收起

```text
┌─────────────────────────────────────────────────┐
│  成员   表单进行中 · 2/4                    [⌃] │
└─────────────────────────────────────────────────┘
```

收起只改变当前界面的占用高度，不改变表单的活动状态；正常输入框仍可用，答案草稿和当前题目继续按会话草稿留存。

### 表单规模

| 限制 | 数值 | 为什么这么定 |
| --- | --- | --- |
| 一份表单最多几题 | 4 题 | 进度是一排细格子，题一多就碎成一片；真要问第五件事，用户早就想直接打字了 |
| 一道选择题最多几个预设选项 | 4 个 | 加上补出来的「自己写」最多五项；仍保持一题一个固定作答区，内容超高时沿用卡片内部滚动 |

超出任何一条都按写法不合规处理：输入框上方不出现卡片，那段内容当普通文字留在正文里。

## 区域与信息

| 区域 | 放什么 | 为什么需要它 |
| --- | --- | --- |
| 卡片外框与进度 | 卡片边界、是哪位成员在问；同一行靠右是一排细进度格与 `1/4`，每格区分已答与未答 | 知道谁在问、总共几题、现在到哪；跳回去时一眼看见哪几题还空着。进度与成员合占一行；卡片内部不画任何横线，三段靠留白分开——它已经是一块有边界的卡，里面再切两刀只会更碎 |
| 收起控制 | 右上角小号、圆角、outline 按钮；展开态显示向下箭头，收起态显示向上箭头 | 暂时收起表单，释放输入框上方空间，但不误认为已经跳过或提交 |
| 当前问题 | 一题的标题，加上这题的作答区 | 一次只看一题，读题和作答都不用在多组之间跳来跳去 |
| 导航行 | 左下角是整份表单的「跳过」；右下角并排上一步与下一步，最后一题右侧换成发送 | 能放弃整份表单，也能往前走或回头改题；「跳过」不代表跳过当前题，当前题仍由下一步/发送支持留空 |

问题标题、每个选项的 title 和 description 全部由 Agent 在运行时写，不是产品文案。写的时候按「读到这题的人不一定是开发者」来写——[产品基线](../prd.md)对用户职业不做进一步细分，一道用行话写的题会把一部分用户直接挡在外面。产品只定下面这些说明位：

| 位置 | 文案 |
| --- | --- |
| 进度 | `1/4`——纯数字，不写成「第 1 题，共 4 题」占地方 |
| 中间各题的前进 | `下一步` |
| 回退 | `上一步` |
| 最后一题 | `发送` |
| 自由输入题的占位 | `写在这里，不写也行` |
| 选择题里「自己写」的占位 | `或者自己写…` |
| 整份表单放弃 | `跳过` |

「跳过」是整份表单的放弃动作，固定在左下角；它不改变当前题的答题规则。没答时「下一步」照样能点，这仍然说明了单题不答也行；「跳过」只解决用户不想继续这份表单的问题。

收起按钮是小号、圆角、outline 风格，使用向下 `chevron-down` 表示收起，收起后用向上 `chevron-up` 表示展开。收起不改变当前题、答案或表单是否有效。

**可访问名称**：卡片区域说明是来自哪位成员的表单；进度整体说明第几题共几题，单个进度格说明第几题以及答没答；每个选项包含它的 title 和 description，「自己写」那一项说明这一项可以自己写答案；动作分别是「跳过表单」「收起表单」或「展开表单」「下一步」「上一步」「发送你的回答」。

## 操作与反馈

### 作答

- 单选、多选都点整行切换，不要求精确点中那个小圆点或方框。
- **选中后不自动跳下一题。** 自动前进会让人来不及看清自己选了什么，也和「可跳过、可回改」的自由度对不上。前进由用户自己点。
- 「自己写」那一项点整行就聚焦到输入框，**写进字就算选中它，清空就算没选**，不用先勾一下再写。单选题里写字会把原来选中的预设项让出来；多选题里它和预设项可以同时选中。
- 一题只要有任何一项被选中、或者「自己写」里有字，这题在进度上就算已答；全部取消或清空，它退回未答。
- 每题都能不答。

### 前进与回退

- 「下一步」始终可点，不因为当前题还没答就禁用。
- 第一题不显示「上一步」，不放一个点不动的按钮在那儿。
- 最后一题的「下一步」换成「发送」。
- 进度上每一格都可点，点了直接跳到那题，不用逐次点「上一步」。
- 回到已答的题，原答案原样带回；改完继续往前走时，后面已经答过的题不清空。
- 键盘：Enter 前进；自由输入题和「自己写」输入项上 Enter 是换行，用 Cmd + Enter 前进。
- 题与题高度不同时，卡片在一档标准时长内改变高度，不瞬间跳变。导航按钮就在刚点它的指针底下，尺寸一跳按钮就从手指底下跑了。

### 跳过与暂时收起

- 点击左下角「跳过」销毁整份活动表单、当前答案草稿和当前题位置，不产生用户消息，不弹确认，也不提供卡片内的撤销。
- 点击右上角收起按钮只折叠卡片；活动表单、当前题、答案草稿和后续可提交能力全部保留。
- 收起状态只属于当前界面，不作为会话草稿持久化；切换会话或重启后，仍有活动表单时默认展开，答案草稿和当前题位置按原规则恢复。
- 收起状态下，用户仍可从正常输入框发送独立消息；这仍按「用户独立发送」规则销毁表单。

### 发送

- 一题都没答时发送禁用，**不解释为什么**。没有可发送的东西这件事，禁用态本身已经说完了；再写一句「答一题就能发送」，是在把产品自己的规则念给用户听。
- 发出去的消息按题目顺序逐行组装，每行是问题标题加这题的答案：单选取选中那项的 title；多选取选中各项的 title，按表单里的原顺序排列；自由输入取用户写的原文。选中的是「自己写」时取用户写的原文，多选里它跟预设项一起按原顺序排在最后。跳过的题不出现在消息里。
- 只用 title，不带 description。description 是帮用户当场判断的，Agent 自己写的东西不用再念给它听。
- 发送后卡片消失，一条普通用户消息进入时间线。**不给卡片留一个「已回答」的壳子**——用户自己那条消息就是最强的确认，再显示一遍是重复。
- 普通输入框独立消息成功进入发送流程后，活动表单同步销毁；这条消息不附带表单答案，也不弹「是否放弃表单」确认。

### 用户独立发送

用户直接在正常输入框打字发送时，视为用户放弃当前表单：活动表单、未发送答案和当前题位置直接销毁，不清除或改写这条普通用户消息，不弹确认。表单被销毁后，原 Agent 消息中的旧表单不会在切换会话、重启或状态刷新时重新出现；之后 Agent 发来的新表单仍可正常出现。

如果这条独立消息发送失败，沿用既有发送失败恢复：消息未成功进入发送流程时不销毁表单，避免用户因网络或运行时失败丢失答案草稿。

### 一个位置，一个表单

输入框上方是一个固定位置，同时只放得下一个活动表单。Agent 发来新表单时旧表单被替换，旧表单里没发送的答案直接丢弃。用户点击「跳过」或成功独立发送消息时，当前表单进入已销毁状态，旧 Agent 消息里的表单不再恢复。Agent 已经往下说了新的话，旧问题的上下文已经过期，留着一个还能答的旧表单比清掉更危险。

### 留存

已答的答案**和当前停在第几题**一起按会话草稿处理：切到别的对话再回来、关掉应用再打开，回到原来那一题、原来那些答案。用户点击「跳过」或成功独立发送消息后，相关草稿与活动状态一并删除；收起状态不持久化。用户常常一边等一边去看别的对话，回来发现答了三题全没了，就再也不敢用表单。

## 页面状态

| 状态 | 表现 |
| --- | --- |
| 多题、答题中 | 卡片显示成员与进度，当前题高亮，已答格实心、未答格空心；导航行是上一步与下一步 |
| 多题、最后一题 | 同上，导航行右侧换成发送 |
| 只有一题 | 不显示进度，导航行只有发送 |
| 表单暂时收起 | 只显示成员、活动状态/当前进度和展开按钮；答案、当前题与发送能力保留 |
| 一题都没答 | 发送禁用，不附任何说明文字，也没有悬停提示 |
| 第一题 | 不显示「上一步」 |
| 已发送 | 卡片消失，时间线出现对应用户消息 |
| 已跳过 | 卡片消失，不产生用户消息，未发送草稿被销毁 |
| 用户独立发送 | 普通用户消息照常进入时间线，活动表单与未发送草稿被销毁 |
| 被新表单替换 | 旧卡片连同未发送的答案一起消失，新表单从第一题开始 |
| Agent 只发了表单、没写别的正文 | 时间线不产生一条空消息，卡片就是这一轮的表达；Agent 另有正文时，那些话照常作为正常正文显示 |
| Agent 表单写法不合规（含超过 4 题、某题预设选项超过 4 个） | 输入框上方不出现卡片，那段内容当普通文字留在正文里 |

写法不合规时不跟用户解释「Agent 刚才写错了格式」。那对他没有任何用处——他看到 Agent 把问题列在正文里，自己打字回答就行。表单是当场生成的，写错是常态，降级必须是安全的。

## 弹层与危险操作

不适用。表单不是弹窗、不夺焦点、不阻断用户做别的事；收起、跳过和独立发送都不弹确认。跳过或销毁会丢弃未发送草稿且不提供撤销，这是本产品对明确放弃动作的处理；它本身也不执行任何操作，只是把用户的回答变成一条普通消息。答案送出后真正做事的是 Agent，那属于 Agent 自己的执行与确认规则。

## 响应式与窗口行为

- 表单卡片宽度跟随输入框区域，不独立设定宽度。
- 窄窗口下，选项的 title 与 description 竖向排列，不因为挤压而截断 description——用户正是靠它判断选哪个。
- 卡片纵向超出可用高度时，卡片内部滚动，进度与导航行保持可见，不把发送按钮推出视野。
- 表单出现不改变时间线的滚动位置，也不把已有的附件草稿和待发射区顶掉。
- 表单收起后只保留一行紧凑卡片，不改变输入框、附件草稿和待发射区的既有顺序。

## 关联流程

暂无专属流程文档。表单是主会话内的一次局部问答，起止都在同一段对话里，不跨页面。它未来最可能服务的端到端目标是「一段对话做完之后如何收尾」，那需要单独的流程 PRD，本页不预定义。

## 指标与验收

判断这个能力成立的标准：

1. 多题表单出现时，卡片显示是哪位成员在问、当前第几题共几题；Agent 没写别的正文时，时间线不出现空消息。
2. 只有一题的表单不显示进度，导航行直接是发送。
3. 第一题看不到「上一步」；最后一题看不到「下一步」而看到「发送」。
4. 当前题一项没选时「下一步」仍可点，该题在进度上保持未答的样子。
5. 从第三题点进度第一格能跳回去，原答案原样在；改掉它再往前走，后面已答的题没被清空。
6. 一题都没答时发送禁用，界面上不出现解释这条规则的文字，悬停也不出现。
7. 单选、多选、自由输入混合作答并跳过一题后发送，消息按题序逐行呈现问题与答案，多选按原顺序排列，跳过的题不出现，全程不含 description。
8. 发送后卡片消失，时间线出现对应用户消息，没有多余的「已回答」标记。
9. 答到第二题切换到别的会话再回来、或退出应用重开，都停在第二题且前面的答案还在。
10. 表单没发送时用户直接在输入框打字发送，普通消息照常进入时间线；消息发送成功后表单、当前题位置和未发送答案草稿销毁，发送失败时表单与草稿保留。
11. 旧表单答到一半时 Agent 发来新表单，旧卡片被替换，新表单从第一题开始。
12. Agent 写出不合规的表单写法时，输入框上方没有卡片，那段内容作为普通文字显示在正文里。
13. 全程只用键盘可以完成一次完整作答并发送。
14. 表单出现时，已有的附件草稿和文本胶囊仍在表单与输入框之间，没有被顶掉。
15. 每道单选题和多选题的最后一项都是「自己写」输入项，即使 Agent 只写了一个预设选项；一题的选项总数不超过五项。
16. 在「自己写」里写字，这题在进度上变成已答，不用另外勾一下；单选题里原来选中的预设项自动让出，多选题里预设项保持选中。把字清空，这题回到未答。
17. 选中「自己写」并发送时，那一行取用户写的原文；多选题里它排在选中的预设项之后。
18. Agent 写出 5 题的表单、或某题写了 5 个预设选项时，输入框上方没有卡片，那段内容作为普通文字显示在正文里。
19. 展开表单右上角显示小号圆角 outline 的向下箭头按钮；点击后卡片收起为紧凑一行，按钮变为向上箭头，点击后恢复原题和原答案。
20. 收起期间答案草稿、当前题位置和发送能力保留；切换会话或重启后表单默认展开，但答案和当前题按原规则恢复。
21. 点击左下角「跳过」后整份表单消失，不产生用户消息，未发送答案草稿被销毁，旧 Agent 消息中的表单不会重新出现。
22. 有活动表单时从正常输入框成功发送独立消息，普通消息照常进入时间线，表单和未发送草稿直接销毁，不弹确认；发送失败时表单按失败恢复保留。

## 非目标

- **Agent 收工场景的按钮化。** 「这段对话做完了，要不要合并、要不要清理独立工作空间」是这个能力最先要服务的用例，但它需要自己的一份流程定义，本页只做表单能力本身。
- **表单的层级化配置。** 不做内置、团队、项目三层的收尾动作清单，也不做任何形式的表单配置文件。表单只能由 Agent 当场产出。
- **题目之间的条件跳转。** 不做「答了 A 才出现第三题」。
- **必填校验与默认值。** 每题都能跳过，唯一的限制是整份表单全空时不能发送。
- **发送前的汇总确认屏。** 答完最后一题不额外多一屏让用户复核全部答案。想回看点进度跳回去就行，为此多加一屏不值。
- **已跳过或已销毁表单的撤销/恢复。** 明确放弃动作不提供撤销入口。
- **把用户手打的回答沉淀成下次的按钮。**
- 表单在右侧栏分析会话中的呈现。

## 待讨论

- **Agent 表达表单的具体写法。** 产品这边已经定死了能表达什么：最多 4 题，每题是单选、多选或自由输入，选择题最多 4 个预设选项，「自己写」由产品补。剩下的是用什么语法把这些写出来，属于实现，但它直接决定 Agent 能不能稳定写对——写不对，这个能力就等于不存在。建议实现前先定，判定不通过时一律走本页的降级规则，不新增别的失败表现。
