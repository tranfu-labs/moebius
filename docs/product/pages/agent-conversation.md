## 页面目标

单 Agent 会话让用户不必阅读完整日志，也能持续判断三件事：

1. 这名 Agent 现在是否仍在实际执行；
2. 它最近正在做什么可观察动作；
3. 这一步已经实际执行多久，结束后总共耗时多久。

它既可以作为子任务标签中的一段独立会话出现，也可以嵌入团队全局时间线，表现主 Agent 或专业成员的单次工作。两种承载方式复用同一套活动、计时、终态、完整输出与恢复语义，不各自发明一套状态。

主 Agent 在全局会话中的运行记录同样复用本页规则，但继续显示在全局时间线里，不额外打开一份独立会话。

## 用户场景

- Agent 一段时间没有产生新文字，用户想确认它仍在执行还是已经停住。
- Agent 连续读取文件、搜索代码、修改文件和运行测试，用户只想看到当前最新动作，不想在主时间线里读工具日志。
- 用户想知道这一轮实际执行了多久，并明确区分运行时长与完成时刻。
- 用户发现 Agent 做法不对，想只停下这一名 Agent，不影响同时工作的其他成员。
- 用户在运行中看到额度、认证或服务繁忙异常，想及时停下并用另一执行配置在当前对话重跑，而不是等待一个固定总时长上限。
- 用户使用自备 API 的 Pi Agent，想像查看 Codex 一样看到计划、工具、Web、MCP、Skill、子 Agent 与上下文压缩过程，而不是只得到最终回复。
- 用户的 Provider 档案、Key、模型或服务商已经不可用，想知道本次运行能否修复后继续、只能临时重跑，还是需要永久迁移当前会话。
- 应用关闭或会话进入可恢复暂停后，用户重新打开并继续同一次 run。
- 一步没跑起来、卡住、被停下或无法继续原执行，用户需要看到明确事实并决定是否重试、重新运行或换做法。

## 入口与去向

- 团队全局时间线为每个正在工作的成员嵌入一条本页定义的运行记录；主 Agent 也复用同一套规则。
- 用户点击全局时间线中的子会话卡片行，在[主页面右侧栏](./main-right-sidebar.md)打开该子任务标签。标签内部是一段完整的单 Agent 会话。
- 用户点击「完整输出」，在右侧栏打开这一步唯一的过程标签；同一步的任一次尝试都进入同一标签，并定位到用户点击的那次尝试。
- 子任务标签关闭只关闭查看入口，不取消或停止其中的 Agent。
- 单 Agent 会话不进入主侧边栏，不提供创建、重命名或删除子任务的入口。

```text
│                                                         │

│ 正在运行命令 · pnpm test                                │
│                                   [完整输出 →] [停下]    │
│ ─────────────────────────────────────────────────────── │
│ ┌─────────────────────────────────────────────────────┐ │
│ │ 继续说点什么…                                  ↑   │ │
│ └─────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────┘
```

### 最新活动原地更新

```text
时间点 A                                      同一条运行记录
│ 测试                                      已进行 00:18 │
│ 正在搜索代码 · “activeRun”                            │
│                                   [完整输出 →] [停下] │

                    ↓ 下一条真实事件到来

时间点 B
│ 测试                                      已进行 01:24 │
│ 正在修改文件 · run-block.tsx                          │
│                                   [完整输出 →] [停下] │

                    ↓ run 进入终态

时间点 C
│ 测试                                       耗时 02:18 │
│ 已完成 Markdown 接入；相关测试通过。                  │
│                                           [完整输出]  │
```

这里的“滚动”是事件驱动的原地替换，不是按定时器轮播旧动作。没有新事件时保留当前活动行，只继续更新「已进行」；不得为了制造动感循环播放历史事件。

### 运行监督与异常重跑

```text
服务繁忙·运行中
│ 开发                                      已进行 03:18 │
│ 对方服务繁忙，正在第 3 次重试                         │
│                                   [完整输出] [停下]   │

用户停止·保留半截正文
│ 开发                                       耗时 03:26 │
│ 已经定位到 Kimi ACP 的终局映射，下一步需要…          │
│ 内容不完整                                             │
│ ⏹ 已停止（系统侧；用户自己停的不显示状态）            │
│          [完整输出] [重试] [换执行配置重跑…]          │

换执行配置重跑
│ 执行引擎  [Pi API ▾]                                  │
│ Provider  [DeepSeek · 我的开发 Key ▾]                 │
│ 模型      [deepseek-chat ▾]                           │
│ 思考程度  [默认 ▾]                                    │
│ 只用于这一次重跑，不会修改团队成员设置。              │
│                                  [取消] [仅本次重跑]  │
```

选择 Codex、Claude Code 或 Kimi 时显示对应 CLI 的模型与实际支持的思考程度；选择 Pi API 时只显示当前已就绪 Provider 档案、该档案已验证模型与模型实际支持的思考程度，不显示 Key，也不要求 Base URL。档案仍可用但默认模型已经下架时，模型字段保持空白，用户明确选择前不能提交。运行中的重试次数只显示执行引擎明确提供的值；没有可靠次数时省略数字。异常终局中的半截正文仍使用既有安全 Markdown 渲染，窄宽度下正文、说明和操作自然换行，不产生页面级横向滚动。配置目录加载失败时保留原终局内容与普通重试；本页允许迁移当前会话，但不修改团队默认配置。

当一组尚未完成的工具从没有变为至少一个时，系统开始一个连续的工具在途区间，直到这组工具全部收到对应结果并再次清空；区间内并行工具陆续开始或结束，不会重置这个区间的独立工具等待上限。该上限默认是两小时（120 分钟），以容纳正常的大型构建、全量测试、签名和打包；它仍是有限上限，不等于无限等待。本次只调整默认时长，不改变这段连续在途区间的计时方式，也不改变现有空转窗口、服务繁忙等待和长运行提醒的窗口、触发条件或用户反馈。本地部署仍可调整该上限。

### 完成时间

```text
默认
│ 测试                                       耗时 02:18 │

悬停或键盘聚焦耗时
│ 测试                         耗时 02:18（完成于 14:32）│

长任务
│ 测试                                    已进行 1:02:18 │

非今天完成
│ 测试              耗时 1:02:18（完成于 7月25日 14:32）│
```

不足一小时的时长显示 `mm:ss`，达到一小时后显示 `h:mm:ss`，小时位不补零。运行中常驻显示「已进行」，进入终态后常驻显示「耗时」。

「完成于」只在悬停或键盘聚焦耗时后出现，并提供等价的可访问说明：今天完成显示「完成于 14:32」，本年内非今天显示「完成于 7月25日 14:32」，跨年显示「完成于 2025年7月25日 14:32」。界面不再显示无法分辨是开始时间还是结束时间的裸时间。

### 可恢复暂停

```text
│ 测试                                      已进行 01:24 │
│ 已暂停，可恢复                                          │
│                              [完整输出 →] [继续]        │
```

暂停期间「已进行」冻结。恢复后继续累计同一次 run 的实际执行时间，不把暂停期间补算进去，也不创建一段让用户误以为是全新工作的重复历史。

### 异常终态

```text
│ (画像) 测试                                耗时 02:18 │
│   已经产出的正文照常显示在这里……                       │
│   [内容不完整] [⚠ 没有启动  ↻ ⚙ 📄]                    │
```

**终局状态不接管消息。** Agent 已经产出的内容（含半截正文）按普通消息渲染——同一个画像、同一个正文位置；终局状态只是它下面额外的一枚气泡，不把正文收进自己的容器里。状态气泡按内容宽度排布，不占满整行；恢复动作用图标按钮加 tooltip 承载，不用文字按钮铺一行。

状态名是**短名词短语**：「没有启动」「无响应」「已停止」「已被系统停止」「无法继续」「多次未能启动」「额度不可用」「服务繁忙」「需要重新登录」「结果不完整」。它们彼此区分，是机器故障、用户动作或恢复校验事实，不解释成 Agent 的业务判断，也不使用「开发失败了」「验收未通过」之类可能混淆专业判断的文案；不使用「这一步…」这类向用户复述其处境的句式。

**终局记录归属到执行它的那名成员。** 界面上显示的身份必须来自这次运行的真实记录——成功与失败是同一次运行的两个终态，不因为结束方式不同而丢掉是谁在跑。无法确定成员时如实呈现：只给出运行事实与时间，不得用占位成员名或默认画像顶替，也不得把它说成与成员无关的系统通知。

**用户自己发起的停止不呈现状态。** 用户按下「停下」后，他已经知道结果；再报一句「你让这一步停下了」是噪音。这条记录只显示已产出的正文与「内容不完整」标记，恢复动作（重试、换执行配置重跑、完整输出）按「历史消息轻操作」在 hover / focus-within 时浮出。系统侧停止仍然呈现状态——那是用户不知道的事。

Kimi ACP 仅返回 `end_turn` 不能单独证明本轮产生了可交付结果。若本轮既没有非空
Agent 可见文本，也没有进入终态的工具结果，系统把它记为「没有启动」，显示
稳定的 Kimi 空响应说明、终端自查引导和重试入口；不得把空白 Agent 回复记成成功，也
不得从本地 wire、stderr 或用户提示词猜测额度、认证或“用户本来就不需要回复”等原因。
无文本但有
已完成或已失败工具结果的本轮仍是合法完成；ACP v1 的裸 `end_turn` 只是终止元数据，
不是终态内容。合法无文本完成不新增空白 Agent 消息，但 run 正常完成并推进该 Agent
的公开时间线 cursor，避免后续 resume 重复接收同一输入。

这类空响应失败仍保留已观察 Kimi session 的身份关联，后续尝试只能 resume 同一
session，不得创建 replacement session；但当前失败 attempt 不建立可持久读取过程的
execution link，因此重启后「完整输出」只如实显示该 attempt 的记录不可用。原始
provider 诊断只留在本机诊断日志，不进入普通时间线。

## 区域与信息

### 步骤、尝试与 run

- **步骤**是用户可见的一次工作单元，也是过程标签的聚合单位。初次执行、用户点击「重试」产生的后续执行，都属于同一步。
- **尝试**是步骤内按发生顺序排列的第 1、2、3 次执行；每次尝试恰好对应一个 run。首个 run 是第 1 次尝试，每次重试创建一个新 run 并成为下一次尝试。
- **继续**恢复同一外部执行会话中的同一未完成 run，因此不增加尝试次数。**重试 / 重新运行**创建新的 run 和尝试，但若仍是同一持久 Agent 身份，provider 层继续 resume 该身份已经建立的同一个 external session，不创建 replacement session。
- Codex thread、Claude Code session、Kimi session 与 Pi session 都属于这里的外部执行会话。用户在页面上只看到“继续原生上下文”“原生上下文已重新建立”或“已迁移到新配置”等可理解事实，不显示外部 ID、执行代或内部关联字段。
- **改一改重发**会新增用户消息，因此开启一个新步骤和新 run，不与原步骤的尝试聚合。
- 关联用户消息包含合法 `moebius-ref:` 时，**继续 / 重试 / 重新运行 / 恢复失败后的重新执行 / 改一改重发**都只使用各自关联消息中已持久化的可见文本，不读取或刷新链接目标。该规则不改变步骤聚合、尝试编号或持久 Agent 的 provider session 复用规则。
- 产品内部用稳定的步骤关联把多次尝试聚合起来，但界面不显示 session、step、run 或外部会话 ID。

### 消息时间线

- 用户与 Agent 消息按时间顺序显示；普通消息的发送或完成时刻只在悬停时显示。
- 已完成消息使用完整 Markdown 静态渲染；安全规则与全局会话一致。
- 一个运行中的 run 无论产生多少结构化事件、工具调用或进度 Markdown，都只占一条临时运行记录。
- run 进入终态后，临时记录由最终 Agent 消息或结构化系统事实接管，不在历史中同时留下临时记录和最终消息。
- 「耗时」只在承接该 run 的一处显示，不在临时记录、最终消息和系统事实中重复。

### 最新活动

活动行只能来自当前 run 已经产生的可观察事实，不得由模型根据上下文猜测。

展示层按以下规则选择一条最新活动：

1. 显示所有来源中时间最新、且晚于或等于当前活动游标的事件；活动游标只向前移动，不因某个较早开始的并发工具仍在执行而回退；
2. 若最新事件来自仍在执行的结构化工具或命令，显示其进行态；若来自刚完成的工具，显示完成态并保持到更晚事件到来；
3. 只有多个事件时间相同时，才按「结构化工具或命令 → 文件读取、搜索或修改 → Agent 主动输出的可见进度 Markdown」裁决；
4. 当前 run 尚无可展示事实时，显示中性的「正在处理…」。

展示层把事实清洗成「一个动作 + 一个安全对象」，例如：

- `正在运行命令 · pnpm test`
- `正在搜索代码 · “activeRun”`
- `正在读取文件 · operator-console.tsx`
- `正在修改文件 · run-block.tsx`

开始事件使用「正在…」，完成事件立即改为「已完成…」，随后再被更新事件替换。已经完成的工具不得继续显示成「正在运行」；较新的并发工具完成后，也不得闪回显示更早工具的旧开始事件。

活动行不展示命令参数、命令输出、绝对路径、运行目录、内部 ID、原始事件名或其他机器细节。对象过长时单行截断，悬停与键盘聚焦提供完整的安全文本。更详细但已经安全清洗的过程进入「完整输出」；未经清洗的 Provider 错误、请求响应载荷、授权信息和内部协议数据只能进入受信任的本机诊断，不得进入任何用户可复制界面。

运行监督只把新增 Agent 正文、非空 reasoning、工具调用开始或结束、明确文件改动视为真实进展。当一组工具已经开始、但仍有至少一个工具没有收到匹配的结束或结果时，属于用户可见的在途工作：通用空转计时暂停，改由独立且更宽的工具执行上限监督；只要这组在途工具还没有清空，并行工具的开始或结束都不会重置该上限；全部工具完成并清空后，才从那个时刻重新判断是否有新进展。这样既不能把合法长命令误判成卡住，也不能让卡在凭据、网络或子进程里的工具无限运行。重试回显、配置更新、usage、状态心跳和重复事件可以更新诊断或说明，但不得延后“多久没有真实进展”的判断。执行引擎明确报告可重试的服务繁忙时，活动行原地显示正在重试；能取得可靠次数时显示第几次，取不到时只说正在重试，不编造次数或把服务繁忙写成额度耗尽。某个 provider 没有上报该信号时，界面不得声称已经识别服务繁忙。

### 运行耗时

运行耗时衡量的是本次 run 真正占用 Agent 执行进程的累计时间：

- 排队等待不计入；
- 从 Agent 执行进程真正启动时开始累计；
- 应用关闭或 run 进入可恢复暂停时停止累计；
- 恢复后继续累计同一次 run 的实际执行时间；
- run 进入成功、没跑起来、卡住、停下或无法继续中的任一终态时停止累计；
- 「完成于」记录真正进入该终态的本地时刻，不是 run 创建、排队或开始执行的时刻。

总运行时长只用于提醒用户这一步已经运行较久，不得仅因达到固定墙钟上限而杀掉仍有真实进展的进程。系统仍可按“距离上一次真实进展的时间”识别空转，也可对一组工具尚未全部完成的连续在途区间、或执行引擎持续明确报告的服务繁忙使用各自独立、可配置的等待上限；这些判据都必须留下可理解的结构化原因。

计时显示至少精确到秒。界面短暂失焦、滚动离开记录或切换右侧栏标签不改变累计；是否正在执行由运行事实决定，不由组件是否可见决定。

只有执行进程真正启动过，才显示「已进行」或「耗时」。启动前即进入「没跑起来」的 run 不显示虚假的 `00:00`；如果进程已经启动后退出，则显示真实累计耗时。「完成于」仍可用于说明终态发生时刻。

### 完整输出

- 当前执行引擎能提供稳定过程记录时，运行中与异常记录常驻提供「完整输出」入口；不能提供时，同一位置常驻明确的不可用说明，不显示可点击入口。
- 过程记录可用时，成功结束后入口仍保留；在全局时间线中可收敛为消息悬停或键盘聚焦时出现的图标，在独立子任务会话中可以保留文字入口。不可用说明不伪装成按钮。
- 入口按「所属会话 + 步骤」去重。同一步任一次尝试的入口都聚焦同一过程标签，并定位到该尝试；不同步骤即使由同一成员执行，也不能借用或合并。
- 过程记录不可用时明确说明不可用，并保留最终回复；不得拿最终回复冒充完整输出。
- 「完整输出」只在当前执行引擎能提供稳定、可读取的过程记录时可用；能力不足时显示明确的局部不可用说明，不自动改用另一套执行引擎的记录。
- Pi 的计划、reasoning 摘要、文件与命令工具、Web、MCP、Skill、子 Agent、按模型能力处理的图片输入、压缩与恢复事件按发生顺序进入同一次尝试的过程记录。首版 DeepSeek V4 是文本输入模型，图片在请求服务商前原位显示限制。尚未配置或本次不可用的外部能力显示其真实不可用事实；不得把未执行的能力写成已调用，也不得因为某一扩展不可用而隐藏仍然完成的基础编码活动。
- 长上下文被 Pi 压缩后，时间线与主对话共用唯一一条「已整理较早上下文」系统事实；完整输出可以额外保留压缩发生的时点和执行引擎返回的安全摘要，但不得再生成第二个压缩事件名称。后续消息仍属于同一原生会话，不显示成新步骤或新 Agent。
- 完整输出与普通时间线都不得显示完整 API Key、Authorization 值、其他可复用凭据、服务商原始错误正文、原始请求响应载荷或内部协议对象；Provider 只以服务商与用户可辨认的档案名称出现。用户需要行动时显示经结构化和脱敏后的原因摘要及可执行去向，未经清洗内容只留在受信任的本机诊断。
- 完整输出的内容、分页、跟随最新和标签行为由[主页面右侧栏](./main-right-sidebar.md)定义。

## 操作与反馈

### 继续说话

- 独立子任务会话的输入框把消息送入该子会话；用户可以继续说话或按团队规则提及成员。
- 嵌入全局时间线的运行记录不额外带输入框；用户继续说话使用全局会话 composer，并由主 Agent 接收和调度。
- 用户发送新消息不会默认停止当前 run。需要立即停止时使用明确的「停下」。

### 添加与发送附件

- 独立子任务会话与主对话复用同一附件草稿：点击「＋」、拖入文件或粘贴图片都把内容复制到应用托管区，保留文件名、类型、大小与顺序，不把原始本地路径放进消息或 Provider 请求。
- PNG、JPEG、GIF 与 WebP 按当前 run 绑定模型的真实图片输入能力交付；SVG 与其他文件作为普通文件及安全副本清单交付。当前模型不支持图片时原位说明限制，不改用另一模型、Provider 或 CLI。
- 正文与附件全部准备成功才共同发送；失败时保留完整草稿。已经发送的托管副本随消息用于继续、重试、重新建立或迁移后的新上下文，不重新读取可能已经移动、改名或删除的原文件。
- Pi 只获得当前消息及本轮任务需要的附件内容；同一 Provider 档案不会让它自动读取其他消息附件、项目外文件或应用数据目录。

### 停下

- 「停下」只作用于这条运行记录绑定的当前 run，不连带停止父会话、主 Agent或其他并行成员。
- 独立子任务会话和专业成员的嵌入记录在运行时直接提供「停下」。
- 主 Agent 嵌入全局时间线时复用本页的停止语义，但入口位于全局 composer 的方形按钮，不在运行记录中重复。
- 停下后留下「已停下」事实、累计耗时、完成时刻、已经产生的完整输出，以及中断前已经对用户可见的 Agent 正文。半截正文与终局事实一起显示并明确标注“内容不完整”，不得因 run 结束而清空，也不得冒充成功回复。

### 重试与恢复

- 首版不自动重试，也没有“重试耗尽”状态或次数上限。「重试」全部由用户显式触发。
- 「重试」使用原输入创建新的 run；「改一改重发」把原用户消息回填供用户修改，发送后创建新消息和新 run。两者都从零计时，不修改原消息，也不复用原 run；未选择临时执行配置时，同一持久 Agent 身份已有 external session 仍只 resume 该 session。原消息包含合法 `moebius-ref:` 时，重试与重发都只把对应消息中可见的 Markdown 交给 Agent，不读取链接目标。
- 已停下、卡住、认证或凭据失败、额度不可用、服务持续繁忙或没有产出完整结果时，用户可以在终局记录上选择执行引擎、模型与实际支持的思考程度后重跑；Pi API 还需选择已就绪 Provider 档案。该选择默认且首版只作用于这一次新 run，不修改团队成员配置或会话冻结快照，也不自动切换引擎。每次用户确认都代表一次新的重跑意图；即使再次选择同一配置也必须能创建下一次尝试，同时同一次提交的网络重放不得重复创建。
- 临时执行配置不能 resume 原引擎会话。系统为这次新 run 建立独立的一次性 provider 身份并走 full，把当前公开时间线作为上下文；正常退出后恢复同一 run 时仍 resume 这次一次性会话。该 run 终结后，后续未显式选择临时配置的消息继续使用成员原冻结配置及其原 canonical provider session。
- 可恢复暂停提供「继续」；「继续」只恢复同一外部执行会话、同一次尝试与同一 run，并继续累计原耗时。恢复期间仍使用对应用户消息的可见文本，不读取引用目标。「重试」「改一改重发」与「继续」不得混用。
- 恢复校验失败或外部执行会话丢失时不自动重新执行。原 run 进入「无法继续」，冻结已有耗时；只有原冻结配置完整可用时才提供「重新建立原执行」。用户确认后页面先明确提示原生上下文将从 Moebius 已保存的可见时间线重新建立，再以原输入创建新的 run 并从零计时；旧尝试、耗时、过程和文件副作用继续保留，不读取其中的链接目标。
- Pi 的 Key 或凭据明确失效时显示「Provider 需要处理」和匹配的设置修复入口；档案停用时显示「Provider 已停用」和重新启用入口。修复、重新启用、验证及保存完成后，用户回到原记录显式继续或重试，页面不得静默代发请求。
- 冻结模型或服务商下架时，页面同时提供「换执行配置重跑」与「迁移当前会话」：前者只影响一次尝试，后者让用户选择另一已就绪模型或 Provider 档案，并永久改变这段会话中该 Agent 后续运行的冻结配置，但不修改团队默认值。迁移完成后显示旧配置、新配置及「原生上下文已从当前可见时间线重新建立」。
- 历史 Provider 档案已经缺失时保留服务商、档案历史标识、冻结模型与思考程度；不提供必然失败的修复或原配置重建，只允许迁移到另一已就绪档案，或「结束继续能力并保留历史」。结束后本页仍可阅读消息、尝试、过程和附件，但不能再向该 Agent 发送消息或重跑。
- 迁移提交期间禁用重复操作；失败时保持原冻结配置与旧过程不变并给出重试，不能留下配置已经变更但原生上下文没有建立的半成品。迁移成功后的新 run、后续消息与应用恢复都使用新配置；旧原生会话和过程只读保留，不再 resume。
- 用户关闭右侧栏或切到父会话不会取消迁移；返回时继续显示同一进度或终态。只有本地尚未提交前可以主动取消；一旦进入提交阶段便等待明确的成功或失败结果。
- 链接目标缺失、不可访问或读取失败都不是创建新 run 的失败阶段；重试、重新运行与改一改重发继续服从各自原有的消息、附件、计时和 provider 恢复规则。
- 同一步的完整输出按第 1、2、3 次尝试依次聚合，保留每一次的独立过程与计时，方便用户对照；主会话不得另加一个跨重试累计耗时。
- 普通重试沿用同一持久 Agent 的 provider 上下文；显式临时执行配置只按上一条的一次性身份例外处理。两种重跑都不回滚已经产生的文件改动，界面必须保持这一说明。

### 退出应用与恢复

- 用户正常退出且当前 run 已经建立原生会话时，本页先进入「已暂停，可恢复」并冻结耗时；下次启动自动继续同一次尝试，不新增用户消息、不从零计时，也不要求重新选择附件。原生会话尚未建立便失败时只显示对应的「没跑起来」。
- 崩溃、强制结束或断电后的遗留 run 在下次启动显示「一步卡住了」，等待用户显式重试；不得自动发出新的 Provider 请求或产生服务商用量。重新打开右侧栏只恢复查看现场，不等于用户授权重跑。
- 恢复前若 Pi 档案、凭据、服务商或模型状态已经变化，页面进入与原因匹配的修复、迁移或结束路径，不以通用卡住覆盖，也不静默换配置。
- 应用退出或崩溃打断迁移后，重新打开只出现两种可观察结果：迁移完整成功并显示新配置，或恢复迁移前配置并显示「上次迁移未完成」及重试入口。不得显示已迁移却继续使用旧原生上下文，也不得自动重发迁移请求。

## 页面状态

下表中的「完整输出」只在当前执行引擎提供稳定过程记录时是可点击操作；否则同一位置显示不可用说明，不影响其他操作。

| 状态 | 主要表现 | 可用操作 |
| --- | --- | --- |
| 排队中 | 明确显示「等待开始」，不显示「已进行」 | 继续说话；按所属容器规则取消或停下 |
| 已启动、尚无事件 | 「已进行」+「正在处理…」 | 完整输出、停下 |
| 工具执行中 | 「已进行」+ 最新一条结构化活动 | 完整输出、停下 |
| 仅有 Agent 进度 | 「已进行」+ 最新可见进度摘要 | 完整输出、停下 |
| 服务繁忙并重试 | 「已进行」+ 可确认的繁忙与重试事实；次数仅在可靠时显示 | 完整输出、停下 |
| 可恢复暂停 | 已启动过则显示冻结的「已进行」+「已暂停，可恢复」 | 完整输出、继续 |
| 成功结束 | 最终回复 +「耗时」 | 完整输出、继续说话 |
| 没跑起来 | 原因摘要；仅进程真实启动过时显示「耗时」 | 完整输出、重试、继续说话 |
| 卡住 | 卡住事实；仅进程真实启动过时显示「耗时」 | 完整输出、重试、继续说话 |
| 已停下 | 停下事实；仅进程真实启动过时显示「耗时」；有正文时保留并标记不完整 | 完整输出、重试、换执行配置重跑、改一改重发、继续说话 |
| 额度或服务不可用 | 可靠时显示已确认原因；仅有间接证据时保守说明没有产出完整结果及可能原因；已有正文标记不完整 | 完整输出、重试、换执行配置重跑、继续说话 |
| Pi Key 或凭据需要处理 | 明确显示档案需要修复；保留原终态与已有耗时，不把暂时网络失败写成 Key 失效 | 完整输出、前往设置修复、换执行配置重跑 |
| Provider 已停用 | 明确显示档案已停用，不把它写成 Key 失效 | 完整输出、前往设置重新启用、换执行配置重跑 |
| Pi 冻结模型不可用 | 保留原模型，不预选档案默认模型，明确后续普通运行仍不可继续 | 完整输出、迁移到同档案另一已验证模型、换执行配置重跑、结束继续能力并保留历史 |
| Pi 服务商已不受支持 | 明确原档案无法修复，需要另一份已就绪档案 | 完整输出、添加或选择新档案并迁移、换执行配置重跑、结束继续能力并保留历史 |
| 历史 Provider 档案缺失 | 保留服务商、档案历史标识、模型和思考程度，不提供无效修复 | 完整输出、迁移当前会话、结束继续能力并保留历史 |
| 迁移中 | 显示旧配置 → 新配置和正在建立新原生上下文；操作防重复 | 查看已有完整输出、等待；本地尚未提交前取消 |
| 迁移失败 | 原冻结配置与旧过程保持不变，显示失败摘要 | 完整输出、重试迁移、选择其他已就绪配置、保留历史 |
| 已迁移 | 显示旧配置 → 新配置和原生上下文已重新建立 | 完整输出、继续说话 |
| 无法继续 | 恢复校验失败事实 + 已有耗时（若有）；原配置仍可用时才可重建 | 完整输出、重新建立原执行或按原因迁移、继续说话 |
| 已结束继续能力 | 消息、尝试、过程和附件保持只读，明确不再接受新运行 | 查看完整输出、返回父会话 |
| 过程记录不可用 | 最终回复或终态事实仍保留 | 查看不可用说明、继续说话 |

排队、执行、暂停和终态必须来自结构化运行事实；不得根据「验收」「通过」「完成」等自然语言关键词推断程序状态。

## 弹层与危险操作

本页不包含删除、回滚或清理历史。迁移会永久改变当前会话中这一 Agent 的后续运行配置，「结束继续能力并保留历史」会永久关闭该 Agent 在当前会话中的继续、重试与恢复能力，二者都不改变团队默认配置，也不删除既有消息、附件、过程或文件结果。

「停下」会中断当前执行，但不删除已产生的消息、过程或文件改动，不弹二次确认；按钮文案和作用对象必须明确。用户如何处理半截文件改动由跨页面恢复流程另行定义。

「迁移当前会话」确认前必须并列显示旧配置、新配置、将建立新原生上下文、旧过程仍会保留以及不会修改团队默认值。「结束继续能力并保留历史」必须二次确认并列出被关闭的操作；取消后回到原终局，不改变配置或引用。

## 响应式与窗口行为

- 最新活动、运行耗时和主要操作必须在同一记录内可扫视；窄宽度下优先保留角色、耗时与「停下」。
- 活动对象先单行截断；「完整输出」可收敛为带可访问名称的图标，不把内部信息换行铺满时间线。
- 独立子任务会话位于窄窗口的覆盖式右侧栏时，滚动、输入和停止仍可完成；关闭覆盖层后回到父会话原滚动位置。
- 耗时的悬停信息必须同时支持键盘聚焦和屏幕阅读器，不依赖鼠标才能理解「完成于」。

## 关联流程

- 团队如何派工、并行、接回专业成员结果并最终收束，由[主页面会话区](./main-conversation.md)定义。
- 子任务如何从全局会话进入、如何在右侧栏开关和保留标签，由[主页面右侧栏](./main-right-sidebar.md)定义。
- Provider 修复、停用、验证、模型引用和删除保护由[设置](./settings.md)定义；当前会话只投影故障事实和可执行去向。
- 团队成员默认执行配置与日常调整由[Agent 团队](./agent-teams.md)定义；一次性重跑与迁移当前会话都不修改团队默认值。
- Pi API 的跨页面运行、恢复、迁移和数据边界由[BYOK Agent 运行流程](../flows/byok-agent-runtime.md)定义。

## 指标与验收

### 产品指标

- 用当前版本与候选版本执行相同的可用性测试；每个版本都必须取得至少 10 个“执行已持续至少 30 秒且运行记录处于可见窗口”的有效任务。运行中打开「完整输出」的有效任务数 / 有效任务总数，候选版本相对当前版本下降 20%。若当前版本比率为零，则候选版本目标改为保持零并报告绝对比率，不计算相对下降。测试记录只记动作与时刻，不用主观访谈替代计数。
- 在同一批测试中，每个版本都必须取得至少 10 个“进程仍存活且最近 30 秒存在结构化活动”的有效任务。用户停下后 60 秒内又对同一步重试或重新运行的有效任务数 / 有效任务总数，候选版本相对当前版本下降 30%，作为“正常工作被误停”的代理指标。若当前版本分子为零，则候选版本目标改为继续保持零并报告绝对比率。
- 每个版本至少 5 名目标用户完成时间辨识任务：分别指出运行中时长、终态总耗时与完成时刻；候选版本三题全对人数 / 参与人数必须为 100%。失败样本记录误读的是哪个字段，不用“理解错误下降”这类无分母表述。

### 验收标准

1. 任一执行中的 Agent 只显示最新一条活动，新事件到来时原地替换，历史工具事件不在会话时间线中堆积或循环轮播。
2. 活动摘要只来自当前 run 的结构化事件或 Agent 可见进度；无事实时显示「正在处理…」，不生成猜测文案。
3. 最新活动游标只向前移动；较新的并发工具完成后不闪回较早工具的旧开始事件，只有更晚的新事件才能替换。
4. 工具完成后不得继续显示「正在…」；展示文本不泄露参数、输出、绝对路径、内部 ID 或运行目录。
5. 排队期间不显示或累计「已进行」；执行进程真正启动后才开始累计。
6. 应用关闭或进入可恢复暂停时耗时停止，恢复后继续累计同一次 run 的实际执行时间。
7. 不足一小时的时长显示 `mm:ss`，达到一小时后显示 `h:mm:ss`；运行中常驻显示「已进行」，终态常驻显示一次「耗时」。
8. 「完成于」对应真正进入终态的时刻，不是创建、排队或开始执行的时刻。
9. 今天完成显示「完成于 HH:mm」，本年内非今天显示「完成于 M月D日 HH:mm」，跨年增加年份；悬停、键盘聚焦和屏幕阅读器获得等价信息。
10. 一个步骤聚合一次初始执行和用户触发的后续重试；每次尝试恰好对应一个 run 并独立计时，同一步只打开一个过程标签，不显示跨重试累计耗时。
11. 主 Agent 在全局时间线中复用本页活动与计时规则，但不另开独立会话；其停止入口仍在全局 composer。
12. 独立子任务会话和专业成员记录可以只停下自身，不影响主 Agent 或其他并行成员。
13. 首版不自动重试；「重试」和「改一改重发」分别出现为新的尝试或新步骤，「继续」仍停留在原尝试、保留原耗时和已经产生的正文。用前一轮约定的临时记忆标记继续对话时，普通新消息和重试仍能使用同一原生上下文；页面不会在没有提示的情况下变成一段全新对话。
14. 进程未真正启动时不显示 `00:00`；过程记录、暂停、重试和终态在切换标签或重启应用后仍能恢复，不可用时如实说明，不用最终回复冒充完整输出。
15. 自然语言中的「完成」「验收」「通过」不会触发程序终态或改变耗时累计。
16. 以包含合法 `moebius-ref:` 的用户消息启动 run，在链接目标随后新增、修改或变得不可用后执行「继续」「重试」「重新运行」或「改一改重发」，每次都只使用对应用户消息中可见的文本，不读取目标新增内容，也不把历史隐藏来源上下文拼入 prompt。
17. 在嵌入全局时间线和独立子任务会话中，链接目标不可用不阻塞「重试」或「重新运行」，新尝试按普通规则创建并保留原终态、原消息与完整输出。
18. 通过「改一改重发」修改正文、附件和来源引用后，新消息按编辑后的可见 Markdown 提交；链接目标状态不形成发送前读取阶段或额外失败状态。
19. Kimi、Claude、Codex 与 Pi API 的额度、认证或凭据、服务繁忙、中断、空转和崩溃都显示与实际原因匹配的运行状态；额度或无结果失败不得显示成成功完成，用户停下不得显示成“没跑起来”。
20. 只有真实进展事件才能刷新空转监督；持续配置更新、心跳或重试回显而没有真实进展时，系统在配置的分钟级窗口内进入可理解终态。
21. 总运行时长达到报告阈值时只更新可见提醒，不停止仍有真实进展的 run；可重试服务繁忙超过独立上限时可以停止，并明确说明服务持续繁忙。
22. 异常或用户中止前已经可见的 Agent 正文刷新或重启后仍与终局事实一起显示，并标注内容不完整。
23. 用户从终局记录选择另一 CLI 模型或 Pi Provider 与模型进行「仅本次重跑」后，新尝试仍聚合在当前步骤并显示实际选中的配置；该尝试结束后发送普通新消息，页面重新显示并使用原冻结配置，团队页默认配置也保持不变。
24. Kimi 没有返回可见文本或已结束工具结果时，页面显示可重试的「没有启动」、稳定空响应说明及终端自查引导，不出现空白 Agent 回复、具体额度猜测或原始执行载荷；重试后仍能引用此前同一 Kimi 原生上下文中的可见约定，记录不可读取时「完整输出」如实不可用。
25. Agent 启动托管服务、watcher 或跨本轮任务后，运行项面板能够继续显示和控制它；Agent 本轮成功、失败、停止或进入下一轮都不会让该运行项无提示消失。Kimi 在托管工具完成后迟迟没有结束回复时，页面在有限时间后形成可重试终态，不无限显示运行中，也不把工具成功冒充为 Agent 回复成功。
26. 分别用 Codex、Claude Code、Kimi 与 Pi API 创建并恢复一段会话时，四者都能启动同样的托管运行项；运行前后的用户全局 CLI 配置和 Provider 档案在对应设置界面保持原值，普通 Agent 正文中的伪造运行项描述不会在面板产生进程。
27. 托管能力不可用时，本轮显示明确失败且运行项面板没有新增目标进程；页面不会显示后台进程已经启动。普通一次性 Python、测试和构建结束后直接把结果交给 Agent，只有用户明确要求跨本轮继续或持续监督的有限任务才留在运行项面板。
28. 在只有一个已就绪 DeepSeek Provider、没有任何 ready CLI 的环境中，用户能启动 Pi API 成员并完成一次受控编码任务：页面依次显示读取文件、修改文件和运行测试的活动，最终回复、测试结果及磁盘文件内容彼此一致，全程不出现 sandbox 或逐次工具审批。
29. Pi API 运行的「完整输出」按实际发生顺序显示计划、文件或命令工具、Web、MCP、Skill 与子 Agent 活动；在受控环境让其中任一外部能力不可用后重新运行，页面只把该能力标记为未配置或不可用，仍然发生的基础文件与命令活动继续可见，不宣称缺失能力已经执行。
30. 给 Pi API 成员发送普通文件及 PNG、JPEG、GIF、WebP 图片后，时间线保留文件名、类型、大小、顺序与预览；支持图片的模型能基于图片完成任务，不支持时显示当前模型的真实限制，不静默切换执行引擎。重试与重启恢复仍使用历史消息中的托管附件，不要求重新选择原文件。
31. 在受控长上下文任务触发 Pi 压缩后，主时间线与单 Agent 页只出现同一条「已整理较早上下文」，完整输出可定位压缩时点但不另造第二条压缩事件；随后询问压缩前的公开约定仍能得到连续回答，页面没有新增步骤、成员或迁移提示。
32. Pi 运行与完整输出中的 Provider 只显示服务商、档案名称、模型与思考程度；在输入、工具结果和诊断中准备可识别的测试凭据、服务商原始错误正文及原始请求响应载荷后，普通时间线、活动摘要、错误详情、完整输出和其他可复制界面都不出现完整 Key、Authorization 值、原始错误正文或内部载荷，只显示经清洗的原因摘要与可执行去向。
33. 冻结 Pi Key 明确失效时，原记录显示「Provider 需要处理」并进入匹配的设置修复；档案停用时显示「Provider 已停用」并进入重新启用。暂时断网或限流只保留可重试运行错误，不误导用户更换 Key。修复或启用完成后回到原记录不会自动发请求，用户显式继续或重试后才产生新活动。
34. 冻结模型下架或服务商被支持目录移除时，终局同时区分「仅本次换执行配置重跑」与「迁移当前会话」。完成一次性重跑后，下一条普通消息仍显示原配置不可用；完成迁移后，页面显示旧配置、新配置与「原生上下文已从当前可见时间线重新建立」，之后普通消息持续使用新配置，团队页默认值不变。
35. 历史 Provider 档案缺失时，页面仍显示服务商、档案历史标识、冻结模型和思考程度，只提供迁移或结束继续能力，不出现修复原档案或重新建立原执行。选择结束后消息、附件、尝试和完整输出仍可阅读，输入和重跑入口不可用。
36. 迁移提交期间重复点击不会产生第二次迁移；模拟迁移失败后，页面仍显示原配置、旧过程和失败摘要，可重试或另选配置。只有新配置和新原生上下文都建立成功时才显示「已迁移」，重启后仍保持该结果。
37. 原冻结配置仍然可用、但原生会话本身丢失时，页面才提供「重新建立原执行」并在确认前说明上下文来源；确认后新尝试从零计时，旧尝试、旧耗时、完整输出和已有文件副作用仍保留。配置已经失效或档案缺失时不显示这一操作。
38. Pi 运行中产生的最终回复、计划、reasoning 摘要、工具结果和子 Agent 活动都归入该成员当前步骤；停止该成员只结束这次 Pi 请求，不停止其他成员或已经独立托管的运行项，半截正文刷新页面后仍标记为内容不完整。
39. 迁移、一次性重跑、重新建立原执行和普通重试分别发生后，「完整输出」仍按步骤和尝试定位到用户选择的那次记录；旧 Pi 过程保持只读，新过程不覆盖旧过程，也不借用其他成员或其他执行引擎的输出。
40. 用户从 Provider 修复、迁移或重新启用流程返回窄窗口中的单 Agent 标签时，原终局、滚动位置和操作焦点可恢复；状态变化通过可读文本和可访问名称表达，不只依赖颜色。
41. 正常退出有活动 Pi run 的应用并重新打开后，页面继续原尝试、原耗时与原生上下文；强制结束后只显示「一步卡住了」并等待显式重试。两条路径都不会因为重新打开应用而自动新增用户消息、迁移配置或重复产生一次 Provider 请求。
42. 在迁移提交前关闭右侧栏再返回，页面恢复同一迁移进度；在应用退出或崩溃打断迁移后重新打开，页面要么显示完整成功的新配置，要么恢复旧配置并显示「上次迁移未完成」和重试入口，不出现配置与原生上下文各自成功一半的状态。
43. 「迁移当前会话」确认层并列显示旧配置、新配置、上下文重建、旧过程保留和团队默认值不变；「结束继续能力并保留历史」经过二次确认并列出被关闭的继续、重试与恢复。取消任一操作后原终局、配置、消息、附件和过程保持不变。

## 待讨论

- 是否要在总耗时之外持续显示“多久没有真实进展”。本次只确定机器判据与终局，不新增常驻的无进展计时字段。
- 重试时如何处理上一次已经产生的文件改动，是否需要在新 run 启动前提供差异提醒。
- 排队状态是否允许取消，以及取消后是否记作「已停下」或独立的「已取消」事实。

## 现状参考与产品缺口

当前操作台已经有运行记录、完整输出、停止、失败与卡住事实，也已经能读取 Codex 的结构化过程事件。相较本页定义，主要产品缺口是：

- 主时间线仍以 Agent 可见进度为主，没有稳定投影最新一条结构化工具活动；
- 运行中与终态时间语义未完整区分，用户可能把裸时间理解成开始或结束时刻；
- 实际执行时长尚未明确排除排队与可恢复暂停；
- 现有全局会话与子任务标签尚未在实现中复用本页定义的同一套单 Agent 会话规则。
- Pi API 尚未接入单 Agent 的原生过程、上下文压缩、Provider 故障恢复、一次性重跑与永久迁移状态。

这些是现状差距，不改变本页对完整产品的定义。

## 非目标

- 不显示无法可靠计算的完成百分比。
- 不把全部工具日志、命令输出或 reasoning 铺进会话时间线。
- 不按定时器轮播历史工具动作来制造“正在工作”的假象。
- 不在本页定义团队调度顺序、成员汇合、人工闸门或最终交付流程。
- 不新增侧边栏运行项状态或全局通知；当前会话的托管运行项入口由[主页面会话区](./main-conversation.md#托管运行项入口与面板)定义，不属于本页的 Agent run 状态栏。
- 不承诺停止或重试会自动回滚已经产生的文件改动。
- 不在额度或服务异常时自动切换引擎；每次临时执行配置都必须由用户明确选择。
- 不在本页新增、编辑、轮换或删除 Provider 档案；这些操作统一进入设置页。
- 不展示 API 用量、费用明细或预算控制；验证请求的用量提示与持续任务费用展示分别服从 BYOK 流程的既定边界。
