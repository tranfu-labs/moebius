# 主页面侧边栏

> 状态：普通 sidebar chat 与分析对话的归属边界，以及阅读状态、置顶、悬浮信息与对话重命名增量均已获用户确认，并通过用户视角复评
>
> 所属页面：主页面
>
> 范围：只定义左侧栏及其直接触发行为，包括普通根对话与非分析 sidebar chat 的列表、选中态、状态点、阅读状态、置顶区、悬浮信息、对话菜单、整段分析入口和找回路由；分析对话不进入左侧栏，只由直接父对话的分析面板找回。[新建对话窗口](./new-conversation.md)、[全局搜索](./search.md)、Agent 团队管理和[设置](./settings.md)分别定义。
>
> 产品基线：[moebius 产品需求文档](../prd.md)
>
> 关联流程：[会话分析流程](../flows/session-analysis.md)；关联页面：[主页面会话区](./main-conversation.md)、[主页面右侧栏](./main-right-sidebar.md)

本文统一使用三个不互换的术语：

- **选中会话**：左侧栏唯一高亮、代表用户当前导航目标的会话。
- **主内容承载会话**：当前显示在中间主内容区的会话。
- **右侧会话**：当前显示在右侧栏会话标签中的会话。

普通主会话被选中时，选中会话与主内容承载会话是同一个对象；sidebar chat 组合路由中，选中会话和右侧会话是 sidebar chat，主内容承载会话是它的来源会话。后文未带限定的“当前会话”仅用于二者相同的普通状态。

分析对话不是本文所说的 sidebar chat：它没有左侧栏行、选中态、状态点或独立菜单。用户从根对话或分析对话的分析面板打开它时，左侧栏继续高亮当前根对话；右侧栏标签与逐层找回由对应父对话及[主页面右侧栏](./main-right-sidebar.md)承载。

## 页面目标

侧边栏是主页面中稳定存在的导航与任务入口。它让用户可以快速发起对话、在项目之间定位已有对话、识别和主动管理需要关注的新结果或人工处理事项，并把高频对话固定在跨项目可达的位置，同时进入 Agent 团队管理或打开应用设置。

侧边栏只回答五个问题：

1. 我现在可以从哪里开始一段对话？
2. 我的项目和对话在哪里，哪一段正在运行或等待我？
3. 我如何进入 Agent 团队管理，并在不离开当前任务的情况下打开应用设置？
4. 我从右侧栏创建的普通会话在哪里，怎样回到当时并排工作的现场？
5. 哪些对话是我持续关注的，它们属于哪个文件夹、正在哪个分支工作？

侧边栏不是工作流图、运行日志、项目仪表盘或主内容承载会话的消息目录。用户无需先理解内部编排结构，便能找到项目和对话；主内容承载会话的目录轨与原文导航属于[主页面会话区](./main-conversation.md#会话目录轨)。

## 用户场景

- 用户打开应用，从最近使用的项目和对话继续工作。
- 用户不关心具体项目入口，直接从顶部创建一段新对话。
- 用户已明确目标项目，直接在该项目下创建新对话。
- 用户在多个项目间切换，查找正在运行、产生新结果或等待人工处理的对话。
- 用户把已经知晓的红点或蓝点标记为已读，或把一段静止对话标记为未读，作为稍后处理的提醒。
- 用户把高频对话移入跨项目置顶区，取消置顶后仍按原有顺序回到所属项目。
- 用户在不同对话之间移动指针，不打开对话就能连续查看名称、项目文件夹和可用的 Git 分支信息。
- 用户从对话菜单修改应用内标题，不改变项目文件夹、Git 分支或历史记录。
- 用户不先打开目标对话，直接从左侧栏对话菜单把整段对话作为文本片段送入右侧栏分析草稿。
- 用户从右侧栏创建并推进了一段普通 sidebar chat，稍后从项目列表中找回它及其来源主线。
- 用户尚未添加项目时，从固定的新建对话入口进入添加项目流程。
- 用户需要重命名、排序、修复或移除已有项目。
- 用户需要进入 Agent 团队管理或搜索，或在当前工作区上方打开设置。
- 用户希望临时扩大对话区域，关闭侧边栏后继续工作。

## 入口与去向

### 入口

- 应用完成首次启动配置后，默认进入主页面并显示侧边栏。
- 非首次启动时，应用恢复用户上次成功打开的项目和用户发起的对话；最后选中的是 sidebar chat 时，同时恢复其来源主线与右侧栏标签，让用户从离开的位置继续工作。
- 上次工作现场停留在分析对话标签时，恢复承载这棵分析对话树的根对话及其右侧栏标签组；左侧栏只恢复根对话选中态，不为活动分析标签生成临时选中行。分析面板开合状态仍按主会话规则在软件重启后重置为关闭。
- 没有可恢复的历史选择，或上次选择的对话已归档、所属项目已移除时，主内容区进入“新建对话”且不预选项目；应用不得擅自打开项目列表中的第一个项目或对话。
- 用户从 Agent 团队或搜索结果返回主页面时，恢复离开前的项目展开状态、选中会话、主内容承载会话与右侧会话组合；设置始终覆盖在当前主工作区上方，关闭后直接回到打开前的同一位置，不产生离开与返回。
- 侧边栏关闭时，主内容区顶部保留“打开侧边栏”按钮。

### 去向

- “新建对话”打开[新建对话窗口](./new-conversation.md)；项目选择、添加项目和对话创建由该窗口承接。
- “搜索”打开[全局搜索](./search.md)。搜索内容与结果行为由该页面定义。
- “Agent 团队”进入 Agent 团队管理界面。
- 项目内“新建对话”打开同一个[新建对话窗口](./new-conversation.md)，并预选对应项目。
- 点击普通主会话进入对应主页面时间线。
- 从任一可用左栏对话行选择「在右侧栏分析这段对话」时，该对话显示在主内容区，右侧栏打开或聚焦它的分析草稿；来源引用、草稿归并与发送行为由[对话分析与优化流程](../flows/session-analysis.md)定义。
- 点击 sidebar chat 时，选中态落在被点击的 sidebar chat 行：来源会话仍可用时，来源会话显示在主内容区、sidebar chat 在右侧栏打开或聚焦；没有来源会话或来源已经不可用时，sidebar chat 作为普通会话直接在主内容区打开。
- “重新查看引导”以回看模式打开[首次启动引导](./onboarding.md)，退出或完成后返回进入前的主页面状态。
- “设置”在当前主工作区上方打开[设置弹窗](./settings.md)，不改变当前页面、项目、对话、草稿、滚动位置或侧边栏状态。

## 页面结构

### 默认展开

```text
┌──────────────────────────────┐
│ ● ● ●                [关闭] │  红绿灯安全区与侧栏控制行
│ [Logo] Moebius               │  独立品牌行与窗口拖拽区
├──────────────────────────────┤
│ ＋ 新建对话                  │
│ ⌕ 搜索                       │
│ ◇ Agent 团队                 │
├──────────────────────────────┤
│ 置顶                         │
│  » 对话 2                  ● │  置顶后从原项目列表移入此处
│    对话 5                    │
├──────────────────────────────┤
│ 项目                         │
│                              │
│ ▾ 项目 A            [＋][⋯] │
│    对话 1                  ● │  红点：需要人工处理
│    对话 2                  ● │  选中：中性底与前景文字；闪烁点：运行中
│    对话 3                    │
│    对话 4                  ● │  蓝点：未读
│                              │
│ ▸ 项目 B              ● [⋯] │  折叠时显示最高优先状态点
├──────────────────────────────┤
│ ? 重新查看引导               │
│ ⚙ 设置             [安装更新]│  仅在更新包已下载并校验通过后出现
└──────────────────────────────┘
```

图例：

- 当前选中的对话只使用中性选中底与前景文字，不显示 `»`、`>>` 或其他标题前缀。
- 红色 `●`：需要用户回答、确认、验收或处理异常。
- 蓝色 `●`：对话处于未读状态，来源可以是 Agent 的新结果，也可以是用户主动设置的稍后返回提醒。
- 闪烁 `●`：Agent 正在运行。
- 无点：当前静止，且没有需要继续显示的阅读提醒；已经被用户标记为已读的待处理事实仍可能保留在时间线中。
- “置顶”只在至少存在一段置顶对话时出现；置顶对话不在所属项目中重复显示。
- 折叠项目只显示一个代表其当前仍留在项目列表中的子对话最高优先状态的点，优先级为红点、蓝点、闪烁点；展开后由对话行自行显示，不在项目行重复，也不重复聚合已经移入置顶区的对话。

### 侧边栏关闭

```text
┌──────────────────────────────────────────────┐
│ [打开侧边栏]    主内容项目 / 主内容承载会话  │
├──────────────────────────────────────────────┤
│                                              │
│                 主内容区                     │
│                                              │
└──────────────────────────────────────────────┘
```

侧边栏关闭时，主内容顶部的项目与会话名称始终描述屏幕中间实际显示的主内容承载会话；组合路由下因此显示来源会话，而不是隐藏起来的 sidebar chat。重新打开侧边栏后，sidebar chat 仍作为唯一选中会话高亮，右侧栏与主内容共同恢复关闭前的完整组合。

关闭后侧边栏完全隐藏，主内容区占用释放出的宽度。打开按钮属于主页面在侧栏关闭状态下的恢复入口；本文档只规定它必须存在，不规定主内容区其他结构。

### 没有项目

```text
┌──────────────────────────────┐
│ ● ● ●                [关闭] │
│ [Logo] Moebius               │
├──────────────────────────────┤
│ ＋ 新建对话                  │
│ ⌕ 搜索                       │
│ ◇ Agent 团队                 │
├──────────────────────────────┤
│ 项目                         │
│                              │
│ 还没有项目                   │
│ 从“新建对话”添加第一个项目   │
├──────────────────────────────┤
│ ? 重新查看引导               │
│ ⚙ 设置                       │
└──────────────────────────────┘
```

顶部“新建对话”仍然可点击，并打开[新建对话窗口](./new-conversation.md)。没有可用项目时，该窗口禁止创建对话并提供添加项目入口；侧边栏自身不承载添加项目流程。

### 项目目录不可用

```text
│ ▾ 项目 A            [🔧][⋯] │  红色扳手：修复项目文件夹
│   原文件夹已不可用             │
│    历史对话 1                  │
│    历史对话 2                  │
```

历史时间线仍可查看但只读；置顶或取消置顶、标记已读或未读、重命名等只改变 Moebius 内应用状态的操作仍可用。项目目录不可用时，不允许创建新对话、发送新消息、切换团队或启动新的 Agent 执行。项目行显示独立的红色扳手修复按钮；悬停提示“当前项目本地文件夹未找到，可以指定新的文件夹”，点击后让用户指出同一项目被移动或重命名后的新位置。修复入口不得藏入项目更多菜单。

项目在 Agent 运行期间变为不可用时：已经拥有有效隔离工作副本的执行可以完成当前一步，但完成后停止自动接力并把对话标为红点；依赖原目录、已经无法安全继续的执行立即停止并标为红点。侧边栏不得在执行已经无法继续时仍长期显示闪烁运行点。

## 区域与信息

### 品牌、标题栏与关闭按钮

- 顶部第一行使用统一的窗口 header 高度并保留桌面窗口拖拽区域；系统交通灯和该行内控件由同一容器自然垂直居中，不使用单独的位置补偿。
- 顶部固定显示产品 Logo 和品牌名 `Moebius`，形成主窗口持续可见的产品识别；Logo 必须使用[总 PRD](../prd.md#品牌与发行平台)规定的品牌母版派生图像，不得使用另一枚手绘或图标库无限符号代替；`moebius` 只作为项目与技术标识，不作为该位置的界面文案。
- macOS 为系统交通灯预留空间；Logo、品牌名、拖拽区域和系统交通灯不得重叠。
- “关闭侧边栏”固定在顶部右侧，不随项目列表滚动。
- 图标按钮必须有“关闭侧边栏”辅助名称和悬停提示。

### 应用级操作

应用级操作固定在项目列表上方，不随项目列表滚动：

1. 新建对话。
2. 搜索。
3. Agent 团队。

三个入口使用相同的导航行高度、文字层级和交互样式，不把 Agent 团队藏入设置，也不通过特殊颜色或徽标额外突出。它的常驻位置本身负责让用户意识到产品存在可配置的 Agent 团队。英文界面对应名称为 `Agent Teams`；侧边栏全部 Moebius 静态文案、提示、菜单和可访问名称继承[设置](./settings.md#语言覆盖范围)的中英文覆盖规则，不得因侧边栏遗漏而与当前界面语言混用。

### 置顶区

- 置顶区位于三个应用级操作下方、项目区上方，是跨项目的高频对话入口。
- 没有置顶对话时整区隐藏，不显示空标题或空状态；首次置顶后原位出现。
- 对话被置顶后从所属项目列表移入置顶区，不在两个位置重复显示；项目归属、来源关系、时间线、运行、阅读状态和选择行为都不改变。
- 置顶区按置顶时间倒序排列，最近置顶的对话在最上方；首版不提供拖动排序。
- 取消置顶后，对话离开置顶区并回到所属项目，按它原本的创建时间在项目内重新归位。项目是否展开不影响归位；折叠项目只是在视觉上暂时隐藏该行。
- 置顶与取消置顶都必须持久保存，并在应用重启后恢复。归档对话或移除所属项目时，对话不再留在置顶区。
- 置顶区和项目区属于同一个中部滚动区域；置顶数量或窗口高度不得让项目区永久不可达，用户始终可以在该区域内滚动到两者。

### 项目标题行

- 显示“项目”区标题。
- 添加项目不在侧边栏出现，由[新建对话窗口](./new-conversation.md)统一承接。
- 置顶区与项目列表共同组成侧边栏唯一可滚动的主要区域；顶部应用级操作和底部设置保持固定。

### 项目行

每个项目行包含：

- 展开或折叠控制。
- 项目显示名称。
- 项目内新建对话按钮。
- 项目更多菜单。
- 折叠时必要的状态聚合。
- 项目目录不可用时的独立红色扳手修复按钮。
- 项目行自身承载的拖动排序能力，不另设独立拖动把手。

项目默认显示本地文件夹名。用户设置显示名称后，只改变应用内名称，不重命名磁盘上的文件夹。

项目顺序由用户控制并持久保存，不因对话运行、产生新消息或出现任何状态点而自动变化。刚添加的项目默认出现在列表最上方、自动展开并成为当前项目。用户直接拖动项目行调整顺序，不显示独立拖动把手；点击与拖动必须通过明确的移动阈值区分，拖动结束不得误触展开或折叠。项目菜单不提供上移、下移或移到顶部命令。

### 对话行

每个对话行只显示：

- 一行对话标题。
- 一个必要的状态图标。
- 当前选中态。

当前选中态只改变行背景与文字等不占据标题布局的视觉属性，不在标题前增加 `»`、`>>`、图标或其他占位；同一行在选中、未选中、hover 和 focus 之间切换时，标题左边界与可用宽度保持不变。

长标题单行截断。指针悬停或键盘聚焦时，侧边栏通过一份共享的跟随浮层显示完整对话名称、项目文件夹名称，以及这段对话实际工作空间的真实 Git 分支名称；同一项目的默认工作空间和独立工作空间必须分别显示自己的真实分支。detached HEAD 显示 `detached`；确认是非 Git 文件夹时不显示第三行，也不显示占位说明；Git 分支暂时无法读取或项目目录失效且没有可用工作空间信息时，第三行显示“分支不可用”，不得退回显示项目文件夹的分支冒充会话分支。侧边栏不显示运行角色、消息摘要、消息数量、阶段名称、成员名称、消息目录或完整文件路径。

整份侧边栏同一时刻只显示一份对话信息浮层。用户在相邻对话间上下移动指针时，浮层沿列表平滑移动并原位替换内容，形成同一信息面连续跟随的感觉；不得让每行各自弹出并叠加浮层，也不得因快速移动出现闪烁、重影或过时内容。指针和焦点离开对话区域、打开对话菜单、打开重命名弹层、侧边栏关闭或目标行因置顶迁移而离开当前位置时，浮层立即收起；重新出现时只读取新目标的当前信息。浮层只借鉴“共享信息面连续跟随”这一交互原则，不采用参考设计的刻度轨、邻近项放大、金字塔形变或视觉样式；颜色、圆角、描边、层级与动效克制原则全部服从 Moebius 设计语言。

侧边栏只列用户自己发起的根对话和非分析 sidebar chat。用户从普通右侧栏新对话首次发送后创建、且不是由分析入口形成的 sidebar chat，仍按发送瞬间最终选择的项目列入对应项目，使用普通会话标题、菜单、排序、归档与状态点规则。

由「在右侧栏分析这段对话」或消息级分析入口创建的分析对话是明确例外：首次发送成功后只登记到直接父对话的分析面板，不因用户主动发送、改选项目、切换团队或之后继续运行而生成左侧栏行；更深层分析对话同样只登记在自己的直接父分析对话面板。

sidebar chat 行与来源会话行是两个独立会话对象：各自只显示自己的运行、未读和待处理状态，不把 sidebar chat 的状态点复制到来源行，也不把来源状态复制到 sidebar chat 行。首版不要求专用图标、标题前缀或来源摘要；标题仍按普通会话规则单行显示。

团队为了推进一个目标而拆出的子对话不出现在这里，它们的入口是父对话时间线中的卡片，见[主页面会话区](./main-conversation.md#区域与信息)。

分析对话也不出现在这里，但它与团队拆出的子任务不是同一对象：分析对话由用户主动发起，入口是直接父对话的分析面板；团队子任务仍使用父对话时间线卡片。两者都不得退化为左侧栏普通对话行。

> **子对话是否进侧边栏已在 2026-07-21 被重新裁决。** 本文原先规定子对话与普通对话平铺为同级条目、以“来自：<父对话名称>”标明来源。该规定被推翻，理由是：子任务是团队的内部产物，不是用户主动管理的对象，而侧边栏是用户管理自己工作的地方；让它们进入侧边栏会使侧栏长度随团队的拆分行为膨胀，用户拆得越细、侧栏越不可用。代价是用户不能从侧边栏直接跳到某个子任务，必须先回到父对话——这被接受，因为子任务本来就只在父对话的语境里有意义。

### 底部应用操作

- “重新查看引导”和“设置”共同固定在侧边栏底部，不随项目列表滚动；前者位于后者上方，并复用侧边栏导航行的图标、文字与键盘交互样式。
- “重新查看引导”直接进入回看模式，不弹确认框；回看本身可退出，进入操作可逆。
- “设置”和条件式“安装更新”固定在侧边栏底部，不随项目列表滚动；两者是并列按钮，不嵌套。点击“设置”在当前工作区上方打开[设置弹窗](./settings.md)，关闭后焦点回到“设置”入口；“安装更新”只在更新包完整下载并校验通过后出现，其他更新状态不占位、不显示红点。
- 点击“安装更新”不直接关闭应用，先打开安装确认弹窗。无运行任务时确认后重启安装；有 Agent、托管运行项、AI 建队或 CLI 安装任务时显示独立的重启安装弹窗，取消或选择“继续工作”都保留该按钮，只有“停止任务并重启安装”才进入安全收尾。
- 底部不常驻数据库路径、运行目录、内部标识或原始错误。
- 本地引擎异常若导致主功能不可用，可以在设置入口附近显示非技术化状态提示；诊断细节进入独立诊断界面，不塞进设置入口或设置弹窗的常驻信息。更新状态不通过底部通知或常驻红点表达，安装按钮本身只表达“包已就绪”。

## 操作与反馈

### 关闭与打开侧边栏

- 点击关闭按钮后立即隐藏侧边栏，主内容区扩展。
- 主内容区出现固定的打开按钮；点击后恢复侧边栏。
- 恢复时保留选中会话、主内容承载会话、右侧会话、项目展开状态和项目列表滚动位置；sidebar chat 组合路由不能被压成其中任意一个会话。
- 应用记住用户最后一次选择；下次启动恢复关闭或展开状态，但在首次启动引导期间始终保持侧边栏可见。

### 应用级新建对话

- 点击后打开[新建对话窗口](./new-conversation.md)，不在侧边栏内直接创建空白对话。
- 没有可用项目时仍可进入该窗口，但创建操作不可用，用户需要先在窗口内添加项目。
- 项目选择、Agent 团队选择、取消、创建和失败恢复由新建对话窗口定义。

### 搜索

- 点击打开[全局搜索](./search.md)。
- 侧边栏保持在背景中，关闭弹窗后恢复原选中会话及其主内容、右侧栏组合。
- 搜索范围、结果分组、键盘行为和空态由全局搜索文档定义。

### Agent 团队

- 点击进入 Agent 团队管理界面。
- 进入后该入口呈现当前选中态。
- 返回主页面时恢复离开前的选中会话、主内容承载会话、右侧会话、项目展开和侧边栏状态。

### 设置

- 点击后在当前主工作区上方打开[设置弹窗](./settings.md)，侧边栏、项目区和主内容保持原状态并作为不可操作的背景留在原位。
- 关闭设置后直接回到打开前的工作区位置，焦点回到侧边栏“设置”；该动作不属于页面导航，不产生单独的返回主页面步骤。
- 设置中的语言、应用身份、版本与检查更新属于应用级能力，不依赖项目列表、当前项目、对话数据或本地运行是否可用；项目数据加载中、加载失败、没有项目或项目目录不可用时仍可打开。
- 弹窗内分类、异步操作、关闭恢复与外部链接行为由设置页定义，侧边栏不复制这些内部规则。

### 项目内新建对话

- 点击项目行的加号，打开[新建对话窗口](./new-conversation.md)并预选该项目；不会在侧边栏点击瞬间直接创建持久化空白对话。
- 项目目录失效或项目正在变更时，该按钮不可用并说明原因。

### 展开和折叠项目

- 点击项目行的展开箭头或项目名称切换项目子列表，不改变选中会话、主内容承载会话或右侧会话；项目本身不进入独立项目主页，也不产生项目选中态。
- 项目行同时是拖动排序载体；超过拖动阈值后只执行排序，结束时不得继续触发点击展开或折叠。项目行内的 `＋` 和 `⋯` 是独立按钮，不触发行点击或拖动排序。
- 项目展开时，由子对话自行显示状态，项目行不重复展示状态点。
- 项目折叠时只显示一个代表子对话最高优先状态的点，不显示数量。红点优先于蓝点，蓝点优先于闪烁点。
- 选中会话所在项目允许被用户手动折叠；组合路由下即使 sidebar chat 行被隐藏，主内容仍显示来源会话、右侧栏仍显示 sidebar chat，不退出、不切换。主内容承载会话所在的另一项目也可独立折叠，两者都不得因组合路由被自动重新展开。
- 项目折叠时暂时隐藏其对话列表，不产生项目选中态；再次展开选中会话所属项目后，原 sidebar chat 或普通主会话仍显示唯一选中态。

### 选择对话

- 点击普通主会话行打开对应时间线，并将选中态移动到该行。
- 点击 sidebar chat 行时，选中态只移动到该 sidebar chat 行，来源会话行不同时高亮。来源会话可用时，应用把来源会话放在主内容区，并打开右侧栏、创建或聚焦绑定该 sidebar chat 的标签；没有来源或来源不可用时，在主内容区直接打开 sidebar chat。无论显示在哪个容器，状态点仍属于 sidebar chat 自己。
- sidebar chat 的来源会话与自身可能分属不同项目；列表位置始终由 sidebar chat 首次发送时最终选择的项目决定，不因为恢复来源会话而移动到来源项目。
- 点击 sidebar chat 后，只有来源主内容与目标右侧标签都成功呈现，才提交新的选中态。任一必要路由失败时保留之前的主内容、右侧栏与侧栏选中态，并给出可理解说明；不得让 sidebar chat 行已选中而右侧栏仍显示另一段会话。
- 点击没有来源或来源失效的 sidebar chat 时，只要它已在主内容区成功呈现就可以提交选中态；来源失效不作为会话不可访问错误。
- 点击普通主会话后，右侧栏继续按[主页面右侧栏](./main-right-sidebar.md)恢复该主会话自己的标签现场；若其中原本就有某段 sidebar chat 标签，不因此把选中态改到该 sidebar chat 行。
- 普通主会话切换失败时保留原对话，不出现侧栏选中了新对话而主内容仍是旧对话的双事实状态。
- Agent 新结果形成的蓝点在用户明确打开对话并成功展示最新结果后清除。用户手动设置的蓝点按“标记为已读与未读”中的再次进入规则清除，当前会话刚被标记为未读时不得立即自清。
- 打开带红点的对话不会仅因查看而清除红点；导致红点的事实被处理掉时清除，用户也可以通过「标记为已读」确认已经知晓当前提醒并停止显示红点。
- 闪烁运行点在运行结束时自动消失；若本轮结束后产生尚未查看的新结果且最后一条未提及任何成员则转为蓝点，若这一步没跑起来、卡住或反复重试仍未成功则转为红点。

### 组合路由中的来源即时失效

sidebar chat 已作为选中会话显示在右侧栏后，来源会话可能因为被归档、所属项目被移除、会话记录失效或其他原因不再能承载主内容。来源失效只改变容器路由，不归档 sidebar chat，不改变其项目、权限、历史、运行或状态点。

- 应用检测到主内容承载会话已经不再可用时，把当前选中的 sidebar chat 原地迁移到主内容区；侧栏仍只选中该 sidebar chat。
- 迁移保留 sidebar chat 的时间线阅读位置、输入草稿、运行状态和当前焦点语义；它在原来源外层右侧栏中的标签被移除，不能同时在主内容与旧右侧标签重复出现。
- 原来源标签组中的其他兄弟标签不因迁移被删除；来源重新可用也不自动把 sidebar chat 移回右侧栏，只有用户下一次从该行明确打开时再按当时来源状态路由。
- 应用控制的归档或项目移除必须先确认 sidebar chat 能在主内容区呈现，再原子提交来源失效与新路由；迁移失败时不完成对应归档或移除，保留原组合并说明原因。
- 来源因为应用外变化突然失效、无法撤回时，迁移失败不得清空页面或改选其他会话：保留最后成功呈现的组合和 sidebar chat 选中态，标明来源已失效并提供重试；下一次成功迁移或重启恢复时直接在主内容区打开 sidebar chat。

### 项目与对话菜单

项目更多菜单只包含：

- 在文件管理器中显示。
- 修改显示名称。
- 移除项目。

菜单打开时必须明确对应哪个项目。菜单操作不得因为列表滚动或项目状态刷新而错误作用到其他项目。项目文件夹修复不属于更多菜单，而由项目行上的独立红色扳手按钮承载。

每个对话行在悬停、键盘聚焦或上下文操作时提供同一份对话菜单。菜单依次包含：

- 「在右侧栏分析这段对话」；
- 最终可见点为红点或蓝点时显示「标记为已读」，无点时显示「标记为未读」，最终可见点为闪烁点时不显示阅读状态操作；
- 未置顶时显示「置顶」，已置顶时显示「取消置顶」；
- 「重命名」；
- 「复制对话记录路径」；
- 「归档」。

鼠标右键、对话行悬停或聚焦后出现的菜单按钮，以及键盘打开上下文菜单，必须到达同一组操作并明确绑定同一段对话。菜单按钮的辅助名称包含对话标题；每个菜单项有独立可读名称，不能依赖图标、位置或当前选中态判断作用对象。后续增加的对话操作不得混入项目菜单。

分析对话没有左侧栏行，因此不从左侧栏获得整段分析、复制记录路径或独立归档菜单。根对话仍可使用本菜单发起整段分析；分析对话若继续创建下一层，只能从其具体消息发起。

### 标记为已读与未读

阅读状态操作只根据当前最终可见的点提供，而不是根据被更高优先级点遮住的后台事实提供。红点与后台运行同时存在时，用户看到红点，因此仍提供「标记为已读」；确认后红点消失，若 Agent 仍在运行则行状态转为闪烁点。功能对应关系如下：

| 当前可见状态 | 阅读状态菜单 | 操作结果 |
| --- | --- | --- |
| 红点 | 仅「标记为已读」 | 用户确认已经知晓当前待处理事实，红点立即消失；事实本身仍保留在时间线中 |
| 蓝点 | 仅「标记为已读」 | 当前未读提醒立即清除，不区分它来自新结果还是用户手动提醒 |
| 闪烁点 | 不提供 | 运行期间不允许手动改变阅读状态 |
| 无点 | 仅「标记为未读」 | 对话转为蓝点，作为用户稍后返回的提醒 |

“标记为已读”确认操作提交时已经共同形成当前红点的全部已知待处理事实，不解决、删除或改写这些事实；刷新、状态轮询和应用重启都不得让其中任一同一事实重新点亮红点。提交之后新出现的待处理事实仍会再次点亮红点。这个确认范围面向用户表现为“一次确认当前看到的提醒”，不要求用户逐个处理同一时刻已经汇聚的后台事实。

“标记为未读”不制造 Agent 新结果，只建立用户自己的返回提醒；蓝点的提示与辅助名称统一为“未读”，不得声称一定存在 Agent 新结果。手动未读必须跨刷新和应用重启保留。当前已打开的对话被标记为未读后，不因内容已经在屏幕上、状态刷新或应用自动恢复该会话而立即清除；用户先离开它，之后再次明确选择并成功看到内容时才自动清除。非当前对话被标记为未读后，下一次明确选择并成功看到内容时清除。Agent 新结果产生的蓝点继续在用户明确打开并成功展示最新结果后自动清除。

阅读状态变更只有在持久保存成功后才更新圆点。保存失败时保留原圆点和原菜单语义，显示可理解的失败说明并允许重试；请求进行中禁用同一操作，避免重复提交。菜单打开后若运行或提醒状态已经改变，用户选择操作时必须按最新可见状态重新判断：陈旧操作不执行，菜单收起并让重新打开后的菜单展示当前可用项。

### 置顶与取消置顶

- 「置顶」把当前对话从所属项目列表移入置顶区；只有移动与置顶状态都成功保存后，界面才提交结果。
- 「取消置顶」把当前对话移回所属项目并按创建时间归位；失败时继续留在置顶区，不出现丢失或双份条目。
- 置顶不改变当前选中会话、主内容承载会话或右侧会话组合。对 sidebar chat 执行置顶或取消置顶时，同样保留它的来源主线和右侧栏找回语义。
- 键盘触发置顶后，焦点跟随同一对话进入置顶区；取消置顶且所属项目已展开时，焦点跟随到归位后的同一行。所属项目已折叠时不强制展开，焦点移到该项目的展开控制，并通过可读反馈说明对话已回到该项目。

### 重命名对话

- 「重命名」打开轻量弹层并预填当前完整标题；确认后只改变 Moebius 内的对话名称。
- 新名称去除首尾空白后必须非空；允许与同项目或其他项目中的对话重名。
- 重命名不改变项目归属、置顶状态、排序依据、文件夹、Git 分支、来源关系、消息、运行或交付结果。
- 保存失败时保留原名称和输入内容并给出可理解说明；取消不产生变化。置顶区、项目列表、主内容标题和右侧会话标签中的同一对话必须在成功后使用一致的新名称，且应用重启后继续保留。

### 在右侧栏分析这段对话

- 该操作把当前行代表的整段根对话转换为[对话分析与优化流程](../flows/session-analysis.md#2-收集来源引用)定义的公开对话级文本片段；胶囊可读取的完整 Markdown 文本就是发送后所选 Agent 获得的全部片段内容，应用不读取引用指向的时间线、运行记录或输出。
- 对话正在运行、已有未读结果、当前未选中或项目目录不可用，都不改变引用语义；只要这段对话记录仍可访问，入口保持可用。记录不可访问时，菜单项禁用并说明「对话记录不可用，暂时无法分析」，不得打开没有来源引用的分析草稿。
- 选择当前对话时，保持主内容与左侧栏选中态，打开或聚焦当前对话自己的右侧栏分析草稿。
- 选择非当前对话时，只有目标对话在主内容区、对应分析草稿在右侧栏都成功呈现后，该行才成为左侧栏唯一选中项。进入前对话的右侧栏标签、未发送草稿和阅读状态按原对话保留，切回时恢复。
- 目标对话或分析草稿任一步加载失败时，保留进入前的选中行、主内容和右侧栏，不留下只切了一半的状态；原位显示可理解原因并允许重试。
- 这是可逆的导航与草稿追加动作，不弹确认框，不停止来源对话，也不改变归档、运行、未读或待处理状态。

### 复制对话记录路径

- 服务复盘：用户想把一段对话的完整经过交给对话之外的工具或另一个 AI 阅读分析。
- 每段对话的完整经过——消息、系统记录和各步运行过程——本来就以机器可读的记录文件持续落在磁盘上（见 [ADR-0004](../../adr/0004-jsonl-session-fact-log.md)）。触发菜单项时把该文件的路径复制到剪贴板；成功反馈说明“路径已复制”，让用户知道下一步是把它粘给要读的工具。
- 路径指向的是持续更新的记录本身，不是导出时刻的快照：对话继续推进时，拿到路径的阅读工具可以重新读取并跟上最新经过。运行中的对话同样可以复制。
- 同一段对话的路径稳定不变，复制一次即可长期使用。
- 复制路径是显式动作；这不违背“界面文案不出现内部标识”——菜单项和反馈文案不展示路径本身，路径只进剪贴板。
- 该文件就是对话记录的事实本身：外部工具应只读；文件被用户或外部工具修改、删除时，对话历史随之受损，产品按加载异常如实呈现，不承诺恢复。

### 对话状态点与顺序

侧边栏只用一个小圆点表达需要用户感知的状态：

1. **红点**：这段对话遇到了尚未被用户知晓、且需要用户处理的事，红点表示它已经无法自己往下走。触发来源由[主页面会话区](./main-conversation.md#侧边栏状态点的触发)定义，本文不重复列举；用户标记为已读后只停止侧栏提醒，不改变该事实。
2. **蓝点**：这段对话处于未读状态。它既可以来自 Agent 已结束且尚未查看的新结果，也可以来自用户主动设置的稍后返回提醒；蓝点不代表任务已经完成，也不得通过提示或辅助名称声称一定存在新结果。最后一条提及了某个成员时属于团队内部仍在传递，不因该消息自动给蓝点，但已有的手动未读提醒仍可在运行结束后恢复显示。
3. **闪烁点**：Agent 正在运行。闪烁必须克制，不造成持续视觉干扰。
4. **无点**：对话静止，且没有需要继续显示的阅读提醒。用户自己按下“停下”之后是无点；用户已确认知晓但尚未解决的待处理事实可以继续保留在时间线中而不显示状态点。

同一时刻只显示一个点：红点始终优先；没有红点但 Agent 正在运行时显示闪烁点，蓝色未读提醒暂时隐藏并在运行结束后恢复；只有没有红点且没有运行时才显示蓝点，否则无点。折叠项目聚合的是不同对话各自已经得出的最终可见点，因此仍按红点、蓝点、闪烁点的顺序选一个代表点。点的颜色不是唯一信息来源，悬停提示和辅助名称必须分别读作“需要你处理”“未读”“正在运行”。

sidebar chat 完整复用同一套状态点判定，但只读取它自己的运行和消息事实。用户打开 sidebar chat 并成功展示最新结果后，只清除该行自己的蓝点；来源会话是否已读不随之改变。项目折叠时，仍留在项目列表中的 sidebar chat 与普通主会话一起参与该项目的最高优先状态聚合；已经移入置顶区的对话不再重复参与项目行聚合。

> **红点来源已在 2026-07-21 被重新裁决。** 本文原先定义红点为“需要用户回答、确认、验收或处理异常”。该定义被推翻，理由是：它假设 Agent 会主动声明自己需要人工裁决，而产品目前没有这样的信号源，导致红点既可能漏报（Agent 卡住却不声明），也可能误报（把正常的团队内部传递当成等待用户）。新定义只认那些**产品能确定判断**的事实，从而保证一条硬性质——用户被红点带回一段对话时，页面上一定有一条说明发生了什么的记录，不会出现“被叫回来却看不出要我干什么”。让成员主动声明“我需要用户裁决”是更精确的红点来源，需要另行约定，见[主页面会话区](./main-conversation.md#待讨论)的待讨论条目。

项目内未置顶对话只按创建时间倒序排列，最新创建的普通主会话或 sidebar chat 固定在最上面，最早创建的在最下面；置顶区单独按置顶时间倒序排列。人工打开、当前选中、后台 Agent 的流式输出、新结果、等待人工、运行状态、阅读状态和计时更新都只改变对应界面状态，不得改变任一区域的顺序，避免并行任务让侧边栏持续跳动。置顶和取消置顶是用户主动改变所在区域的例外；取消置顶后仍按原创建时间归位。

### 归档

- 产品不设置“已完成”侧栏状态，也不自动把对话收入完成分组。
- 用户可以从对话菜单主动归档一段不再需要出现在侧边栏中的对话。
- 归档不会删除消息、执行记录或交付结果。
- 当前根对话或任一分析后代仍有运行中、待接回的控制工作或托管运行项时不能归档；用户需要先逐层打开对应对话并停止，或等待整棵树全部结束。
- 归档根对话时，通过直接父子关系连接的全部分析后代递归隐藏；分析对话的父子关系和记录仍保留。恢复根对话时整棵树一起恢复，用户再从各自直接父面板逐层找回。
- 选中会话被归档后，选择其所属项目中相邻的可见对话；没有其他对话时显示项目空态。
- sidebar chat 完整复用归档规则。归档时关闭它在右侧栏中的对应标签，但不影响来源会话或其他兄弟标签；被归档的 sidebar chat 当前已选中时，再按同项目相邻对话规则提交新的选中态。
- 归档后的查找和恢复由[全局搜索](./search.md)承接；搜索提供“包含已归档对话”开关，并为归档结果提供恢复入口。

## 弹层与危险操作

### 修改对话名称

- 使用轻量弹层输入应用内对话名称，打开时预填当前完整名称。
- 名称去除首尾空白后为空时禁止保存并原位说明；不同对话允许使用相同名称。
- 修改只改变应用内标题，不改变项目文件夹、Git 分支、对话记录、运行上下文或交付结果。
- 保存成功后新名称跨应用重启保留；保存失败时弹层保持打开、输入不丢失、侧栏及其他位置继续使用原名称。

### 修改项目显示名称

- 使用轻量弹层输入应用内显示名称。
- 空名称恢复为文件夹名，而不是产生“未命名项目”。
- 修改不影响磁盘目录、已有会话或 Agent 执行路径。

### 修复项目文件夹

- 该能力只处理同一个项目文件夹在应用外被移动或重命名的情况，不用于把一份项目历史改接到另一个项目。
- 项目文件夹不可用时，项目行显示独立的红色扳手图标按钮；悬停提示“当前项目本地文件夹未找到，可以指定新的文件夹”。
- 用户点击该修复按钮后，通过系统文件夹选择器指出项目的新位置。
- 确认前同时显示原位置和用户选择的新位置，说明应用将从新位置继续使用原项目历史。
- 确认成功后更新当前项目的位置，保留项目顺序、显示名称、对话历史和当前选择，并恢复新建、发送、团队切换和 Agent 执行。
- moebius 不移动、复制或重命名磁盘上的任何文件；它只更新自己记录的项目位置。
- 用户取消、所选目录不可访问或更新失败时，项目继续保持原记录和只读状态，不产生第二个项目或部分更新。
- 一个本地文件夹同一时刻只能绑定一个项目。所选目录已经被另一个现有项目使用时，禁止重复绑定或合并两个项目记录；提示用户该目录已绑定其他项目，并允许转到已有项目或重新选择。

### 移除项目

- “移除项目”必须经过确认弹窗。
- 用户确认前，弹窗必须同时明确四项当前后果：项目将从 Sidebar 消失；该项目下的对话将全部归档；消息、执行记录和交付结果仍保留；当前版本没有查看或恢复这些已移除项目与已归档对话的入口。项目内存在根对话或分析对话时，还必须说明每段因此归档的对话都会连同自己的全部分析后代一起隐藏，即使某个后代使用其他项目。弹窗另需说明移除绝不删除或修改磁盘上的项目文件夹，不得只用“数据仍保留”弱化当前无法访问的事实。
- 移除后项目从 Sidebar 消失，项目语义为“已移除”；以该项目作为工作项目的普通主会话、非分析 sidebar chat 和分析对话统一转为“已归档”，消息、执行记录、交付结果及分析对话的直接父子关系仍保留。当前设置只提供“常规”和“关于”，不提供已移除项目或已归档对话的查看入口；查看、恢复和保留规则待对应设置分类完成产品定义后再加入。
- 该项目下的非分析 sidebar chat 与普通主会话一起批量归档；无论它们当前挂在哪个来源会话的右侧栏中，都关闭对应会话标签并保留未归档的兄弟标签。若因此关闭某个右侧栏的最后标签，该栏按[主页面右侧栏](./main-right-sidebar.md#标签全部关闭)自动关闭。
- 任何普通根对话因此归档时，它通过逐层直接归属连接的全部分析后代递归隐藏，不因后代选择了其他项目而脱离这棵树；这些后代的右侧栏标签与父面板入口同时隐藏。任一分析对话仅因自己的工作项目被移除而归档时，也以它为子树根递归隐藏全部分析后代，不论后代使用哪个项目；它不改挂到其他父面板、不生成左侧栏行，子树之外的未归档父对话和兄弟分析对话保持原位置。
- 其他项目中的 sidebar chat 即使把本项目会话作为来源，也不随本项目移除而归档。它们的来源关系立即变为不可用：当前选中的 sidebar chat 按“组合路由中的来源即时失效”迁移到主内容；未选中的条目保留在各自项目中，下一次打开时直接进入主内容区。
- 项目移除是一个原子结果：批量归档、分析后代递归隐藏、父面板入口与跨来源标签清理、当前组合迁移和项目消失必须全部成功后才提交。任一步失败都保留项目、会话归档状态、分析父子关系、面板入口、标签现场和选中组合，不得留下已归档会话仍作为右侧标签或只完成一半的来源失效。
- 重新添加与已移除项目相同的本地路径时，创建一个新的活动项目；旧项目继续作为“已移除项目”保留，旧对话继续归档，不自动合并、恢复或混入新项目。项目被移除后释放该路径的活动绑定，因此这不违反“一个文件夹同一时刻只能绑定一个活动项目”。
- 项目本身的任意对话或将递归隐藏的分析后代存在运行中、托管运行项或待接回控制工作时，不直接执行普通移除，而是显示独立警告弹窗。弹窗分别说明将被停止的 Agent 运行与托管运行项，以及“专业成员已返回、主 Agent 尚未处理”但将被明确放弃接回的结果；同时说明放弃接回只结束控制义务，既有消息、运行记录和结果仍保留。
- 用户可以取消，也可以明确确认强制移除。确认后严格按“停止全部相关 Agent 运行与托管运行项 → 把全部待接回结果标记为已放弃接回 → 递归归档对应对话树并移除项目”的顺序执行；停止或放弃接回任一步失败时不得开始归档，归档或项目移除失败时不得把部分对象伪装成完整成功。整个操作不删除历史记录，也不把被放弃结果重新派发给其他对话。
- 正在移除的项目包含选中会话时，不自动切换到相邻项目或对话；主内容区进入[新建对话窗口](./new-conversation.md)且项目未选择的状态。若该项目只包含主内容承载的来源会话，而选中的 sidebar chat 属于其他项目，则不走此空态，按来源即时失效规则把 sidebar chat 迁移到主内容。
- 移除失败时项目保持可见，当前选择不变，并提供重试。

全局搜索、Agent 团队管理和设置弹窗的内部内容不属于本文档。

## 响应式与窗口行为

- 侧边栏提供可拖动的右侧分隔边界，用户可以在保证 Sidebar 与主内容仍可用的最小、最大范围内调整宽度；精确范围由高保真设计和实现验证确定。
- 长名称单行截断，并通过共享跟随浮层和辅助名称提供完整名称；浮层不能遮挡当前对话行的主要状态和菜单入口。
- 窗口高度不足时只滚动由置顶区和项目列表组成的中部区域，顶部操作和底部“重新查看引导”/“设置”保持可达。
- 窗口宽度低于主页面最低可用宽度时，可以自动关闭侧边栏；窗口恢复后遵循用户最近一次明确选择，不反复自动开合。
- macOS 集成标题栏下，侧边栏顶部正确避让系统交通灯并保留可拖拽区域；侧边栏打开和关闭状态下的控制按钮都与系统交通灯垂直中心对齐。
- 除品牌 Logo 外，同一类图标在控制按钮或文本行中使用一致的图形尺寸、描边与宿主盒；图标由所在行或按钮自然居中，不使用针对单枚图标的垂直偏移。图标、文字与状态点切换不得改变同层文字的基线或横向起点。
- 所有图标按钮必须可键盘聚焦，并提供可读名称和悬停说明。对话菜单无论由右键、菜单按钮还是键盘上下文操作打开，都暴露相同菜单项、禁用原因和焦点顺序；关闭菜单后焦点回到对应对话行或其菜单按钮。
- 键盘焦点在对话行之间移动时，必须提供与指针悬停等价的名称、文件夹和可用分支信息；用户启用 reduced-motion 时，共享浮层立即移动到目标行，不依赖动画才能读到正确内容。

## 关联流程

以下流程将在对应流程 PRD 建立后链接，本文档只记录侧边栏职责：

- 首次启动与添加第一个项目。
- 添加、目录不可用、重新定位和移除项目。
- 创建对话并选择 Agent 团队。

- [对话分析与优化](../flows/session-analysis.md)：侧边栏负责发出对话级入口、提交完整的主内容与右侧栏组合，并在失败时保留进入前现场。

## 指标与验收

### 产品指标

- 用户从打开应用到进入目标对话所需的操作次数和时间。
- sidebar chat 从首次创建成功到出现在最终项目列表中的成功率，目标为 100%。
- 用户从 sidebar chat 行恢复正确来源主线与右侧标签、或在来源失效时降级打开主内容的成功率，目标为 100%。
- 用户从任意主页面状态创建一段项目内对话所需的操作次数。
- 项目或对话选择失败后产生错误选中状态的次数，目标为零。
- 从左侧栏对话菜单进入分析后，主内容来源、右侧栏草稿和选中行一致的成功率，目标为 100%。
- 分析对话首次发送及后续运行后错误生成左侧栏行、独立状态点或独立归档菜单的次数，目标为零。
- 重复添加项目、重复创建空白对话和误移除项目的次数，目标为零。
- 红点对话被用户定位并完成所需动作的比例。
- 阅读状态变更正确保存并在刷新或重启后保持的成功率，目标为 100%。
- 置顶或取消置顶后对话恰好出现在目标区域一次、且重启后位置一致的成功率，目标为 100%。
- 对话信息浮层与当前指针或键盘目标匹配的准确率，目标为 100%，同时可见的信息浮层数量不得超过一份。
- 重命名成功后所有当前入口和重启恢复标题一致的成功率，目标为 100%。

sidebar chat 列表成功率的分母是已经原子创建会话与首条消息的每段 sidebar chat，只有它恰好一次出现在发送瞬间最终项目下才计成功；Agent 随后启动失败不移出分母。找回成功率的分母是用户对仍存在的 sidebar chat 行发起的每个逻辑选择动作，重复点击去重后只计一次；来源可用时完整呈现主内容与右侧标签、来源无效时在主内容呈现，才计成功，任何读取、路由或呈现失败均计入失败。两项在受支持且本地状态有效的路径上目标均为 100%，有效状态与失败不得事后排除的口径沿用[主页面右侧栏](./main-right-sidebar.md#指标与验收)。

左侧栏分析入口成功率的分母，是用户通过右键、行内菜单按钮或键盘上下文操作，对一段记录可访问的根对话明确选择「在右侧栏分析这段对话」后产生的每个逻辑分析动作；同一次菜单动作因事件冒泡、重复回调或界面重渲染触发的底层请求只计一次，三种打开方式分别保留来源维度但不得重复记为多个逻辑动作。只有目标行成为唯一选中项、该对话完整显示在主内容区、对应分析草稿显示在右侧栏且恰好追加一个对话级来源胶囊时才计成功；引用生成、主内容切换、右侧栏打开、草稿呈现或原子提交任一步失败都计入分母并记为失败，不得因回退保住旧现场、用户随后重试成功、项目目录不可用或入口方式不同而排除。对话记录不可访问时菜单项本应禁用，未产生明确选择动作，不进入该指标分母；若禁用项仍错误触发，则作为失败计入。

阅读状态成功率的分母是用户对当时可见状态发起的每个有效标记动作；只有目标圆点按矩阵改变、同一已确认事实不在刷新或重启后重新点亮、手动未读按明确再进入规则清除才计成功。置顶成功率的分母是每个有效置顶或取消置顶动作；只有对话在目标区域恰好出现一次、排序与焦点正确且重启一致才计成功。浮层准确率的分母是指针或键盘依次定位到一段可见对话的每次稳定目标变化；只有始终最多一份信息面、最终字段与目标对话一致且位置对齐目标行才计成功。重命名成功率的分母是用户每次对满足名称输入条件的重命名发起确认；只有保存成功、所有当前入口同步使用新名称且重启后仍恢复新名称才计成功，保存或同步失败均计入分母。上述操作失败不得从分母中事后排除。

指标采集必须遵守本地产品的数据边界；是否上传或仅保存在本地由设置与隐私规则另行定义。

### 验收标准

1. 打开中文主页面，侧边栏首行只保留 macOS 红绿灯安全区和与红绿灯垂直中心对齐的关闭按钮，来自全局品牌母版的产品 Logo 与品牌名位于下一独立行，随后依次显示新建对话、搜索和 Agent 团队；三个应用级入口使用相同视觉层级，项目区与设置分别位于中部和底部。
2. 点击关闭侧边栏，主内容区扩展并出现打开按钮；重新打开后，选中会话、主内容承载会话、右侧会话、项目展开状态和滚动位置保持不变。
3. 点击新建对话进入新建对话窗口；没有项目时该窗口禁止创建并提供添加项目入口，侧边栏不直接承载添加流程。
4. 点击项目行加号进入同一个新建对话窗口，并预选对应项目；进入窗口本身不创建持久化空白对话。
5. 红点、蓝点和闪烁点分别表达需要人工处理、未读和运行中；静止且没有阅读提醒的对话无点，用户按下“停下”后无点，且辅助名称不依赖颜色即可读懂状态。红点的具体触发来源按[主页面会话区](./main-conversation.md#侧边栏状态点的触发)核对。
6. 项目内未置顶对话只按创建时间倒序稳定排列，置顶区按置顶时间倒序排列；人工打开、当前选中、后台 Agent 输出和任何状态变化都不得改变各自顺序。取消置顶后对话按原创建时间回到所属项目。
7. 对话没有“已完成”状态或完成折叠组；归档后从侧栏消失但记录仍保留。当前根对话或任一分析后代仍有运行中或待接回控制工作时，归档入口不可执行并显示原因；全部结束后恢复可用。
8. 团队拆出的子对话不出现在侧边栏；项目下只列用户自己发起的对话，侧栏长度不随团队的拆分行为变化。子对话的入口由[主页面会话区](./main-conversation.md#区域与信息)的时间线卡片承担。
9. 项目目录不可用后，项目行显示带明确提示的独立红色扳手修复按钮；历史对话仍可只读查看，但不能新建、发送、切换团队或启动 Agent。选择同一项目的新位置且通过“一个文件夹只能绑定一个项目”的校验后，原项目和对话历史保持不变并恢复工作能力。
10. 用户可以直接拖动项目行排序且无需独立拖动把手；拖动不误触展开或折叠，重启应用后顺序保持，新项目默认置顶，任何运行或状态变化都不自动重排项目。
11. 移除项目的确认弹窗在确认操作前同时显示“项目将从 Sidebar 消失”“其对话将全部归档”“消息、执行记录和交付结果仍保留”“当前版本没有查看或恢复入口”，并另行说明不会删除或修改磁盘文件；项目内存在根对话或分析对话时，还要说明以这些对话为子树根的全部分析后代会一起隐藏，即使某个后代使用其他项目。缺少任一项都不得执行移除。重新添加同一路径时创建新项目，旧历史不自动混入。项目内任意对话或将递归隐藏的后代存在运行中或待接回控制工作时，必须先经独立警告弹窗选择取消或强制移除；被移除项目包含选中会话时进入新建对话且项目未选择的状态，只包含 sidebar chat 来源时则把选中 sidebar chat 迁移到主内容，移除失败时项目和完整组合保持不变。
12. 搜索只打开全局搜索，Agent 团队只进入对应管理界面；设置在当前工作区上方打开模态弹窗，不改变选中会话、主内容承载会话、右侧会话、草稿、滚动位置或侧边栏状态，关闭后焦点回到设置入口。本文档定义的侧边栏不承载这些界面的内部内容。
13. 项目或对话切换失败时，侧边栏选中态与主内容保持在原对象，不出现双事实状态。
14. 用户可以拖动 Sidebar 右侧边界调整宽度；长名称仍单行截断并可查看完整名称。
15. 置顶对话与项目数量合计超过一屏时，只有包含置顶区和项目列表的中部区域滚动，二者都能滚动到达；红绿灯安全区、侧栏关闭按钮、Logo、顶部操作和底部设置始终可达。
16. 窗口过窄时 Sidebar 自动关闭；窗口重新变宽后，最近一次明确选择为打开则恢复打开，用户手动关闭过则保持关闭。
17. 所有图标入口均可使用键盘操作，并具有无需依赖图标外形即可理解的辅助名称。
18. 选择第二个项目中的任意用户对话并重启应用后，恢复同一选中会话；它是 sidebar chat 时同时恢复主内容承载会话与右侧会话组合。没有历史选择或选中会话已不可恢复时进入未选择项目的新建对话，不回退到第一个项目的默认或最早对话。
19. 对话菜单提供“复制对话记录路径”：触发后这段对话记录文件的稳定路径进入剪贴板；把该路径交给对话之外的阅读工具即可读到包含消息、系统记录和各步运行过程的完整经过，且对话继续推进后重新读取能跟上最新内容；复制失败时有可理解说明且剪贴板不被写入。
20. “重新查看引导”固定在侧边栏底部的“设置”上方，键盘顺序与视觉顺序一致；点击后进入引导回看，退出或完成回看时恢复进入前的项目展开、选中会话、主内容承载会话、右侧会话、草稿和应用页面状态。
21. 在没有项目、项目目录不可用、项目数据加载中或加载失败四种状态下，底部“设置”都保持可操作并能打开语言与关于分类；项目数据状态不得让设置入口禁用、消失或进入无限等待。
22. 非分析 sidebar chat 首次消息成功创建后，按发送瞬间最终选择的项目作为普通会话加入项目列表；标题、顺序、菜单和归档与普通主会话一致。
23. 点击有可用来源的 sidebar chat 行时，只高亮该行，来源行不高亮；来源会话显示在主内容区，目标会话显示在右侧栏。点击普通来源会话行时则高亮来源行，即使右侧栏恢复了 sidebar chat 标签也不反向改变选中态。
24. 点击没有来源或来源失效的 sidebar chat 行时，该会话直接在主内容区打开并保持可继续；来源失效不会阻止选中。
25. sidebar chat 与来源会话各自独立显示并清除红点、蓝点和闪烁点，互不复制；项目折叠时只有仍留在该项目列表中的对话参与最高优先状态聚合，已经移入置顶区的对话不重复聚合。
26. sidebar chat 与来源会话跨项目时，sidebar chat 始终列在自己首次发送所选的最终项目下；恢复来源主线不会移动列表位置或同时选中来源项目中的行。
27. 有来源的 sidebar chat 只有在来源主内容与目标右侧标签都成功呈现后才提交选中态；任一路由失败都保留此前主内容、右侧栏和选中态。最后选中 sidebar chat 后重启应用，同样恢复这一组合；没有来源或来源失效时以主内容成功呈现为提交条件。
28. 归档 sidebar chat 时关闭它在右侧栏中的对应标签，不影响来源会话或其他兄弟标签；若它是当前选中行，则按同项目相邻对话规则提交新选中态，搜索恢复后仍按 sidebar chat 找回路由打开。
29. 全文的选中会话、主内容承载会话和右侧会话按术语定义区分；折叠项目、关闭再打开侧边栏、离开并返回主页面或重启应用，都完整保留 sidebar chat 选中、来源主内容与右侧会话组合。侧边栏关闭时主内容顶部显示来源会话名称，重新打开后仍高亮 sidebar chat 行。
30. 已选中 sidebar chat 的来源在组合呈现后失效时，sidebar chat 保持唯一选中并原地迁移到主内容区，阅读位置、草稿、运行与状态点不变，旧来源右侧标签被移除且不重复显示。应用内归档或移除导致迁移失败时不提交原操作；外部失效导致迁移失败时保留最后成功组合、显示说明并可重试。
31. 移除项目会原子归档以该项目工作的普通主会话、非分析 sidebar chat 和分析对话；每个因此归档的根对话或分析对话都作为子树根递归隐藏其全部分析后代，即使后代使用其他项目。对应父面板入口与右侧栏标签同时隐藏，子树之外的未归档父对话、兄弟分析对话和其他兄弟标签保持；分析对话的直接父子关系不改写，也不生成左侧栏行。任一步失败不提交半套移除。
32. 任一根对话行都能通过右键、可聚焦的菜单按钮和键盘上下文操作打开同一菜单并选择「在右侧栏分析这段对话」。当前行只追加对话级来源胶囊；非当前行在来源主内容与右侧栏草稿都呈现后才成为唯一选中项，并保留此前对话现场。项目目录不可用但对话记录可访问时入口仍可用；记录不可访问时菜单项带原因禁用，且不创建空分析草稿。
33. 从根对话整段入口或任一对话的消息入口创建分析对话并成功发送首条消息后，所有项目列表都不新增该分析对话行，当前根对话仍是左侧栏唯一选中项；该分析对话只出现在直接父对话的分析面板。再从分析对话消息创建下一层时，同样只进入直接父分析对话的面板，不进入根对话面板或左侧栏。
34. 分析对话没有左侧栏状态点、对话菜单或独立归档入口。归档根对话时整棵分析后代树一起隐藏；移除项目时，以该项目工作的每段分析对话及其全部后代递归隐藏，该项目中的根对话也连同全部分析后代递归隐藏。上述操作不得改变任何分析对话的直接父子归属，也不得留下父对话已隐藏但后代仍可运行却无法找回的孤立对象。
35. 关闭应用前让某个分析对话标签处于活动状态，重新启动后左侧栏仍只恢复其根对话为唯一选中行，并恢复该根对话自己的右侧栏标签组；分析对话不生成临时行或选中态，分析面板默认关闭。
36. 令项目移除范围内同时存在运行中的 Agent、托管运行项和已返回但尚未由主 Agent 接回的结果，普通移除不执行；独立警告分别列明三类影响，并说明历史仍保留。用户取消时不改变任何运行项、待接回状态、归档、面板、标签或项目；用户确认强制移除时，先停止全部相关 Agent 运行与托管运行项，再把待接回结果标记为已放弃接回，最后才递归归档对话树并移除项目。任一步失败都不得开始后续步骤或留下被宣称为完整成功的半套结果。
37. 以最终可见点为准：红点和蓝点菜单只提供「标记为已读」，闪烁点不提供阅读操作，无点只提供「标记为未读」；红点与运行重叠时先显示红点并允许标记已读，成功后仍在运行则转为闪烁。一次标记已读确认提交时形成当前提醒的全部已知事实，同一事实在刷新和重启后不再点亮，后来新事实仍能提醒。手动未读的当前会话必须先离开再明确返回才自动清除，并跨重启保留；保存失败、重复触发或菜单状态陈旧时保持原状态且不误执行。
38. 置顶区只在至少存在一段置顶对话时出现在三个应用级操作与项目区之间，并与项目区共同滚动。置顶后对话从所属项目列表移入该区且不重复显示；项目全部对话被置顶时显示“对话均在置顶区”。取消置顶后按原创建时间归位。两种操作失败时都不产生丢失、双份条目或半套状态，重启应用后位置保持；键盘焦点跟随迁移，取消置顶进入折叠项目时落到项目展开控制而不强制展开。
39. 依次把指针或键盘焦点定位到对话 A、对话 B 后，整个过程中最多只有一份可见信息面，最终信息面只包含 B 的完整名称、文件夹名称和 B 实际工作空间的分支信息，并对齐 B 行；非 Git 不出现第三行，detached 显示 `detached`，分支不可读显示“分支不可用”。离开列表、打开菜单或重命名弹层后信息面收起；reduced-motion 下无需等待动画即可得到同一最终信息。
40. 任一普通主会话或 sidebar chat 都能从对话菜单重命名；空名称不能保存，重名允许。成功后置顶区、项目列表、主内容标题和右侧会话标签使用一致的新名称，重启后仍保留，项目、文件夹、分支、排序依据、来源关系、历史与运行均不改变；保存失败时原名称保持、弹层不关闭且输入不丢失。
41. 更新包未完整下载并校验通过时，底部只显示“设置”；包就绪后在“设置”右侧出现独立、可聚焦且有明确辅助名称的“安装更新”按钮，下载中、检查中、失败或已是最新版时不显示该按钮。
42. “安装更新”与“设置”是两个并列操作，安装按钮不嵌套在设置按钮中；点击安装先打开确认弹窗，取消或“继续工作”不改变侧边栏状态，确认停止任务后才开始安全收尾。
43. 普通退出和重启安装共享任务保护与资源回收边界，但使用不同的弹窗标题、说明和确认按钮；Agent、托管运行项、AI 建队与 CLI 安装都计入运行任务。没有运行任务时，用户执行一次 `Command + Q` 不新增确认弹窗并直接安全退出；有运行任务时才显示退出保护。确认后托管运行项全部停止且下次启动不恢复；任一资源回收失败时应用保持打开并说明未能安全退出。收尾后进程结束、Dock 不再显示运行中指示；若应用未固定在 Dock，图标消失，不要求第二次退出。
