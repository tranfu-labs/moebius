# 主页面侧边栏

> 状态：已完成产品采访，sidebar chat 增量已同步，首轮用户视角评审意见已修订，待复评
>
> 所属页面：主页面
>
> 范围：只定义左侧栏及其直接触发行为，包括普通主会话与 sidebar chat 的列表、选中态、状态点和找回路由；[新建对话窗口](./new-conversation.md)、[全局搜索](./search.md)、Agent 团队管理和[设置](./settings.md)分别定义。
>
> 产品基线：[moebius 产品需求文档](../prd.md)
>
> 关联流程：[会话分析流程](../flows/session-analysis.md)；关联页面：[主页面会话区](./main-conversation.md)、[主页面右侧栏](./main-right-sidebar.md)

本文统一使用三个不互换的术语：

- **选中会话**：左侧栏唯一高亮、代表用户当前导航目标的会话。
- **主内容承载会话**：当前显示在中间主内容区的会话。
- **右侧会话**：当前显示在右侧栏会话标签中的会话。

普通主会话被选中时，选中会话与主内容承载会话是同一个对象；sidebar chat 组合路由中，选中会话和右侧会话是 sidebar chat，主内容承载会话是它的来源会话。后文未带限定的“当前会话”仅用于二者相同的普通状态。

## 页面目标

侧边栏是主页面中稳定存在的导航与任务入口。它让用户可以快速发起对话、在项目之间定位已有对话、识别需要关注的新结果或人工处理事项，并进入 Agent 团队管理或打开应用设置。

侧边栏只回答四个问题：

1. 我现在可以从哪里开始一段对话？
2. 我的项目和对话在哪里，哪一段正在运行或等待我？
3. 我如何进入 Agent 团队管理，并在不离开当前任务的情况下打开应用设置？
4. 我从右侧栏创建的普通会话在哪里，怎样回到当时并排工作的现场？

侧边栏不是工作流图、运行日志、项目仪表盘或主内容承载会话的消息目录。用户无需先理解内部编排结构，便能找到项目和对话；主内容承载会话的目录轨与原文导航属于[主页面会话区](./main-conversation.md#会话目录轨)。

## 用户场景

- 用户打开应用，从最近使用的项目和对话继续工作。
- 用户不关心具体项目入口，直接从顶部创建一段新对话。
- 用户已明确目标项目，直接在该项目下创建新对话。
- 用户在多个项目间切换，查找正在运行、产生新结果或等待人工处理的对话。
- 用户从右侧栏创建并推进了一段普通 sidebar chat，稍后从项目列表中找回它及其来源主线。
- 用户尚未添加项目时，从固定的新建对话入口进入添加项目流程。
- 用户需要重命名、排序、修复或移除已有项目。
- 用户需要进入 Agent 团队管理或搜索，或在当前工作区上方打开设置。
- 用户希望临时扩大对话区域，关闭侧边栏后继续工作。

## 入口与去向

### 入口

- 应用完成首次启动配置后，默认进入主页面并显示侧边栏。
- 非首次启动时，应用恢复用户上次成功打开的项目和用户发起的对话；最后选中的是 sidebar chat 时，同时恢复其来源主线与右侧栏标签，让用户从离开的位置继续工作。
- 没有可恢复的历史选择，或上次选择的对话已归档、所属项目已移除时，主内容区进入“新建对话”且不预选项目；应用不得擅自打开项目列表中的第一个项目或对话。
- 用户从 Agent 团队或搜索结果返回主页面时，恢复离开前的项目展开状态、选中会话、主内容承载会话与右侧会话组合；设置始终覆盖在当前主工作区上方，关闭后直接回到打开前的同一位置，不产生离开与返回。
- 侧边栏关闭时，主内容区顶部保留“打开侧边栏”按钮。

### 去向

- “新建对话”打开[新建对话窗口](./new-conversation.md)；项目选择、添加项目和对话创建由该窗口承接。
- “搜索”打开[全局搜索](./search.md)。搜索内容与结果行为由该页面定义。
- “Agent 团队”进入 Agent 团队管理界面。
- 项目内“新建对话”打开同一个[新建对话窗口](./new-conversation.md)，并预选对应项目。
- 点击普通主会话进入对应主页面时间线。
- 点击 sidebar chat 时，选中态落在被点击的 sidebar chat 行：来源会话仍可用时，来源会话显示在主内容区、sidebar chat 在右侧栏打开或聚焦；没有来源会话或来源已经不可用时，sidebar chat 作为普通会话直接在主内容区打开。
- “重新查看引导”以回看模式打开[首次启动引导](./onboarding.md)，退出或完成后返回进入前的主页面状态。
- “设置”在当前主工作区上方打开[设置弹窗](./settings.md)，不改变当前页面、项目、对话、草稿、滚动位置或侧边栏状态。

## 页面结构

### 默认展开

```text
┌──────────────────────────────┐
│ ● ● ●                [关闭] │  红绿灯安全区与侧栏控制行
│ [Logo] Moebius               │  独立品牌行与窗口拖拽区
├──────────────────────────────┤
│ ＋ 新建对话                  │
│ ⌕ 搜索                       │
│ ◇ Agent 团队                 │
├──────────────────────────────┤
│ 项目                         │
│                              │
│ ▾ 项目 A            [＋][⋯] │
│    对话 1                  ● │  红点：需要人工处理
│  » 对话 2                  ● │  闪烁点：运行中
│    对话 3                    │
│    对话 4                  ● │  蓝点：有未读结果
│                              │
│ ▸ 项目 B              ● [⋯] │  折叠时显示最高优先状态点
├──────────────────────────────┤
│ ? 重新查看引导               │
│ ⚙ 设置                       │
└──────────────────────────────┘
```

图例：

- `»`：当前选中的对话。
- 红色 `●`：需要用户回答、确认、验收或处理异常。
- 蓝色 `●`：Agent 本轮已经结束并产生用户尚未查看的新结果。
- 闪烁 `●`：Agent 正在运行。
- 无点：当前静止，且没有未读结果或人工处理事项。
- 折叠项目只显示一个代表其子对话最高优先状态的点，优先级为红点、蓝点、闪烁点；展开后由对话行自行显示，不在项目行重复。

### 侧边栏关闭

```text
┌──────────────────────────────────────────────┐
│ [打开侧边栏]    主内容项目 / 主内容承载会话  │
├──────────────────────────────────────────────┤
│                                              │
│                 主内容区                     │
│                                              │
└──────────────────────────────────────────────┘
```

侧边栏关闭时，主内容顶部的项目与会话名称始终描述屏幕中间实际显示的主内容承载会话；组合路由下因此显示来源会话，而不是隐藏起来的 sidebar chat。重新打开侧边栏后，sidebar chat 仍作为唯一选中会话高亮，右侧栏与主内容共同恢复关闭前的完整组合。

关闭后侧边栏完全隐藏，主内容区占用释放出的宽度。打开按钮属于主页面在侧栏关闭状态下的恢复入口；本文档只规定它必须存在，不规定主内容区其他结构。

### 没有项目

```text
┌──────────────────────────────┐
│ ● ● ●                [关闭] │
│ [Logo] Moebius               │
├──────────────────────────────┤
│ ＋ 新建对话                  │
│ ⌕ 搜索                       │
│ ◇ Agent 团队                 │
├──────────────────────────────┤
│ 项目                         │
│                              │
│ 还没有项目                   │
│ 从“新建对话”添加第一个项目   │
├──────────────────────────────┤
│ ? 重新查看引导               │
│ ⚙ 设置                       │
└──────────────────────────────┘
```

顶部“新建对话”仍然可点击，并打开[新建对话窗口](./new-conversation.md)。没有可用项目时，该窗口禁止创建对话并提供添加项目入口；侧边栏自身不承载添加项目流程。

### 项目目录不可用

```text
│ ▾ 项目 A            [🔧][⋯] │  红色扳手：修复项目文件夹
│   原文件夹已不可用             │
│    历史对话 1                  │
│    历史对话 2                  │
```

历史对话仍可查看，但全部只读。项目目录不可用时，不允许创建新对话、发送新消息、切换团队或启动新的 Agent 执行。项目行显示独立的红色扳手修复按钮；悬停提示“当前项目本地文件夹未找到，可以指定新的文件夹”，点击后让用户指出同一项目被移动或重命名后的新位置。修复入口不得藏入项目更多菜单。

项目在 Agent 运行期间变为不可用时：已经拥有有效隔离工作副本的执行可以完成当前一步，但完成后停止自动接力并把对话标为红点；依赖原目录、已经无法安全继续的执行立即停止并标为红点。侧边栏不得在执行已经无法继续时仍长期显示闪烁运行点。

## 区域与信息

### 品牌、标题栏与关闭按钮

- 顶部第一行使用统一的窗口 header 高度并保留桌面窗口拖拽区域；系统交通灯和该行内控件由同一容器自然垂直居中，不使用单独的位置补偿。
- 顶部固定显示产品 Logo 和品牌名 `Moebius`，形成主窗口持续可见的产品识别；Logo 必须使用[总 PRD](../prd.md#品牌与发行平台)规定的品牌母版派生图像，不得使用另一枚手绘或图标库无限符号代替；`moebius` 只作为项目与技术标识，不作为该位置的界面文案。
- macOS 为系统交通灯预留空间；Logo、品牌名、拖拽区域和系统交通灯不得重叠。
- “关闭侧边栏”固定在顶部右侧，不随项目列表滚动。
- 图标按钮必须有“关闭侧边栏”辅助名称和悬停提示。

### 应用级操作

应用级操作固定在项目列表上方，不随项目列表滚动：

1. 新建对话。
2. 搜索。
3. Agent 团队。

三个入口使用相同的导航行高度、文字层级和交互样式，不把 Agent 团队藏入设置，也不通过特殊颜色或徽标额外突出。它的常驻位置本身负责让用户意识到产品存在可配置的 Agent 团队。英文界面对应名称为 `Agent Teams`；侧边栏全部 Moebius 静态文案、提示、菜单和可访问名称继承[设置](./settings.md#语言覆盖范围)的中英文覆盖规则，不得因侧边栏遗漏而与当前界面语言混用。

### 项目标题行

- 显示“项目”区标题。
- 添加项目不在侧边栏出现，由[新建对话窗口](./new-conversation.md)统一承接。
- 项目列表是侧边栏唯一可滚动的主要区域；顶部应用级操作和底部设置保持固定。

### 项目行

每个项目行包含：

- 展开或折叠控制。
- 项目显示名称。
- 项目内新建对话按钮。
- 项目更多菜单。
- 折叠时必要的状态聚合。
- 项目目录不可用时的独立红色扳手修复按钮。
- 项目行自身承载的拖动排序能力，不另设独立拖动把手。

项目默认显示本地文件夹名。用户设置显示名称后，只改变应用内名称，不重命名磁盘上的文件夹。

项目顺序由用户控制并持久保存，不因对话运行、产生新消息或出现任何状态点而自动变化。刚添加的项目默认出现在列表最上方、自动展开并成为当前项目。用户直接拖动项目行调整顺序，不显示独立拖动把手；点击与拖动必须通过明确的移动阈值区分，拖动结束不得误触展开或折叠。项目菜单不提供上移、下移或移到顶部命令。

### 对话行

每个对话行只显示：

- 一行对话标题。
- 一个必要的状态图标。
- 当前选中态。

长标题单行截断，悬停显示完整标题。侧边栏不显示运行角色、消息摘要、消息数量、阶段名称、成员名称、消息目录或文件路径。

侧边栏只列用户自己发起的对话。用户在右侧栏首次发送后创建的 sidebar chat 也属于用户发起的普通会话，按发送瞬间最终选择的项目列入对应项目，使用普通会话标题、菜单、排序、归档与状态点规则。分析入口只是创建前的切入方式，不给已创建行增加专用阶段、来源团队权限或另一套生命周期。

sidebar chat 行与来源会话行是两个独立会话对象：各自只显示自己的运行、未读结果和待处理状态，不把 sidebar chat 的状态点复制到来源行，也不把来源状态复制到 sidebar chat 行。首版不要求专用图标、标题前缀或来源摘要；标题仍按普通会话规则单行显示。

团队为了推进一个目标而拆出的子对话不出现在这里，它们的入口是父对话时间线中的卡片，见[主页面会话区](./main-conversation.md#区域与信息)。

> **子对话是否进侧边栏已在 2026-07-21 被重新裁决。** 本文原先规定子对话与普通对话平铺为同级条目、以“来自：<父对话名称>”标明来源。该规定被推翻，理由是：子任务是团队的内部产物，不是用户主动管理的对象，而侧边栏是用户管理自己工作的地方；让它们进入侧边栏会使侧栏长度随团队的拆分行为膨胀，用户拆得越细、侧栏越不可用。代价是用户不能从侧边栏直接跳到某个子任务，必须先回到父对话——这被接受，因为子任务本来就只在父对话的语境里有意义。

### 底部应用操作

- “重新查看引导”和“设置”共同固定在侧边栏底部，不随项目列表滚动；前者位于后者上方，并复用侧边栏导航行的图标、文字与键盘交互样式。
- “重新查看引导”直接进入回看模式，不弹确认框；回看本身可退出，进入操作可逆。
- “设置”固定在侧边栏底部，不随项目列表滚动；点击在当前工作区上方打开[设置弹窗](./settings.md)，关闭后焦点回到该入口。
- 底部不常驻数据库路径、运行目录、内部标识或原始错误。
- 本地引擎异常若导致主功能不可用，可以在设置入口附近显示非技术化状态提示；诊断细节进入独立诊断界面，不塞进设置入口或设置弹窗的常驻信息。

## 操作与反馈

### 关闭与打开侧边栏

- 点击关闭按钮后立即隐藏侧边栏，主内容区扩展。
- 主内容区出现固定的打开按钮；点击后恢复侧边栏。
- 恢复时保留选中会话、主内容承载会话、右侧会话、项目展开状态和项目列表滚动位置；sidebar chat 组合路由不能被压成其中任意一个会话。
- 应用记住用户最后一次选择；下次启动恢复关闭或展开状态，但在首次启动引导期间始终保持侧边栏可见。

### 应用级新建对话

- 点击后打开[新建对话窗口](./new-conversation.md)，不在侧边栏内直接创建空白对话。
- 没有可用项目时仍可进入该窗口，但创建操作不可用，用户需要先在窗口内添加项目。
- 项目选择、Agent 团队选择、取消、创建和失败恢复由新建对话窗口定义。

### 搜索

- 点击打开[全局搜索](./search.md)。
- 侧边栏保持在背景中，关闭弹窗后恢复原选中会话及其主内容、右侧栏组合。
- 搜索范围、结果分组、键盘行为和空态由全局搜索文档定义。

### Agent 团队

- 点击进入 Agent 团队管理界面。
- 进入后该入口呈现当前选中态。
- 返回主页面时恢复离开前的选中会话、主内容承载会话、右侧会话、项目展开和侧边栏状态。

### 设置

- 点击后在当前主工作区上方打开[设置弹窗](./settings.md)，侧边栏、项目区和主内容保持原状态并作为不可操作的背景留在原位。
- 关闭设置后直接回到打开前的工作区位置，焦点回到侧边栏“设置”；该动作不属于页面导航，不产生单独的返回主页面步骤。
- 设置中的语言、应用身份、版本与检查更新属于应用级能力，不依赖项目列表、当前项目、对话数据或本地运行是否可用；项目数据加载中、加载失败、没有项目或项目目录不可用时仍可打开。
- 弹窗内分类、异步操作、关闭恢复与外部链接行为由设置页定义，侧边栏不复制这些内部规则。

### 项目内新建对话

- 点击项目行的加号，打开[新建对话窗口](./new-conversation.md)并预选该项目；不会在侧边栏点击瞬间直接创建持久化空白对话。
- 项目目录失效或项目正在变更时，该按钮不可用并说明原因。

### 展开和折叠项目

- 点击项目行的展开箭头或项目名称切换项目子列表，不改变选中会话、主内容承载会话或右侧会话；项目本身不进入独立项目主页，也不产生项目选中态。
- 项目行同时是拖动排序载体；超过拖动阈值后只执行排序，结束时不得继续触发点击展开或折叠。项目行内的 `＋` 和 `⋯` 是独立按钮，不触发行点击或拖动排序。
- 项目展开时，由子对话自行显示状态，项目行不重复展示状态点。
- 项目折叠时只显示一个代表子对话最高优先状态的点，不显示数量。红点优先于蓝点，蓝点优先于闪烁点。
- 选中会话所在项目允许被用户手动折叠；组合路由下即使 sidebar chat 行被隐藏，主内容仍显示来源会话、右侧栏仍显示 sidebar chat，不退出、不切换。主内容承载会话所在的另一项目也可独立折叠，两者都不得因组合路由被自动重新展开。
- 项目折叠时暂时隐藏其对话列表，不产生项目选中态；再次展开选中会话所属项目后，原 sidebar chat 或普通主会话仍显示唯一选中态。

### 选择对话

- 点击普通主会话行打开对应时间线，并将选中态移动到该行。
- 点击 sidebar chat 行时，选中态只移动到该 sidebar chat 行，来源会话行不同时高亮。来源会话可用时，应用把来源会话放在主内容区，并打开右侧栏、创建或聚焦绑定该 sidebar chat 的标签；没有来源或来源不可用时，在主内容区直接打开 sidebar chat。无论显示在哪个容器，状态点仍属于 sidebar chat 自己。
- sidebar chat 的来源会话与自身可能分属不同项目；列表位置始终由 sidebar chat 首次发送时最终选择的项目决定，不因为恢复来源会话而移动到来源项目。
- 点击 sidebar chat 后，只有来源主内容与目标右侧标签都成功呈现，才提交新的选中态。任一必要路由失败时保留之前的主内容、右侧栏与侧栏选中态，并给出可理解说明；不得让 sidebar chat 行已选中而右侧栏仍显示另一段会话。
- 点击没有来源或来源失效的 sidebar chat 时，只要它已在主内容区成功呈现就可以提交选中态；来源失效不作为会话不可访问错误。
- 点击普通主会话后，右侧栏继续按[主页面右侧栏](./main-right-sidebar.md)恢复该主会话自己的标签现场；若其中原本就有某段 sidebar chat 标签，不因此把选中态改到该 sidebar chat 行。
- 普通主会话切换失败时保留原对话，不出现侧栏选中了新对话而主内容仍是旧对话的双事实状态。
- 打开带蓝点的对话并成功展示最新结果后，清除蓝点。
- 打开带红点的对话不会仅因查看而清除红点；只有导致红点的那件事被处理掉（重试成功、换人接手推进、项目文件夹或团队恢复可用）之后才清除。
- 闪烁运行点在运行结束时自动消失；若本轮结束后产生尚未查看的新结果且最后一条未提及任何成员则转为蓝点，若这一步没跑起来、卡住或反复重试仍未成功则转为红点。

### 组合路由中的来源即时失效

sidebar chat 已作为选中会话显示在右侧栏后，来源会话可能因为被归档、所属项目被移除、会话记录失效或其他原因不再能承载主内容。来源失效只改变容器路由，不归档 sidebar chat，不改变其项目、权限、历史、运行或状态点。

- 应用检测到主内容承载会话已经不再可用时，把当前选中的 sidebar chat 原地迁移到主内容区；侧栏仍只选中该 sidebar chat。
- 迁移保留 sidebar chat 的时间线阅读位置、输入草稿、运行状态和当前焦点语义；它在原来源外层右侧栏中的标签被移除，不能同时在主内容与旧右侧标签重复出现。
- 原来源标签组中的其他兄弟标签不因迁移被删除；来源重新可用也不自动把 sidebar chat 移回右侧栏，只有用户下一次从该行明确打开时再按当时来源状态路由。
- 应用控制的归档或项目移除必须先确认 sidebar chat 能在主内容区呈现，再原子提交来源失效与新路由；迁移失败时不完成对应归档或移除，保留原组合并说明原因。
- 来源因为应用外变化突然失效、无法撤回时，迁移失败不得清空页面或改选其他会话：保留最后成功呈现的组合和 sidebar chat 选中态，标明来源已失效并提供重试；下一次成功迁移或重启恢复时直接在主内容区打开 sidebar chat。

### 项目与对话菜单

项目更多菜单只包含：

- 在文件管理器中显示。
- 修改显示名称。
- 移除项目。

菜单打开时必须明确对应哪个项目。菜单操作不得因为列表滚动或项目状态刷新而错误作用到其他项目。项目文件夹修复不属于更多菜单，而由项目行上的独立红色扳手按钮承载。

每个对话行在悬停、键盘聚焦或上下文操作时提供对话菜单。当前侧栏范围内，对话菜单只包含“归档”和“复制对话记录路径”；后续增加的操作不得混入项目菜单。

### 复制对话记录路径

- 服务复盘：用户想把一段对话的完整经过交给对话之外的工具或另一个 AI 阅读分析。
- 每段对话的完整经过——消息、系统记录和各步运行过程——本来就以机器可读的记录文件持续落在磁盘上（见 [ADR-0004](../../adr/0004-jsonl-session-fact-log.md)）。触发菜单项时把该文件的路径复制到剪贴板；成功反馈说明“路径已复制”，让用户知道下一步是把它粘给要读的工具。
- 路径指向的是持续更新的记录本身，不是导出时刻的快照：对话继续推进时，拿到路径的阅读工具可以重新读取并跟上最新经过。运行中的对话同样可以复制。
- 同一段对话的路径稳定不变，复制一次即可长期使用。
- 复制路径是显式动作；这不违背“界面文案不出现内部标识”——菜单项和反馈文案不展示路径本身，路径只进剪贴板。
- 该文件就是对话记录的事实本身：外部工具应只读；文件被用户或外部工具修改、删除时，对话历史随之受损，产品按加载异常如实呈现，不承诺恢复。

### 对话状态点与顺序

侧边栏只用一个小圆点表达需要用户感知的状态：

1. **红点**：这段对话遇到了需要用户处理的事，红点表示它已经无法自己往下走。触发来源由[主页面会话区](./main-conversation.md#侧边栏状态点的触发)定义，本文不重复列举。
2. **蓝点**：本轮 Agent 已结束并产生用户尚未查看的新结果，且最后一条消息没有提及任何成员。蓝点不代表任务已经完成，也不要求用户立即行动；最后一条提及了某个成员时属于团队内部仍在传递，不给蓝点。
3. **闪烁点**：Agent 正在运行。闪烁必须克制，不造成持续视觉干扰。
4. **无点**：对话静止，且没有未读结果或需要用户处理的事项。用户自己按下“停下”之后是无点。

同一时刻只显示一个点：红点优先于蓝点，蓝点优先于闪烁点。点的颜色不是唯一信息来源，悬停提示和辅助名称必须分别读作“需要你处理”“有新结果”“正在运行”。

sidebar chat 完整复用同一套状态点判定，但只读取它自己的运行和消息事实。用户打开 sidebar chat 并成功展示最新结果后，只清除该行自己的蓝点；来源会话是否已读不随之改变。项目折叠时，sidebar chat 与普通主会话一起参与该项目的最高优先状态聚合。

> **红点来源已在 2026-07-21 被重新裁决。** 本文原先定义红点为“需要用户回答、确认、验收或处理异常”。该定义被推翻，理由是：它假设 Agent 会主动声明自己需要人工裁决，而产品目前没有这样的信号源，导致红点既可能漏报（Agent 卡住却不声明），也可能误报（把正常的团队内部传递当成等待用户）。新定义只认那些**产品能确定判断**的事实，从而保证一条硬性质——用户被红点带回一段对话时，页面上一定有一条说明发生了什么的记录，不会出现“被叫回来却看不出要我干什么”。让成员主动声明“我需要用户裁决”是更精确的红点来源，需要另行约定，见[主页面会话区](./main-conversation.md#待讨论)的待讨论条目。

对话只按创建时间倒序排列，最新创建的普通主会话或 sidebar chat 固定在最上面，最早创建的在最下面。人工打开、当前选中、后台 Agent 的流式输出、新结果、等待人工、运行状态和计时更新都只改变对应界面状态，不得改变对话顺序，避免并行任务让侧边栏持续跳动。

### 归档

- 产品不设置“已完成”侧栏状态，也不自动把对话收入完成分组。
- 用户可以从对话菜单主动归档一段不再需要出现在侧边栏中的对话。
- 归档不会删除消息、执行记录或交付结果。
- 运行中的对话不能归档；用户需要先中止或等待当前运行结束。
- 选中会话被归档后，选择其所属项目中相邻的可见对话；没有其他对话时显示项目空态。
- sidebar chat 完整复用归档规则。归档时关闭它在右侧栏中的对应标签，但不影响来源会话或其他兄弟标签；被归档的 sidebar chat 当前已选中时，再按同项目相邻对话规则提交新的选中态。
- 归档后的查找和恢复由[全局搜索](./search.md)承接；搜索提供“包含已归档对话”开关，并为归档结果提供恢复入口。

## 弹层与危险操作

### 修改项目显示名称

- 使用轻量弹层输入应用内显示名称。
- 空名称恢复为文件夹名，而不是产生“未命名项目”。
- 修改不影响磁盘目录、已有会话或 Agent 执行路径。

### 修复项目文件夹

- 该能力只处理同一个项目文件夹在应用外被移动或重命名的情况，不用于把一份项目历史改接到另一个项目。
- 项目文件夹不可用时，项目行显示独立的红色扳手图标按钮；悬停提示“当前项目本地文件夹未找到，可以指定新的文件夹”。
- 用户点击该修复按钮后，通过系统文件夹选择器指出项目的新位置。
- 确认前同时显示原位置和用户选择的新位置，说明应用将从新位置继续使用原项目历史。
- 确认成功后更新当前项目的位置，保留项目顺序、显示名称、对话历史和当前选择，并恢复新建、发送、团队切换和 Agent 执行。
- moebius 不移动、复制或重命名磁盘上的任何文件；它只更新自己记录的项目位置。
- 用户取消、所选目录不可访问或更新失败时，项目继续保持原记录和只读状态，不产生第二个项目或部分更新。
- 一个本地文件夹同一时刻只能绑定一个项目。所选目录已经被另一个现有项目使用时，禁止重复绑定或合并两个项目记录；提示用户该目录已绑定其他项目，并允许转到已有项目或重新选择。

### 移除项目

- “移除项目”必须经过确认弹窗。
- 用户确认前，弹窗必须同时明确四项当前后果：项目将从 Sidebar 消失；该项目下的对话将全部归档；消息、执行记录和交付结果仍保留；当前版本没有查看或恢复这些已移除项目与已归档对话的入口。弹窗另需说明移除绝不删除或修改磁盘上的项目文件夹，不得只用“数据仍保留”弱化当前无法访问的事实。
- 移除后项目从 Sidebar 消失，项目语义为“已移除”；该项目下的对话统一转为“已归档”，消息、执行记录和交付结果仍保留。当前设置只提供“常规”和“关于”，不提供已移除项目或已归档对话的查看入口；查看、恢复和保留规则待对应设置分类完成产品定义后再加入。
- 该项目下的 sidebar chat 与普通主会话一起批量归档；无论它们当前挂在哪个来源会话的右侧栏中，都关闭对应会话标签并保留未归档的兄弟标签。若因此关闭某个右侧栏的最后标签，该栏按[主页面右侧栏](./main-right-sidebar.md#标签全部关闭)自动关闭。
- 其他项目中的 sidebar chat 即使把本项目会话作为来源，也不随本项目移除而归档。它们的来源关系立即变为不可用：当前选中的 sidebar chat 按“组合路由中的来源即时失效”迁移到主内容；未选中的条目保留在各自项目中，下一次打开时直接进入主内容区。
- 项目移除是一个原子结果：批量归档、跨来源标签清理、当前组合迁移和项目消失必须全部成功后才提交。任一步失败都保留项目、会话归档状态、标签现场和选中组合，不得留下已归档会话仍作为右侧标签或只完成一半的来源失效。
- 重新添加与已移除项目相同的本地路径时，创建一个新的活动项目；旧项目继续作为“已移除项目”保留，旧对话继续归档，不自动合并、恢复或混入新项目。项目被移除后释放该路径的活动绑定，因此这不违反“一个文件夹同一时刻只能绑定一个活动项目”。
- 项目存在运行中的 Agent 时，不直接执行移除，而是显示独立警告弹窗；用户可以取消，也可以选择强制中止全部相关运行后继续移除。强制中止和移除必须作为受控顺序执行，任一步失败都不得伪装成完整成功。
- 正在移除的项目包含选中会话时，不自动切换到相邻项目或对话；主内容区进入[新建对话窗口](./new-conversation.md)且项目未选择的状态。若该项目只包含主内容承载的来源会话，而选中的 sidebar chat 属于其他项目，则不走此空态，按来源即时失效规则把 sidebar chat 迁移到主内容。
- 移除失败时项目保持可见，当前选择不变，并提供重试。

全局搜索、Agent 团队管理和设置弹窗的内部内容不属于本文档。

## 响应式与窗口行为

- 侧边栏提供可拖动的右侧分隔边界，用户可以在保证 Sidebar 与主内容仍可用的最小、最大范围内调整宽度；精确范围由高保真设计和实现验证确定。
- 长名称单行截断，并提供完整名称的悬停提示和辅助名称。
- 窗口高度不足时只滚动项目列表，顶部操作和底部“重新查看引导”/“设置”保持可达。
- 窗口宽度低于主页面最低可用宽度时，可以自动关闭侧边栏；窗口恢复后遵循用户最近一次明确选择，不反复自动开合。
- macOS 集成标题栏下，侧边栏顶部正确避让系统交通灯并保留可拖拽区域；侧边栏打开和关闭状态下的控制按钮都与系统交通灯垂直中心对齐。
- 所有图标按钮必须可键盘聚焦，并提供可读名称和悬停说明。

## 指标与验收

### 产品指标

- 用户从打开应用到进入目标对话所需的操作次数和时间。
- sidebar chat 从首次创建成功到出现在最终项目列表中的成功率，目标为 100%。
- 用户从 sidebar chat 行恢复正确来源主线与右侧标签、或在来源失效时降级打开主内容的成功率，目标为 100%。
- 用户从任意主页面状态创建一段项目内对话所需的操作次数。
- 项目或对话选择失败后产生错误选中状态的次数，目标为零。
- 重复添加项目、重复创建空白对话和误移除项目的次数，目标为零。
- 红点对话被用户定位并完成所需动作的比例。

sidebar chat 列表成功率的分母是已经原子创建会话与首条消息的每段 sidebar chat，只有它恰好一次出现在发送瞬间最终项目下才计成功；Agent 随后启动失败不移出分母。找回成功率的分母是用户对仍存在的 sidebar chat 行发起的每个逻辑选择动作，重复点击去重后只计一次；来源可用时完整呈现主内容与右侧标签、来源无效时在主内容呈现，才计成功，任何读取、路由或呈现失败均计入失败。两项在受支持且本地状态有效的路径上目标均为 100%，有效状态与失败不得事后排除的口径沿用[主页面右侧栏](./main-right-sidebar.md#指标与验收)。

指标采集必须遵守本地产品的数据边界；是否上传或仅保存在本地由设置与隐私规则另行定义。

### 验收标准

1. 打开中文主页面，侧边栏首行只保留 macOS 红绿灯安全区和与红绿灯垂直中心对齐的关闭按钮，来自全局品牌母版的产品 Logo 与品牌名位于下一独立行，随后依次显示新建对话、搜索和 Agent 团队；三个应用级入口使用相同视觉层级，项目区与设置分别位于中部和底部。
2. 点击关闭侧边栏，主内容区扩展并出现打开按钮；重新打开后，选中会话、主内容承载会话、右侧会话、项目展开状态和滚动位置保持不变。
3. 点击新建对话进入新建对话窗口；没有项目时该窗口禁止创建并提供添加项目入口，侧边栏不直接承载添加流程。
4. 点击项目行加号进入同一个新建对话窗口，并预选对应项目；进入窗口本身不创建持久化空白对话。
5. 红点、蓝点和闪烁点分别表达需要人工处理、有未读结果和运行中；静止对话无点，用户按下“停下”后无点，且辅助名称不依赖颜色即可读懂状态。红点的具体触发来源按[主页面会话区](./main-conversation.md#侧边栏状态点的触发)核对。
6. 对话只按创建时间倒序稳定排列，最新创建的在最上面；人工打开、当前选中、后台 Agent 输出和任何状态变化都不得改变顺序。
7. 对话没有“已完成”状态或完成折叠组；归档后从侧栏消失但记录仍保留，运行中的对话不能归档。
8. 团队拆出的子对话不出现在侧边栏；项目下只列用户自己发起的对话，侧栏长度不随团队的拆分行为变化。子对话的入口由[主页面会话区](./main-conversation.md#区域与信息)的时间线卡片承担。
9. 项目目录不可用后，项目行显示带明确提示的独立红色扳手修复按钮；历史对话仍可只读查看，但不能新建、发送、切换团队或启动 Agent。选择同一项目的新位置且通过“一个文件夹只能绑定一个项目”的校验后，原项目和对话历史保持不变并恢复工作能力。
10. 用户可以直接拖动项目行排序且无需独立拖动把手；拖动不误触展开或折叠，重启应用后顺序保持，新项目默认置顶，任何运行或状态变化都不自动重排项目。
11. 移除项目的确认弹窗在确认操作前同时显示“项目将从 Sidebar 消失”“其对话将全部归档”“消息、执行记录和交付结果仍保留”“当前版本没有查看或恢复入口”，并另行说明不会删除或修改磁盘文件；缺少任一项都不得执行移除。重新添加同一路径时创建新项目，旧历史不自动混入。存在运行任务时必须先经独立警告弹窗选择取消或强制中止；被移除项目包含选中会话时进入新建对话且项目未选择的状态，只包含 sidebar chat 来源时则把选中 sidebar chat 迁移到主内容，移除失败时项目和完整组合保持不变。
12. 搜索只打开全局搜索，Agent 团队只进入对应管理界面；设置在当前工作区上方打开模态弹窗，不改变选中会话、主内容承载会话、右侧会话、草稿、滚动位置或侧边栏状态，关闭后焦点回到设置入口。本文档定义的侧边栏不承载这些界面的内部内容。
13. 项目或对话切换失败时，侧边栏选中态与主内容保持在原对象，不出现双事实状态。
14. 用户可以拖动 Sidebar 右侧边界调整宽度；长名称仍单行截断并可查看完整名称。
15. 项目数量超过一屏时，只有项目列表滚动，红绿灯安全区、侧栏关闭按钮、Logo、顶部操作和底部设置始终可达。
16. 窗口过窄时 Sidebar 自动关闭；窗口重新变宽后，最近一次明确选择为打开则恢复打开，用户手动关闭过则保持关闭。
17. 所有图标入口均可使用键盘操作，并具有无需依赖图标外形即可理解的辅助名称。
18. 选择第二个项目中的任意用户对话并重启应用后，恢复同一选中会话；它是 sidebar chat 时同时恢复主内容承载会话与右侧会话组合。没有历史选择或选中会话已不可恢复时进入未选择项目的新建对话，不回退到第一个项目的默认或最早对话。
19. 对话菜单提供“复制对话记录路径”：触发后这段对话记录文件的稳定路径进入剪贴板；把该路径交给对话之外的阅读工具即可读到包含消息、系统记录和各步运行过程的完整经过，且对话继续推进后重新读取能跟上最新内容；复制失败时有可理解说明且剪贴板不被写入。
20. “重新查看引导”固定在侧边栏底部的“设置”上方，键盘顺序与视觉顺序一致；点击后进入引导回看，退出或完成回看时恢复进入前的项目展开、选中会话、主内容承载会话、右侧会话、草稿和应用页面状态。
21. 在没有项目、项目目录不可用、项目数据加载中或加载失败四种状态下，底部“设置”都保持可操作并能打开语言与关于分类；项目数据状态不得让设置入口禁用、消失或进入无限等待。
22. sidebar chat 首次消息成功创建后，按发送瞬间最终选择的项目作为普通会话加入项目列表；标题、顺序、菜单和归档与普通主会话一致，不显示分析专用阶段或来源团队权限。
23. 点击有可用来源的 sidebar chat 行时，只高亮该行，来源行不高亮；来源会话显示在主内容区，目标会话显示在右侧栏。点击普通来源会话行时则高亮来源行，即使右侧栏恢复了 sidebar chat 标签也不反向改变选中态。
24. 点击没有来源或来源失效的 sidebar chat 行时，该会话直接在主内容区打开并保持可继续；来源失效不会阻止选中。
25. sidebar chat 与来源会话各自独立显示并清除红点、蓝点和闪烁点，互不复制；项目折叠时两者按各自所属项目参与最高优先状态聚合。
26. sidebar chat 与来源会话跨项目时，sidebar chat 始终列在自己首次发送所选的最终项目下；恢复来源主线不会移动列表位置或同时选中来源项目中的行。
27. 有来源的 sidebar chat 只有在来源主内容与目标右侧标签都成功呈现后才提交选中态；任一路由失败都保留此前主内容、右侧栏和选中态。最后选中 sidebar chat 后重启应用，同样恢复这一组合；没有来源或来源失效时以主内容成功呈现为提交条件。
28. 归档 sidebar chat 时关闭它在右侧栏中的对应标签，不影响来源会话或其他兄弟标签；若它是当前选中行，则按同项目相邻对话规则提交新选中态，搜索恢复后仍按 sidebar chat 找回路由打开。
29. 全文的选中会话、主内容承载会话和右侧会话按术语定义区分；折叠项目、关闭再打开侧边栏、离开并返回主页面或重启应用，都完整保留 sidebar chat 选中、来源主内容与右侧会话组合。侧边栏关闭时主内容顶部显示来源会话名称，重新打开后仍高亮 sidebar chat 行。
30. 已选中 sidebar chat 的来源在组合呈现后失效时，sidebar chat 保持唯一选中并原地迁移到主内容区，阅读位置、草稿、运行与状态点不变，旧来源右侧标签被移除且不重复显示。应用内归档或移除导致迁移失败时不提交原操作；外部失效导致迁移失败时保留最后成功组合、显示说明并可重试。
31. 移除项目会原子归档该项目下全部普通主会话与 sidebar chat，并关闭这些 sidebar chat 在任何来源标签组中的对应标签；未归档兄弟标签保持。其他项目中仅把该项目作为来源的 sidebar chat 不归档，当前选中的迁移到主内容，未选中的下次按来源失效路由打开；任一步失败不提交半套移除。

## 现状参考与产品缺口

现有 `ConversationSidebar` 已实现项目分组、项目内新建会话、会话选择、状态排序和已完成折叠；现有主页面壳已实现打开项目、项目列表、底部诊断入口和本地引擎状态。

这些实现是现状参考，不是本文档的需求上限。相较完整侧边栏，当前仍缺少或尚未达到本文要求的主要产品能力包括：

- 侧边栏关闭、恢复和状态记忆。
- 应用级新建对话、搜索和 Agent 团队入口。
- 标准设置入口。
- 重新查看引导入口。
- 项目折叠和状态聚合。
- 项目显示名称、手动排序、文件夹重新定位、移除及安全确认。
- 无项目、项目空白、目录不可用和局部失败状态。
- 红点、蓝点和闪烁点状态。
- 对话归档与恢复入口。
- 对话菜单的“复制对话记录路径”：对话消息目前只存在应用数据库中，磁盘上没有可直接阅读的对话记录文件；存储分层见 [ADR-0004](../../adr/0004-jsonl-session-fact-log.md)。

旧 `docs/wireframes/pages/console.md` 和 `openspec/changes/conversation-console/wireframes.md` 中与侧边栏有关的有效原则已被重新评估。本文保留项目与对话两层结构和运行状态可见；旧设计中的“已完成折叠”和“无未读语义”被本轮产品裁决取代，改为红点、蓝点、闪烁点和用户主动归档。2026-07-21 另有两项裁决：红点来源改由[主页面会话区](./main-conversation.md#侧边栏状态点的触发)定义，子对话不再进入侧边栏——两处的推翻理由都记在对应正文的引述块里。本文已经确认，后续侧边栏产品需求以本文为事实源，旧 Wireframe 不再新增侧边栏事实。

## 非目标

本文档不定义：

- 全局搜索的内部结构、搜索范围和结果交互；这些内容由[全局搜索](./search.md)定义。
- 新建对话窗口内的项目添加、团队选择和对话创建流程；这些内容由[新建对话窗口](./new-conversation.md)定义。
- Agent 团队管理页面的内容。
- 设置弹窗和诊断界面的其他内容；已移除项目与已归档对话的查看、恢复和保留规则继续开放，待对应设置分类完成产品定义后再纳入本文入口与验收。
- 主对话时间线、输入区、运行块、验收卡片或交付物区域。
- Agent 团队的文件存储格式。
- 子任务和父子会话在主内容区的详细呈现。
- 高保真颜色、字体数值、精确像素和动效参数。
