## 页面目标

用户手上有一个具体任务，现有团队不趁手，但他不想从零设计一套分工。这一页让他看到别人已经做好的团队有哪些，并挑出一支值得进一步细看的。

这一页只负责**找到候选**。判断要不要装是下一页的事，装不装得成是再下一页的事。用户在这里离开时应该带走的是一个具体的仓库，不是一个决定。

## 用户场景

- 用户的任务超出通用助手的能力，想找一支干过这行的人调好的团队。
- 用户在公司内部维护着一支私有团队，想在自己的机器上装它。
- 用户想看看 `moebius-team` 这个 topic 下到底有什么，没有具体目标。
- 用户搜不到自己公司的团队，需要判断是真的没有，还是本地 gh 没登录。
- 用户搜索时撞上 GitHub 限流，需要知道多久之后能再搜，以及有没有办法提高额度。

## 入口与去向

- 从[Agent 团队](./agent-teams.md)首页的「找现成团队」进入。这是唯一入口。
- 点击结果条目进入[安装前预览](./github-team-preview.md)。
- 结果条目上的仓库名在浏览器中打开该 GitHub 仓库。
- 返回退回 Agent 团队首页，不保留本次搜索词——用户下次来通常是为了另一件事。
- 从预览页返回本页时，保留搜索词、语言过滤和结果列表；用户往往要连着看好几支才决定。

## 区域与信息

### 页面标题

固定为「找现成团队」，与首页入口保持一致。用户进入后能立刻确认自己正在寻找已有团队，而不是创建新团队。

### 搜索框

- 占位文字「搜索团队名称或用途」。
- 搜索命中的是 GitHub 仓库的名称和描述，**不包含成员名或 `AGENT.md` 正文**——GitHub 搜索接口读不到仓库内文件。占位文字因此不能承诺「搜成员」。
- 输入必须防抖，不能按键即请求。限流额度按分钟计，逐字符发请求会在一个词打完之前耗尽额度。
- 空查询不发请求，也不显示全部结果；页面停在中性初始状态。

### 搜索范围说明

你能搜到的内容取决于当前 GitHub 登录状态：公开仓库可以搜索；私有仓库只显示你有权限访问的内容。

这一句存在的唯一理由是：搜不到自己公司的团队时，用户要能自己判断是没有这支团队，还是自己没登录。没有它，用户只会以为产品坏了。

产品不自建 GitHub 登录，也不引导用户在应用里输入 token。私有仓库能不能搜到，完全跟随本地 gh CLI 的登录态。

### 语言过滤

- 三个选项：中文 / English / 全部。默认跟随应用界面语言。
- **默认过滤但必须能一键看全部。** 界面语言管的是界面，不是用户能读什么。一个界面用中文的人完全可能想装一支英文提示词的团队——某个领域只有英文版做得好。产品可以替用户预设，不能替用户决定他只配看中文团队。
- 语言来自仓库 topic，不来自仓库内文件。原因见「团队仓库约定」。

### 结果条目

每条包含：

- 团队名称。
- 一句话用途，来自仓库描述。
- 仓库全名 `owner/repo`，可点击打开 GitHub。
- star 数。图标加数字，不加文字标签。
- 最近更新时间，显示为「{time}更新」。
- 语言标记。
- 私有仓库额外显示「私有」。

这几项是用户在陌生团队之间做取舍时手上仅有的信号，因此一项都不省。star 与更新时间不构成质量判断，产品也不据此排序加权或推荐——排序沿用 GitHub 搜索接口的返回顺序，不做二次加权。产品不做评分、精选、审核或榜单。

结果条目**不显示成员数和成员名**。那需要逐个仓库再发一次请求，几十个结果会当场把限流额度打光；这些信息留到预览页，那时只查一个仓库。

### 团队仓库约定

搜索、预览、安装、更新都建立在这份约定上。它是产品要求作者遵守的最小契约：

- 仓库必须打 `moebius-team` topic。所有团队都打这一个，搜索恒定用它，保证搜得全。
- 仓库同时打一个语言 topic：`moebius-team-zh` 或 `moebius-team-en`。它只用于过滤和在结果里标语言。
- 一个仓库一支团队一种语言。仓库根目录就是团队目录：`team.json` 加 `members/<slug>/AGENT.md`。
- 同一支团队的中英版本是两个独立仓库，也就是两支独立的团队。产品不把它们关联起来，不提供跨语言切换，也不检测两者是否同步。它们会分叉——改了中文忘了改英文——产品不解决这件事。

三个设计取舍值得写下来：

**语言为什么必须落在 topic 上，而不是写进 `team.json`。** GitHub 搜索接口读不到仓库内文件。要读就得对每个结果再发一次请求，认证状态下每分钟 30 次的额度会被一页结果打光。

**为什么是双 topic，而不是两个各自独立的语言 topic。** 完全独立时没有任何一个 topic 能搜到全部团队，搜索实现要维护一张「语言 → topic」映射表，将来加一门语言就要改代码。恒定的 `moebius-team` 让语言退化成可选过滤而不是硬隔断。

**为什么不建注册中心。** GitHub 的 topic 本身就是目录，公开仓库人人可搜、私有仓库跟随登录态，这两件事在 GitHub 侧直接成立。自建索引服务或团队注册表要额外维护一套东西，换来的只是排序权和审核权——而产品明确不要这两样。代价是搜索结果的质量完全取决于 topic 约定被遵守的程度，会有打了 topic 却装不上的仓库；这类仓库在[安装前预览](./github-team-preview.md)里被识别并说明。

约定文档本身面向作者，是官网「看看一支团队是怎么做的」出口的落点。它必须先有一个可访问地址，官网那条出口才能上线。

## 操作与反馈

- 输入关键词后经防抖发起搜索；清空输入回到中性初始状态并清除结果与错误。
- 切换语言过滤时，若当前已有有效查询，立即用新范围重新搜索；查询为空时只更新过滤器，不发请求。
- 点击结果条目进入预览页。点击条目内的仓库名只打开 GitHub，不进入预览页——两个动作必须能分开，用户想先在 GitHub 上看一眼是正常需求。
- 限流状态下不自动重试。倒计时结束后按钮恢复可用，由用户决定要不要再搜；自动重试会在用户没看着的时候继续消耗额度。
- 搜索进行中修改查询或过滤条件时，旧搜索立即失效，不得用晚到的结果覆盖当前状态。

## 页面状态

| 状态 | 页面表现 |
| --- | --- |
| 中性初始 | `输入团队名称或用途，看看有没有适合你的现成团队。` |
| 加载中 | 结果区显示「正在搜 GitHub…」，保留上一次结果的结构占位 |
| 有结果 | 按 GitHub 返回顺序陈列结果条目 |
| 空结果 | `没有找到匹配的团队。换个关键词或语言，再试一次。` |
| 触发限流 | 「GitHub 这一分钟的搜索次数用完了，约 {seconds} 秒后可以再搜。」未登录时追加「本地登录 gh 能把搜索额度提高约三倍。」 |
| 无网络或 GitHub 不可用 | 「连不上 GitHub。检查网络后重试；已装的团队不受影响，照常可用。」 |
| gh 已登录 | 搜索范围说明包含私有仓库 |
| gh 未登录 | 搜索范围说明只含公开仓库，并说明登录后私有仓库会一起搜 |

三种失败必须分别表达，不能合并成一句「没找到」：

- **空结果**是搜索成功了，只是没有匹配。用户该做的是换词。
- **限流**是搜索没执行。说成「没找到」会让用户立刻重试，而重试只会继续撞墙——限流是这个功能特有的失败方式，必须说出等多久。
- **连不上**是网络问题。这里额外说明「已装的团队不受影响」，因为用户看到一屏 GitHub 错误时的第一反应是担心自己的团队也出事了。

限流文案里的额度写「约三倍」而不是「10 次提到 30 次」。比值比绝对值稳定，GitHub 调整限流时这句话不会变成假话；剩余秒数则从接口返回的重置时间实算，那是准确的。

## 弹层与危险操作

不适用。本页只读取 GitHub 公开数据，不写盘、不修改任何本地团队，也没有不可逆操作。安装动作在[安装前预览](./github-team-preview.md)。

## 响应式与窗口行为

- 结果条目在窄窗口下把仓库名、star 与更新时间移到团队名下方纵向排列，不产生页面级横向滚动。
- 语言过滤在窄窗口收成一个下拉，仍保留「全部」选项。
- 搜索范围说明可以换行，不可省略或折叠——它是用户自查「为什么搜不到」的唯一依据。

## 指标与验收

1. 用户能从 Agent 团队首页的「找现成团队」进入本页，输入关键词后看到打了 `moebius-team` topic 的仓库列表。
2. 每条结果显示团队名、一句话用途、`owner/repo`、star 数、最近更新时间和语言；私有仓库额外标注「私有」。仓库名可单独点击打开 GitHub，不误触进入预览。
3. 本地 gh 已登录时，用户有权限的私有仓库出现在结果中；未登录时只有公开仓库，且页面明确说明登录后私有仓库会一起搜。产品在任何位置都不要求用户输入 GitHub token。
4. 语言过滤默认跟随界面语言，且能一键切到「全部」看到所有语言的团队。
5. 搜索输入经过防抖，连续输入一个词不会逐字符发起请求。
6. 空结果、触发限流、连不上 GitHub 三种状态分别表达；限流状态说明还要等多久，未登录时说明登录 gh 能提高额度，且不自动重试。
7. 结果列表不为每个结果额外请求仓库内文件；成员构成等信息留到预览页。
8. 页面不提供评分、精选、审核或榜单，也不对 GitHub 返回顺序做二次加权。
9. 从预览页返回时保留搜索词、语言过滤与结果；从本页返回 Agent 团队首页时不保留。

## 非目标

- 自建团队市场、注册中心、评分、审核、推荐榜或收藏夹。
- 应用内 GitHub 登录、token 输入或 OAuth；私有仓库可见性完全跟随本地 gh CLI。
- 搜索仓库内文件内容、成员名或 `AGENT.md` 正文。
- 团队的安装、更新、卸载动作本身。
- 引导流程中的团队发现。首次引导只让用户从内置团队里选一支，不在那里放搜索——引导要的是相信这支团队会替自己接力，不是让新用户当场挑供应商。
- 把中英两个语言版本的同一支团队关联、同步或检测分叉。
