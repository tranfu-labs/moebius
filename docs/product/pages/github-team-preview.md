# 安装前预览

> 状态：2026-08-16 采访确认、待实现
>
> 所属页面：应用级 Agent 团队管理的子页面
>
> 当前范围：定义安装一支 GitHub 团队之前的完整内容呈现——团队身份、成员构成、每名成员的 `AGENT.md` 全文——以及安装动作、安装后果说明、已装重复与仓库格式不符的处理。搜索与结果陈列由[从 GitHub 找团队](./github-team-discovery.md)承载；安装后的管理与更新由[Agent 团队](./agent-teams.md)承载。
>
> 产品基线：[Moebius 产品需求文档](../prd.md)
>
> 关联入口：[从 GitHub 找团队](./github-team-discovery.md)；关联流程：[Agent 进化](../flows/agent-evolution.md)

## 页面目标

装一支来自 GitHub 的团队，等于让一段陌生人写的提示词在自己的机器上真实执行。这一页存在的全部理由是：**在那件事发生之前，用户能把要执行的东西完整读一遍。**

用户离开这一页时应该能回答一个问题——要不要让这段提示词在我的机器上跑。为了让他能回答，这一页必须把答案所需的东西全部摆出来，而不是摘要、评分或推荐。

本产品的目标用户是用过编码 Agent、有能力也有意愿读懂 `AGENT.md` 的人。这一页按这个前提设计：它不替用户判断安全，而是让用户自己判断。期待「装完即用、不看内容」的人不是本页的服务对象。

## 用户场景

- 用户从搜索结果里挑中一支团队，想先看看它到底由哪些角色组成、各自被交代了什么。
- 用户读到某名成员的 `AGENT.md` 里有一条自己不认同的规则，想知道装完之后能不能改。
- 用户已经装过这支团队，想确认自己没有重复安装。
- 用户点开一个打了 topic 但根本不是团队的仓库，需要知道这不是自己的问题。
- 用户读完决定不装，直接返回继续看别的。

## 入口与去向

- 从[从 GitHub 找团队](./github-team-discovery.md)的结果条目进入。这是唯一入口。
- 返回退回搜索页，保留搜索词、语言过滤与结果列表。
- 仓库名在浏览器中打开该 GitHub 仓库。
- 安装成功后进入[Agent 团队](./agent-teams.md)中这支团队的详情页，它已在“跟随上游”分组内且立即可用于新建对话。
- 已装过时提供直接打开本地那支团队的入口。

## 区域与信息

### 团队身份

- 团队名称与一句话用途。
- `owner/repo`，可点击打开 GitHub。
- 最近更新时间、star 数、语言。

这一区回答的是「我在看哪个仓库」。作者是谁就写在 `owner` 里，产品不额外渲染头像或简介——那会把注意力从内容引到人身上，而这一页要用户判断的是内容。

### 成员构成

- 主 Agent 与成员总数，沿用团队页的「{primary} 接单 · {count} 人」表达。
- 扁平成员列表，主 Agent 排第一位，与[Agent 团队](./agent-teams.md#扁平成员表达)的规则一致：不画连接线、层级或执行顺序。
- 每名成员的推荐运行配置显示为「推荐 {model} · {effort}」。

推荐配置要显示，因为它决定这支团队跑起来要花多少钱。仓库里给出的推荐配置引用了用户本机没有的 Pi Provider 档案时，这名成员在预览里显示为需要用户安装后自行选择，不伪造一个可用值。

### `AGENT.md` 全文

**这是本页存在的理由。** 成员切换加正文，逐名可读，完整不截断、不折叠、不摘要、不由 AI 概括。

- 区首一句：「下面是装上后真正会执行的内容，可以逐名成员看。」
- 正文按 Markdown 渲染，与团队详情页的阅读态一致。
- 长正文在区域内滚动，不影响底部安装区。
- 正文只读。这一页不提供编辑——用户要改，装完在团队详情里改，那里有完整的保存、冲突与修订机制。

产品不对正文做安全扫描、风险评分或「这段提示词看起来可疑」之类的提示。做了就等于产品在替用户背书，而这份背书是产品给不出的：`AGENT.md` 是自然语言，判断它会做什么这件事本身没有可靠答案。产品能诚实提供的只有原文。

### 安装操作与它意味着什么

按钮文字是「安装」。按钮上方三条说明安装的后果范围：

| 说明 | 它回答的问题 |
| --- | --- |
| 装完就能在团队列表里选它开对话。文件在本机，你可以随时改 | 我立刻得到什么 |
| 作者改了上游，你这份会跟着更新；你自己改过的地方会保留，改完会告诉你哪里变了 | 之后它会自己变成什么样 |
| 不想要了随时删，删了还能再装回来 | 后悔了怎么办 |

第二条特意写「改完会告诉你哪里变了」而不是「先告诉你」：合并是自动发生的，告知在事后，由团队详情页的同步结果横幅承担。写成事前确认就是假的。

第一条的「你可以随时改」不只是补充说明。用户刚读完全部正文，很可能有一两条不认同；知道装完能改，他才敢装。

## 操作与反馈

- 成员切换只换正文，不重新请求仓库。进入本页时一次取完全部成员内容，读第四名成员时不该再等一次网络。
- 「安装」把仓库内容写入本机团队目录，登记上游记录与初始基线，然后进入该团队详情页。
- 安装期间按钮显示「正在安装…」并禁用，避免重复提交。
- 安装是一个用户可观察的原子结果：团队文件、上游记录、初始基线和逐名推荐配置全部成功后，团队才出现在列表和选择器里。任一步失败都不留下半支团队，保留可理解原因和重试入口。
- 安装失败不改变任何已有团队，也不留下残留目录。
- 本地已存在同一 `owner/repo` 的团队时，按钮区改为说明与「打开它」，不提供重复安装。用户想要第二份，走团队详情的「复制团队」——那样得到的是一支只在本地的团队，语义清楚。
- 本地已有一支同名但来自别处（或没有上游）的团队时，两支并存，不阻止安装、不合并、不重命名。同名不是冲突，来源才是身份。

## 页面状态

| 状态 | 页面表现 | 能否安装 |
| --- | --- | --- |
| 加载中 | 保留身份区结构，成员区与正文区显示占位 | 否 |
| 正常 | 身份、成员、全文、安装区完整 | 是 |
| 已装过 | 「你已经装过这支团队」与「打开它」取代安装按钮 | 否 |
| 仓库格式不符 | 「这个仓库打了 `moebius-team`，但没有按团队格式组织，装不了」，并提供「看看团队格式」 | 否 |
| 部分成员文件读不到 | 已读到的成员正常显示，读不到的明确标出是哪一名及原因 | 否 |
| 连不上 GitHub | 「连不上 GitHub。检查网络后重试；已装的团队不受影响，照常可用。」 | 否 |
| 触发限流 | 「GitHub 这一分钟的请求次数用完了，约 {seconds} 秒后可以再看。」 | 否 |
| 正在安装 | 按钮显示「正在安装…」并禁用 | 进行中 |
| 安装失败 | 保留页面内容，显示原因与重试；不留下残留团队或目录 | 可重试 |

「仓库格式不符」不是边缘情况。topic 是任何人都能打的，打了 topic 却不符合结构的仓库一定会出现在搜索结果里。这条状态的文案必须把责任说清楚——是这个仓库不符合格式，不是用户操作错了——并给出「看看团队格式」的出口，让想自己发一支的用户顺路学会怎么做。

「部分成员文件读不到」时禁止安装，不允许装一支缺人的团队。用户读不到的那名成员，正是他最应该读的那名。

## 弹层与危险操作

- 安装不使用二次确认弹窗。这一整页就是那次确认——用户已经逐名读过全文，再弹一个「确定要安装吗」既不增加信息，也会暗示这一页没起作用。
- 安装本身可逆：装完随时能删，删了能再装。它不是删除级别的操作，不使用警告语气。
- 本页不提供编辑、删除或任何修改本地既有团队的操作。

## 响应式与窗口行为

- 窄窗口下成员切换器保持单行并允许横向滚动，与团队详情页一致，不换行堆成多层。
- 正文区在窄窗口占满宽度；底部安装区仍然常驻，三条说明可以折成更紧凑的排列，但**一条都不能省**——它们是安装后果的完整交代。
- 窗口缩放与成员切换不重置正文滚动到顶部之外的意外位置，也不重新请求内容。

## 关联流程

- 从[从 GitHub 找团队](./github-team-discovery.md)进入，安装成功后落到[Agent 团队](./agent-teams.md)的团队详情。
- 安装时登记的上游记录与初始基线，是[Agent 进化流程](../flows/agent-evolution.md)三方比较中的 A。装完立刻就有 A，因此这支团队从第一次检查起就走正常的自动合并路径，不进入「A 不可考」的降级分支。

## 指标与验收

1. 用户在安装之前能读到每一名成员的 `AGENT.md` 全文，完整、不截断、不折叠、不由 AI 概括。
2. 页面显示团队名、用途、`owner/repo`、最近更新、star、语言、主 Agent、成员列表与逐名推荐运行配置。
3. 安装按钮附近说明安装的三项后果：装完能做什么、之后如何跟随作者更新且本地改动会保留、随时可删且可重装。
4. 成员切换不重新请求 GitHub；进入页面时一次取完全部成员内容。
5. 安装是原子结果：团队文件、上游记录、初始基线与推荐配置同成同败；失败不留下半支团队或残留目录，且不改变任何已有团队。
6. 安装成功后进入该团队详情，它出现在“跟随上游”分组、带上游仓库名，并立即可用于新建对话。
7. 已装过同一 `owner/repo` 时不提供重复安装，改为提供打开本地团队的入口；同名但来源不同的团队可以并存。
8. 仓库打了 topic 却不符合团队格式时，说明是仓库不符合格式并给出「看看团队格式」出口，安装禁用。
9. 部分成员文件读不到时禁止安装，并明确标出是哪一名成员、什么原因。
10. 页面不对 `AGENT.md` 做安全扫描、风险评分、可疑提示或质量评价，只呈现原文。
11. 安装不使用二次确认弹窗。
12. 装完的团队从第一次上游检查起就走正常自动合并，不落入「A 不可考」的一次性显式合并分支。

## 非目标

- 在本页编辑 `AGENT.md`、成员构成或运行配置；这些属于安装后的[Agent 团队](./agent-teams.md)详情。
- 对提示词做安全扫描、恶意内容检测、风险评分或质量评价。
- 试运行、沙箱预览或「装之前先跑一下看看」。
- 选择性安装部分成员；安装的单位是一整支团队。
- 指定安装某个历史 commit 或分支；安装的永远是默认分支的当前内容。
- 卸载、更新、回滚等安装之后的动作。
- 向上游仓库提交用户的改动。
