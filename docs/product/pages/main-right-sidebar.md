## 页面目标

主对话区保留当前工作的主线，右侧栏按需承载证据、子任务和与主线并排的普通会话。

用户想核实「团队到底改了什么」「这个成员那一步究竟做了什么」「拆出去的子任务跑到哪了」，或想一边保留来源会话、一边另开普通会话复盘和处理问题时，都能在当前窗口内完成。

证据标签帮助用户得到一个判断：**这段工作可以接受，或者哪里不对**。会话标签则继续承载正常对话；右侧栏容器本身不提供文件编辑器，但会话中的 Agent 可以在自身流程与权限范围内执行工作。

产品当前阶段尚未稳定，用户需要监督的不只是结果，还有团队的推进过程本身。右侧栏是这份监督需求的落点——把它集中在一个可以随手关掉的区域，主对话区才能保持安静。

## 用户场景

- 团队说这一步做完了，用户想知道它动了哪几个文件、每个文件改了哪几行，再决定是否继续。
- 某一步没跑起来，主对话区只给了一句人话，用户要读原始错误输出才能判断是环境问题还是团队走错了路。
- 团队把目标拆成几个子任务，卡片上显示其中一个「没跑起来」，用户要点进去看那一条到底怎么了。
- 用户想对照着看：左边是改动后的文件内容，右边是产生这个改动的那一步说了什么。
- 用户想复盘当前对话，从某条 Agent 消息选择「在右侧栏分析这条消息」，或从左侧栏根对话菜单选择「在右侧栏分析这段对话」，在右侧栏打开同一种带来源引用胶囊的分析新对话。
- 用户已经创建了右侧栏会话，想在其中继续对话，并把它的完整输出、文件或子任务打开为同一标签条中的兄弟标签。
- 用户点击成员给出的工作区文件路径，想看到完整文件而不是只看到第 1 行附近；如果是 Markdown，想先读渲染结果，必要时再切回原始源码。
- 用户浏览项目文件时只想读当前源码，不希望未提交改动让普通文件页看起来像 Review；真正的增删对比只留在「改动」。
- 用户在右侧栏阅读完整文件、Review、过程记录或普通会话时，需要足够的横向空间理解内容，不希望一个承担完整工作面的区域默认退化成窄辅助栏。
- 用户给一段已经在右侧栏打开的会话重命名，希望标签立即使用新标题，但仍是原来的标签、位置和内容。
- 用户已经信任这支团队，什么都不想看——右侧栏保持关闭，界面回到两栏。

## 入口与去向

右侧栏**默认关闭**。开与关的状态属于当前根对话的外层工作现场：每段根对话独立保存自己的状态，并在应用重启后恢复；它不是跨对话携带的全局工作习惯。

打开方式共七种，前六种同时决定打开后落在哪个标签上：

1. 主对话区在一轮工作结束时留下的**结果卡片**，点「查看」→ 打开并新建一个改动标签。
2. 主对话区某个成员那一步可用的**完整输出入口** → 打开该步骤唯一的过程标签。该入口的位置和不可用说明由[主页面会话区](./main-conversation.md)定义，本页只规定点击后的结果。
3. 主对话区**子会话卡片**的某一行 → 打开并新建该子任务的标签。
4. 主对话区 Agent 消息的**在右侧栏分析这条消息**入口 → 按[对话分析流程](../flows/session-analysis.md)打开或聚焦直接归属于该消息所在对话的分析新对话草稿，并追加消息级来源胶囊。
5. 左侧栏根对话菜单的**在右侧栏分析这段对话**入口 → 先按[主页面侧边栏](./main-left-sidebar.md#在右侧栏分析这段对话)完成来源根对话切换，再打开或聚焦直接归属于该根对话的同一种分析草稿，并追加对话级来源胶囊。
6. 主会话、子任务或右侧栏会话正文中的**本地绝对文件路径** → 先按所属会话解析实际工作空间；工作区内打开完整文件，工作区外打开有界预览。
7. 主内容区右上角的**显示/隐藏按钮** → 有已保留标签时恢复上次的标签条；没有任何标签时进入「这个标签要看什么」的内容选择状态。

从结果卡片、完整输出、子任务或分析入口打开时，右侧栏直接落在目标标签，不先要求选择类型。用户仅通过显示按钮打开且当前没有标签时，才先选择这个标签要承载什么。

关闭右侧栏后主内容区收回全部宽度，会话区回到关闭前的滚动位置。关闭不销毁已打开的标签：同一段对话内再次打开时，标签条恢复原样并停在关闭前选中的标签上。

切换到另一段根对话时，右侧栏同时恢复那段根对话自己的外层标签条和开关状态。此前从未打开过右侧栏的根对话保持关闭：例如用户在对话 A 打开右侧栏后切到对话 B，若 B 尚未打开过，B 仍显示关闭；返回 A 时恢复 A 的打开现场。标签与开关都不跨根对话任意携带，但**跨应用重启保留**。普通 sidebar chat 标签可以绑定另一段持久化会话；它仍属于当前外层工作现场，用户从左侧栏找回时继续按普通 sidebar chat 路由处理。分析对话没有左侧栏找回或主内容区降级：它始终属于自己的对话树，打开时恢复该树的根对话及外层标签组，并在其中打开或聚焦目标分析标签。

证据标签不通往其他页面，也不提供在外部编辑器中打开文件的出口（记入「待讨论」）。普通新会话与已有会话继续保留主会话已有的产品内去向，例如添加项目、团队修复与团队管理；右侧栏不得为了维持证据区的只读边界而移除这些正常入口。

```text
│ ▸ DEVELOPER_PROMPT                      [展开]       │
```

过程标签第一次打开时定位在最底部；停在底部时跟随正在工作的步骤实时追加，用户向上阅读后暂停跟随，新内容只给「到最新」提示，不抢走阅读位置。切换标签、关闭后重开或应用重启后，都恢复该标签最后一次成功保存的阅读位置；只有从未保存过位置时才落到底部。向上滚动按需加载更早过程，界面只挂载可视区域附近的内容。同一步骤被重试时，每次执行在同一个标签内依次追加并标明第几次；每次执行都保留自己的 prompt stack、运行元数据和调用过程。

每次尝试的标题常驻显示自己的运行状态、「已进行」或「耗时」、开始时间和完成时间；紧邻标题显示实际模型、effort、provider 与 CLI 版本等可用元数据。时间戳使用带时区和毫秒的 ISO 8601 原值，不因“更易读”丢掉调试精度。某一次尝试的过程记录缺失时，只在该次尝试内部显示「这次执行的过程记录不可用」；同一步其他尝试仍完整可读，步骤级标签不得整体降级为空。

每次尝试首先提供当前执行引擎原生记录中的提示词与上下文分区，不要求三家引擎具有相同字段：Codex 按 rollout 原值展示 `SYSTEM_PROMPT`、`DEVELOPER_PROMPT` 与 `USER_INPUT`；Claude Code 按 transcript 原值展示实际用户 / assistant 内容及可用 session 元数据；Kimi 按 wire 原值展示 `systemPrompt`、`turn.prompt`、上下文消息及可用请求元数据。所有分区都标明来源；当前引擎没有记录的字段明确显示「该引擎未记录」，不得根据当前团队配置、当前时间线、Moebius prompt 或另一引擎的字段事后补造。

命令、工具、函数、MCP、文件、错误与 Agent 原始输出按发生顺序显示。每条记录保留原始事件类型、时间戳、call id、参数、结果、状态、绝对路径以及 session / run / thread 等内部标识，不做脱敏；很长的提示词、输入、参数、结果和原始输出默认折叠，展开后仍保留全文，不做头尾截断。终端控制字符以可见转义形式呈现，所有原始内容都作为只读文本渲染，不能执行其中的 HTML、Markdown、脚本或终端控制序列。

这是本地调试视图，不是面向分享的安全摘要。每次尝试常驻提示原始信息可能包含提示词、本机路径、内部标识和工具返回内容；内容可选择和复制，但首版不提供“一键导出”或自动脱敏副本。token 统计纳入「完整调用链」，以独立事件显示当前引擎实际存在的 usage 字段。Codex 继续过滤 reasoning 文本与 encrypted reasoning payload；Claude transcript 与 Kimi wire 已持久化为可读原生事件的 thinking / reasoning 按来源标识展示，opaque 或 encrypted payload 不尝试解密。其他尚未识别事件不能静默丢弃，必须显示执行引擎、事件类型和可展开的原始 payload，并遵守各引擎自己的敏感 payload 边界。

某次执行引擎的原生过程记录文件找不到时，不拿主对话区最后一段回复冒充完整输出：

```text
│ 开发 · 这一步的完整输出                             │
│ ─────────────────────────────────────────────────── │
│ 第 2 次执行的 Claude 过程记录已不可用                │
│ 这一步的最终回复仍保留在主对话区。                  │
```

```text
│ ─────────────────────────────────────────────────── │
│ 空状态验收 · 测试 · 没跑起来                        │
│ ─────────────────────────────────────────────────── │
│ (测) 测试                                           │
│ 正在核对空状态的验收语句…                           │
│ ⚠ 没有启动（退出码 1）                    ↻ 📄      │
│ ─────────────────────────────────────────────────── │
│   ┌───────────────────────────────────────────┐     │
│   │ 说点什么，或 @ 一个成员…               ↑ │     │
│   └───────────────────────────────────────────┘     │
```

子任务标签承载一段[单 Agent 会话](./agent-conversation.md)，子任务在别处没有说话的地方。它的历史 Agent 回复、活动运行、计时、终态与操作统一复用单 Agent 会话规则；「完整输出」按子会话自己的所属会话与步骤聚合多次尝试，不借用父会话输出。

### 新会话与已有会话标签

右侧栏的会话标签分为两种归属，但不分裂页面布局：

- 从加号内容选择手动进入的「新会话」是普通 sidebar chat；首次发送成功后按普通会话进入左侧栏。
- 从「在右侧栏分析这条消息」或「在右侧栏分析这段对话」进入的是分析新对话；首次发送成功后只登记在直接父对话的分析面板，不进入左侧栏。

两者都显示与[主页面会话区的新对话](./main-conversation.md#新对话从项目行进入项目已带上)相同的上下文选择、空态、输入框和普通附件。分析草稿额外显示来源胶囊和候选问题；消息入口追加消息级来源胶囊，对话入口追加对话级来源胶囊，两者复用同一分析草稿、标签、发送和后续会话状态。右侧栏只承载这些页面内容，不另行解释或转换引用。

用户从内容选择手动进入「新会话」时，则是一段没有分析预填内容的普通新会话。它默认继承当前主会话的项目和**实际工作空间**，包括当前主会话正在使用独立工作空间时继续预选同一份独立工作空间；团队初始预选内置「通用助手」。项目、工作空间和团队都只是初值，首次发送前可以按普通新会话规则改选。当前主内容区还没有已创建会话时，继承主内容区新会话已经选定的项目与工作空间；其中任一项尚未选择就保持未选择，不自行猜测最近项目或默认工作空间，团队仍初始预选「通用助手」。

首次消息发送成功后，当前标签原地切换为已有会话，不另开标签，也不增加「分析中」「等待优化」之类的专用页面状态。普通 sidebar chat 按发送瞬间的最终项目进入左侧栏；分析对话只登记到直接父面板。两者的标题、时间线、运行记录、输入、停止、重试、恢复和团队切换都完整复用[主页面会话区](./main-conversation.md)，右侧栏只负责把这段会话放进当前标签。

已有会话标签始终显示这段会话当前已保存的完整标题。用户从[主页面侧边栏](./main-left-sidebar.md#重命名对话)成功重命名后，所有已打开或已保留标签组中绑定该会话的标签都原位改用新标题；标签按钮、截断文字、悬停完整标题和独立关闭按钮的可访问名称同步更新。标题变化不创建新标签，不改变标签身份、去重关联、所在外层标签组、顺序、选中态、内容、草稿、阅读位置或正在进行的会话。

已有会话内部的完整输出、结果卡片、子任务行、文件链接，以及分析对话从具体消息继续创建的下一层分析对话，仍然指向当前外层右侧栏：目标作为兄弟标签打开或聚焦，不能在会话标签内部再嵌套第二层右侧栏。关闭兄弟标签后，原会话标签及其阅读位置保持不变。

## 区域与信息

### 宽度调整分隔线

- 并排布局中，会话区与右侧栏之间始终有一条贯穿内容高度的细分隔线；它同时是宽度调整入口，鼠标移入显示横向调整光标，悬停、拖动或键盘聚焦时使用强调色，抵达边界后保持在边界且不抖动、不越界。覆盖布局不显示宽度调整入口。
- 分隔线的可点击范围大于可见细线，但不能遮挡两侧内容的正常点击。拖动分隔线向左扩大右侧栏、向右缩小右侧栏，拖动过程中两侧内容连续重排；到达最小或最大边界时继续拖动不再改变宽度，不弹 toast 或制造额外位移。
- 分隔线必须进入正常键盘顺序并具有可读名称、当前宽度与最小 / 最大值。`←` 每次把右侧栏扩大 16px，`→` 每次缩小 16px；按住 `Shift` 时每次调整 64px；`Home` 到最小宽度，`End` 到当前最大宽度。每次调整后的宽度都作为同一份用户偏好保存，鼠标拖拽不是唯一入口。

### 标签条

- 标签条是「用户打开过的东西」的列表，不是固定分类。同类内容可以并存多个标签，用户能一边看某成员的输出、一边看它造成的改动。
- **没有常驻标签，每个标签都可以关闭。** 右侧栏是用户自己组装的工作台，不预设哪一样必须一直在。
- 标签有两种来源：主对话区的点击，以及标签条上的**加号**。
- 加号新开一个**空白标签**，由用户在标签内选择要看什么。空白标签由用户显式创建，是一个可以关闭的正常标签；它不同于标签数为零时由显示按钮打开的无标签内容选择状态。
- 主对话区点击产生的标签**去重**：过程标签用「所属会话 + 步骤」作为稳定来源，同一步的初次执行、重试和重新运行都聚焦同一个标签；点击某次历史尝试时，同时滚动定位到该尝试。其他标签按各自绑定对象去重。界面不显示这些内部关联。
- 加号产生的标签**不去重**：用户手动开就是明确要一个新的，例如同时开两个改动标签、各自停在不同文件上做对照。
- 分析入口产生的未发送草稿按[对话分析流程](../flows/session-analysis.md)选定的草稿身份去重；已创建分析对话按对话标识去重。同一直接父面板的同一入口、消息中的同一分析对话引用或其他内部入口被重复激活时，只聚焦这一唯一标签，不创建副本。
- **关掉最后一个标签同时关闭右侧栏**，不自动补建空白标签。关闭标签仍不删除已创建会话，也不停止任何正在进行的推进。
- **过程标签的标题就是成员名**；同一个成员在这段对话里的第二个及以后不同步骤的过程标签追加序号，例如「开发」「开发 2」「开发 3」。同一步增加尝试不增加序号。产品无法从第三方 Agent 的输出里取到「这一步在做什么」的可靠描述，不得凭猜测生成描述性标题——标签标题宁可平淡，也不能是编出来的。
- 子任务标签用子任务名；新会话与已有会话沿用普通会话标题规则；用户通过加号显式创建的空白标签用「新标签」。已有会话重命名后使用当前已保存标题，不继续显示旧标题。标题过长时截断，悬停显示当前完整标题。
- 同一标签组内出现两个或更多当前标题相同的会话标签时，每个标签必须在标签条中提供稳定、用户可读且彼此不同的区分信息；悬停完整信息、标签按钮和关闭按钮的可访问名称也包含同一份区分信息。区分不能只依赖会随关闭或重排改变的当前位置，也不能只给屏幕阅读器而让视觉用户仍无法判断；项目、文件夹、创建时间等已有会话事实可组合使用，直到组内唯一。具体采用后缀、次要文字或其他视觉形式留给高保真阶段。同名关系因重命名产生或消失时只增减区分信息，不改变标签身份、顺序、选中态或内容。

### 分析对话标签与跨树路由

- 一棵对话树只使用根对话的一条外层标签组。根对话的直接分析子项、分析对话自己的直接子项，以及这些会话内部打开的完整输出、结果、子任务和文件目标，都作为这条标签组中的兄弟标签；分析对话内部不得创建第二层右侧栏或嵌套标签组。
- 从直接父对话的分析面板激活入口时，在当前根对话的标签组中打开或聚焦目标分析对话唯一标签，并把焦点移入该标签；失败时保留原标签、选中态、阅读位置和面板入口焦点。
- 同一树内的 `moebius-ref:` 目标复用当前根对话和标签组。目标属于另一棵树时，一次激活必须原子切换到目标根对话、恢复该根对话自己的标签组并打开或聚焦目标；任一步失败都保留进入前的根对话、标签组、活动标签和阅读位置，不能把目标临时挂入当前树。
- 关闭分析对话标签只关闭视图，不删除、停止或归档对话。再次打开必须从它的直接父对话分析面板逐层进入；关闭标签不生成左侧栏行，也不改变直接父子归属。

### 空白标签与类型选择

- 空白标签的内容是一句提问和一组类型，用户选完之后这个标签就变成对应类型，标题随之更新。
- 类型共有三种：**新会话**（打开一段普通 sidebar chat）、**改动**（当前绑定工作区相对该会话基线变了什么）和**项目文件**（浏览完整项目树）。它们都不需要先绑定某一步或某个子任务。
- 项目文件夹不是 git 仓库时，类型选择里保留「新会话」和「项目文件」，并说明改动为什么不可用。不静默少一项。
- 过程和子任务**不进类型选择**。它们必须绑定某一个步骤或某一个子任务，让用户在空白页里翻一个长列表去找「开发的第 3 步」是反的——那些东西在主对话区里点，比在这里找快得多。空白标签应当说明这一点，而不是让用户以为这里少了东西。
- **类型选择的边界写死在这三种。** 终端、通用运行预览、浏览器不得从这里长出来：加号菜单一旦存在，往里添东西就是顺水推舟，而那会把这一栏推成一个小型编辑器，正是它的非目标。Markdown Preview 是完整 Markdown 文件内部的只读阅读模式，不是第四种标签类型，也不承接跑测试、起服务或浏览网页。

### 改动标签

- 顶部一句话说明**这里显示的是什么**：「当前工作区相对这段对话基线有这些改动」。
- **基线按当前会话绑定的工作区保存，全程累计**。切换到另一个已有工作区后，改动标签跟随新绑定重新读取；共享 worktree 中其他会话或用户造成的变化可能出现在列表里，产品不声称这些变化由当前对话或 Agent 产生。
- **必须说明看的是哪一边**，用词是「项目文件夹」与「独立工作空间」，不出现路径、目录名或其他机器词。选独立工作空间时还要多说一句后果：**这些改动在一份隔离副本里，你的项目文件夹没有被动过**。用户真正需要知道的不是文件在磁盘哪个位置，而是「我切到编辑器为什么看不到」——回答这个问题才算说清楚了。选独立工作空间的恰恰是最谨慎、最需要被说服的那批用户。
- **当前绑定工作区不是 git 仓库时，不提供改动标签**。这类工作区无法计算相对会话基线的变化；与其给一份可能不准的清单，不如不给。此时空白标签的类型选择里仍有「新会话」和「项目文件」，并说明为什么少了「改动」。
- **不做改动归因**。产品无法区分某个改动来自团队成员还是用户自己在编辑器里手改的，因此绝不声称「团队改了这些文件」。这不是措辞洁癖：右侧栏存在的唯一理由是建立信任，猜错一次归因，用户对整个区域的信任就没了。
- 只列出有改动的文件，并给出每个文件的增删行数。第一诉求是「改了什么」，铺开整个项目树会把它淹没；要浏览未改动的文件，用「项目文件」类型另开一个标签。
- 文件内容以行为单位区分新增、删除与未改动，用户不需要在脑子里做对比。

### 项目文件标签

- 浏览项目的完整文件树并查看文件内容，包含没有被改动的文件。
- 当前会话 workspace binding 或 workspace revision 变化后，项目文件标签必须丢弃旧文件树、选中文件和内容快照，并重新读取新绑定的工作区；旧请求不得覆盖新工作区内容。
- 文件内容使用普通源码阅读视图：只显示当前文件的一列行号，不显示旧 / 新双行号、增删色、`+` / `−` 或其他 Review 语义。文件树可以继续说明文件是否发生变化，但内容区不因此切成 diff；需要审查增删时进入「改动」。
- `.md` 与 `.markdown` 文件没有显式目标行时默认显示 Preview，并可切换源码；从带行号的正文路径进入同一文件时默认源码并定位该行。两种模式读取同一份完整文件快照。
- 同样必须说明看的是项目文件夹还是独立工作空间的副本。

### 文件引用标签

- 显示显式 Markdown 链接或裸绝对路径指向的本地文本文件。canonical 目标位于所属会话工作空间内时读取完整文件，并按普通源码或 Markdown Preview 规则呈现；引用显式携带行号时把目标行滚入视野、突出显示，列号存在时同时显示目标列信息。
- 文件完整路径在详情内可选择、复制，但不回填或展开到主时间线正文。
- canonical 目标位于工作空间外时允许读取本机任意位置的普通文本文件，包括 `/tmp` 与符号链接指向的外部文件，但只返回目标行附近的有界上下文窗口，并明确标注「预览」与内容不完整；外部预览不渲染 Markdown，也不提供读取整个外部文件的入口。
- 工作区完整文件超出既有整文件读取上限时明确失败，不静默降级成附近预览；外部预览继续受既有扫描、单行与响应预算约束。目录、不可显示文本、不存在、不可读或超出对应预算的目标沿用已有失败原因。
- 此类标签只能由正文中的显式文件引用或裸绝对路径打开，不加入加号的通用类型选择。

这是本机桌面应用中的用户主动只读操作，不是分享安全边界。放开位置范围意味着用户点击 Agent 给出的路径后可能看到本机敏感文本；本轮明确接受这个取舍，以保证团队产出的任意本地文件都能从对话进入查看。HTML、脚本、协议导航、二进制执行与写文件能力不随之放开。

### 过程标签

- 承载**单个成员单个步骤的完整过程**。步骤、尝试与 run 的层级遵循[单 Agent 会话](./agent-conversation.md)：一个步骤只有一个过程标签，每次尝试恰好对应一个 run。
- Codex、Claude Code 与 Kimi run 都提供可点击的「完整输出」入口，并只读取当前 run 所属执行引擎的原生可恢复记录：Codex rollout、Claude transcript、Kimi main Agent wire。不得自动读取另一引擎的记录、切换 CLI，或因为三家字段不同而把一种引擎的字段名称强加给另两家。
- 「完整」按 provider 原生事实定义，不按 Codex 字段集合定义。Codex 展示 rollout 中实际 prompt stack、模型 / effort / provider / CLI 元数据以及 Agent 输出、命令、工具 / 函数 / MCP、文件、错误、诊断和结束事实；Claude 展示 transcript 中实际 user / assistant、thinking、tool use、tool result、system / metadata 等已记录事实；Kimi 展示 wire 中实际 system prompt、turn prompt、上下文、thinking / loop event、LLM request、工具、权限、usage 与结束事实。当前引擎没有记录的字段只说明「该引擎未记录」，不得补造、推断或借用另一数据源。
- 提示词与上下文按当前引擎原生角色和分区显示，不把不同来源拼成一个无法辨别来源的大文本块。每一项显示原生记录值和可用时间；缺失时只标记对应项未记录。
- 「调用与输出」按时间顺序呈现当前引擎全部受支持事件；Agent 输出、thinking、参数、结果和原始 payload 使用只读等宽文本，不做内容摘要、不截头、不截尾，不脱敏绝对路径和内部标识。遇到尚未支持的新事件时显示执行引擎、原始协议 event type、时间戳和可展开的原始 payload，不得静默丢失。token / usage 统计作为独立事件显示；Codex reasoning 与 encrypted reasoning 仍过滤，Claude/Kimi 已持久化的可读 thinking 按原生事件展示，opaque / encrypted payload 不解密。
- 终端控制序列必须转成可见转义文本，原始内容不得获得 HTML、Markdown、脚本或终端执行能力；未知事件 fallback 必须遵守来源引擎自己的敏感 payload 过滤边界。
- **同一步骤被重试或重新运行时，每次尝试在同一个标签内依次追加并标明第几次**，不覆盖上一次。每次尝试的标题显示独立计时；用户靠对照前后两次的报错判断团队是在往前走还是原地打转——这个判断决定他继续放手还是自己上手，是这个标签最有价值的用途之一。
- 每次重试都保留自己的 prompt stack、模型元数据、开始 / 结束状态和调用事件，因为两次执行实际收到的输入与环境可能已经不同。
- 内容来自当前执行引擎自己维护的过程记录文件。`claude-stream.jsonl`、`kimi-acp.jsonl`、Moebius stdout / stderr tail 与会话最终回复都只保留原有执行期诊断语义，不成为完整过程的替代品或第二份事实源。某次尝试的关联或原生文件不存在、重复、损坏、越出受信任根或不可读时，只把该次尝试标为过程记录不可用；主对话区的最终回复与同一步其他尝试仍照常保留，不在这里降级冒充过程。
- 只读，但**内容必须可以选中和复制**，文件路径同样可以复制。「只读」指不能改，不是不能拿走：用户读懂错误之后的下一个动作永远是复制它——贴给团队、贴到别处、或者拿路径去自己的编辑器里打开。为这个理由把用户推回命令行，比不提供这一栏还糟。

### 子任务标签

- 显示该子任务的名称、负责成员和当前状态，以及它自己的推进内容。
- 子任务标签打开后，主对话区的子会话卡片上对应行标记为当前正在查看。
- 子任务标签内嵌一段[单 Agent 会话](./agent-conversation.md)：输入、活动、计时、完整输出、重试和停下全部复用该页规则。本页只规定它位于哪个标签、如何打开和关闭，不重复定义单 Agent 交互。
- 子任务标签不提供改动视图。子任务改的文件同样算进这段对话的改动，去改动标签看；单独给子任务算一份改动会立刻带出「父子改动怎么合并」这类没必要的问题。

## 操作与反馈

### 打开与关闭右侧栏

- 显示/隐藏按钮位于主内容区右上角，任何时候可用，包括新对话还没有任何消息时。
- 打开与关闭不影响会话区的滚动位置、草稿和正在进行的推进。
- 打开与关闭都使用 150ms 的无弹性标准缓动。打开时从窗口右缘展开，关闭时沿原路径收回；并排布局中主会话同步让出或收回空间，覆盖布局中右侧栏从右缘覆入或退出。内容只随容器边界显露或裁切，不缩放、不弹跳、不先显示空白工作面。
- 用户在 150ms 尚未结束时再次开关，以最后一次意图为准，从当下进度立即反向，不排队、不先跑完上一段，也不重新从端点开始。连续快速操作结束后只能留下最后一次意图对应的稳定开 / 关状态。
- 关闭一开始，右侧栏内容立即停止接收指针和键盘操作，若焦点原本在其中则移到主内容区的显示/隐藏按钮；视觉内容保留到收起完成，随后才从页面结构移除并恢复主会话原滚动位置。打开不主动把焦点送进右侧栏，开关按钮继续保留焦点，用户下一次 Tab 才进入已展开内容。
- 用户启用「减少动态效果」时立即完成开关和焦点转移，不播放空间动效。
- 开关状态按当前根对话的外层工作现场保存。切换根对话时只恢复目标根对话自己的状态；通过任一右侧栏入口打开目标时，只打开该目标所属的工作现场。应用重启后，各根对话仍恢复各自最后保存的状态。

### 选择文件

- 点击文件树中的文件，在下方显示完整当前内容；当前选中的文件在树中保持可见。源码视图不显示 Review 增删语义，Markdown 默认 Preview 并可切源码。
- 切换文件不改变标签，也不新建标签。
- 文件过大或不是文本时，说明无法显示的原因，不静默留白。
- 文件读取期间切换目标、父级重渲染或回调身份变化，不得让较慢的旧请求覆盖当前文件与模式；读取失败保留当前目标身份并提供重试。文件在磁盘变化时不自动热更新，用户明确刷新、重新选择或重新打开后读取新快照；刷新不能让源码与 Preview 显示两个不同版本。

### 关闭标签

- 关闭标签只关闭这一个视图，不影响对话本身，也不影响正在进行的推进。
- 关闭子任务标签不取消该子任务。这一点必须让用户看得出来，否则用户会不敢关。
- 关闭已创建的普通 sidebar chat 标签只移除当前视图，不删除会话；用户仍可从左侧栏找回。关闭分析对话标签同样只移除视图，但只能从它的直接父对话分析面板再次打开，不得引导用户去左侧栏查找。
- 关闭尚未发送的新会话标签时，以**关闭瞬间的最终草稿**判断是否需要确认：已有正文、文本胶囊、普通附件，或项目、工作空间、团队任一最终值不同于该草稿建立时的系统预选值，就先询问是否丢弃；确认后丢弃并关闭，取消则保持原标签和焦点。用户曾经改选但关闭前已全部改回系统预选值，且没有正文、胶囊或附件时，可以直接关闭。
- 关闭未选中的标签时，当前选中标签与其内容保持不变；通过键盘关闭后，焦点回到当前选中标签。关闭选中标签且仍有其他标签时，优先选中它右侧紧邻的标签；没有右侧标签时选中左侧紧邻标签，焦点落在新选中标签的标签按钮上，不擅自跳进内容。
- 每个标签按钮和独立关闭按钮都可通过键盘聚焦与激活。标签按钮使用当前完整标题作为可访问名称；关闭按钮使用「关闭“{当前完整标题}”」作为可访问名称，不能只读作「关闭」。同一标签组存在同名会话时，两者还必须包含标签条显示的稳定区分信息。会话重命名后可见文字与辅助名称必须在同一次呈现更新中使用新标题及当时需要的区分信息，不能一新一旧。
- 被关闭的标签是最后一个时，完成对应关闭或丢弃裁决后同时关闭右侧栏。直接隐藏整个右侧栏不等于逐个关闭标签，不丢弃草稿或已保存的标签现场。

### 会话重命名同步

- 保存成功后，新标题立即替换该会话所有当前可见及已保留标签中的原标题；隐藏右侧栏后重开、切换主对话再返回和应用重启都继续显示新标题。重命名只改变标题展示，标签稳定身份与全部现场保持不变。
- 保存失败时，所有标签、悬停完整标题与可访问名称继续使用原标题；不出现新旧标题混用。重命名弹层的失败反馈与输入保留由[主页面侧边栏](./main-left-sidebar.md#重命名对话)定义。
- 标题已经保存成功、但某个右侧栏标签未能读取新标题时，该标签不得继续显示旧标题或用旧标题作为可访问名称。它原位显示中性的「标题更新中」并保留同名标签规则要求的稳定区分信息，关闭按钮读作「关闭标题更新中的会话，{区分信息}」；标签身份、顺序、选中态、内容、阅读位置和焦点全部保持。页面以非阻断说明告知「会话名称已保存，标签标题正在重试」，并自动重新读取当前已保存标题。重试成功后原位显示新标题；持续失败时保留该说明和手动「重试标题」入口。关闭重开、切换返回或应用重启也只能重新读取已保存的新标题，不能恢复旧标题。

### 会话归档与来源迁移

会话归档、项目移除和 sidebar chat 来源失效由[主页面侧边栏](./main-left-sidebar.md)决定；本页只消费已经裁决的结果并维护标签现场。

- 一段 sidebar chat 被单独归档或随所属项目批量归档时，关闭所有外层标签组中绑定这段会话的标签。未归档兄弟标签、阅读位置与顺序保持不变；当前选中标签被关闭时沿用相邻标签选择规则，某个标签组因此变为零时关闭对应右侧栏。
- 根对话归档时，关闭该根对话标签组及其中绑定全部分析后代的标签；恢复根对话时只恢复对话树及各自直接父面板中的入口，不自动重开归档前的分析标签，用户按需要从直接父面板逐层打开。未归档工作现场的软件重启仍按本页规则恢复保存的活动分析标签，两种恢复不得混用。
- 项目移除时，侧边栏裁决出的每个被归档根对话或分析对话都作为子树根；右侧栏递归关闭这些子树中全部分析对话标签。某段分析对话只因自身工作项目被移除时，只关闭它及其后代标签，子树之外的父分析对话、兄弟标签、顺序和阅读位置保持。
- 强制移除的停止运行与放弃待接回步骤全部成功、归档结果提交后，才清理对应分析标签；前置步骤失败时标签现场不变。归档或项目移除提交失败并回滚时，右侧栏也恢复清理前的活动标签、顺序与阅读位置。
- 批量归档结果必须一次清理全部目标标签，不能出现左侧栏已无会话、某个来源右侧栏却仍保留可操作历史标签的半套状态。项目移除失败并回滚时，右侧栏也恢复清理前的完整标签现场。
- 已选中 sidebar chat 因来源失效迁移到主内容区时，只有主内容成功呈现该会话后，才从旧来源外层标签组移除它的标签。旧标签组中的其他兄弟标签与阅读位置继续保留，不复制到 sidebar chat 自己的标签组。
- 来源迁移失败时不提前清理旧标签：应用内归档或项目移除随整体操作回滚；应用外失效则保留最后成功呈现的标签与内容并显示说明，待迁移成功后再完成清理。
- 来源后来恢复不会自动重建或选中已迁移的右侧标签。用户下一次从左侧栏明确打开时，再按当时路由决定显示在主内容还是右侧栏。

### 内容更新

- 正在工作的步骤，其过程标签实时追加输出。用户停在底部时自动跟随；向上滚离底部后暂停跟随并累计新内容提示，点击「到最新」或手动回到底部才恢复。
- 过程标签首次打开且从未保存阅读位置时定位最底部，向上滚动按需加载更早事件；加载前页不得让当前阅读内容跳位。切换标签、关闭再打开或应用重启后恢复该标签最后一次成功保存的阅读位置；从主对话区再次点击同一步的总入口只聚焦已有标签、不重置位置，从某次历史尝试点击则定位到该尝试。
- 改动标签在一轮工作结束时刷新。**团队正在工作期间必须说明「这份列表截至上一轮结束」并提供手动刷新**，否则用户开着它盯着看，只会看到一个纹丝不动的列表，第一反应是它坏了或者团队根本没动文件。工作空间切换成功是例外：标签必须立即改读新绑定工作区。
- 改动标签不因文件中途变化而实时跟随。文件在一步的中途处于半成品状态，实时刷新会让列表反复抖动，也会把注意力从会话区拽走；工作空间切换只刷新绑定目标，不改变这一规则。
- 用户正在阅读某个文件时刷新，不得跳走或丢失当前阅读位置；有新的改动时给出可点击的提示，由用户决定何时看。
- 用户在别的标签上时，右侧栏不因为有新内容而自动切换标签。抢焦点会让用户不敢把它开着。

| 改动·对话还没开始 | 说明团队尚未工作，不说成「没有改动」 | 加号、关闭标签 |
| 改动·跑过但没有改动 | 说明当前绑定工作区相对会话基线没有变化 | 加号、关闭标签 |
| 改动·有改动 | 文件树 + 选中文件的 Review / Diff，显示旧 / 新行号和增删语义 | 选文件、加号、关闭标签 |
| 改动·团队正在工作 | 说明列表截至上一轮结束，提供手动刷新 | 刷新、选文件、关闭标签 |
| 改动·加载中 | 保持结构的加载占位，不说成空态 | 等待、关闭标签 |
| 项目文件·源码 | 完整项目树 + 选中文件的完整当前源码，仅一列当前行号 | 选文件、复制、Markdown 时切 Preview、加号、关闭标签 |
| 工作区 Markdown·Preview | 完整 Markdown 的安全渲染结果；显示 Preview / 源码切换 | 阅读、打开受控链接、切源码、关闭标签 |
| 工作区文件·显式行号 | 完整源码并把目标行滚入视野、非纯颜色突出 | 阅读、复制、Markdown 时切 Preview、关闭标签 |
| 工作区外文件·预览 | 完整路径 + 明确「预览」标识 + 目标行附近有界文本 | 阅读、复制、关闭标签 |
| 文件·不可用 | 说明目标不存在、不是普通文本、不可读或超出对应完整读取 / 外部预览预算 | 重试、关闭标签 |
| 改动·读取失败 | 说明原因并提供重试，不显示半份结果 | 重试、关闭 |
| 改动·项目文件夹不可用 | 说明文件夹已不可用、当前无法读取改动 | 关闭；修复入口在会话区 |
| 改动·项目不是 git 仓库 | 不提供此标签，类型选择里说明原因 | 改开项目文件标签 |
| 过程·进行中 | 输出实时追加 | 阅读、关闭标签 |
| 过程·已结束 | 内容定格 | 阅读、关闭标签 |
| 过程·内容为空 | 说明这一步没有产生输出 | 关闭标签 |
| 过程·单次尝试不可用 | 只在该尝试内说明对应执行引擎的原生过程记录找不到、重复、损坏、越界或不可读；其他尝试保留 | 阅读其他尝试、关闭标签 |
| 过程·离底阅读 | 保持当前位置，显示新内容数量与「到最新」 | 继续阅读、到最新、关闭标签 |
| 子任务·进行中 | 显示子任务内容与当前状态 | 说话、提及成员、停下、关闭标签 |
| 子任务·没跑起来 | 与主对话区使用同一套说法 | 重试、说话、提及成员、关闭标签 |

三种不可继续状态（项目文件夹不可用、团队已删除、团队需要修复）由[主页面会话区](./main-conversation.md)定义并承担恢复入口。右侧栏在这些状态下只说明自己读不到什么，不重复提供恢复按钮，避免出现两个事实源。

窄窗口下右侧栏覆盖会话区时，恢复入口正好被自己盖住。此时右侧栏必须提供一个回到会话区的方式，而不是让用户自己想到「先关掉我」——项目文件夹失效通常发生在用户刚挪过目录之后，而挪完目录第一件事就是打开应用看看还认不认得。

## 弹层与危险操作

右侧栏容器不直接编辑项目文件，也不提供文件操作或 git 操作。证据标签全部只读；会话标签发起的 Agent 工作继续服从对应普通会话或流程的确认与权限规则。

- 不提供直接编辑、保存、撤销、回滚、丢弃项目改动。
- 不提供删除文件、删除标签以外的删除动作。
- 不提供任何 git 动作（提交、推送、切分支、创建分支）。
- 内容可以选中、复制。不改变东西不等于不能拿走。

改动、项目文件、文件引用与过程四类证据标签**全部只读**。用户对来源主对话某一步的干预（重试、停下、说话、提及成员）留在主对话区，右侧栏不重复提供。

**子任务标签与普通会话标签是会话容器，不属于只读证据标签。** 它们可以输入、提及成员、重试、停下，并由对应 Agent 按普通权限执行工作；右侧栏不另加一套文件权限。分析入口创建的会话何时允许持久写入，由[对话分析流程](../flows/session-analysis.md)唯一规定。
- 界面不得出现暗示「可以把改动还原回去」的控件或文案。产品当前阶段只解决「看得见」；「可退」是尚未裁决的更大问题，见「待讨论」。这与[主页面会话区](./main-conversation.md)对「停下」的规定一致——已经产生的改动不会被回滚，界面不得暗示可以撤销。

## 响应式与窗口行为

- 右侧栏是承载完整文件、Review、过程记录和会话的辅助工作区，不是窄信息栏。「可用内容宽度」指应用窗口扣除当前可见左侧导航后的水平空间。没有用户宽度偏好时，并排布局的右侧栏取可用内容宽度的 50%，像素取整误差不得超过 1px，让主会话和右侧工作面获得对等宽度。
- 并排布局中，主会话与右侧栏都必须至少保留 480px。右侧栏最小宽度为 480px；当前最大宽度取「可用内容宽度的 75%」与「给主会话保留 480px 后的剩余宽度」中的较小者。用户调整后的宽度跨对话与重启保留；窗口变化导致偏好暂时越界时只按当前边界呈现，不覆盖原偏好，空间再次足够时恢复原值。
- 可用内容宽度小于 960px 时不能同时满足两面的最低可读宽度，右侧栏改为覆盖会话区并占满可用内容面；达到或超过 960px 时使用并排布局。覆盖布局提供独立关闭按钮，关闭后回到会话区原滚动位置；若出现只能在会话区处理的状态（三种不可继续状态），右侧栏必须给出回到会话区的方式。
- 并排与覆盖布局使用同一组 150ms 无弹性开关节奏；仅因窗口或左侧导航变化而跨过 960px 边界时，不额外播放开关动画，也不得让已经打开的内容闪烁、缩放或丢失焦点。
- 文件树、文件内容、过程输出各自独立滚动，互不牵动。
- 过程输出使用虚拟化的时间顺序列表：首次只呈现最底部可视窗口，向上滚动加载更早页；无论过程记录多大，DOM 节点数都只随可视窗口与缓冲区增长，不随完整文件行数线性增长。
- 长行不换行，横向滚动，不撑宽整个页面。行号列在横向滚动时保持可见。
- 左侧导航开合只重新计算可用内容宽度、默认比例和当前可用边界，不改变右侧栏开关状态、标签、阅读位置或已保存宽度偏好。

## 关联流程

本文档只记录右侧栏的容器职责，流程顺序由关联 PRD 维护：

- 团队接力推进一个目标直到结束——右侧栏提供用户在每一轮结束时核实结果的证据。
- 从没跑起来、卡住或停下的状态恢复——右侧栏提供判断原因所需的完整过程与错误细节，恢复动作本身在会话区。
- 团队拆出子任务并各自推进——右侧栏是查看单个子任务的唯一位置。
- [对话分析流程](../flows/session-analysis.md)——右侧栏承载消息级与对话级入口共用的分析新对话、已有分析对话唯一标签、草稿关闭、直接父面板找回、跨树切换以及会话内部目标的兄弟标签路由。

## 指标与验收

右侧栏同时服务两组产品指标：

- **证据核实效率**：用户不必为了确认「改了哪些文件、这一步报了什么错」而退回命令行，以任务成功率与非预期人工干预率观察。
- **普通 sidebar chat 创建成功率**：用户从加号手动新建的普通会话首次发送后，当前标签原地成为可继续且能从左侧栏找回的普通会话次数，占对应有效首次发送尝试的比例。
- **分析对话创建与找回成功率**：分析草稿首次发送后，当前标签原地成为分析对话、左侧栏不新增行，并能从直接父面板打开或聚焦唯一标签的次数，占对应创建与找回尝试的比例。
- **来源主线保留率**：用户明确触发一个满足自身启用条件的消息级或对话级分析入口后，根对话来源仍留在主内容区；分析父对话来源则保留在同一外层标签条中，根对话仍留在主内容区；目标草稿或分析对话在右侧栏成为活动标签的次数，占对应逻辑入口动作总数的比例。
- **普通 sidebar chat 找回成功率**：用户从左侧栏选择已创建的非分析 sidebar chat 后，来源可用时恢复来源主会话与对应右侧标签、来源失效时在主内容区打开成功的次数，占找回尝试的比例。

四项比例在受支持且本地状态有效的路径上目标均为 **100%**，并按以下唯一口径计算：

- **有效本地状态**按每项指标自己的入口条件判断，不能用发送或创建条件过滤打开指标：两类创建成功率都要求最终项目、工作空间和团队满足发送校验且本地会话存储已经初始化；来源主线保留率只要求来源对话仍存在、对应分析入口可用且用户明确触发，来源项目目录不可用不构成打开阻断；普通 sidebar chat 找回要求左侧栏条目仍存在；分析对话找回要求直接父对话及其面板入口可用。动作一旦进入各自分母，随后发生的意外读写、路由或呈现失败仍按失败计算，不能事后以“状态无效”移出分母。
- **创建成功率分母**：通过前端发送校验并实际向本地会话创建链路发出的每个逻辑首次发送请求，按“加号手动普通新会话”与“分析入口草稿”分别计量。正文为空、必填上下文缺失、附件仍在准备等禁用状态不计入；同一请求的重复点击去重后只计一次。会话创建请求报错或原子创建失败计入分母且不计成功；会话与首条消息已经创建、但 Agent 随后启动失败，仍算创建成功。普通 sidebar chat 必须恰好进入一次左侧栏，分析对话必须不进入左侧栏且恰好登记到直接父面板，才分别计成功。
- **分析找回成功率分母**：用户从直接父面板对仍存在的分析对话入口发起的每个逻辑打开动作；打开或聚焦该对话唯一标签并进入焦点才计成功。重复点击聚焦同一标签仍是成功，不得生成副本；跨树目标必须同时恢复正确根对话及其标签组，任一路由或呈现失败都计入失败。
- **来源主线保留率分母**：来源对话仍存在、对应入口满足自身启用条件时，用户明确选择「在右侧栏分析这条消息」或「在右侧栏分析这段对话」产生的每个逻辑入口动作；从用户触发这一刻起立即进入分母，不以引用生成、来源切换、标签打开、草稿呈现或后续发送成功作为前置过滤。重复回调或归并到同一草稿只计一次，消息级与对话级入口保留来源维度但不得互相排除。根对话作为来源时，只有根对话继续显示在主内容区且目标草稿或分析对话完整显示为右侧栏活动标签才计成功；分析对话作为直接父来源时，只有这棵树的根对话继续显示在主内容区、来源分析对话保留为同一外层标签条中的兄弟标签、目标子分析草稿或对话成为活动兄弟标签才计成功，不得把分析父对话搬到主内容区或生成嵌套右侧栏。任一步失败都留在分母且不计成功。来源项目目录不可用但入口仍可用的路径必须计入；分析草稿当前项目是否满足发送条件与本指标无关。
- **普通 sidebar chat 找回成功率分母**：用户对一个仍存在的非分析 sidebar chat 左侧栏条目发起的每个逻辑打开动作。来源可用时必须恢复来源主会话与右侧标签；来源失效时必须在主内容区打开该会话，任一路由读取或呈现失败都计入分母且不计成功。

会话重命名不在本页另起一套指标分母，统一计入[主页面侧边栏](./main-left-sidebar.md#指标与验收)的重命名成功率；本页负责的成功条件是所有绑定标签的可见标题、悬停完整标题和可访问名称一致更新，同时标签身份、顺序、选中态、内容、阅读位置与焦点不变。任一标签同步失败均按该统一指标计为失败，不能因稍后重试成功而移出原分母。

指标口径到此为止，不把分析质量、分析耗时或确认后修改成功率重复记在本页，它们由[对话分析流程](../flows/session-analysis.md)衡量；也不扩大到「用户完全不必离开产品」。用户的核实动作本来就不止读改动——跑测试、起服务、亲眼看一次页面，这些都在右侧栏的能力之外，也不应该成为它的目标。完整 Markdown 文件的 Preview 只优化文档阅读，不把通用运行预览、终端或浏览器带进这一栏。

可核查的完成标准：

1. 右侧栏默认关闭，界面为两栏；每段根对话分别在切换与应用重启后恢复自己的开关状态。对话 A 已打开而此前未打开过的对话 B 保持关闭，返回 A 时恢复打开。
2. 标签条在切换对话时随对话切换，并在重启应用后恢复。
3. 一轮工作结束后，主对话区的结果卡片能一步打开改动标签。
4. 改动标签列出的是当前绑定工作区相对这段对话基线的累计改动，不是最后一步的改动。
5. 改动标签的说明文案不声称改动来自团队成员。
6. 改动标签说明当前看的是项目文件夹还是独立工作空间的副本。
7. 项目文件夹不是 git 仓库时不提供改动标签，类型选择仍保留「新会话」和「项目文件」并说明原因。
8. 「改动」中的文件内容能以行为单位分辨新增、删除与未改动，并保留旧 / 新行号等 Review / Diff 语义。
9. 改动标签只列改动文件；浏览未改动文件通过「项目文件」类型另开标签完成。项目文件内容只显示完整当前源码和一列当前行号，即使文件有改动也不出现增删色、`+` / `−` 或旧 / 新双行号。
10. 团队正在工作时，改动标签说明列表截至上一轮结束并提供手动刷新。
11. 「对话还没开始」「跑过但没有改动」「还在读取」三种情况的措辞互不相同。
12. 点击某成员某一步的完整输出入口，按「所属会话 + 步骤」打开或聚焦唯一过程标签；每次尝试按自身执行引擎展示原生记录中的提示词 / 上下文分区、模型 / effort / provider / CLI、精确时间戳、运行状态、Agent 原始输出、thinking、工具调用与结果。当前引擎没有记录的字段明确说明未记录，不补造为 Codex 式字段。
13. 过程标签的标题为成员名，同一成员的第二个及以后不同步骤的标签带序号；同一步增加尝试不增加序号，标题中不出现产品自行编写的步骤描述。
14. 同一步骤重试或重新运行后，多次尝试在同一标签内依次可见并标明第几次；每次尝试保留自己的提示词栈、模型元数据、独立计时、结束状态和调用事件。
15. 重复点击同一步不产生第二个标签；点击某次历史尝试定位到该尝试，通过加号可以开出多个同类型标签且不去重。
16. 每个标签都可以关闭，关闭后不影响已创建会话与推进；关掉最后一个标签时右侧栏关闭且标签数为零，不自动留下或高亮「新标签」。
17. 标签条提供加号，空白标签与无标签内容选择均只给「新会话」「改动」「项目文件」三种类型，不出现终端、通用运行预览或浏览器；Markdown Preview 只作为完整 Markdown 文件内部的模式出现。
18. 空白标签说明成员完整输出与子任务从主对话区点开，而不是让用户以为类型选择里少了东西。
19. 有新内容时不自动切换用户当前所在的标签。
20. 用户正在阅读文件时发生刷新，阅读位置不丢失。
21. 全区找不到直接编辑项目文件、保存、撤销、回滚或 git 操作；改动、项目文件、文件引用与过程标签只读，子任务和普通会话标签按对应会话规则提供输入与推进操作。
22. 文件内容、过程输出和文件路径都可以选中复制。
23. 窄窗口下右侧栏覆盖会话区并可独立关闭，关闭后会话区回到原滚动位置。
24. 过程标签首次打开且没有保存位置时位于最底部；停在底部时跟随新内容，向上阅读后暂停跟随并显示新内容数量，回到底部后恢复；加载更早事件、切换标签、关闭重开或应用重启都恢复最后一次成功保存的阅读位置。
25. Codex rollout、Claude transcript 与 Kimi wire 都通过反向分页、按需上下文读取与虚拟列表从头可读到尾，DOM 规模保持有界；未支持的新事件显示执行引擎、协议 event type 和可展开原始 payload，不被静默丢弃；token / usage 独立可见，并遵守各引擎的 thinking / sensitive payload 边界。
26. 某次尝试的原生过程记录关联或文件不存在、重复、损坏、越界或不可读时，只在该尝试内明确显示对应引擎记录不可用，不使用 `claude-stream.jsonl`、`kimi-acp.jsonl`、Moebius stdout / stderr tail、最终 Agent 回复或按时间猜出的其他记录冒充，也不影响同一步其他尝试。
27. 子任务标签中同一步任一次历史 Agent 回复、活动运行和终态事实都聚焦该子会话同一个过程标签，并定位到对应尝试。
28. 每次尝试独立显示「已进行 / 耗时 / 完成于」；某一次 provider 原生记录不可用只影响该尝试，同一步其他尝试仍可读。
29. Claude run 从精确 session transcript 恢复原生 thinking、工具调用与结果，Kimi run 通过 source home 的 session index 定位 main wire 并恢复同类原生事实；两者都不得借用 Codex rollout 或 Moebius 诊断流冒充。任一 transcript 或 wire 被清理时，只让对应 attempt 显示该引擎过程记录不可用，最终回复和其他 attempts 保持可读。
30. 从主会话、子任务或右侧栏会话正文点击工作区内普通文本路径时，按所属会话的实际工作空间和 canonical 目标打开完整只读文件；裸路径从文件开头进入，显式行列路径进入源码并把目标位置滚入视野、非纯颜色突出。完整路径、源码与目标信息均可复制。
31. 工作区内 `.md` / `.markdown` 裸路径默认进入 Preview，能切到完整源码；显式带行号的 Markdown 路径默认进入源码并定位，仍能切 Preview，再切回源码后恢复目标位置。Preview 与源码来自同一次完整文件读取，不出现版本错配。
32. 从内容选择打开「新会话」时，标签显示正常新会话布局：有当前主会话就继承其项目与实际工作空间，没有已创建主会话就继承主内容区已经选定的值、缺失项保持未选择；团队初始为「通用助手」，三项均可在首次发送前改选。从「在右侧栏分析这条消息」或「在右侧栏分析这段对话」进入时，同一布局分别带消息级或对话级来源胶囊、交付范围说明与相同候选问题，不出现两套草稿或分析专用页面。
33. 首次消息成功后，当前标签原地成为普通已有会话布局；加号手动新会话成为可从左侧栏找回的普通 sidebar chat，分析草稿则成为只登记到直接父面板的分析对话。两者的完整输出、结果卡片、子任务和文件链接都在当前外层标签条打开或聚焦兄弟标签；分析对话从具体消息创建的下一层也进入同一外层标签条，不出现嵌套右侧栏。
34. 关闭瞬间有正文、文本胶囊、普通附件，或最终项目、工作空间、团队任一值不同于草稿建立时系统预选值的未发送会话标签时必须先确认丢弃；改选后已全部改回系统预选值且没有用户内容的空草稿可直接关闭。取消后内容和焦点不变，确认后草稿不再恢复；隐藏右侧栏、切换主对话或重启应用不会被当作丢弃。
35. 关闭已创建会话标签不会删除或停止会话；普通 sidebar chat 从左侧栏按其来源状态找回，分析对话则只从直接父面板逐层找回。关闭分析标签不得生成左侧栏行、主内容区降级入口或改变直接父子归属。
36. 用户在标签数为零时通过显示按钮重开右侧栏，直接看到无标签的内容选择状态；选定类型后才创建并计入一个标签。
37. 无标签内容选择和空白标签中的三种类型均为可聚焦、带可访问名称的操作，能够通过键盘选择；关闭最后一个标签后，焦点回到主内容区的显示按钮。
38. 关闭未选中标签不改变当前选中内容；关闭选中标签时优先选中右侧相邻标签、没有右侧时选中左侧相邻标签，并把焦点放在新标签按钮上。全部标签及其独立关闭按钮均可通过键盘操作，关闭按钮的可访问名称包含完整标签标题。
39. 普通会话中的添加项目、团队修复和团队管理等既有产品内入口保持可用；证据标签仍不提供页面跳转或外部编辑器出口。
40. 普通 sidebar chat 创建与找回、分析对话创建与直接父面板找回、来源主线保留分别按本页定义的逻辑请求分母统计，在各自受支持的验收路径上均达到 100%。分析入口满足自身启用条件且用户明确触发后立即计入来源主线保留率分母：根对话来源必须保持在主内容区，目标草稿或分析对话成为右侧栏活动标签；分析父对话来源必须让根对话保持在主内容区、来源父分析对话保留为同一外层标签条中的兄弟标签，并让目标子分析草稿或对话成为活动兄弟标签。把分析父对话搬到主内容区、生成嵌套右侧栏，以及引用生成、来源切换、标签打开或呈现失败均计失败；来源项目目录不可用但入口仍可用的动作不得排除，分析草稿当前项目的发送条件不得参与过滤；创建请求失败计入对应创建失败，正常禁用态不计请求，同一逻辑动作的重复回调不重复计数。
41. 非分析 sidebar chat 被单独或随项目批量归档后，它在所有来源标签组中的标签都被移除，未归档兄弟标签、顺序和阅读位置保持；当前标签关闭时按相邻规则选中，最后标签关闭时右侧栏关闭。批量操作失败回滚后标签现场也完整恢复。
42. 已选中 sidebar chat 因来源失效迁移到主内容时，主内容成功呈现后才清理旧来源标签；迁移失败不提前清理或复制标签，来源恢复也不自动重建，用户下一次明确打开时才重新按来源状态路由。
43. 同一直接父面板重复激活同一分析对话入口时，只打开或聚焦一个绑定该对话的标签；从分析对话自身的面板打开下一层时，下一层作为同一外层标签条中的兄弟标签出现，不创建嵌套右侧栏。
44. 同一树内激活分析对话引用时复用当前根对话和标签组；跨树激活时一次操作原子切换到目标根对话、恢复其标签组并打开或聚焦目标唯一标签。任一步失败都保留原根对话、标签组、活动标签与阅读位置，目标不得出现在错误的树中。
45. 归档根对话后，它的外层标签组及全部分析后代标签一起关闭；恢复根对话只恢复对话树和各直接父面板入口，不自动重开归档前的分析标签，用户仍从直接父面板逐层找回。某段分析对话因自身工作项目被移除而归档时，该对话及全部后代标签关闭，子树之外父对话、兄弟标签、顺序和阅读位置保持。
46. 项目移除把每段因此归档的根对话或分析对话作为子树根，递归关闭全部分析后代标签。强制移除必须等停止运行与放弃待接回结果均成功后才清理标签；任一前置步骤或移除提交失败时，标签现场不得提前消失，回滚后活动标签、顺序和阅读位置完整恢复。
47. 关闭应用前让某个分析对话标签处于活动状态，重启后恢复该分析树的根对话及其外层标签组，并聚焦原分析标签；左侧栏仍只选中根对话，分析面板按主会话规则默认关闭。
48. 在可见标签组甲和当前保留但不可见的标签组乙中分别放入绑定同一会话的标签 A，并在 A 前后各放一个兄弟标签；记录两组中 A 的稳定身份、顺序、选中态、内容、阅读位置与焦点，再把 A 成功重命名为 B。甲立即更新，切换到乙时不得短暂显示 A；两组的标签可见文字、悬停完整标题、标签按钮可访问名称和「关闭“B”」均为 B，原稳定身份及全部现场不变，不新增或重排标签。隐藏重开、在两组间往返和应用重启后仍为 B。另起一份标题为 A、标签组结构相同的独立初始夹具，模拟 A → B 保存失败；两组所有入口继续使用 A，不出现 B 或新旧混用。
49. 在可见标签组甲和保留标签组乙中模拟标题已经保存为 B，但乙读取新标题失败：甲可正常显示 B；切换到乙时不得显示 A，而是在原位置显示带稳定区分信息的「标题更新中」及可宣告的非阻断说明。两组标签身份、顺序、选中态、内容、阅读位置和焦点保持。自动或手动重试成功后乙的同一标签原位显示 B，隐藏重开、两组往返与应用重启均不得恢复 A。
50. 在同一标签组打开两个标题相同的会话，两者在标签条中的区分信息必须可见、稳定、用户可读且彼此不同，悬停完整信息、标签按钮和关闭按钮的可访问名称包含各自同一份区分信息；关闭兄弟标签、切换主对话再返回和应用重启后不互换。把其中一段重命名为唯一标题后区分信息可以收起但标签身份和现场不变；让两个标题更新同时失败时，两个「标题更新中」仍可区分。
51. 让横向标签条已经溢出，把当前选中标签从短标题重命名为会扩宽标签的长标题：焦点不在标签条时，选中标签仍完整可见；再将键盘焦点放在另一个标签按钮或其关闭按钮并触发会改变宽度的标题更新，聚焦控件仍完整可见且焦点不变。更新未选中且未聚焦标签时横向位置不跳动；三种情况都不改变标签身份、顺序、选中态或内容。
52. 从「项目文件」先后选择未改动源码、已改动源码和 Markdown：前两者都读取完整当前文件并使用单行号源码视图，后者默认 Preview 且可切源码；三者内容区都不出现 Review 增删语义。「改动」选择同一已改动文件时仍显示累计基线 diff，二者不会复用错误的数据或样式。
53. 点击工作空间外普通文本路径（含工作区内符号链接真实指向外部）时，标签标题与内容区明确显示「预览」和「仅显示目标位置附近内容」，只返回有界窗口且不渲染 Markdown；点击工作区外别名但 canonical 真实目标位于工作区内时按完整工作区文件打开。
54. 工作区完整文件超过既有整文件上限、不是可显示文本、目录、不存在或不可读时沿用对应失败反馈，不用相似文件、不显示半份成功结果，也不降级成外部预览；工作区外预览遇到目标行过长、响应过大或扫描预算不足时沿用既有反馈。
55. 文件读取尚未返回时切换文件、切换源码 / Preview、让父级重渲染或更新回调身份，较慢或失败的旧响应不得覆盖当前目标、模式与内容。磁盘文件变化不自动改写正在阅读的快照；明确刷新、重新选择或重新打开后，源码与 Preview 一起切到新快照并保持有效定位。
56. Markdown Preview 继续清洗原始 HTML、阻止脚本与危险协议；`http`、`https`、`mailto` 按现有确认规则交给系统浏览器，绝对本地文件链接继续在应用内按工作区内外规则打开。相对链接、本地图片和 `.mdx` 不因本次获得新的解析或渲染能力。
57. 让当前可见左侧导航之外的可用内容宽度分别为 1200px、960px 与 959px，并清除已保存宽度：前两者使用并排布局，右侧栏分别为 600px 与 480px，像素取整误差不超过 1px；959px 使用占满可用内容面的覆盖布局。并排时分隔线通过鼠标和键盘都能调整宽度，右栏不得小于 480px，最大值不得超过可用内容宽度的 75% 且必须给主会话保留 480px；悬停、操作、键盘焦点与抵达边界都有本页规定的反馈。保存一个合法宽度后缩窄再放宽窗口，呈现值只做临时边界收敛，最终恢复原偏好。
58. 在并排和覆盖布局分别打开与关闭右侧栏，工作面都在 150ms 内从右缘展开并沿原路径收回；并排时主会话同步让出和收回空间。动画中途连续反向开关时，运动从当前进度响应最后意图，不排队、不跳回端点，最终开关状态与最后意图一致。关闭开始后右侧内容不可再交互，内部焦点立即回到显示/隐藏按钮，视觉内容保留到收起完成且不闪空白；关掉最后标签也走同一出场过程。开启「减少动态效果」后立即完成；仅因窗口或左侧导航变化切换并排 / 覆盖时不播放开关动画，内容、焦点与阅读位置保持。

## 已知隐患

以下问题已经识别，本版**接受它带来的后果**，不作为待讨论挂起，也不因此推迟交付：

### Provider 原生过程记录可能不可用

过程标签读取 Codex、Claude Code 或 Kimi 自己维护的原生过程记录，不复制一份内容归 Moebius 保管。用户清理 provider 数据、切换 provider 数据根、文件损坏或未来 provider 改变记录格式时，历史步骤中的一次或多次尝试可能无法读取。本版接受这个后果：页面只在对应尝试内明确说明该执行引擎的过程记录文件已不可用，不拿残缺 tail、最终回复或按时间猜出的另一份文件冒充。

这项取舍换来的是单一内容来源：执行引擎拥有过程记录，Moebius 只保存一次运行到该 provider external session 的稳定关联。

## 待讨论

以下问题本版**明确不作答**，不得由实现自行决定：

### 改动的「可退」

本页只解决「看得见」。以下四件事仍然悬空，需要一次完整裁决：按「停下」之后已经产生的半截改动怎么办；用户看到不该有的改动时能否在产品内还原；选择独立工作空间的用户如何把成果带回项目；默认工作空间直接改真实文件夹这一默认值是否需要首次提醒。这组问题跨越会话区、右侧栏和项目设置，可能需要一份流程 PRD 承接。

### 只看这一轮的改动

改动标签目前只有「全程累计」一个视角。长对话里逐轮验收时，用户每一轮都要重新扫同一棵树才能找出这轮新增的部分，返工越多越费劲。是否增加「本轮／全程」切换未裁决。**本版明确不做**：同类产品（编辑器的源代码管理面板、Codex 的评审视图）同样只给全量对比，用户对这套心智是熟的，不构成使用障碍。

### 改动规模很大时的表现

一次涉及几百个文件、或单个文件改动上万行时，改动标签如何呈现与截断，未讨论。日常的一次依赖安装就足以让锁文件和构建产物占满列表，是否需要排序、折叠或过滤，同样未裁决——本版按原样照列。

### 在外部编辑器中打开

目标用户有自己的编辑器。是否提供「在编辑器中打开这个文件」的出口，以及它是否会削弱右侧栏本身的存在理由，未裁决。

### 归属其他页面的衔接问题

**「非预期人工干预」的定义边界**。用户为了跑测试、起服务、看一眼真实页面而离开产品，算不算非预期干预，属于总 PRD 的指标定义问题，不由本页承担。本页只把自己的指标口径收窄到「确认改了什么、报了什么错」。

## 现状参考与产品缺口

右侧栏容器、过程标签与三种文件阅读模式已经落地：项目文件与工作区内正文路径使用完整源码或 Markdown Preview，工作区外路径使用明确标识的有界预览，只有改动标签使用 Review / Diff。Claude/Kimi 当前仍被运行时 capability 硬编码挡在过程标签之外。三种 provider 现在都会为 run 写入带 engine、external session id 与 workspace context 的稳定执行关联；产品目标是在不复制原生记录的前提下，让过程标签按 engine 分派到 Codex rollout、Claude transcript 或 Kimi wire，并复用现有反向分页、活动增量、虚拟列表、attempt 聚合和阅读位置恢复。升级前没有稳定关联的旧 run 不做猜测回填，打开时明确显示过程记录不可用。

## 非目标

- 不做代码编辑器。右侧栏不提供编辑、保存与格式化。
- 不做终端、通用运行预览与浏览器。加号的类型选择只有新会话、改动与项目文件三种，这条边界写死；Markdown Preview 只是完整 Markdown 文件内部的只读阅读模式，不承接跑测试、起服务或看真实页面。
- 不做语法高亮、代码编辑、格式化、保存、文件监视或全局 Markdown 默认偏好；Preview / 源码选择只属于当前文件标签。
- 不为相对 Markdown 链接、本地图片、目录索引或 `.mdx` 增加解析规则，也不允许把工作空间外预览扩成任意外部完整文件读取。
- 不做版本控制客户端。不提供提交、推送、分支、暂存或历史浏览。
- 不做改动归因。不声称某个改动由哪个成员造成。
- 不做撤销与回滚。本版只解决看得见。
- 不做跨对话的改动汇总。右侧栏只对当前这段对话负责。
- 不做任何 provider 原生过程记录的第二份内容存储。Moebius 只保存稳定关联；`claude-stream.jsonl` 与 `kimi-acp.jsonl` 继续只做执行期诊断，记录缺失时如实显示不可用。
- 不解密或推断 opaque / encrypted reasoning payload。Codex reasoning 继续过滤；Claude/Kimi 原生记录中已持久化为可读事件的 thinking 按来源展示。
- 不提供面向分享的自动脱敏副本、全链路导出、搜索或筛选；本版只把单次 Agent 调用完整、分层、可复制地呈现出来。
- 不复制来源主对话的推进操作。来源会话的重试、停下、说话和提及成员留在主内容区；子任务标签与普通会话标签推进的是各自绑定的会话。
- 不承载子会话的管理。子任务不进入侧边栏，也不在右侧栏被创建、重命名或删除。
- 不服务「离开很久后回来快速读懂全部经过」的场景，界面也不暗示自己能做到。
