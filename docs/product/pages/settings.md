> **2026-07-27 产品决定：**设置不再作为离开主工作区后进入的独立页面，而改为覆盖当前工作区的居中弹窗。原因是语言等应用级配置应当随时可改，同时保留用户正在进行的项目、对话和输入上下文。首期只显示可用的“常规”分类，提供简体中文与英文；选择新语言时先完成本地持久化，再原子切换整个桌面客户端的界面语言。

## 页面目标

设置弹窗集中承载应用级配置和不适合常驻主界面的数据管理入口。用户无需离开当前任务即可查看或修改配置；首期可以在“常规 → 语言”中切换简体中文与英文，切换后继续原任务时看到一致的目标语言界面。

设置未来也可承接“Agent 与团队”“已移除项目与已归档对话”等分类，但这些分类只有在内容可用时才出现；首期不显示禁用项或“即将推出”占位。

## 用户场景

- 用户希望把 Moebius 的静态界面文案切换为自己更容易阅读的语言。
- 用户在对话或任务进行过程中打开设置，希望修改后原任务和输入上下文不丢失。
- 用户重启应用后，希望继续使用上次选择的语言。

## 入口与去向

- 从[主页面侧边栏](./main-left-sidebar.md)底部“设置”打开居中的设置弹窗。
- 打开弹窗不会改变当前项目、当前对话、对话滚动位置、未发送草稿、Sidebar 开关或项目展开状态。
- 关闭弹窗后回到打开前的工作区位置，并继续原任务。
- 如果弹窗打开期间当前项目已因其他操作变为不可用，关闭后遵循对应页面已有的恢复规则；设置弹窗本身不创建新的导航去向。
- 首期只显示可用的“常规”分类；“Agent 与团队”“已移除项目与已归档对话”待内容可用后再出现，不显示禁用项或“即将推出”占位。

## 区域与信息

### 弹窗标题区

- 标题显示当前应用语言下的“设置”。
- 关闭按钮始终可见，并具有与当前语言一致的可访问名称。
- 弹窗打开时，背景工作区保持可辨认，帮助用户确认自己没有离开当前任务；背景内容不可操作。

### 分类导航

- 首期只显示“常规”；没有可用内容的后续分类不出现在导航中。
- 默认进入“常规”，当前分类有明确选中态。
- 后续分类只有在内容可用并完成各自产品确认后才加入，不以禁用项或“即将推出”占位提前展示。

### 常规

- “语言”作为常规分类中的独立设置项。
- 语言选项显示为“简体中文”和“English”，使用户即使在不熟悉当前界面语言时也能识别目标语言。
- 当前生效的语言必须有清晰、非仅依赖颜色的选中标记。
- 没有已保存选择的用户默认使用简体中文，不根据系统语言自动改变默认值。

### 语言覆盖范围

- 切换覆盖整个桌面客户端中由 Moebius 提供的静态界面文案，包括页面标题、导航、按钮、菜单、表单标签、占位提示、空态、状态说明、确认与错误提示、悬停提示和可访问名称。
- 同一次界面中不得因组件遗漏而混用简体中文和英文；新增的产品静态文案也必须同时具备两种语言版本后才能进入交付。
- 用户输入、Agent 回复、项目名、对话中引用的文件内容和本地路径保持原文，不随界面语言被翻译或改写。

## 操作与反馈

### 打开与关闭

- 点击 Sidebar 的“设置”后，弹窗在当前主工作区上方打开。
- 用户可以点击标题区关闭按钮或按 `Esc` 关闭；关闭只退出设置，不撤销已经成功保存的语言选择。
- 弹窗打开后，键盘焦点进入弹窗；关闭后，焦点回到触发设置的入口。
- 为避免用户在调整设置时误关闭，点击背景遮罩不关闭弹窗。

### 切换语言

- 用户选择另一种语言后，无需额外点击“保存”或重启应用。
- 应用先把新选择保存到本地；保存成功后，再把设置弹窗和整个桌面客户端原子切换为新语言。正常本地写入下，用户感知为立即生效。
- 页面结构、当前任务和用户内容不因语言切换被重置；下次启动直接使用已保存语言。
- 重复选择当前语言不会产生额外提示或打断用户。
- 若新选择无法持久保存，应用保持此前已保存且当前生效的语言，显示可理解的失败提示，并允许用户重试；不得先切换再回退，也不得表现为已经保存但重启后悄然恢复旧语言。

## 页面状态

| 状态 | 表现 | 可用操作 |
| --- | --- | --- |
| 默认 | 打开“常规”，显示当前生效语言 | 切换语言、关闭 |
| 首次使用且无保存选择 | 简体中文为当前语言 | 切换到 English、关闭 |
| 语言切换成功 | 弹窗及整个桌面客户端立即显示目标语言，选中态同步更新 | 继续设置或关闭 |
| 语言保存中 | 标明目标语言正在保存，整个应用继续使用此前语言，避免重复提交造成跳变 | 关闭能力保持可用；重复选择不产生新操作 |
| 语言保存失败 | 整个应用保留此前已保存语言并显示失败提示 | 重试或关闭 |

语言资源随桌面应用提供，不出现需要联网下载语言资源的加载态。

## 弹层与危险操作

- 设置本身是主工作区上方的模态弹窗；打开时背景不接受鼠标或键盘操作。
- 弹窗内若将来出现需要二次确认的操作，确认层位于设置弹窗之上，关闭确认层后回到原设置位置。
- 语言切换可逆，不需要危险操作确认。

## 响应式与窗口行为

- 弹窗在桌面常规宽度下居中显示，宽度足以让分类与内容形成清楚的左右层级，但不遮蔽到让用户无法辨认原工作区。
- 窗口变窄时，分类导航移到内容上方；不得压缩到截断当前语言、选项名称或关闭入口。
- 内容超出可用高度时只滚动设置内容，标题与关闭入口保持可达。
- 用户缩放或移动窗口时，当前分类、语言选择和滚动位置保持稳定。

## 关联流程

- 从 Sidebar 打开设置、切换语言、关闭并继续当前任务是本页面内完成的单弹窗旅程，不另建跨页面流程。

## 指标与验收

1. 从 Sidebar 点击“设置”会在当前工作区上方打开居中的设置弹窗，不进入独立设置页面。
2. 弹窗默认打开“常规”，并能明确看到当前语言以及“简体中文”“English”两个选项。
3. 没有保存过语言选择时，应用使用简体中文；选择另一语言并在本地保存成功后，设置弹窗和整个桌面客户端的产品静态文案立即一致切换。
4. 关闭设置或重启应用后，语言选择仍然保留，不需要再次设置。
5. 切换语言不会改变当前项目、当前对话、Sidebar 状态、未发送草稿或用户与 Agent 已产生内容。
6. 用户输入、Agent 回复、项目名、文件内容和本地路径保持原文。
7. 错误、空态、提示、菜单、悬停提示和可访问名称与当前界面语言一致，不出现可见的中英混用。
8. 新语言只在本地保存成功后全局生效；保存失败时不会先切换再回退，也不会制造“已保存”的假象，用户可以理解失败并重试。
9. 首期分类导航只显示可用的“常规”，不显示禁用的未来分类或“即将推出”占位。
10. 仅使用键盘即可打开设置、到达“常规”分类并切换语言、关闭弹窗，并在关闭后回到设置入口。

## 非目标

- 首期不提供简体中文和英文之外的语言。
- 首期不根据 macOS 系统语言自动选择或切换界面语言。
- 不翻译、改写或自动检测用户输入、Agent 回复、项目名、文件内容和本地路径的语言。
- 不在本次交付中补齐“Agent 与团队”的全部设置能力。
- 不在本次交付中定义已移除项目或归档对话的恢复、永久删除和数据保留期限。
