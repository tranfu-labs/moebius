> **2026-08-09 产品决定：**“常规”新增默认开启的“任务提醒”总开关，统一控制 macOS 系统通知、系统通知声音与 Dock 角标，不拆分按项目、对话、终局类别或通道的细粒度选项。设置始终显示真实 macOS 通知权限；未决定时由用户明确发起权限请求，被拒绝时提供系统设置恢复入口。应用内总开关与系统权限是两项独立事实：权限被拒绝不会把开关伪装成关闭，总开关仍开启时侧边栏与 Dock 继续按真实提醒工作。系统通知可能显示应用内对话名称，授权与恢复前必须让用户知道这一点。

## 页面目标

设置弹窗集中承载应用级配置、应用身份信息和不适合常驻主界面的数据管理入口。用户无需离开当前任务即可切换语言、管理任务提醒与系统权限、在“AI 服务商”中维护可复用的 Pi Provider 档案，或在“关于”中查看版本与自动更新状态；完成后继续原任务时，工作上下文保持不变。

“Moebius 的技能”让用户看清应用替自己自动做的那些小事现在是怎么做的、最近变成了什么样、凭什么变，并在不满意时改回去。这个分类的第一优先是“看得见”：与“改得动”冲突时让位的是编辑与退回能力——一个用户改不动但能查清的技能仍然成立，一个能改却查不清改过什么的技能不成立。

设置未来也可承接“Agent 与团队”“已移除项目与已归档对话”等分类，但这些分类只有在内容可用时才出现；首期不显示禁用项或“即将推出”占位。

## 用户场景

- 用户希望把 Moebius 的静态界面文案切换为自己更容易阅读的语言。
- 用户排查问题、提交反馈或确认更新前，希望快速查看当前安装版本和适用平台。
- 用户希望应用自动确认是否有新版本并在后台下载，但安装和重启必须由自己确认。
- 用户在对话或任务进行过程中打开设置，希望修改后原任务和输入上下文不丢失。
- 用户重启应用后，希望继续使用上次选择的语言。
- 用户希望任务已完成或正在等待自己时收到系统通知、声音与 Dock 提醒，也希望能从设置统一停用这些通道。
- 用户拒绝过 macOS 通知权限后，希望看清应用开关与系统权限的差异，并从准确入口恢复权限。
- 用户已经拥有 DeepSeek 等受支持服务商的 API Key，希望新增一份可供多个 Agent 复用的档案，而不需要理解 Base URL。
- 用户需要轮换 Key、增加或移除已验证模型、修改默认模型，且失败的新草稿不能破坏旧的有效配置。
- 用户需要停用、迁移或删除 Provider 档案，并在操作前看清受影响的团队成员、AI 建队草稿、任务和可恢复会话。
- 用户注意到 Moebius 起的对话标题最近变了个样子，想知道它是不是自己改了规则、凭什么改。
- 用户不满意当前的自动标题，想直接改掉规则，而不是等应用慢慢学。
- 用户不希望应用继续自己改这些规则，但仍想保留查账的能力。
- 用户发现自动标题最近反而更不合用，想退回到上一版。

## 入口与去向

- 从[主页面侧边栏](./main-left-sidebar.md)底部“设置”打开居中的设置弹窗。
- 打开弹窗不会改变当前项目、当前对话、对话滚动位置、未发送草稿、Sidebar 开关或项目展开状态。
- 关闭弹窗后回到打开前的工作区位置，并继续原任务。
- 如果弹窗打开期间当前项目已因其他操作变为不可用，关闭后遵循对应页面已有的恢复规则；设置弹窗本身不创建新的导航去向。
- 当前显示“常规”“AI 服务商”“Moebius 的技能”和“关于”四个可用分类；“Agent 与团队”“已移除项目与已归档对话”待内容可用后再出现，不显示禁用项或“即将推出”占位。
- “Moebius 的技能”在同一内容区内由列表钻取到详情，“返回”回到列表并保留滚动位置；技能详情不构成独立页面，也不新增离开设置的去向。
- “查看发布记录”“反馈问题”“开源仓库”和更新失败时的浏览器兜底都交给系统浏览器打开对应公开页面；设置弹窗与当前工作区留在原处。正常的检查、下载和安装准备不离开应用。

## 区域与信息

### 弹窗标题区

- 标题显示当前应用语言下的“设置”。
- 关闭按钮始终可见，并具有与当前语言一致的可访问名称。
- 弹窗打开时，背景工作区保持可辨认，帮助用户确认自己没有离开当前任务；背景内容不可操作。
- 标题区只承担弹窗身份和关闭操作；内容区不再重复显示与当前分类同名的大标题。

### 分类导航

- 当前显示“常规”“AI 服务商”“Moebius 的技能”和“关于”；没有可用内容的后续分类不出现在导航中。
- 默认进入“常规”，当前分类有明确选中态。
- 每个分类使用图标、文字和非仅依赖颜色的选中态；导航保持紧凑，不以大面积底色或独立卡片制造多余层级。
- 切换分类只替换设置内容，不关闭弹窗、不改变背景工作区，也不重置另一分类已经产生的本次反馈。
- 后续分类只有在内容可用并完成各自产品确认后才加入，不以禁用项或“即将推出”占位提前展示。

### 常规

- “语言”作为常规分类中的独立设置项。
- 语言选项显示为“简体中文”和“English”，使用户即使在不熟悉当前界面语言时也能识别目标语言。
- 当前生效的语言必须有清晰、非仅依赖颜色的选中标记。
- 两个语言选项组成一个连续、紧凑的设置组，以行分隔和单一外框表达归属；不再把每个选项渲染成彼此分离的大卡片。
- 没有已保存选择的用户默认使用简体中文，不根据系统语言自动改变默认值。
- “默认 Agent”作为常规分类中的第二个独立设置项，位于“语言”下方，使用与语言相同的紧凑设置组表达。

#### 默认 Agent

默认 Agent 是应用自己发起的后台工作所使用的 Agent，不属于任何一支团队、任何一次会话，也不代替用户在会话里工作。它当前服务三件事：为每次 `AGENT.md` 变化写一句用日常语言表达的说明、在软件升级后官方内容与用户内容都改动过时完成合并（两者来自[Agent 进化流程](../flows/agent-evolution.md)），以及读用户改过的对话标题、学着把标题起得更合用户的意（来自[Agent 技能进化流程](../flows/agent-skill-evolution.md)）。

- 设置项复用团队页成员运行配置的同一套选择方式：执行引擎、Provider（仅 Pi）、模型和思考程度，选项范围、静态校验与旧值保留规则完全一致，不新增第二套控件语言。
- 没有已保存选择时使用内置「通用助手」的官方推荐配置，用户无需先打开设置。页面必须显示这个默认值本身，不显示为空白或“未设置”。
- 用途必须用一句用户语言写清，让用户知道改这里会影响什么；不使用“后台任务”“合并引擎”这类实现说法。
- 这里的选择不影响任何团队成员的运行配置，也不影响任何既有或新建会话；反过来，团队成员的配置变化也不回写这里。
- 所选配置不可用时，摘要与合并按 [Agent 进化流程](../flows/agent-evolution.md)降级：官方单方改动照常合入，需要语义合并的部分保留用户内容并可重试。设置页只显示配置本身的状态，不承担合并失败的解释。

#### 任务提醒

- 设置组标题使用“任务提醒”，说明固定为“任务完成或需要你处理时提醒你”；用户界面不得出现“终局”“投递”“通道”“应用总开关”等内部术语。
- “任务提醒”与语言同属常规分类中的独立设置组。总开关默认开启，并跨关闭设置与应用重启保留用户最后一次选择。
- 总开关统一控制之后形成终局时的 macOS 系统通知、系统通知声音和 Dock 角标；关闭后不提交新通知、不请求声音并立即隐藏 Dock 角标，侧边栏状态点、时间线事实和已经进入 macOS 通知中心的历史通知不被删除。
- 重新开启只让之后形成的新终局恢复通知与声音，并按当前未归档对话中可见的红点或蓝点重建 Dock；关闭期间的终局不补发通知。
- 本组不提供按项目、团队、Agent、对话、终局类别、声音或 Dock 分开的开关。更新检查、下载结果和设置保存后的应用内轻量提示不属于任务提醒，不受本开关控制。
- 总开关表示用户在 Moebius 内的提醒意愿，系统权限表示 macOS 是否允许通知与声音，两者分别展示且不得互相改写。系统返回拒绝或策略限制时统一显示“已拒绝”，总开关仍可保持开启；此时不提交系统通知或声音，但 Dock 继续按总开关工作。
- macOS 通知状态只显示用户可理解的“尚未开启”“已允许”“已拒绝”三种，不展示内部枚举，也不再另造含义不明的“受限”。打开设置、应用重新获得焦点及从系统设置返回时刷新真实状态，不靠缓存声称权限已经恢复。
- 系统权限尚未由用户选择时显示“尚未开启”和“允许系统通知”；只有用户点击后才触发 macOS 权限请求。允许后原地显示“已允许”；拒绝后原地显示“已拒绝”和“打开系统设置”，不循环弹权限请求。
- 权限已拒绝时，“打开系统设置”前往 Moebius 的 macOS 通知设置；打开成功只说明系统设置已经打开，不提前显示“已恢复”。用户返回后按系统真实状态更新，打开失败时保留原状态并提供重试。
- 权限之外另显示系统通知通道状态。正常时不增加说明；系统不支持或暂时无法初始化通知、或者最近一次任务提醒提交失败时，显示“暂时无法发送系统通知”，说明本次系统通知与声音可能未送达、Dock 与侧边栏仍在工作，并提供“重新检查”和“反馈问题”。“重新检查”只重新读取系统支持、通道初始化与权限，不发送测试通知、不补发失败终局；检查恢复后回到正常状态，仍异常时保留说明。之后的新终局可以再次尝试，已经失败的通知不延迟补发。
- 最近一次提交失败不会把“已允许”权限改成“已拒绝”，系统不支持或初始化失败也不伪装成权限问题。通道异常会一直保留到重新检查确认恢复或后续任务提醒真实提交成功；页面不得用原始系统错误、路径或内部枚举要求用户自行判断。
- 权限说明明确：系统通知会显示 Moebius、“已完成／正在等待你”，并可能显示应用内对话名称；锁屏预览、静音、专注模式和通知中心展示仍由 macOS 控制。

### AI 服务商

“AI 服务商”管理应用级 Pi Provider 档案，与首次引导读写同一份状态。这里保存的是可被多支团队、多个成员和既有会话引用的稳定档案，不是某个成员私有的 Key 表单。

#### 档案列表与空态

- 空态显示“还没有 API 服务商”和主操作“添加服务商”，说明配置完成后可在 Agent 团队中选择 Pi API；不要求先安装 Codex、Claude Code 或 Kimi。
- 每个档案行显示服务商、用户命名的档案名称、默认模型、有效状态、最近一次验证结果和引用该档案的团队成员数量。存在草稿、任务或可恢复会话引用时，在详情“引用”区分别列出，不把它们压成一个无法行动的总数。
- 有效状态只有“已就绪”“需要处理”“已停用”。“正在验证”或“正在保存”作为叠加活动显示，不能覆盖旧有效状态。只有“已就绪”允许新绑定、AI 建队和新运行。
- 档案不显示完整 Key、Base URL 或可复制的凭据字段。Key 区只显示“已安全保存 / 需要重新输入 / 无法读取”等状态和“替换 Key”动作。
- 同一服务商允许多个档案，但档案名称在应用内必须唯一；列表用服务商和档案名称共同帮助用户区分，不使用 Key 尾号作为身份。

#### 新增档案与能力验证

- “添加服务商”在当前分类内打开表单，字段为服务商、唯一档案名称、API Key 和目录内模型。服务商目录至少包含 DeepSeek；页面不显示 Base URL、自定义地址或任意模型 ID。
- 服务商身份在档案创建后不可更换。用户要改用另一服务商时新增档案，再迁移引用；编辑页不能把一份档案原位改成另一服务商。
- 提交前行内说明：固定验证会产生极少量 API 用量且不读取项目；真实任务会把必要项目内容、附件和工具结果发送给所选服务商。
- “验证并保存”依次显示模型回复、无项目副作用的受控工具调用和本地安全保存。前两项通过但保存未完成时，不显示“已就绪”；保存失败明确说明没有创建档案，并在当前表单生命周期内允许不重复调用服务商的“重试保存”。
- 验证失败保留当前表单与 Key 输入，显示 Key、模型兼容、额度或限流、服务暂不可用和无法确认等安全类别；不显示原始响应、内部地址或完整 Key。离开失败表单会丢弃未保存 Key，再进入必须重新输入。
- 新档案只有凭据和元数据作为同一份结果保存并重读成功后才出现在列表。任何失败或应用崩溃都不得留下只有凭据、只有元数据或可被团队选择的半成品。

#### 编辑、Key 轮换与模型管理

- 档案名称可直接修改；名称保存失败时保留旧名称。修改默认模型只影响此后首次选择该档案时的预选，不回写成员配置或既有会话。
- 手动移除当前默认模型前，用户必须先从仍可用的已验证模型中选择新的默认模型；“保存新默认值并移除旧模型”作为同一次操作提交，任一步失败都保留原默认模型和模型集合。不能把默认模型清空，也不能由系统静默挑选另一模型。
- 新增模型必须从该服务商目录选择，并完成与首个模型相同的真实能力验证；成功后加入“已验证模型”集合。每名成员只能选择这个集合中的可用模型。
- 替换 Key 时，确认层先显示“将验证 n 个模型、每个模型都会发起一次固定能力测试并产生少量 API 用量”，并逐项列出模型；用户确认后，新 Key 才逐一验证当前全部已验证模型。详情显示总体进度和逐模型结果；任一模型失败时整次轮换不生效，旧 Key 和全部旧模型继续作为原有效版本使用。全部通过并安全保存后才原子切换。
- 编辑现有档案时，“正在验证 / 正在保存”是叠加活动。列表和所有现有消费者继续读取操作开始前的有效版本；未通过的模型、Key 或默认值草稿不允许被成员选择。
- 从已验证模型集合移除模型前，先列出冻结该模型的团队成员、AI 建队草稿、运行中或排队任务和可恢复会话。存在任何引用时阻止移除，用户必须迁移到同一档案的另一已验证模型，或结束相应草稿或会话的继续能力。运行中请求先按真实结果结束，不在中途偷换模型。
- 模型被支持目录移除时，该模型标记“不可用”。若它不是默认模型，档案还有其他可用模型时仍可保持“已就绪”，但受影响引用不能继续；没有任何可用模型时档案进入“需要处理”。若被移除的是默认模型且仍有其他可用模型，档案显示“已就绪 · 需设置默认模型”：既有成员和会话按各自冻结模型继续或迁移，新的档案选择必须由用户明确选模型，不能预选；详情置顶要求用户从其他已验证模型中保存新的默认值，保存前不静默代选。

#### 有效状态与修复

- Key 明确失效、本机凭据文件无法读取、服务商从支持目录移除，或档案已经没有任何可用已验证模型时，档案进入“需要处理”，不再接受新绑定、新建队或新运行，也不计入首次引导门槛。
- 普通限流、额度暂时不足和短暂服务不可用只影响当前请求，详情显示最近失败，但不永久撤销“已就绪”。
- Key 或仍受支持模型的问题提供“修复并重新验证”。服务商已移除时不进入无解的旧服务商表单，而显示“添加新的服务商并迁移引用”；模型已移除时显示迁移到同档案其他已验证模型。
- 用户可以停用“已就绪”档案。停用阻止新绑定和新运行，已发出的请求按真实结果结束，排队但未启动的请求进入可修复状态；现有团队、草稿和会话引用继续保留。
- “重新启用”不是纯本地开关。确认层先显示将对当前全部可用已验证模型发起固定能力测试、模型数量和每个模型都会产生少量 API 用量；用户确认后依次显示模型回复、工具调用和本地状态保存。有效状态在验证期间保持“已停用”，全部模型通过并保存后才切到“已就绪”。
- 用户取消、确认离开，或只发生限流、额度暂时不足、网络失败和服务暂不可用等暂时性失败时，唯一终态仍是“已停用”，显示“尚未重新启用”和“稍后重试”；这些结果不冒充配置已经失效。
- Key 明确失效、本机凭据文件无法读取、服务商已移除、已验证模型被目录移除或不再兼容工具调用等配置性失败时，唯一终态转为“需要处理”。页面按原因提供“替换 Key”“迁移或移除模型”或“添加新服务商并迁移”，不再显示普通“重试启用”。用户从该入口完成修复、对修复后的全部已验证模型通过真实验证并安全保存后，直接进入“已就绪”，视为完成原来的启用意图，不要求再点一次“重新启用”；取消修复则保持“需要处理”。
- 所有模型验证通过但本地状态保存失败时，档案保持“已停用”，显示“验证已通过，但尚未重新启用”和不再调用服务商的“重试保存”。离开遵循 Provider 验证的迟到结果与未保存敏感数据规则。

#### 引用清单、迁移与结束继续能力

- 详情“引用”区按团队成员、AI 建队草稿、运行中任务、排队任务和可恢复会话分组，显示名称、当前模型、状态和可执行去向；只读历史不属于运行引用。
- 同档案模型迁移要求用户选择另一已验证模型。团队成员永久改绑新模型；AI 建队草稿和可恢复会话保留 Moebius 已保存内容、封存旧 Pi 外部会话，并明确建立新会话；排队任务停止并提供用新模型重新运行。迁移不改写更早尝试或静态历史。
- 服务商被支持目录移除时，用户先创建另一服务商的已就绪档案，再从原档案引用清单选择目标档案及其已验证模型。每一类引用都明确显示服务商发生变化；不得用“全部修复”静默把所有对象改到系统默认值。
- 团队成员的同一次迁移是原子批量修改，任一保存或重读失败都回滚本次所选成员。草稿和可恢复会话逐项迁移，每项先保存 Moebius 内容、封存旧 Pi 会话，再建立新会话；失败时保留原引用和重试入口，不出现已经迁移但无法继续的假成功。
- 运行中任务不能迁移或中途换服务商，必须先按真实结果结束。排队任务不自动改绑；停止后只提供用户明确触发的“用新配置重新运行”。
- 对 AI 建队草稿或可恢复会话，用户也可以选择“结束并保留历史”。确认后该对象变为只读，不再允许继续、重试或恢复，并解除对原档案或模型的运行引用；已有对话、文件结果和过程仍可阅读。

#### 删除档案

- 删除前执行完整引用检查。只要仍有团队成员、AI 建队草稿、运行中或排队任务、或可恢复会话引用，删除操作保持禁用并把用户带到对应引用分组；不得静默改回 Codex、其他 CLI 或另一 Provider。
- 无运行引用时，“删除档案”打开危险确认层，明确显示服务商、档案名称和删除后 Key 无法恢复。用户输入档案名称后才能确认；取消返回原详情。
- 删除完整成功后，档案从设置列表、首次引导和所有 Provider 选择入口消失，且不能再发起新运行。删除未完成时恢复操作前的可见档案状态，显示“未删除档案”和可重试入口；用户不需要判断底层凭据或元数据完成了哪一步。
- 删除后，与该档案已无运行关系的静态历史继续可读。只要旧会话仍允许继续、重试或恢复，它就必须作为引用阻止删除。

### Moebius 的技能

“Moebius 的技能”管的是**应用自己发起的后台工作所依据的规则**，不是团队成员在会话里使用的能力。这里的每一个技能都不属于任何团队、任何成员、任何一次对话。首期只有一个技能：给对话起标题。完整的记录、学习、回放与回退规则见[Agent 技能进化](../flows/agent-skill-evolution.md)，本页只承接界面上的区域、控件、状态与文案。

本页用户可见文字统一使用“对话”，不使用“会话”。

#### 技能列表

- 分类说明固定为：“Moebius 会替你做几件小事，比如给新对话起标题。这里能看清它现在是怎么做的，也能改。”第一句划清与团队成员能力的界限——“技能”在本产品里已有另一个含义，不划界用户会以为走错了地方。
- 每个技能行显示显示名、一句它管什么、最近一次变化的时间。给对话起标题的副行固定为：“你发出第一条消息，它就自己起一个。”
- 从没变过的技能，时间位置显示“还是原样”，不显示“0 次”“从未进化”这类说法。
- 技能存在异常时，行尾不写“需要注意”这种没有信息量的词，直接说事：“正在用原始版本”或“暂时不会自己学”，与详情页异常带同源同措辞。
- **列表层没有空状态**：内置技能随软件发行，至少有一条，用户删不掉也装不进新的。这是不适用，不是遗漏。
- 首期只有一个技能，列表不提供搜索、筛选、排序或批量操作。

#### 技能详情 · 身份说明

- 位于详情第一位，只读，内容来自技能自身的身份说明，用户与应用都不能在这里改。
- 给对话起标题的身份说明固定为三段：

  > 这个技能管什么
  >
  > 新对话发出第一条消息后，Moebius 会自己给它起个标题。
  >
  > 你要是把标题改掉了，它会把这次改动记下来；攒够一批就回头读一遍，学着起得更接近你的习惯。
  >
  > 它能学的只有“标题怎么起更好”这一件事。要不要起标题、什么时候起，它改不了。

- 第二段是**告知**：用户在侧边栏重命名对话时对记录零感知，这里是产品中唯一能告诉他的位置，不得删减或弱化。第三段是**边界**：不写，用户就得自己猜这东西能自作主张到什么程度。
- 身份说明不显示版本号、内容指纹、文件路径或标准字段名。

#### 技能详情 · 异常带

- 位于详情第二位，有事才出现，无事时整区不占位。放在第二位是因为“你写的那份没生效”这类事实放在页面底部等于没告知。
- 正在用保底版本：

  > 这个技能现在用的是软件自带的原始版本——你保存的那份读不出来了。标题照常会起，但你自己写的那些暂时没生效。

- 默认 Agent 不可用（未配置、凭据失效或调用失败）：

  > 暂时找不到可用的 Agent，这个技能这阵子不会自己学。你改标题它照样记着，等能用了再一起看。

- 观察窗显示改名反而变多时，警示同样出现在异常带：

  > 这次改动之后，你改标题的次数反而变多了。可能它这次学偏了，要不要退回上一版？

- 三句共用同一个句式：**先说停的是什么，再说没停的是什么**。“关掉的是学、不是记”这条区分用户看不见机制，只能靠文案传达。
- 效果警示可点击，直接展开并滚动到对应那条记录；退回入口同时出现在警示旁边。出问题的进化未必是最新一条，沉在列表里等于没告知。
- 异常带不显示原始系统错误、堆栈、路径或内部枚举，不要求用户自行判断原因。

#### 技能详情 · 最近变化

- 一行摘要加时间与作者，让用户不展开完整内容也知道最近发生了什么。作者只显示“你”或“Moebius”。
- 格式示例：“上次变化：3 天前 · Moebius 自己改的 / 起标题时更看重第一句话在说的事”。
- 从没变过时显示：“还是原样。Moebius 没有自己改过，你也没改过。”
- 摘要写不出来时，这一行用中性说明占位，不影响记录、编辑或退回。

#### 技能详情 · 条目编辑器

- 区标题“它现在的规则”，说明固定为：“这些是 Moebius 起标题时照着做的规则。你可以直接改，存下就生效——和它自己改的一样能查、能退回。”
- 编辑对象是技能的规则条目，不是一段散文；用户的每一次保存与 Moebius 自己的改动共用同一套留痕、来历与回退。
- 保存中、保存失败与重试沿用本页既有的反馈方式，不新造第二套控件语言。
- 内容被改到解析不出条目时不静默丢弃，原位显示：“这份内容现在读不出规则来。你写的原文一个字没动，接着改就行，也可以退回上一版。”先说“没丢”再说“怎么办”——用户是在不顺的时候读这句话。
- 编辑器不显示逐行对比、版本号或内容指纹。技能条目是自然语言写的规则，不是代码。

#### 技能详情 · 自动学习开关

- 位于条目编辑器之后、记录区之前，作为记录区的区头控件。**不放在技能列表层**：关掉是有后果的动作，应当发生在用户看过记录之后，而不是在他还不知道这个技能改过什么的时候。
- 标签“自动学习”，说明“让 Moebius 读你改过的标题，自己调整上面的规则”。默认开启，按技能保留，跨关闭设置与应用重启保持用户最后一次选择。
- 关闭后不再触发学习与写回，但配对记录继续产生、继续可查。关闭状态下记录区顶部显示：

  > 你关掉了自动学习，Moebius 不会再自己改这个技能。你改标题它还是记着，在下面随时能查。

- 这条说明不进异常带——用户自己关的不是异常。

#### 技能详情 · 记录区

- 两个互斥视图，标签用动作不用名词：“它改过什么”与“你改过的标题”。默认显示前者。切换视图不改变滚动位置，也不清空已展开的条目。
- “它改过什么”按时间倒序列出三类记录，**三类长得一样重要**。只显示成功的那些，用户会以为它每次出手都改得动。
  - 生效的一次：“3 天前 · 起标题时更看重第一句话在说的事 / 依据你改过的 4 次标题；另有 2 次它判断是话题变了，没采信”，附“看这 6 次”与“退回这次改动”。被判定未采信的那几条必须一并可查，不是只列采信的。
  - 试过没通过的一次：“5 天前 · 试着改了一次，没生效 / 它拿新规则重新给这 4 段对话起了一遍标题，没有比原来更接近你当初改成的那个，就放弃了”，附“看这 4 次”。
  - 读完没找出规律的一次：“5 天前 · 读了 4 次改名，没找出共同的规律，这次没改”，附“看这 4 次”。
- 退回确认层内容固定为：“退回后，这个技能回到这次改动之前的样子。退回本身也会记一条，你随时能再退回来。”
- **两处空状态是常态而不是边缘情况**，大多数用户的技能一次都没进化过。
  - 已有改名记录时：

    > 这个技能还是原样，Moebius 没有自己改过。
    > 你改过 6 次标题，它都记下了；再攒够 4 次，它会回头读一遍，看能不能学着起得更好。
    > 到那时改了什么、凭什么改，都会列在这里，你随时可以退回去。

  - 一条记录都没有时：

    > 这个技能还是原样。
    > 以后你要是改了 Moebius 起的标题，它会记下来；攒够一批之后回头看看，学着起得更好。改了什么都会列在这里。

  - 两处的次数由运行时事实填入，页面不写死具体数值。**不说“0 次”**——说了会让用户以为自己漏做了什么。
- “你改过的标题”按时间倒序列出全部配对记录，每条显示时间、它起的标题、用户改成的标题，例如“3 天前 / 它起的：季度预算讨论 / 你改成：Q3 预算 · 待定”。空态显示：“这里还是空的。以后你改了 Moebius 起的标题，每一次都会记在这里。”
- 记录不合并、不压缩、不设保留期限；已经被提炼过的配对记录仍然留在这个视图里。

### 关于

- 顶部品牌区使用产品品牌母版派生的 Moebius 图标、产品名和一句话定位“把你在用的 AI，变成一个会自己推进的团队。”，让用户确认正在查看的应用身份；品牌区不承担营销落地页的完整介绍。
- 版本信息显示当前安装版本，并明确正式适用平台是 Apple Silicon Mac。版本号保持可选择，并提供显式“复制版本信息”操作；复制内容使用 `Moebius <版本号> · Apple Silicon Mac`，不包含内部构建路径、提交标识或本机环境信息。
- 更新区把当前版本、自动更新状态、手动检查动作与最近一次结果放在同一信息组中。应用启动后自动检查，运行期间每 4 小时自动检查一次，设备唤醒后补检一次；用户也可手动“立即检查”。全部时机共用同一进行中闸门，不得重复发起，也不打断已经在进行的下载。检测节奏只改变本区状态更新的频率，不改变展示方式。
- 若当前已经是最新正式版本，明确显示“已是最新版”；若存在更新，显示最新版本号并显示后台下载状态与进度；若下载完成并校验通过，显示“已准备好”和“重启并安装”，用户对该版本选择过“跳过此版本”时在同一行补一句说明该决定的文案并保留安装动作；若检查或下载失败，保留当前版本信息，显示可理解的失败说明和重试或重新下载入口。
- 下载完成前不显示安装操作；下载完成后，关于更新区显示“重启并安装”，侧边栏“设置”右侧同时显示独立的“安装更新”。两个入口进入同一任务保护确认，不直接执行安装。
- 底部公开链接提供“查看发布记录”“反馈问题”“开源仓库”。“查看发布记录”进入全部正式发布记录列表，“反馈问题”进入 GitHub 新建 Issue 页面并预填当前 Moebius 版本与 Apple Silicon Mac，“开源仓库”进入仓库首页；三者均明确表现为外部去向，通过系统浏览器打开，不在设置弹窗内嵌网页。

### 语言覆盖范围

- 切换覆盖整个桌面客户端中由 Moebius 提供的静态界面文案，包括页面标题、导航、按钮、菜单、表单标签、占位提示、空态、状态说明、确认与错误提示、悬停提示和可访问名称。
- 同一次界面中不得因组件遗漏而混用简体中文和英文；新增的产品静态文案也必须同时具备两种语言版本后才能进入交付。
- 用户输入、Agent 回复、项目名、对话中引用的文件内容和本地路径保持原文，不随界面语言被翻译或改写。

## 操作与反馈

### 打开与关闭

- 点击 Sidebar 的“设置”后，弹窗在当前主工作区上方打开。
- 用户可以点击标题区关闭按钮或按 `Esc` 关闭；关闭只退出设置，不撤销已经成功保存的语言或任务提醒选择。
- 弹窗打开后，键盘焦点进入弹窗；关闭后，焦点回到触发设置的入口。
- 为避免用户在调整设置时误关闭，点击背景遮罩不关闭弹窗。
- 关闭设置弹窗不取消已经开始的语言保存、更新检查、更新下载，以及已经确认提交的 Provider 引用迁移或无引用删除。相关进行中状态与最终结果不依赖弹窗保持打开，重新打开时恢复同一操作而不是重复创建。任务提醒偏好保存是例外：它在前台短事务结束前暂时阻止关闭、切换分类和重复切换，不能让用户带着未知生效值离开。
- 未保存的 Provider 表单和真实验证是例外：切换分类、关闭设置或按 `Esc` 时，若存在新 Key、模型草稿或进行中的验证，先提示尚未保存以及服务商可能已经处理并计费。选择离开后停止本地等待、忽略迟到结果、丢弃未保存 Key，只保留可重新选择的非敏感字段；旧有效档案不受影响。
- 前两项能力验证已经通过而本地安全保存仍在进行时，离开确认提供“返回等待”和“放弃并关闭”。选择放弃后，应用先让本地事务完成或回滚到无半成品状态，再关闭设置；不得在凭据和元数据状态未知时直接消失。
- 操作尚未结束时重新打开设置，必须恢复原进行中状态并继续阻止重复发起；操作已经结束时重新打开，必须显示该操作在当前应用会话中的最近一次结果。
- 弹窗关闭后语言操作才结束时，当前工作区显示一次不抢焦点的轻量通知并指向“常规”。更新检查、下载和下载完成不显示这类轻量通知；用户通过全局提醒弹窗、侧边栏安装按钮或重新打开“关于”了解状态。通知关闭或忽略不丢失设置内保留的语言结果。
- 若语言保存成功，整个桌面客户端仍按既定规则切换到新语言，工作区通知使用新语言；若保存失败，客户端保持原语言并在工作区通知中提供重新打开设置的入口。
- 若弹窗始终打开，终态只在弹窗内反馈，不重复显示工作区通知。

### 管理 AI 服务商

- 打开“AI 服务商”默认显示列表；选中档案后进入详情，“返回列表”保留列表滚动位置、筛选和当前应用会话内的操作结果。
- 新增或编辑表单中的“取消”遵循与关闭设置相同的未保存 Key 规则。仅修改非敏感名称且尚未提交时可直接放弃；替换 Key、验证模型或保存凭据时必须经过离开确认。
- 所有会产生服务商请求的动作都由用户明确触发。验证、Key 轮换和模型验证失败后不无限自动重试；“重试验证”会再次产生用量，“重试保存”只重试本地保存并明确标注不再调用服务商。
- 重命名、设置默认模型、停用、重新启用、模型移除、引用迁移和删除都使用单次提交状态，进行中禁止重复点击。成功后只更新受影响档案与引用，失败时保留操作前的可见状态和可重试说明。
- 已确认的迁移或删除在设置关闭后继续；完成时工作区显示一次不抢焦点的轻量通知并指向“AI 服务商”。
- 应用退出或崩溃会中断尚未完成的迁移或删除。重开后只有两个可观察结果：操作已完整提交时显示真实成功终态；否则恢复未提交对象的操作前状态，并在原档案详情顶部显示“上次操作未完成”。团队成员的原子批量迁移若未完整提交，整批恢复原配置；删除若未完整提交，档案恢复到删除前的列表和详情状态。两者都提供“重试”和“查看影响”。
- 草稿、排队任务和可恢复会话按对象逐项提交；重启后页面明确分组显示“已完成 n 项 / 未完成 n 项”。已完整迁移的对象保留新配置，未完成对象恢复原引用并显示重试，不能重新执行已完成项，也不能把整批笼统显示为成功或失败。
- 详情中的团队、草稿、任务和会话名称可点击前往对应产品位置；离开设置前保留当前详情位置，用户返回设置时仍能看见原档案与最近操作结果。

### 管理 Moebius 的技能

- 打开“Moebius 的技能”默认显示技能列表；选中技能后在同一内容区进入详情，“返回”回到列表并保留滚动位置与本次应用会话内的操作结果。
- 条目编辑器保存成功即刻生效，下一次自动起标题就用新规则；不需要额外的“应用”动作，也不需要重启应用。
- 切换自动学习开关是一次单独提交，进行中禁止重复切换；成功后原位更新，失败时回到此前生效值并提供重试。关闭不影响正在记录的配对事实。
- “退回这次改动”打开确认层；确认后技能回到该次改动之前的内容，记录区顶部新增一条署名为“你”的退回记录，用户停留在原位置而不是被弹回列表。退回本身可以再次退回。
- 点击异常带中的效果警示直接展开并滚动到对应那条记录，不要求用户自己在列表里找。
- 两个记录视图之间切换、展开某条记录的依据、退回确认的取消，都不改变滚动位置，也不重置另一视图已经产生的展开状态。
- 用户在这一分类中的任何操作都不改变当前项目、当前对话、未发送草稿与侧边栏状态。

### 切换语言

- 用户选择另一种语言后，无需额外点击“保存”或重启应用。
- 应用先把新选择保存到本地；保存成功后，再把设置弹窗和整个桌面客户端原子切换为新语言。正常本地写入下，用户感知为立即生效。
- 页面结构、当前任务和用户内容不因语言切换被重置；下次启动直接使用已保存语言。
- 重复选择当前语言不会产生额外提示或打断用户。
- 若新选择无法持久保存，应用保持此前已保存且当前生效的语言，显示可理解的失败提示，并允许用户重试；不得先切换再回退，也不得表现为已经保存但重启后悄然恢复旧语言。
- 用键盘选择语言后，保存期间焦点保留在所选语言控件；成功或失败只更新该设置组的状态与可访问通知，不把焦点移动到页面开头或关闭按钮。

### 选择默认 Agent

- 用户修改默认 Agent 的任一字段并保存后立即生效，不需要重启，也不影响任何团队成员或既有会话。
- 选项范围、联动规则、静态校验、Pi 档案空态与旧值保留完全复用 [Agent 团队页](./agent-teams.md)的运行配置规则，本页不定义第二套。
- 保存失败时保留用户选择、说明原因并允许重试，继续使用上一次已保存的配置，不静默回落到默认值。
- 修改默认 Agent 不追溯已经写好的变化说明，也不重新执行已经完成的合并。

### 管理任务提醒

- 用户切换总开关后，控件保持此前生效位置并显示“正在改为开启／关闭”，同时锁定本开关、分类切换、关闭按钮和 `Esc`，避免冲突提交或隐藏结果；其他内容保持可读。持久保存成功后才原子更新开关、Dock 与页面状态，并恢复所有入口。
- 本地保存必须在 3 秒内成功或进入失败；超时与写入失败都回到此前生效值，原位显示“通知设置未更改”和“重试”。失败终态形成后关闭与分类切换立即恢复，用户不会在未知值下继续使用。
- 保存中再次点击、按键切换或重复事件不创建第二次提交。应用在保存完成前异常退出时，重启只读取最后完整保存的值，不恢复半成品或根据最后一次点击猜测生效值。
- 关闭总开关立即隐藏 Dock 角标，但不改变侧边栏当前唯一状态点；重新开启后只从当前可见的红点和蓝点重建数字。
- 开关开启且权限尚未决定时，页面不因打开设置自动请求权限；用户可单独点击“允许系统通知”。权限请求进行中禁止重复触发，系统返回后焦点回到该设置组并通过可访问状态通知读出结果。
- 权限被拒绝、系统设置打开失败或用户从系统设置返回但仍未授权时，页面继续显示真实“已拒绝”状态；这些失败不关闭总开关、不删除提醒，也不影响用户继续使用设置或任务。
- 权限已允许但暂时无法发送系统通知时，页面同时显示“已允许”和“暂时无法发送系统通知”，列明系统通知／声音可能不可用而 Dock、侧边栏仍可用；用户可以重新检查、反馈问题、关闭总开关或继续其他设置。
- 总开关或权限状态变化不产生任务提醒，也不使用工作区右下角轻量提示自我提醒；结果始终在当前设置组中显示。

### 更新检查、下载与安装

- 应用启动后、运行期间每 4 小时、设备唤醒后自动检查正式 macOS 更新；用户也可以点击“立即检查”。按钮进入检查中状态并给出持续可见的反馈；同一次检查结束前不得重复发起。已处于“有新版本”“下载中”“已准备好”“安装中”时，自动检查直接跳过。
- 一次更新检查必须在 15 秒内进入“已是最新版”“有新版本”或“检查失败”之一；达到上限仍没有结果即按检查失败处理并允许重试，不得永久停在检查中。
- 检查只比较当前安装版本与最新正式发布版本；发现更新后自动在后台下载并校验安装包，不自动安装、不自动重启，也不打开浏览器。
- 已是最新版时，更新区原地显示成功结果，用户可以继续查看关于信息或关闭设置。
- 有新版本时，更新区显示最新版本号和下载进度；下载中不得显示安装操作。安装包完整下载并校验通过后，更新区显示“已准备好”和“重启并安装”，侧边栏底部设置入口右侧同步出现独立的“安装更新”按钮。用户选择过“跳过此版本”时保留两个安装入口。
- 检查或下载失败时，应用不得把未知状态表述为“已是最新版”；应显示简短、可理解的失败说明和“重试”或“重新下载”，同时保留当前安装版本，并保留浏览器 Release 页面作为失败兜底。
- 点击关于区“重启并安装”或侧边栏“安装更新”后，始终先显示同一确认弹窗。没有运行任务时，弹窗说明应用将关闭、安装更新并重新打开，提供“取消”和“重启并安装”。
- 有 Agent、AI 建队或 CLI 安装任务运行时，安装流程显示独立的“重启安装”弹窗，明确列出任务数量和停止影响，提供“继续工作”和“停止任务并重启安装”。选择前者只关闭弹窗并保留安装按钮；选择后者才停止任务、等待资源回收并执行安装。
- 安装确认期间按钮进入“正在准备安装…”并禁止重复点击；任务停止失败或安装失败时 Moebius 保持打开，并在当前界面立即显示应用内失败弹窗，准确说明任务是否仍在运行、安装是否已经开始，提供稍后处理与重试。失败弹窗的重试重新读取当前任务数并进入同一保护链路。已下载包仍按可重试状态呈现。
- “查看发布记录”“反馈问题”和“开源仓库”不依赖检查更新成功即可使用。外部页面无法打开时，在当前弹窗中给出失败反馈，不关闭设置。
- 检查按钮在检查中和终态都保持同一焦点位置，不因结果出现而被替换；结果通过可访问状态通知读出。“重试”“重新下载”和就绪后的“重启并安装”作为同一更新组中的后续操作出现，用户按正常 Tab 顺序即可到达，系统不得自动把焦点抢到新操作上。关于区与侧栏的安装操作进入同一确认流程。

### 复制版本与公开链接

- 点击“复制版本信息”后，把当前显示的产品名、版本和适用平台写入系统剪贴板，并在原位置显示可访问的成功反馈；复制失败时保留原内容，显示失败反馈并允许重试。
- “反馈问题”打开 GitHub 新建 Issue 页面时，预填内容必须包含与页面当前显示一致的产品名、版本和适用平台；不预填用户对话、项目名、本地路径或其他工作区内容。
- 打开任何外部页面都不关闭设置弹窗。系统浏览器打开失败时，焦点留在原操作，当前弹窗原地显示失败反馈。

## 弹层与危险操作

- 设置本身是主工作区上方的模态弹窗；打开时背景不接受鼠标或键盘操作。
- 弹窗内若将来出现需要二次确认的操作，确认层位于设置弹窗之上，关闭确认层后回到原设置位置。
- 语言切换可逆，不需要危险操作确认。
- Provider 停用会阻止新运行，必须在确认层中显示受影响的团队成员、草稿、排队任务和可恢复会话数量；运行中请求会按真实结果结束。重新启用不需要“危险影响”确认，但必须显示逐模型真实验证与少量用量确认；凭据或模型异常时先进入修复，不得直接启用。
- 模型移除、结束草稿或会话继续能力、跨服务商迁移和删除档案都使用设置弹窗之上的确认层。确认层必须点名来源与目标、受影响对象和不可恢复影响；模型或档案仍有阻塞引用时不能以确认层绕过检查。
- 删除档案要求输入档案名称；“结束并保留历史”必须说明历史仍可阅读但不能继续、重试或恢复。取消确认回到原详情、引用分组和滚动位置。
- 检查更新与后台下载不打开浏览器、不安装、不重启；打开发布页、反馈页和仓库不会修改本地数据，不需要确认层。
- 安装更新会关闭并重新打开应用，属于危险操作，必须使用确认层；有运行任务时确认层必须说明将停止任务，任务记录保留。

## 响应式与窗口行为

- 弹窗在桌面常规宽度下居中显示，宽度足以让分类与内容形成清楚的左右层级，但不遮蔽到让用户无法辨认原工作区。
- 窗口变窄时，分类导航移到内容上方；不得压缩到截断当前语言、选项名称、版本号、更新结果或关闭入口。
- 内容超出可用高度时只滚动设置内容，标题与关闭入口保持可达。
- 用户缩放或移动窗口时，当前分类、语言选择、更新结果和滚动位置保持稳定。
- “AI 服务商”在常规宽度下可以在同一内容区用列表与详情形成清楚层级；窄窗口下必须改成“列表 → 详情”的纵向钻取，不并排压缩字段。返回列表时保留滚动位置。
- Provider 名称、模型名和引用对象名允许换行或省略显示并提供完整可访问名称；状态、危险说明、主操作和 Key 不回显规则不得因窗口变窄而被截断或隐藏。
- 迁移预览和引用清单过长时只滚动内容区；来源、目标、确认操作和关闭入口保持可达，不产生页面级横向滚动。
- “Moebius 的技能”同样在常规宽度下用列表与详情形成层级，窄窗口下改成“列表 → 详情”的纵向钻取。异常带、自动学习开关状态、退回入口与空状态说明不得因窗口变窄被截断或折叠隐藏；条目编辑器可以缩短可见高度但必须保持可滚动与可保存。

## 待讨论

以下四项是「Moebius 的技能」增量中由产品侧自行选定、尚未经用户确认的判断。四项都易于推翻，改动范围已注明。

- **分类名「Moebius 的技能」**：不叫「Agent 技能」，是因为本页的 Agent 已指向团队成员与默认 Agent，同名会让用户以为这里能配团队成员的能力。推翻只影响导航标签与本节标题。
- **技能显示名「给对话起标题」**：用动作而不是名词，用户不必先理解“技能”是什么就知道它管什么。推翻只影响列表行与详情标题。
- **本页写完整能力、分期由「当前交付范围」承接**：依据 [产品文档约定](../AGENTS.md)“不以短期实现成本反向限制需求定义”。[Agent 技能进化](../flows/agent-skill-evolution.md)明确第一棒（只记事实、不学习）可独立上线，届时本页可先只交付技能列表、身份说明与“你改过的标题”视图，其余模块随后续棒次到位。哪些模块进第一批交付尚未拍板。
- **自动学习开关按每技能一个、放在详情层**：流程 PRD 的措辞是“该技能的自动学习”，按每技能理解。若将来技能变多且用户希望一次全关，需要在列表层另加总开关，那是新的产品判断。

技能相关的全部阈值（触发学习的记录条数、单次样本上限、最小间隔、观察窗长度、正文长度上限）由 [Agent 技能进化](../flows/agent-skill-evolution.md)统一登记，页面只呈现运行时事实，不写死数值。

## 关联流程

- 从 Sidebar 打开设置、切换语言或检查更新、关闭并继续当前任务，都是本页面内完成的单弹窗旅程，不另建跨页面流程。
- AI 服务商的新增、验证、编辑、引用检查和删除在设置弹窗内完成；从引用清单打开团队、草稿、任务或会话时进入对应既有页面，返回设置后恢复原档案详情。
- 任务提醒开关、权限状态和系统设置恢复入口属于常规分类；通知触发、声音、Dock 聚合与点击回流遵循[任务提醒与回流](../flows/state-change-delivery.md)，设置不复制终局判断。
- 服务商或模型迁移在设置中发起，但草稿与会话迁移完成后仍由各自页面呈现重建后的 Pi 运行；设置不复制对话或任务页面。
- 更新失败时的“浏览器下载”和三个公开链接只把用户交给系统浏览器，不构成 Moebius 内部跨页面流程；正常检查、后台下载和安装确认留在 Moebius 内部完成。
- [Agent 进化](../flows/agent-evolution.md)：本页只负责让用户选择默认 Agent 并说明它影响什么；变化说明的撰写、官方内容的自动合并、结果呈现与撤销都不在设置中发生。
- [Agent 技能进化](../flows/agent-skill-evolution.md)：配对记录的产生、学习门槛、事前回放、事后观察窗与写回判断都在流程中定义，设置只呈现结果并承接编辑、关闭与退回。用户改名发生在[主页面侧边栏](./main-left-sidebar.md)，该页规则不因本分类改变。

## 指标与验收

### 产品指标

- **任务闭环：**应用能在启动后自动检查并后台下载更新，用户也可立即手动检查；用户在不离开 Moebius 的前提下看到进度，包就绪后可从关于区或侧边栏经同一确认完成安装并重新打开。
- **上下文保持：**打开、切换分类、切换语言、管理任务提醒与权限、管理 Provider、检查更新、复制版本信息和关闭设置均不改变当前项目、对话、未发送输入、滚动位置与侧边栏状态。
- **通知控制可信：**总开关持久值、系统真实权限和实际可用通道始终一致可解释；关闭后不得继续产生新任务提醒或 Dock，权限被拒绝时不得伪装成总开关已经关闭或权限已经恢复。
- **结果可信：**每次检查在 15 秒内收敛到三个检查终态之一，下载只在完整包校验通过后进入就绪；失败与超时不得显示成“已是最新版”，同一进行中操作不得重复创建。
- **全键盘可达：**从设置入口到分类、语言、任务提醒与权限恢复、Provider 表单与确认、更新、复制和外部操作均有连续的键盘路径；异步状态更新和工作区通知不抢走当前焦点。
- **Provider 管理漏斗：**记录进入“AI 服务商”、开始新增、开始验证、两项能力通过、安全保存成功、失败、取消和重试保存的漏斗，按服务商与安全失败类别聚合，不采集 Key、请求正文或项目内容。
- **生命周期恢复：**记录“需要处理”档案进入修复、恢复就绪、迁移引用、结束继续能力与放弃处理的漏斗，以及各引用类别的失败和重试结果。
- **配置复用：**记录同一档案被不同团队成员选择的数量分布，以及是否出现要求按成员重新输入同一 Key 的异常路径。
- **危险操作可信：**记录停用、模型移除和删除确认的进入、受引用阻止、取消、成功与失败；删除失败和迁移失败不得被计为成功。
- **可查率：**用户能否在不读完整技能内容的情况下说出最近一次自动改动是什么。这是“Moebius 的技能”的首要指标，高于用户是否真的编辑过条目。
- **退回率：**自动进化被用户退回的比例。持续偏高说明该先修学习质量，而不是在写回前加一道用户确认。
- **告知有效性：**用户是否知道自己改过的对话标题会被记录。身份说明是唯一告知位置，不被读到等于没告知。
- **异常可解释：**正在用保底版、默认 Agent 不可用、效果警示三种状态出现时，用户能说出停的是什么、没停的是什么。

### 验收清单

1. 从 Sidebar 点击“设置”会在当前工作区上方打开居中的设置弹窗，不进入独立设置页面。
2. 弹窗默认打开“常规”，分类导航只显示已经可用的“常规”“AI 服务商”和“关于”，并能明确看到当前语言、“简体中文”“English”、任务提醒总开关和系统权限状态。
3. 没有保存过语言选择时，应用使用简体中文；选择另一语言并在本地保存成功后，设置弹窗和整个桌面客户端的产品静态文案立即一致切换。
4. 关闭设置或重启应用后，语言选择仍然保留，不需要再次设置。
5. 切换语言不会改变当前项目、当前对话、Sidebar 状态、未发送草稿或用户与 Agent 已产生内容。
6. 用户输入、Agent 回复、项目名、文件内容和本地路径保持原文。
7. 错误、空态、提示、菜单、悬停提示和可访问名称与当前界面语言一致，不出现可见的中英混用。
8. 新语言只在本地保存成功后全局生效；保存失败时旧语言仍处于选中和生效状态，同一语言设置组显示本地化失败消息与重试操作。
9. 弹窗只显示一个“设置”标题；右侧内容不重复“常规”或“关于”标题。两个语言选项位于同一外框内并以行分隔，任务提醒使用相邻但独立的紧凑设置组；导航中没有禁用分类、占位分类或为未来内容预留的空白区域。
10. “关于”显示统一品牌图标、Moebius、一句话定位、当前安装版本、Apple Silicon Mac、检查更新以及“查看发布记录”“反馈问题”“开源仓库”。
11. 应用启动后自动检查正式 macOS 更新；检查期间设置内显示持续反馈，不能重复发起，并在 15 秒内进入已是最新版、有新版本或检查失败。
12. 检查到新版本后自动在后台下载；设置内显示版本和进度，下载完成并校验通过后显示“已准备好”和“重启并安装”，下载中不显示安装动作。
13. 检查或下载失败不得伪装成“已是最新版”；当前版本保持可见，同一更新组显示失败消息与重试或重新下载，侧边栏不出现安装按钮。
14. 下载包已准备好时，设置“关于”的更新状态附近显示“重启并安装”，侧边栏底部“设置”右侧同时出现独立的“安装更新”；没有就绪包时两个入口都不存在，且不通过右下角通知提示下载完成。
15. 点击关于区或侧边栏的安装入口先显示同一确认弹窗；无运行任务时提供“取消 / 重启并安装”，有运行任务时显示独立的重启安装弹窗并提供“继续工作 / 停止任务并重启安装”。
16. 取消安装确认不改变已下载包；确认后按钮进入准备状态。任务停止失败或安装失败时应用保持打开，当前界面立即显示应用内失败弹窗并准确说明任务与安装结果；About 保留明确的“安装失败”和重试入口，不得显示为“检查失败”或默认归因于网络。
17. 正常退出与重启安装使用同一任务保护与资源回收边界，但显示和文案属于两个独立弹窗；没有运行任务时 `Command + Q` 不新增确认弹窗并直接安全退出，有运行任务时才显示退出保护；一次按键即可完成退出，不要求再次按键。
18. “查看发布记录”进入正式发布记录列表，“反馈问题”进入预填当前版本与 Apple Silicon Mac 的 GitHub 新建 Issue 页面，“开源仓库”进入仓库首页；三者不依赖更新检查结果即可使用。打开失败时设置弹窗保留原位置并反馈失败。
19. 不显示禁用的未来分类或“即将推出”占位。
20. 当前版本文本可选择；点击“复制版本信息”会复制 `Moebius <版本号> · Apple Silicon Mac` 并给出可访问反馈，复制失败时原位置显示失败与重试。
21. 语言保存完成后仍按既有规则显示一次轻量通知；更新检查、下载完成和下载失败不显示通知。重新打开关于分类会恢复当前应用会话中的更新状态，且不会创建重复操作。
22. 已下载并校验通过的更新包在普通重启后不重新下载完整包；关于状态恢复为“已准备好”并显示“重启并安装”，侧边栏“安装更新”同时重新出现。
23. 用键盘触发语言保存、任务提醒或权限操作、更新检查或从关于区、侧边栏进入安装确认后，焦点留在可预期控件；终态通过可访问状态通知读出，下载、重试和安装操作可按正常 Tab 顺序到达，系统不自动抢焦点。
24. 在 `900 × 640` 的内容视口中，分类导航位于内容左侧，“常规”“AI 服务商”和“关于”的主要内容无需页面内部水平滚动即可完整操作；常规中的语言、通知开关、权限状态与恢复入口都可到达。
25. 在 `560 × 640` 的窄内容视口中，分类导航移动到内容上方；语言名称、通知开关与权限恢复入口、Provider 状态与主操作、版本号、更新结果和关闭入口不被截断，弹窗不产生水平滚动。
26. 在 `900 × 480` 的短内容视口中，标题与关闭入口保持可见，只有设置内容区纵向滚动；滚动前后当前分类、语言选择、更新结果和焦点目标保持不变。
27. 仅使用键盘即可打开设置、切换“常规 / AI 服务商 / 关于”、切换语言、切换任务提醒、请求权限或打开系统设置、管理 Provider 表单与确认层、检查更新、复制版本信息、使用结果与公开链接操作、关闭弹窗，并在关闭后回到设置入口。
28. “AI 服务商”空态提供“添加服务商”；已有档案时，每行显示服务商、唯一档案名称、默认模型、有效状态、最近验证和团队成员引用数。页面任何位置都不显示完整 Key、Base URL 或以 Key 尾号代替档案身份。
29. 新增档案只能从明确目录选择服务商和模型，至少可选择 DeepSeek；用户只填写档案名称、API Key 和目录内模型。验证前页面说明极少量用量、验证不读取项目，以及真实任务会把必要项目内容、附件和工具结果发送给所选服务商。
30. “验证并保存”依次呈现模型回复、受控工具调用和本地安全保存。前两项通过但保存失败时，列表不出现新档案，页面明确显示“尚未创建档案”并提供不产生额外服务商用量的“重试保存”；验证失败保留当前表单与 Key 输入，离开后丢弃未保存 Key。
31. 同一服务商可以创建多个唯一命名档案；服务商身份创建后不可编辑。重命名失败保留旧名称，修改默认模型只影响未来选择时的预选，不改变既有成员和会话配置。手动移除默认模型前必须先选择另一可用模型并一起保存；默认模型被目录下架时显示“需设置默认模型”，不静默代选，用户保存新默认值前的新绑定必须明确选择模型。
32. 新模型只有在分别显示模型回复与工具调用通过并安全保存后，才进入“已验证模型”集合。Key 轮换确认层先显示将验证的模型数量、逐项模型及每个模型都会产生少量用量；确认后逐项显示结果。任一失败时页面显示轮换未生效，旧有效版本和全部旧模型继续可用，不能出现部分模型切到新 Key。
33. 档案只显示“已就绪”“需要处理”或“已停用”，验证和保存作为叠加活动。Key 失效、凭据不可读、服务商被移除或无可用模型时进入“需要处理”并停止新绑定和新运行；一次限流、额度暂时不足或短暂服务失败不会永久撤销“已就绪”。
34. 停用确认显示受影响引用数量；确认后新绑定、新建队和未启动运行均被阻止，已有引用仍在详情中可见，运行中请求按真实结果结束。重新启用确认层显示将验证的模型数量及逐项少量用量；确认后逐模型显示模型回复、工具调用和保存状态，全部通过才恢复“已就绪”。取消、离开、限流、额度、网络或服务暂不可用时保持“已停用”并显示“稍后重试”；Key 失效、凭据不可读、服务商或模型下架、模型不再兼容时转为“需要处理”并只显示匹配的修复入口。修复后全部模型验证并保存成功会直接进入“已就绪”，不要求再次启用；只有本地保存失败时保持“已停用”并提供不产生额外用量的“重试保存”。
35. 移除已验证模型前，页面按团队成员、AI 建队草稿、运行中或排队任务和可恢复会话列出引用。存在任何引用时移除被阻止；迁移到同档案另一已验证模型或结束相应继续能力后，才允许再次移除。
36. 服务商下架时页面不提供原位修复，而要求先创建另一服务商的已就绪档案。迁移预览逐项显示来源、目标、模型和服务商变化；团队成员批量迁移要么全部成功、要么全部保持原配置，不出现部分改绑。
37. AI 建队草稿和可恢复会话迁移后保留原 Moebius 可见内容，并明确显示旧 Pi 上下文已封存、新 Pi 上下文已建立；失败项仍显示原引用和重试。运行中任务不在中途换服务商，排队任务停止后只有用户点击才能用新配置重新运行。
38. 对草稿或可恢复会话选择“结束并保留历史”时，确认层明确说明之后不能继续、重试或恢复；确认后已有对话、文件结果和过程仍可阅读，引用清单不再把它计为运行引用。
39. 只要仍有团队成员、草稿、运行中或排队任务、或可恢复会话引用，“删除档案”保持禁用并提供对应去向。零引用后删除必须输入档案名称确认；成功后档案从设置、首次引导和所有 Provider 选择入口消失，不能再发起运行，而既有静态历史仍可阅读。失败时档案恢复删除前状态，明确显示“未删除档案”并提供重试。
40. 切换分类、关闭设置或按 `Esc` 时，未保存 Key、模型草稿或进行中验证触发离开确认，并说明请求可能已计费；确认离开后迟到结果不能创建档案。已确认的迁移或删除在设置关闭后继续；若应用退出或崩溃，重开后完整提交的操作显示成功，未完整提交的团队批次或删除恢复操作前状态并显示“上次操作未完成”。逐项迁移明确列出已完成和未完成对象，只允许重试未完成项，不重复执行成功项。
41. 在 `560 × 640` 视口中，“AI 服务商”使用列表到详情的纵向钻取，返回列表保留滚动位置；长模型名、档案名和引用对象名不会遮挡状态、危险说明、主操作或关闭入口。
42. 首次安装且没有保存过通知偏好时，总开关默认开启；权限已允许时形成终局会发送系统通知和声音，并按侧边栏当前可见的红点与蓝点显示 Dock。关闭并重启 Moebius 后，最后保存的开关值保持。
43. 关闭总开关后形成新的已完成或正在等待你终局：不提交系统通知、不请求声音、Dock 保持隐藏，但时间线事实与侧边栏唯一状态点完整保留；重新开启后只通知未来终局，并按当前未归档对话中可见的红点与蓝点重建 Dock，不补发关闭期间通知。
44. 权限尚未决定时，打开设置不弹系统权限框；点击“允许系统通知”后才请求。允许、拒绝分别更新为真实状态；拒绝不把总开关改成关闭，总开关仍开启时 Dock 继续工作。
45. 权限已拒绝时点击“打开系统设置”，Moebius 不提前显示已恢复；分别在系统设置中允许、保持拒绝后返回应用，页面读取并显示对应真实状态。系统设置打开失败时原状态和焦点保留并可重试。
46. 权限说明在请求与恢复入口附近明确告知系统通知可能显示应用内对话名称，并说明锁屏预览、声音、静音和专注模式由 macOS 控制；页面不提供按声音、Dock、项目、对话或终局类别拆分的开关。
47. 切换总开关后，开关保持此前生效位置并显示目标值正在保存；同一开关、分类切换、关闭按钮和 `Esc` 暂时不可用，快速连续点击或按键只产生一次提交。保存必须在 3 秒内成功，成功后开关、Dock 和页面状态一次更新；超时或失败时全部保持操作前状态并显示“通知设置未更改”和重试，随后才允许关闭。
48. 在任务提醒偏好保存尚未完成时强制结束应用并重启：只恢复最后完整保存的开关值与对应 Dock 表现，不恢复半成品或最后一次未提交点击。总开关或权限状态变化本身不触发任务提醒，也不生成工作区右下角轻量提示。
49. 分别模拟系统不支持通知、通知通道初始化失败与任务提醒提交失败：设置显示“暂时无法发送系统通知”，权限仍保持真实的尚未决定、已允许或已拒绝状态，并明确系统通知／声音可能不可用而 Dock、侧边栏仍工作。用户可执行重新检查和反馈问题；重新检查不发送测试通知、不补发历史，恢复后清除异常，仍失败则保留说明。
50. macOS 因用户选择或系统策略返回不允许通知时统一显示“已拒绝”并提供系统设置入口，不显示含义不明的“受限”；打开系统设置失败时状态不变且可重试。权限已允许但提交失败时不得改成“已拒绝”，下一条新终局仍可重新尝试，失败的旧通知不延迟补发。
51. 常规分类在“语言”下方显示“默认 Agent”，用一句用户语言说明它用来记录 Agent 的每次变化、在软件更新时完成合并并学着把对话标题起得更合用户的意；没有已保存选择时直接显示内置「通用助手」的官方推荐配置，不显示空白或“未设置”。
52. 默认 Agent 使用与团队页成员运行配置相同的选择方式与校验；修改并保存后立即生效，不影响任何团队成员配置与既有会话，保存失败时保留选择、说明原因并可重试。

53. “Moebius 的技能”作为独立分类出现在导航中，进入后显示技能列表；选中技能在同一内容区进入详情，“返回”回到列表并保留滚动位置，全程不离开设置弹窗。
54. 技能详情按身份说明 → 异常带 → 最近变化 → 条目编辑器 → 自动学习开关 → 记录区的固定顺序呈现；异常带无事时不占位。
55. 身份说明只读，并明确告知用户改掉的标题会被记录，以及这个技能能学什么、不能学什么。
56. 技能正在使用保底版本或默认 Agent 不可用时，异常带出现在最近变化之前，说清停的是什么、没停的是什么，且不显示系统错误、路径或内部枚举。
57. 观察窗显示改名反而变多时，警示与退回入口同时出现；点击警示直接展开并滚动到对应那条记录，即使它不是最新一条。
58. 条目编辑器保存成功后下一次自动起标题即使用新规则，且这次编辑与 Moebius 自己的改动出现在同一份记录里，作者显示为“你”。
59. 技能内容被改到解析不出规则时，页面保留用户原文并提供继续编辑与退回上一版，不静默丢弃。
60. 关闭自动学习后不再产生新的自动改动，配对记录继续产生，“你改过的标题”视图继续可查，且记录区顶部说明关掉的是什么。
61. 记录区同等呈现生效、试过没通过、读完没找出规律三类记录；每条都能展开本次依据的改名记录，包括被判定为未采信的那几条。
62. 任意一次自动进化可以退回；退回后原位新增一条署名为“你”的记录，且该退回可以再次退回。
63. 技能一次都没进化过时，记录区说清当前状态与接下来会发生什么，次数来自运行时事实而不是写死的数值，且不出现“0 次”这类表述。
64. 技能列表不显示空状态；首期只有一个技能时不出现搜索、筛选或批量操作。
65. 常规分类的“默认 Agent”说明包含三项职责，其中第三项写明它会读用户改过的对话标题。
66. 本分类的任何操作都不改变当前项目、当前对话、未发送草稿与侧边栏状态。

### 非页面验收的实施投影

- 凭据文件的物理写入与删除、凭据和元数据的一致性、删除后的底层重读校验进入安全与存储 OpenSpec；页面只验收档案及选择入口的可见终态。
- Key 轮换、迁移和删除的事务边界、操作账本及崩溃恢复进入 desktop-shell / local-console OpenSpec；页面只验收“完整成功”或“恢复并明确未完成”的结果。
- 关闭设置后继续运行且需要用户持续监督的迁移或删除任务，实施时必须使用 Moebius 托管进程契约，不得派生不可监督的后台任务。
