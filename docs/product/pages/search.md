## 页面目标

全局搜索帮助用户跨活动项目找到普通主会话与 sidebar chat，并在需要时把已归档对话纳入搜索范围。搜索是已归档对话重新被发现、恢复并回到正确承载位置的入口。

## 用户场景

- 用户从侧边栏固定的“搜索”入口查找已有对话。
- 用户只想搜索当前仍显示在侧边栏中的对话。
- 用户需要查找已经归档的对话，并选择是否恢复它。
- 用户恢复一段已归档 sidebar chat，希望保留原来源关系；来源仍可用时回到并排现场，来源失效时仍能在主内容区继续。

## 入口与去向

- 从[主页面侧边栏](./main-left-sidebar.md)顶部“搜索”进入。
- 选择未归档普通主会话后，返回主页面并打开对应主内容时间线，同时恢复该会话自己的右侧栏标签现场；不得保留上一段主会话的标签组，也不得无条件清空目标会话已保存的标签。
- 选择未归档 sidebar chat 后，按[主页面侧边栏](./main-left-sidebar.md#选择对话)的组合路由返回：来源可用时显示来源主内容与右侧 sidebar chat，来源失效或没有来源时在主内容区打开 sidebar chat。
- 已归档对话不能在仍归档时直接打开；结果提供「恢复并打开」。普通主会话恢复后在主内容区打开并恢复自己的右侧栏标签现场；sidebar chat 恢复后保留来源关系，并按与未归档 sidebar chat 相同的路由打开。
- 关闭或取消搜索后，恢复进入搜索后仍然有效的最新主页面组合。通常就是进入前的选中会话、主内容承载会话、右侧会话、项目展开和侧边栏状态；如果来源在搜索期间失效，则消费侧边栏的即时迁移结果，不能伪造已经无效的旧组合。

## 区域与信息

- 搜索输入：接收用户查询。当前最小可验收命中字段是**完整会话标题**：查询与标题都先去除首尾空白、做 Unicode NFKC 规范化并转为小写；规范化后的标题包含规范化后的非空查询时命中。普通主会话、sidebar chat 与已归档会话使用完全相同的标题匹配，输入完整标题必须命中。正文、消息、路径、模糊纠错与多字段匹配继续开放。
- 「搜索／重试」按钮：规范化查询非空、输入法当前不在组合输入、且当前条件没有搜索正在执行时可用。已经因为查询或归档范围变化而失效的旧搜索即使仍在后台结束，也不算当前搜索，不得让按钮继续禁用。首次执行显示「搜索」；查询执行失败后在同一位置显示「重试」，保持完全相同的查询与归档范围。用户可以点击按钮，或在搜索输入框中按 Enter，发起同一个逻辑搜索请求。
- “包含已归档对话”开关：明确控制归档对话是否进入本次搜索范围。
- 结果列表：覆盖活动项目下用户发起的普通主会话与 sidebar chat，至少能区分项目、对话和归档状态；sidebar chat 沿用普通标题，不增加分析专用图标、前缀或来源摘要。完整分组与正文摘要仍待讨论。
- 「恢复并打开」入口：只对已归档对话出现。已归档结果行本身是不可激活的展示容器，点击标题或按 Enter 不执行打开或恢复；唯一动作是行内「恢复并打开」按钮。未归档结果行整体才是可激活的打开操作。
- 结果的可访问名称必须包含项目显示名称、完整会话标题和归档状态。未归档结果行读作「打开“{完整标题}”，项目“{项目名称}”，未归档」；恢复按钮读作「恢复并打开“{完整标题}”，项目“{项目名称}”，已归档」。不能只读标题或只读「恢复并打开」。

团队拆出的子任务不进入搜索结果，与它们不进入左侧栏的规则一致。已移除项目及其批量归档历史仍不在本版搜索与恢复范围内；本页不得借 sidebar chat 恢复绕过[主页面侧边栏](./main-left-sidebar.md#移除项目)的项目移除边界。

## 操作与反馈

- 初次进入、输入为空，或查询经去首尾空白与 NFKC 规范化后为空时，不发起搜索、不显示全部会话，也不显示“无结果”；内容区保持“输入会话标题开始搜索”的中性初始状态，「搜索」按钮不可用。
- 空查询状态下切换“包含已归档对话”只更新范围开关本身，不发起请求、不显示结果。用户随后输入有效查询并执行搜索时，按当时开关状态决定范围。
- 有效查询通过点击「搜索」或在输入框按 Enter 执行。输入法组合期间，Enter 只用于确认当前候选词，不发起搜索；组合结束后需要再次按 Enter 或点击「搜索」。组合期间「搜索」按钮不可用。
- 清空查询或改成全空白后立即回到中性初始状态，并清除旧结果与旧错误；这不改变归档范围开关。查询失败后只要用户修改输入，按钮就从「重试」恢复为「搜索」。
- 当前规范化输入与最近一次已执行查询相同且非空时，切换“包含已归档对话”后立即用该查询按新范围刷新；输入已被修改但尚未重新执行，或查询为空时，只更新开关，不发起请求。
- 用户每次执行搜索时，当时的规范化查询与归档范围成为这次搜索的提交条件。页面显示的加载、结果或错误只能来自**最近一次提交、且提交条件仍与当前控件一致**的搜索；任何其他搜索完成后都不能改变当前页面。
- 搜索进行中修改非空查询时，立即清除旧结果与旧错误，旧搜索失效，页面回到等待用户执行新查询的就绪状态；用户可以立刻提交当前有效查询，不会自动用尚未提交的新输入搜索。清空输入按空查询规则处理。
- 搜索进行中切换归档范围时，立即清除旧结果与旧错误，并以当前已经执行过的有效查询和新范围发出新请求。旧请求即使稍后成功或失败，也不得覆盖当前输入、范围、加载状态、结果或错误。
- 取消旧搜索还是让它在后台结束并忽略晚到结果属于实现选择；旧搜索一旦失效，既不能阻塞当前查询的按钮、Enter 或范围刷新，也不能覆盖当前加载、结果或错误。
- 关闭该开关时，结果中不得出现已归档对话。
- 打开该开关时，已归档对话必须有明确的归档标识，不能与普通对话混淆。
- 恢复成功后，对话恰好一次重新出现在原活动项目的侧边栏列表中，并保持原创建时间，不作为新对话置顶。
- 恢复 sidebar chat 不改变标题、消息、工作空间、团队、权限、运行历史或来源关系。来源会话仍可承载主内容时，恢复后只选中 sidebar chat 行并打开来源主内容与右侧标签；来源已归档、所属项目已移除、记录失效或没有来源时，恢复后在主内容区打开 sidebar chat。
- 普通主会话无论从未归档结果直接打开，还是归档恢复后打开，都完整消费左侧栏的普通会话路由：主内容显示目标会话，右侧栏切换到该会话自己持久化的标签组和开关状态。
- sidebar chat 自己所属的活动项目目录不可用时，恢复不会绕过项目限制；会话按侧边栏既有规则只读呈现，修复项目后才能继续发送或执行。
- 「恢复并打开」是一个原子结果：只有恢复侧栏条目与目标路由都成功后，才关闭搜索并提交新选中态。任一步失败时对话保持归档，搜索背后的最新有效主页面组合不变，查询、开关和结果位置保留，并提供原地重试。
- 普通结果打开失败时同样保留搜索页面和最新有效主页面组合，不提交左侧栏选中态。
- 未归档结果行与归档结果的「恢复并打开」按钮可通过键盘聚焦和激活；归档结果的展示行不进入交互焦点序列。两类操作的可访问名称都包含项目、完整标题与归档状态。重复点击同一个搜索、打开或恢复动作只提交一个逻辑请求。

### 键盘焦点与来源失效

- 从侧边栏进入搜索时，焦点进入搜索输入框；Tab 顺序固定为搜索输入框 → 「搜索／重试」按钮 → 归档范围开关 → 按显示顺序排列的未归档结果行或「恢复并打开」按钮 → 关闭按钮，Shift+Tab 反向移动。按钮禁用时仍跳过，不能形成焦点陷阱。
- 查询执行失败时，错误通过辅助技术宣告，「搜索」按钮在原位变为「重试」并获得焦点；点击、按 Enter 或 Space 均以原查询和范围重试。普通结果打开失败时焦点回到触发失败的结果行；恢复失败时焦点回到对应「恢复并打开」按钮。查询、开关和结果滚动位置不变。
- 用户关闭或取消搜索时，焦点回到侧边栏「搜索」入口。若搜索期间发生来源即时失效，仍先完成或保留该迁移状态，再回到搜索入口，不尝试恢复失效来源。
- 普通主会话或没有可用来源的 sidebar chat 成功打开后，焦点落在主内容会话标题；来源可用的 sidebar chat 组合成功打开后，焦点落在右侧栏中该会话的标签按钮。
- 搜索保持打开期间，进入前组合仍消费[主页面侧边栏的来源即时失效](./main-left-sidebar.md#组合路由中的来源即时失效)：迁移成功时更新搜索背后的最新有效组合，但不清空查询或抢走搜索焦点；迁移失败时保留最后成功呈现内容和重试状态。用户随后取消搜索时返回这个最新状态。
- 因来源失效而在主内容区打开 sidebar chat 时，会话顶部显示「暂时无法回到来源会话，已在主内容区打开」的非阻断说明。说明不改变会话历史、权限或可用操作；来源恢复也不自动迁回右侧栏。

## 页面状态

| 状态 | 表现 | 可用操作 |
| --- | --- | --- |
| 初始 | 显示搜索输入和归档范围开关 | 输入查询、切换范围、关闭 |
| 查询为空或全空白 | 不发请求、不显示全部会话或“无结果”，显示中性引导；搜索按钮禁用 | 输入有效标题、切换范围、关闭 |
| 搜索中 | 保留输入内容并显示进度 | 修改查询或关闭 |
| 搜索中·条件变化 | 旧结果与错误清除；旧请求失效；查询修改后等待重新执行，范围切换后按新范围刷新 | 搜索、修改查询、关闭 |
| 无结果 | 明确说明当前范围没有匹配项 | 修改查询或切换归档范围 |
| 有普通结果 | 显示项目与对话结果 | 打开对话 |

| 搜索失败 | 显示可理解错误；原位置按钮变为「重试」并聚焦 | 重试、修改查询或关闭 |

| sidebar chat·来源可用 | 关闭搜索后选中 sidebar chat；主内容显示来源、右侧栏显示目标 | 查看；所属项目可用时继续会话 |
| sidebar chat·来源失效 | 关闭搜索后选中 sidebar chat 并在主内容显示 | 查看；所属项目可用时继续会话 |
| 恢复或路由失败 | 搜索保持打开，对话仍归档，最新有效主页面组合不变 | 查看说明、重试 |
| 搜索期间来源失效 | 搜索内容与焦点保持；背后组合按左侧栏规则迁移或保留失败态 | 继续搜索、取消返回最新有效状态 |

## 弹层与危险操作

- 恢复归档不是危险操作，不需要二次确认。
- 搜索页面不提供永久删除对话或历史记录的能力。

## 响应式与窗口行为

- 搜索输入、归档范围开关和结果必须在主页面最小可用宽度下保持可达。
- 具体使用弹窗、抽屉还是独立主内容状态，继续讨论后确定。

## 关联流程

- 搜索并跳转到项目或对话。
- 归档并恢复对话。
- [会话分析流程](../flows/session-analysis.md)：已创建 sidebar chat 保留来源关系，来源失效只改变承载位置，不改变历史与权限。

## 指标与验收

已归档 sidebar chat 的恢复并打开成功率目标为 100%：分母是用户对活动项目中仍存在的已归档 sidebar chat 发起的每个逻辑「恢复并打开」请求，重复点击去重后只计一次；只有会话恰好一次恢复到原项目，并按来源状态完成主内容或组合路由才计成功。任何恢复、读取、路由或呈现失败均计入失败，不能事后移出分母。

1. 从侧边栏点击“搜索”能够进入本页面。
2. 页面提供明确的“包含已归档对话”开关。
3. 开关关闭时不返回归档对话，打开后可以返回并明确标识归档对话。
4. 恢复归档对话后，它重新出现在原项目中，且创建时间与内容不变。
5. 搜索或恢复失败不会清空查询，也不会产生重复对话。
6. 未归档 sidebar chat 与普通主会话一样进入活动项目搜索结果，不增加分析专用标题或图标；团队子任务与已移除项目历史不进入结果。
7. 打开未归档 sidebar chat 时，来源可用则只选中 sidebar chat 行并恢复来源主内容与右侧标签，来源失效或没有来源则在主内容区打开；失败时搜索与最新有效组合保持不变。
8. 已归档 sidebar chat 执行「恢复并打开」后，标题、创建时间、消息、工作空间、团队、权限、历史与来源关系保持不变；来源可用时恢复并排组合，来源失效时在主内容打开。
9. 「恢复并打开」任一步失败时会话仍保持归档，不新增或重复侧栏行，不改变最新有效选中态和主页面组合；查询、归档开关与结果位置保留，可原地重试。
10. 未归档结果行和「恢复并打开」按钮可通过键盘操作，两者可访问名称均包含项目名称、完整标题和归档状态；已归档展示行本身不进入焦点序列，重复点击只产生一个逻辑请求。
11. 输入任意会话的完整标题，在相同归档范围下必定命中；标题匹配按去首尾空白、Unicode NFKC 和小写后的包含关系执行。正文、路径、模糊纠错与排序仍可不实现。
12. 未归档结果行可激活打开；已归档结果行本身不可激活且不进入焦点序列，只有带完整标题辅助名称的「恢复并打开」按钮会执行原子恢复与路由。
13. 进入搜索时焦点位于输入框，Tab 顺序依次经过搜索／重试、归档范围、结果操作和关闭；查询失败后「重试」按钮聚焦且可用 Enter 或 Space 原地重试，打开或恢复失败后回到原触发控件，取消后回到侧边栏搜索入口；成功打开普通主会话或降级 sidebar chat 后焦点位于主内容标题，成功打开并排 sidebar chat 后焦点位于目标右侧标签。
14. 从搜索打开或恢复普通主会话时，主内容显示目标会话并恢复它自己的右侧栏标签组与开关状态，不保留上一段会话的标签，也不清空目标已保存现场。
15. 搜索期间来源失效时，查询、范围、结果位置与搜索焦点保持，背后组合消费左侧栏即时迁移规则；取消后返回最新有效组合。sidebar chat 因来源失效在主内容打开时显示「暂时无法回到来源会话，已在主内容区打开」，迁移失败则保留最后成功内容与重试状态。
16. 初次进入、空查询或规范化后为空时不发起搜索，不显示全部会话或“无结果”，搜索按钮禁用；切换归档范围只更新开关。输入有效标题后可通过按钮或 Enter 搜索，清空后回到初始状态。
17. 页面骨架始终提供带可访问名称的关闭按钮；关闭或取消后按本页焦点与最新有效组合规则返回。
18. 两个项目存在同名会话时，未归档结果行与「恢复并打开」按钮的可访问名称分别包含项目名称、完整标题和未归档／已归档状态，用户不依赖视觉分组也能区分目标。
19. 先以查询 A 和归档范围甲开始搜索，在其结束前改为查询 B 或范围乙并执行新搜索；无论两次搜索以什么顺序结束，加载、结果和错误都只能对应最近提交且仍等于当前控件的 B／乙。旧搜索不能覆盖页面，也不能禁用当前有效查询的按钮或 Enter。
20. 输入法组合期间按 Enter 只确认候选词，不发起搜索，搜索按钮也不可用；组合结束后再次按 Enter 或点击按钮才提交完整查询。

## 非目标

当前草案不定义：

- 搜索结果的高保真视觉。
- 完整搜索字段、匹配算法和相关性排序。
- 永久删除归档对话。
- 项目、Agent 团队和设置内容的搜索范围。
