# 自带 API 的编码 Agent

> 状态：产品命题与核心旅程已确认
>
> 产品基线：[Moebius 产品需求文档](../prd.md)
>
> 涉及页面：[首次引导](../pages/onboarding.md)、[设置](../pages/settings.md)、[Agent 团队](../pages/agent-teams.md)、[主对话](../pages/main-conversation.md)、[单 Agent 会话](../pages/agent-conversation.md)

> **2026-08-04 产品决定：**Moebius 把 Pi 作为与 Codex、Claude Code、Kimi 并列的第四种执行引擎。用户可以从 Moebius 维护的服务商目录中选择 DeepSeek 等明确支持的兼容 API，只填写 API Key 并选择该服务商下适合 Agent 使用的模型，不需要理解或填写 Base URL。一次极小的真实 Agent 能力测试通过后，这个应用级 Provider 档案即视为可用，可以被多支团队和多个 Agent 复用，也可以在没有安装任何 CLI 时单独满足首次引导的环境准备门槛。

> **2026-08-04 产品决定：**Pi 首版只需对标 Moebius 当前使用的本地 Codex 编码 Agent 体验，默认允许 Agent 读取和修改项目、运行命令并调用已配置工具，不提供 sandbox 或逐次审批。首版依靠 Pi 及其官方或社区扩展提供计划、Web、MCP、Skills 和并行子 Agent 等能力；Moebius 负责把这些能力纳入既有团队接力、会话恢复、运行可见性和托管进程体验，不把插件安装与治理暴露给用户。

## 需求进场对照

### 现状

产品当前只允许 Agent 绑定 Codex、Claude Code 或 Kimi，并要求首次引导中至少一套 CLI 完整就绪。设置没有面向用户的 API Provider 管理入口；现有本机配置中的 Provider 覆盖也不是普通用户可以完成的产品流程。因此，仅持有 DeepSeek 等 API Key、但没有安装或登录编码 CLI 的用户无法开始使用 Moebius。

### 期望

用户应当能够像选择一项常见服务一样选择 DeepSeek 或其他受支持的兼容 API，输入 Key、选择模型并完成一次能力验证。验证成功后，用户无需安装 CLI 即可进入产品，把现有 Agent 团队明确改用该 API，并获得对标本地 Codex 的编码 Agent 能力。相同 Provider 档案可以在首次引导和设置中持续管理，而密钥不会出现在团队文件、对话、运行过程或普通诊断信息中。

### 落点

本流程定义从首次配置 API、通过环境准备、绑定团队，到开始和恢复编码会话的跨页面目标。各页面后续只承接属于自身的结构、控件与反馈，不复制本流程的端到端规则。

## 用户目标

核心用户已经愿意让编码 Agent 操作本地项目，也拥有 DeepSeek 等服务商提供的 API Key，但不希望为了使用 Moebius 再安装、登录和维护另一套编码 CLI。

用户希望：

- 不查找或填写服务商 Base URL，只选择认识的服务商并输入 Key。
- 在真正交给团队前确认这组服务商、Key 和模型确实具备编码 Agent 所需能力。
- 一次配置后让多个 Agent 复用，而不是为每个成员重复填写密钥。
- 没有任何 CLI 时仍能完成首次引导并开始任务。
- 在日后轮换 Key、调整模型或改用另一服务商时，有明确入口和可恢复的失败反馈；改用另一服务商会建立新档案，不偷换原档案身份。
- 使用 API Agent 时得到与当前本地 Codex 相近的完整工作方式，而不是只能聊天的简化模型入口。
- 可以像现有 Codex 会话一样发送文件、压缩长上下文并恢复同一 Agent 会话；图片按所选模型真实能力处理。首版 DeepSeek V4 目录模型仅支持文本输入，图片原位说明限制，不静默换模型或伪装已理解。

## 开始条件

流程从以下任一入口开始：

- 新用户进入首次引导的环境准备步骤，尚无任何可用执行引擎。
- 已有用户从设置打开“AI 服务商”，希望新增或维护 Provider 档案。
- 用户在 Agent 团队中调整某名成员的执行引擎，选择使用已经就绪的 API Provider。

用户必须自行拥有受支持服务商的有效 API Key，并理解真实能力验证会产生极少量 API 用量。Moebius 不出售、代领或共享服务商额度。

在用户首次提交验证前，页面必须说明：验证只发送 Moebius 自带的测试内容，不读取用户项目；真正运行 Agent 后，用户消息、Agent 为完成任务读取的必要项目内容、附件和工具结果会发送给用户选择的第三方服务商处理。该说明只在建立档案时集中呈现，不引入逐次审批。

## 参与者与职责

### 用户

- 选择自己拥有账号和额度的服务商。
- 输入 API Key，选择该服务商下可用于 Agent 的模型。
- 明确触发真实能力验证，并在验证成功后决定哪些团队成员改用该 Provider。
- 在密钥失效、额度不足或服务商异常时更换配置或重试。

### Moebius

- 维护面向用户的服务商目录、固定连接信息和可选模型，让普通用户不接触 Base URL。
- 在首次引导和设置中提供同一套 Provider 档案管理能力。
- 只在真实能力测试成功后把档案标记为就绪；失败时保留当前编辑内容并提供可理解的恢复动作。
- 保护 API Key，不在保存后的界面中回显明文，也不把它写入团队内容、会话、运行过程或普通诊断信息。
- 为每个 Provider 档案保持稳定身份；服务商在档案创建后不可更换，用户改用另一服务商时创建新档案。
- 在创建新会话时冻结团队成员所选的 Provider 身份、服务商、模型和思考程度，使日后修改团队默认值不回写既有会话；Key 轮换继续服务所有引用同一档案的现有与未来会话。
- 把 Pi 的运行过程投影到既有会话体验，并继续承担停止、重试、恢复、成员接力和托管进程的产品责任。

### Pi Agent

- 使用用户选定的服务商和模型完成编码 Agent 循环。
- 在默认全部放行的首版边界内读取和修改项目、运行命令，并使用计划、Web、MCP、Skills、子 Agent、文件输入和长上下文压缩等首版能力；图片仅在目录模型明确支持时进入模型输入。
- 返回可被 Moebius 持久化、恢复和展示的正文、工具活动、失败和会话关联。
- 不成为团队、Provider 档案或 Moebius 会话状态的事实源。

### API 服务商

- 对 API Key、模型、额度、限流和服务可用性负责。
- 返回真实模型和工具调用结果。Moebius 不把服务商失败改写成 Agent 已成功完成。

## 主流程

### 1. 选择服务商

- 首次引导在现有 CLI 准备之外提供“添加 API Provider”，两条路径地位对等；用户不必先安装一套 CLI 才能看到 API 路径。
- 设置增加“AI 服务商”分类，展示已保存档案和新增入口。引导页与设置页操作同一批应用级档案；在一处验证成功的档案会立即在另一处可见。
- 服务商以明确名称和品牌识别呈现，至少包含 DeepSeek，并可包含其他经 Moebius 确认兼容的服务商。
- 用户不填写或查看 Base URL。首版不提供“自定义服务商”或“高级地址”入口，避免把协议连接细节转嫁给用户。

### 2. 输入 Key 与选择模型

- 每个档案包含用户可修改的档案名称、创建后不可更换的服务商、API Key 状态、已经验证的模型集合和一个默认模型。同一服务商可以建立多个档案，名称必须能在应用内区分；重名时保存前要求用户改名。
- 服务商一旦选定，页面只显示 Moebius 已确认适合 Agent 使用的模型选项；用户不输入任意模型 ID。
- API Key 初次输入和替换时可临时查看本次输入，离开编辑后只显示已配置状态和便于区分的非敏感尾部提示，不提供取回完整 Key 的能力。
- 修改档案名称和默认模型不改变已经冻结的成员配置。替换 Key 必须重新验证；选择尚未验证的模型时，必须先对该模型完成同样的真实能力测试。在新验证成功前，原先已就绪的保存版本继续可用，未通过的新草稿不能覆盖它。
- Key 轮换面向整个档案：Moebius 必须用新 Key 依次验证档案当前全部已验证模型，并在开始前告诉用户模型数量和每个模型都会产生极少量用量。全部通过后才原子替换旧 Key；任一模型失败就保留旧 Key 和完整旧模型集合，新 Key 草稿不生效。用户若不再需要某个失败模型，可以先从档案的可用集合中移除它，再重新轮换。
- Provider 默认模型只用于 Agent 首次选择该档案时预选。每名成员可以从该档案已经验证的模型中独立选择并冻结自己的模型，不因档案默认模型后来变化而改变。
- Pi 的思考程度属于成员运行配置，不属于 Provider 档案。所选服务商与模型能够提供可区分的思考程度时显示受支持选项；无法可靠控制时隐藏该项并使用固定值，不伪造与 Codex 相同的可调档位。

### 3. 真实能力验证

- 主操作使用“验证并保存”，并在操作前明确说明会向所选服务商发起一次极小的真实请求、产生少量 API 用量。
- 验证目标不是只检查网络或 Key 格式，而是确认所选模型可以完成一次响应并正确发起 Agent 所需的工具调用。
- 验证在 Moebius 自带的隔离测试空间中进行，只使用固定测试内容和一个无项目副作用的受控工具，不读取当前项目、团队内容、附件、MCP 或个人 Skills。成功结果明确显示“模型回复”和“工具调用”均已通过，而不是只显示笼统的“连接成功”。
- 验证进行中持续显示当前服务商和模型，禁止重复提交。用户主动取消、返回上一步或关闭承载页面时，必须先明确说明本地会停止等待，但服务商可能已经处理请求并计费用量；确认离开后取消本地验证、丢弃未保存 Key，只保留服务商、档案名称和模型草稿。重新进入后需要重新输入 Key 并再次验证。
- 只有验证成功才保存新档案或替换既有档案的有效版本，并把它标记为“已就绪”。验证新 Key 或新模型属于叠加在档案上的临时活动，不替换档案当前有效状态；旧版本原本“已就绪”时，既有 Agent 在验证期间仍继续使用旧 Key 和旧模型集合。
- 验证失败不得创建看似可用的档案，也不得泄露原始响应、Key 或内部连接信息。页面应区分可操作的常见方向，例如 Key 无效、模型不兼容、额度或限流、服务暂时不可用，以及无法确认的失败。

### 4. 通过首次引导

- 环境准备的统一门槛从“至少一套 CLI 可用”变为“至少一个执行引擎已就绪”。已就绪的 Codex、Claude Code、Kimi 或 Pi API 任意一个都能满足门槛。
- API 验证成功后，首次引导立即允许继续，不要求用户另外安装 CLI。
- CLI 检查和可选安装可以继续独立运行，但不得阻止已经拥有可用 API 的用户前进。
- 用户返回环境准备步骤时，页面恢复应用级 Provider 的真实就绪状态，不重复能力测试，也不把先前失败显示成成功。

### 5. 使用 Pi API 完成 AI 建队

- “跟 AI 聊出团队”使用当前引导中第一份已就绪的 Pi API Provider 作为候选执行引擎，与现有 ready CLI 共同参与选择；纯 API 用户不因没有 CLI 失去 AI 建队能力。
- 当引导同时存在多种就绪执行引擎时，页面明确显示本次 AI 建队将使用哪一个，并允许用户在开始草稿前选择；草稿开始后冻结所选 Provider、模型和独立执行会话，不在中途静默切换。
- Pi API 建队只接收建队对话和固定团队设计约束，不读取用户项目，也不获得团队写权限。生成方案、用户确认后由 Moebius 创建团队的既有责任不变。
- Key 失效、额度不足、恢复失败或档案进入“需要处理”时，页面保留建队对话和最后有效方案；用户修复同一档案后重试同一草稿，不自动换用 CLI 或另一 Provider。
- 草稿冻结的模型下线时，原 Pi 外部执行会话封存且不再声称可以原生恢复。用户明确选择同一档案中的另一已验证模型后，Moebius 保留已经可见的建队对话和最后有效方案，建立新的 Pi 外部执行会话，并把这份已保存上下文作为新会话起点。页面明确提示“已更换模型，AI 原生上下文已重新建立”，后续轮次只使用新会话；这一迁移不改写旧过程记录。

### 6. 把团队改用 API

- Agent 团队中的运行配置从只表达“CLI”扩展为“执行引擎”。用户可以继续选择 Codex、Claude Code、Kimi，也可以选择 Pi API。
- 选择 Pi API 后，用户再选择一个已就绪的 Provider 档案及其有效模型；API Key 不在团队页出现。
- 首次引导选择团队时，统一检查每名成员的执行配置是否可用。不可用包括本机 CLI 未就绪、Pi Provider 处于“需要处理”或“已停用”、Provider 已不受支持，以及成员冻结模型不可用。页面明确列出受影响成员数量、原因和当前配置，并提供“改用这个 API”。用户确认后，所选 Provider 和模型应用到这些成员之后的新会话；已经可用且使用其他执行引擎的成员保持不变。
- 这次替换必须由用户明确触发，不因某个 CLI 不可用而静默改写团队，也不在运行失败后自动降级到另一服务商。
- 用户也可以暂不替换并继续进入产品；相关成员真正接到任务时按其冻结配置显示不可用，避免把“至少一个执行引擎可用”夸大成整支团队都已就绪。

### 7. 创建并运行会话

- 新会话在创建时冻结每名成员的执行引擎、Provider 档案身份、服务商、模型和思考程度。档案后来轮换 Key 时继续代表同一服务商身份，并恢复所有引用它的现有与未来会话；服务商不可在原档案中切换，档案默认模型变化也不回写已经创建的会话。
- Pi API 成员进入现有团队调度和会话语义：主 Agent 接单、成员 mention 与接力、用户插话、停止、重试、恢复、过程查看和最终收尾不另建一套产品流程。
- 默认全部放行意味着正常文件、命令和工具动作不出现 sandbox 或逐次审批提示。Moebius 仍使用已有的用户可见运行状态、停止入口和托管进程能力管理持续工作。
- API Provider 返回可恢复的限流或暂时繁忙时，页面保持当前会话和已产生内容，给出重试；Key 失效或额度不足时，允许用户前往设置修复，并在返回后重新运行，而不是新建替代会话或静默切换 Provider。
- 冻结模型已不可用时，旧的 Pi 外部执行会话不能冒充可恢复。用户有两条明确路径：
  - “迁移当前会话”把当前会话中受影响 Agent 的后续执行永久改为同一档案中另一已验证模型，保留 Moebius 时间线并建立新的 Pi 外部执行会话；页面说明原生模型上下文会从已保存的可见会话重新建立。迁移不改写团队默认值或更早尝试。
  - “结束并保留历史”把受影响 Agent 在当前会话中转为只读，不再允许继续、重试或恢复，从而解除该会话对原 Provider 档案的运行引用；历史和已有文件结果仍可阅读。
- 排队中的 run 在真正启动时重新确认档案仍可用；档案已停用或进入“需要处理”时，run 不调用服务商并停在可修复状态。已经发出的请求不因档案随后停用而伪装成未执行，仍按服务商真实结果收敛。
- 对标本地 Codex 的首版体验包含：计划并更新任务、Web 搜索与读取、调用用户已经配置的 MCP、加载适用 Skills、启动并汇总并行子 Agent、接收文件输入、压缩长上下文、恢复同一外部执行会话，以及通过 Moebius 托管进程管理需要持续监督的运行项。图片输入服从目录模型的真实能力；DeepSeek V4 首版明确显示文本模型限制。某项外部能力尚未配置时，页面应明确显示不可用原因；基础文件和命令工作可以继续，但不得宣称该项已经可用。

### 8. Provider 生命周期与后续管理

- 设置中的“AI 服务商”允许新增档案、重命名、替换 Key、修改模型、重新验证和删除。
- 档案显示服务商、默认模型、最近一次验证结果和被多少团队成员使用，不显示完整 Key 或 Base URL。
- 档案有效状态为“已就绪”“需要处理”或“已停用”；“正在验证”是叠加活动状态，不替换有效状态。只有有效状态为“已就绪”才计入首次引导门槛、允许新绑定成员、创建新 Pi run 或承接 AI 建队。“需要处理”和“已停用”都保留引用与修复入口，但不允许产生新的服务商请求。验证草稿期间，所有现有消费者继续读取验证开始前的有效版本，直到新版本全部通过后一次切换。
- Key 明确失效、系统凭据无法读取、服务商被 Moebius 支持目录移除，或档案已经没有任何可用的已验证模型，都会把档案转为“需要处理”。普通限流、额度暂时不足和短暂服务不可用只影响当前 run，不永久撤销就绪状态。用户替换 Key或选择仍受支持的模型并重新验证成功后恢复“已就绪”。
- 用户可以随时停用档案，阻止新绑定和新运行，同时保留团队与会话引用以便日后重新启用。运行中请求按真实结果结束；尚未启动的排队 run 进入可修复状态。
- 从档案的已验证模型集合中移除模型前，执行与删除档案相同的引用检查，列出使用该模型的团队成员、AI 建队草稿、运行中或排队任务和可恢复会话。存在任何引用时阻止移除；用户必须先把各引用迁移到同一档案的另一已验证模型，或结束相应继续能力。运行中请求先按真实结果结束，不在中途偷换模型。
- 档案只在没有团队成员、AI 建队草稿、运行中或排队任务、以及可恢复会话引用时允许删除。设置列出全部引用类别并引导用户先迁移或结束；不得静默把引用换回 Codex 或其他 Provider。
- 删除后只剩与该档案无运行关系的静态历史，因此不影响历史阅读。只要一个旧会话仍允许继续、重试或恢复，它就构成引用，档案不能删除。
- 服务商从支持目录移除时，现有档案进入“需要处理”，不再用于新运行。用户先创建并验证另一服务商的新 Provider 档案，再从原档案的引用清单发起迁移：团队成员永久改绑新档案；AI 建队草稿和可恢复会话保留 Moebius 已保存内容、封存旧 Pi 外部会话，并用新档案建立新的 Pi 外部会话；排队任务停止并提供用新配置重新运行，运行中请求按真实结果结束。每项迁移都明确显示服务商已变化，不静默批量替换。用户也可以结束草稿或会话继续能力并保留只读历史，以解除引用。
- 模型从目录移除时，该模型标记为不可用，只阻止冻结该模型的成员和会话继续运行；档案仍有其他已验证模型时保持“已就绪”供用户迁移，没有任何可用模型时才整体进入“需要处理”。

## 分支与异常

| 情况 | 产品行为 | 恢复路径 |
| --- | --- | --- |
| API Key 无效 | 验证失败，不保存草稿为可用档案 | 保留本次输入，修改后重试 |
| 模型能回复但不能正确调用工具 | 视为 Agent 能力验证失败 | 选择其他受支持模型后重试 |
| 服务商限流、额度不足或暂时不可用 | 显示对应的安全分类，不猜测更具体原因 | 稍后重试、补充额度或更换档案 |
| 验证中取消 | 停止本地等待，不产生就绪档案，并说明服务商仍可能计费 | 保留非敏感编辑内容；重新输入 Key 后再次验证 |
| 替换既有 Key 或模型验证失败 | 旧的已验证版本继续有效，新草稿不覆盖 | 修正草稿或放弃修改 |
| 多模型档案轮换 Key | 使用新 Key 逐一验证当前全部已验证模型；期间旧版本继续运行 | 全部通过后原子替换；任一失败则完整保留旧版本 |
| 首次引导只有 API 可用 | API 独立满足环境门槛 | 直接选择团队，不要求安装 CLI |
| 纯 API 用户进入 AI 建队 | 使用明确选定且已就绪的 Pi API Provider | 同一档案修复后重试原草稿 |
| 团队只有部分成员已改用 API | 明确显示剩余不可用成员，不冒充全队就绪 | 返回团队页调整，或在对应成员失败后修复 |
| 运行期间 Key 失效 | 当前 run 以安全原因停止，已有内容和文件改动保留 | 从设置替换并验证 Key，再重新运行 |
| 已冻结模型下线 | 旧外部执行会话不再恢复，历史与 Moebius 会话保留 | 永久迁移当前会话到另一已验证模型，或结束继续能力并保留只读历史 |
| 服务商从支持目录移除 | 原档案进入“需要处理”，停止新绑定和新运行 | 创建已就绪的新 Provider 档案，逐类迁移引用并重建 Pi 会话，或结束继续能力保留历史 |
| 移除仍被引用的已验证模型 | 阻止移除并列出团队、草稿、任务与会话引用 | 先迁移或结束全部引用，再移除模型并轮换 Key |
| 运行期间服务商短暂繁忙 | 当前会话保持，按真实状态显示重试 | 原 Provider 上重试，不静默切换 |
| 档案进入“需要处理” | 不再计入引导门槛，也不接受新绑定、新建队或新运行 | 修复 Key/模型并重新验证 |
| 停用仍有排队任务的档案 | 运行中请求真实收敛，未启动请求不再调用服务商 | 重新启用并重试，或改用其他配置重新运行 |
| 删除仍有任何可运行引用的档案 | 阻止删除并列出团队、草稿、任务与会话引用 | 先迁移或结束引用，再删除 |
| 应用退出或崩溃 | 已保存档案、团队绑定和会话保持；未保存明文 Key 不作为可恢复草稿留存 | 重开后从最后成功状态继续 |

## 等待与自动推进

- 用户必须主动选择服务商、输入 Key、选择模型，并触发“验证并保存”。Moebius 不在用户尚未确认少量 API 用量时自动发起测试。
- 能力测试成功后，Provider 保存与就绪状态自动收敛，不再要求第二次保存确认。
- Provider 已就绪后，首次引导的继续条件自动更新；用户仍需主动选择团队并发送首条消息。
- 纯 API 用户选择 AI 建队时，已就绪 Pi Provider 自动成为可选执行引擎；开始草稿前等待用户确认本次选择，草稿内后续轮次自动复用同一执行会话。
- 团队成员替换必须等待用户确认受影响成员；一次确认后自动完成全部选定成员的调整，不逐名重复确认。
- 正常 Pi Agent 运行按现有团队规则自动接力；只有团队规则要求、出现真正产品取舍或需要用户专属信息时才等待用户。
- 网络失败、服务商繁忙、Key 失效和模型不兼容都不得无限自动重试。页面保留状态和明确重试入口，由用户决定何时产生下一次 API 用量。

## 完成条件

首次配置流程在以下条件同时满足时完成：

- 用户创建了一个真实能力测试通过的应用级 Provider 档案。
- 即使本机没有 Codex、Claude Code 或 Kimi，首次引导也允许用户选择团队并进入新会话。
- 需要使用该 API 的团队成员已经由用户明确绑定到 Pi API、Provider 档案和模型。
- 用户发送目标后，至少一名 Pi API Agent 能在真实项目中完成一次包含工具调用的可见运行，并把结果纳入现有会话时间线。

后续管理流程在修改完成并重新验证后结束。成功反馈必须说明哪个服务商和模型已经就绪，不回显 Key，不要求重启应用。

## 涉及页面

- [首次引导](../pages/onboarding.md)：新增 API Provider，统一执行环境门槛，并承接选中团队中不可用成员的显式替换。
- [设置](../pages/settings.md)：增加“AI 服务商”分类，管理应用级 Provider 档案及其验证状态。
- [Agent 团队](../pages/agent-teams.md)：把运行配置扩展为执行引擎，支持选择 Pi API、Provider 档案和模型。
- [主对话](../pages/main-conversation.md)：使用发送时所选团队的最新有效运行配置创建会话，并沿用团队调度、用户插话、附件、停止和结果呈现。
- [单 Agent 会话](../pages/agent-conversation.md)：呈现 Pi API 的活动、失败、重试、恢复和过程记录，不复制一套 API 专属会话页面。

## 指标与验收

### 产品指标

- **API 配置完成率：**在首次引导中选择受支持服务商、提交验证且服务商返回有效凭据结果的用户里，至少 90% 在 3 分钟内得到“已就绪”；服务商超时不计入有效凭据分母，但必须单独记录。
- **API-only 引导完成率：**没有任何 ready CLI、但在本次应用会话中建立了已就绪 Provider 的用户里，至少 80% 在 10 分钟内进入主对话并发送第一条消息。
- **首次 Agent 成功率：**使用已验证模型发起第一条 Pi API 任务的会话里，至少 90% 在 60 秒内产生首个可见 Agent 正文或工具活动；明确的服务商限流、额度和网络失败单独分组，不能归为产品成功。
- **零地址负担：**受支持服务商的新增与验证路径中，100% 不要求用户输入、复制或理解 Base URL。
- **复用产品约束：**同一档案被任意数量成员选择时，100% 不要求重新输入 Key；任何按成员重复索取同一档案 Key 的路径都视为缺陷。
- **档案复用采用率：**在同一团队中有至少两名 Pi API 成员、且他们选择同一服务商的团队里，至少 80% 主动复用同一档案。该指标用于判断档案选择是否易于发现，不允许用它放宽上面的 100% 产品约束。
- **秘密泄露：**API Key 出现在团队文件、会话、过程记录、普通诊断或可复制 UI 中的次数必须为零。

### 端到端验收

1. 在没有 Codex、Claude Code 和 Kimi 可用的干净环境中，用户能从首次引导选择 DeepSeek、输入 Key、选择模型、知情触发真实能力测试，并在通过后继续。
2. 整条路径没有 Base URL 输入，也不要求用户识别 OpenAI-compatible 协议细节。
3. 验证页面必须明确显示“模型回复”和“工具调用”两项结果；测试只使用 Moebius 固定内容和无项目副作用工具。只显示连通成功、模型列表或普通文本不能算通过。
4. Key 无效、工具调用不兼容、限流和无法确认的失败分别产生可理解反馈；失败后非敏感编辑内容仍在，档案不被伪装成已就绪。取消、返回和关闭会说明可能已经产生用量，并丢弃未保存 Key。
5. 用户选择团队后，能看到所有执行配置不可用的成员，包括未就绪 CLI、异常或停用 Provider、已移除服务商和不可用模型，并通过一次明确操作把这些成员改用所选 API；未选择的成员不被改写。
6. 没有任何 ready CLI 时，用户可以用 Pi API 完成“跟 AI 聊出团队”，调整方案并从失败处恢复；所选执行引擎在草稿期间不静默变化。
7. 在设置中替换 Key 或模型时，新值验证失败不会覆盖旧的有效档案；验证成功后相关未来运行使用新值。
8. Provider 的服务商不可原位切换；多模型档案轮换 Key 时，新 Key 对当前全部已验证模型完成测试后才原子生效，期间旧版本继续服务。轮换后，引用同一档案的旧会话可以恢复。
9. Key 失效、凭据不可读、服务商被移除或档案已无可用模型时，档案进入“需要处理”，立即停止计入引导门槛和接受新运行；只有单个模型被移除而仍有其他已验证模型时，档案保持就绪但受影响配置不能继续。修复并验证后恢复，暂时限流不会永久撤销就绪状态。
10. 模型下线后，用户可以把当前 Moebius 会话永久迁移到同一档案的另一已验证模型并看见“原生上下文已重新建立”，也可以结束继续能力、保留只读历史并解除运行引用；在团队、草稿、任务或可恢复会话仍有引用时删除档案受阻并显示去向。
11. 服务商被支持目录移除后，用户可以建立另一份已就绪 Provider 档案，并分别迁移团队、AI 建队草稿和可恢复会话；草稿与会话保留 Moebius 可见历史、封存旧 Pi 会话并明确建立新会话。排队任务不会偷偷换服务商，用户也能选择结束继续能力并保留只读历史。
12. 在受控验收项目中，用户要求 Pi API Agent 读取一个既有文件、完成一处指定且可核对的内容修改，并运行仓库提供的确定性命令或测试。真实页面必须同时显示读取、文件变更、命令结果和最终说明，磁盘 diff 与测试结果必须吻合；只读活动、无关命令或仅有模型自述不能算基础编码能力通过。页面随后还能停止、重试并恢复同一会话。
13. 在已配置相应能力的验收环境中，Pi API Agent 分别完成一次计划更新、Web 读取、MCP 调用、Skill 加载、并行子 Agent 汇总和文件输入理解；每项都必须在真实页面留下用户可观察结果。给首版 DeepSeek V4 添加图片时，页面必须在请求服务商前明确说明文本模型限制，不得冒充图片理解或静默换模型。
14. 长会话触发上下文压缩时，时间线显示一次不打断工作的“已整理较早上下文”系统事实；压缩后的下一轮仍能引用压缩前的明确用户要求并恢复同一 Pi 会话。两项真实页面观察共同构成压缩验收，不能只检查内部 token 计数。
15. 首次建立 Provider 时，用户能在提交验证前看到第三方数据去向说明；验证不读取项目，正常任务不增加逐次审批。
16. API Key 不出现在团队文件、会话正文、运行过程、普通错误、复制信息或界面可取回字段中。
17. Agent 运行不出现 sandbox 或逐次工具审批；需要跨回合持续监督的运行项仍由 Moebius 现有托管进程入口承接。

## 非目标

- 不提供用户自定义 Base URL、任意 OpenAI-compatible 服务商或任意模型 ID。
- 不建设公开插件市场、插件安装器或用户可编辑的 Pi 扩展目录。
- 不把 Pi 的 sandbox、权限系统或逐次工具审批纳入首版。
- 不为首版单独建设 LSP、云端 Agent、定时任务、Computer Use 或浏览器自动化产品面。
- 不保证所有声称 OpenAI-compatible 的服务商和模型都能运行；只有进入 Moebius 服务商与模型目录并通过真实能力测试的组合才属于支持范围。
- 不让 Moebius 代管服务商账号、购买额度、合并账单或在服务商之间自动切换。
- 不改变既有 CLI 用户继续使用 Codex、Claude Code 或 Kimi 的路径，也不在 API 失败时自动降级到这些 CLI。
- 首发服务商除 DeepSeek 外的精确名单、持续任务的费用展示，以及单项外部能力未配置时的完整设置入口暂保持开放，由后续页面 PRD与实施方案在不改变本流程边界的前提下收束。
