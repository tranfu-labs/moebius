# 应用自动更新

> 状态：检测节奏、下载完成提醒弹窗与三种用户决定已完成产品采访；跨平台发布通道待讨论
>
> 关联页面：[设置](../pages/settings.md)、[主页面侧边栏](../pages/main-left-sidebar.md)
>
> 范围：定义用户从「应用在后台发现并下载了新版本」到「用户决定何时安装、或明确表示不想被打扰」的完整流程，包括运行期的检测节奏、下载完成后的应用内提醒、稍后提醒与跳过此版本的记忆规则，以及安装确认与退出保护的职责边界。安装过程本身的任务清理与退出保护规则由既有退出保护承接，本流程只定义进入它的入口和条件。

本文按用户可观察层级使用术语：

- **检测**：应用向发布通道询问是否存在比当前更高的正式版本。
- **下载**：应用在后台取回并校验安装包，用户不需要参与。
- **提醒**：安装包已经就绪后，应用主动告诉用户并请求一次决定。
- **安装**：应用收尾、退出、替换版本并重新打开。

## 用户目标

用户希望应用自己保持在最新版本，但升级的时机由自己掌握：

- 不需要主动记得去检查有没有新版本；
- 不需要打开设置才知道新版本已经准备好了；
- 新版本就绪时被告知一次，并能当场决定现在装、待会再说、还是这个版本我不想装；
- 正在运行的 Agent 任务不因为一次更新提醒被打断或被迫中止。

## 开始条件

- 用户运行的是正式打包版本，且当前平台在发布通道覆盖范围内。
- 应用已经启动并完成本地控制台就绪。
- 用户没有对这个具体版本表达过「跳过此版本」。

## 参与者与职责

### 用户

- 决定新版本什么时候安装；
- 决定是否放弃某个具体版本；
- 在有任务正在运行时，决定是否为了安装而停止这些任务。

### 桌面应用

- 按固定节奏检测新版本，不要求用户参与；
- 发现新版本后自动在后台下载并校验，不自动安装、不自动重启；
- 安装包就绪后，在不打断用户当前工作的前提下主动提醒一次；
- 记住用户「稍后提醒」和「跳过此版本」的决定，并在正确的时机让提醒重新出现；
- 无论用户从哪个入口发起安装，都先确认，再收尾，再安装。

### 退出保护

- 只负责「安装被确认之后」的任务清理与安全退出；
- 不参与是否提醒、何时提醒的判断；
- 与普通退出共享任务清理逻辑，但使用面向安装的独立确认表达。

## 主流程

### 1. 检测新版本

应用在三个时机检测：

- 启动完成后一次；
- 运行期间每 4 小时一次；
- 设备从睡眠中唤醒后补一次。

另有用户在设置 → 关于主动点击「立即检查」的手动时机。全部时机共用同一个进行中闸门，一次检测未结束前不重复发起。已经处于「有新版本」「下载中」「已准备好」「安装中」时，新的定时检测直接跳过，不打断已经在进行的下载。

检测结果只影响设置 → 关于中的状态展示，不产生任何提醒。用户在这一步应当完全无感。

### 2. 后台下载

检测到更高的正式版本后，应用立即在后台下载并校验安装包，进度显示在设置 → 关于。下载期间不提醒、不弹窗、不打开浏览器，用户可以继续做任何事。

下载与校验完成后，应用记住「这个版本已经就绪」。该记忆跨重启有效：用户关闭再打开应用，不需要重新下载。

### 3. 出现提醒的时机

安装包就绪后，应用准备提醒用户，但不一定立刻弹出：

- 当前没有任务在运行时，立即弹出提醒弹窗；
- 有 Agent 对话、AI 建队或命令行安装任务正在运行时，提醒进入等待，直到运行中的任务数回到零后的第一时间弹出。

等待期间应用不做任何替代性提示，也不改变提醒的形态——它只是还没到时候。安装包就绪时，侧边栏「设置」右侧的「安装更新」与设置 → 关于更新状态附近的「重启并安装」同时出现；用户随时可以从任一入口发起同一安装确认，不需要等提醒。

已经弹出的提醒不因为用户随后开始了新任务而自动撤回。

### 4. 提醒弹窗

提醒弹窗是应用内的居中模态弹窗，带蒙版，压在主界面之上：

```text
        ┌──────────────────────────────────────────────────┐
        │                                                  │
        │  Moebius 0.5.0 已准备好安装                        │
        │                                                  │
        │  当前版本 0.4.3 → 新版本 0.5.0                     │
        │  查看更新内容 ↗                                    │
        │                                                  │
        │                                                  │
        │  [跳过此版本]          [稍后提醒]  [重启并安装]      │
        │                                                  │
        └──────────────────────────────────────────────────┘
                     ▒▒▒▒ 蒙版覆盖主界面 ▒▒▒▒
```

三个操作的位置表达轻重：「重启并安装」是主操作放最右，「稍后提醒」是常规退路紧邻其左，「跳过此版本」是低频的否定决定，与前两者拉开距离放在左端。

弹窗必须可以用蒙版点击和 Esc 关闭。关闭一律等同于「稍后提醒」——最轻的那个决定，绝不等同于「跳过此版本」。

「查看更新内容」在系统浏览器中打开该版本的发布记录，弹窗留在原处不关闭。

### 5. 用户的三种决定

| 决定 | 立即发生什么 | 之后什么时候再提醒 |
| --- | --- | --- |
| 重启并安装 | 进入安装确认（见第 6 步） | 不适用 |
| 稍后提醒（含关闭弹窗） | 弹窗消失，回到原界面 | 本次运行不再提醒；下次启动应用时重新提醒 |
| 跳过此版本 | 弹窗消失，回到原界面 | 该版本永不再提醒；出现比它更高的正式版本时恢复提醒 |

三条配套规则：

- 「跳过此版本」只是不再打扰，不是拒绝这个版本。已下载的安装包保留，侧边栏「安装更新」和设置 → 关于的「重启并安装」继续存在，用户随时可以自己装上。设置 → 关于的「已准备好」状态补一句说明用户自己做过的决定，例如「0.5.0 已准备好 · 你选择了跳过这个版本」，让用户在事后看到安装按钮还在时能想起为什么没有再被提醒。这只是同一状态下的文案修饰，不是新的状态分支。
- 「稍后提醒」不受定时检测影响。检测只负责发现和下载，提醒节奏完全由本表决定，用户点过「稍后提醒」后不会在 4 小时后又被弹一次。
- 跳过的记忆按具体版本号保存并跨重启有效，不是「关闭自动更新」的开关。产品不提供关闭自动检查或自动下载的设置项。

### 6. 安装确认

从提醒弹窗的「重启并安装」、设置 → 关于的「重启并安装」和侧边栏「安装更新」进入的是同一段确认，表达一致：

```text
  无任务运行时                          有任务运行时
  ┌──────────────────────────┐          ┌────────────────────────────────────┐
  │  重启并安装 0.5.0          │          │  安装需要先停止 3 个运行中任务         │
  │                          │          │                                    │
  │  应用会关闭并重新打开。      │          │  安装会关闭应用并停止这些任务，        │
  │                          │          │  重新打开后需要重新开始。              │
  │                          │          │                                    │
  │      [取消]  [重启并安装]  │          │  [继续工作]  [停止任务并重启安装]      │
  └──────────────────────────┘          └────────────────────────────────────┘
```

按钮文案与[设置](../pages/settings.md)、[主页面侧边栏](../pages/main-left-sidebar.md)中既有描述保持一致，三处指同一个弹层，任何一处改字必须三处同步。

确认弹窗与提醒弹窗使用同一套应用内弹窗表达，不使用系统原生对话框。它同样带蒙版、可 Esc 和点击蒙版关闭，关闭等同于「取消」/「继续工作」。

用户确认后，应用按既有退出保护完成任务清理与安全收尾，然后安装并重新打开。这一段的任务清理规则、清理失败的处理与普通退出共享，不在本流程重复定义。

## 分支与异常

### 检测失败

不产生任何提醒。设置 → 关于显示失败说明与重试入口，其余界面无变化。下一个检测时机照常到来。

### 下载或校验失败

不产生任何提醒。设置 → 关于显示失败说明与「重新下载」，侧边栏不出现「安装更新」按钮。

### 提醒等待期间用户自己点了安装

侧边栏「安装更新」按钮随时可用。用户从这里发起安装时，等待中的提醒作废，不再补弹。

### 用户在确认弹窗取消

回到原界面。本次运行不再自动提醒（等同于「稍后提醒」），侧边栏「安装更新」按钮保留，用户可以再次发起。

### 任务未能停止或安装未能完成

用户已经确认安装后，失败结果必须立即出现在当前界面的应用内弹窗中，不能只写进设置 → 关于等用户自行寻找。弹窗按真实阶段说明结果：

- 任务停止失败：明确说明安装尚未开始、任务仍在运行且记录未受影响；提供「继续工作」和「重试」。
- 任务已经停止但安装未能完成：明确说明安装失败、已停止的任务不会自动恢复、会话记录仍保留；提供「稍后重试」和「重试安装」。
- 原本没有运行任务但安装未能完成：明确说明安装失败、应用已经恢复且可以继续工作；提供「稍后重试」和「重试安装」。

「重试」与「重试安装」重新读取当前 ready 状态和运行任务数，再进入同一安装保护链路；不得沿用失败前的任务快照。按 Esc、点击蒙版或选择左侧退路均关闭失败弹窗并留在当前界面，不自动再次发起安装。

设置 → 关于同时保留可回忆的失败状态与重试入口，文案必须区分「检查失败」「下载失败」和「安装失败」，不得把安装失败默认归因于网络。侧边栏「安装更新」按钮继续保留。本次运行不再自动弹出更新就绪提醒，避免同一个失败反复打断用户。

### 应用重启后安装包仍然就绪

用户在上一次运行中选择了「稍后提醒」，或安装未能完成。启动检测阶段直接恢复「已准备好」状态，不重新下载，并按第 3 步的时机规则重新提醒一次。曾被「跳过此版本」的版本不在此列。

### 更高版本覆盖了被跳过的版本

跳过的记忆按版本号保存，因此更高的正式版本照常检测、下载并提醒。被跳过的旧版本记忆不再有意义，可以随之失效。

## 等待与自动推进

- 检测、下载、校验全程自动推进，任何一步都不等待用户。
- 提醒弹窗弹出后必须等待用户，不自动消失、不自动选择、不倒计时。
- 提醒的弹出时机等待「运行中任务数回到零」这一个条件，不等待用户的其他动作，也不设置最长等待时间——用户任务跑多久就等多久。
- 安装确认后不再需要任何用户输入，收尾、安装与重新打开自动完成。

## 完成条件

流程完成的标志是应用以新版本重新打开，且原有的「已准备好」状态自然消失——用户看到的是设置 → 关于显示新版本号且「已是最新版」，关于区不再有「重启并安装」，侧边栏也不再有「安装更新」。

用户选择「跳过此版本」或「稍后提醒」时，本轮提醒完成但流程未完成：安装入口保留，提醒按上表的规则等待下一个时机。

## 涉及页面

- [设置](../pages/settings.md)：关于分类承载版本、检测状态、下载进度、已准备好、安装动作与失败重试；安装动作与侧边栏入口进入同一任务保护确认。
- [主页面侧边栏](../pages/main-left-sidebar.md)：安装包就绪时在「设置」右侧显示「安装更新」按钮，是不依赖提醒弹窗的常驻入口。
- 提醒弹窗与安装确认弹窗是全局弹层，压在当前任何页面之上，不属于某一个页面。

## 指标与验收

### 产品指标

- 新版本发布后，用户在多长时间内完成升级；提醒机制的价值体现在这个时间显著短于「只有打开设置才能发现」的现状。
- 提醒弹出后选择「重启并安装」的比例，与选择「跳过此版本」的比例；跳过率持续偏高说明提醒时机或版本价值表达有问题。
- 提醒弹窗打断正在运行任务的次数应当为零。

### 端到端验收

1. **无任务时的完整路径**：应用空闲，模拟检测到新版本 → 后台下载完成 → 提醒弹窗立即出现 → 点「重启并安装」→ 出现安装确认 → 确认 → 应用退出、安装、以新版本重新打开，且设置 → 关于显示「已是最新版」。
2. **有任务时的排队**：启动一个长时间运行的对话 → 安装包就绪 → 确认提醒弹窗没有出现、侧边栏「安装更新」与设置 → 关于「重启并安装」已出现 → 任务结束 → 提醒弹窗随即出现。
3. **稍后提醒的记忆**：提醒出现后点「稍后提醒」→ 等待跨过一个检测周期，确认没有再次弹出 → 重启应用 → 确认提醒重新出现且未重新下载。
4. **跳过此版本的记忆**：提醒出现后点「跳过此版本」→ 重启应用，确认不再提醒，且设置 → 关于显示「已准备好」、带有「你选择了跳过这个版本」的说明并保留「重启并安装」，侧边栏按钮也仍在 → 从关于区发起安装时进入任务保护确认；模拟出现更高版本，确认提醒恢复且跳过说明消失。
5. **关闭等同稍后**：提醒出现后按 Esc、以及点击蒙版 → 分别确认弹窗关闭，且重启应用后提醒重新出现（即被记为「稍后提醒」而非「跳过」）。
6. **定时检测生效**：应用保持运行、不重启、不手动点「立即检查」，在此期间发布一个新版本 → 跨过一个检测周期后，应用自行完成检测与下载并按第 3 步的时机弹出提醒。这是定时检测唯一的用户可观察结果，产品不为「检测发生过」本身提供额外界面信号。
7. **定时检测不打断**：下载进行中时跨过一个检测周期，确认下载进度继续推进、没有被重新发起，设置 → 关于的状态不回退到「检查中」。
8. **弹窗的通用行为**：提醒弹窗与安装确认弹窗均有蒙版、可 Esc 关闭、可点击蒙版关闭，键盘可达且焦点被限制在弹窗内。
9. **中英文完整**：两个弹窗的全部文案在简体中文和英文下均完整，无混用。
10. **失败结果就地可见**：分别制造任务停止失败、零任务安装失败与任务已停止后的安装失败 → 确认当前界面立即出现应用内失败弹窗，准确说明任务与安装结果 → 点「重试」重新读取当前任务数并进入相应确认；关闭失败弹窗后应用可继续工作、About 显示明确的安装失败而非检查失败，两个安装入口仍在。

## 非目标

- 不解决 Intel Mac 与 Windows 的更新通道。当前发布通道只覆盖 Apple Silicon Mac，其余平台用户不会进入本流程；这是发布范围问题，另行讨论。
- 不提供关闭自动检查或自动下载的设置项，也不提供预发布/测试通道选择。
- 不做静默强制更新、不做到期强制升级、不做企业策略下发。
- 不定义安装过程中的任务清理与退出保护细节，那由既有退出保护承接。
- 不改动普通退出（有任务运行时按 `Command + Q`）的确认弹窗。本轮的弹窗组件统一只覆盖更新提醒与安装确认两个弹层，普通退出保护继续使用系统原生对话框。这是明知的取舍：两个弹窗语义相近，短期内会出现视觉规格不一致，但普通退出发生在窗口已进入关闭时序的时刻，改造风险与本流程无关，单独一轮处理更稳妥。
- 不定义增量更新、回滚到旧版本或多版本并存。
