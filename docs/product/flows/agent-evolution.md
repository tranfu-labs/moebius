# Agent 进化

> 状态：2026-08-27 方案确认、实现中。
>
> 2026-08-27 产品决定：官方安装与 GitHub 安装都产生普通本地团队；安装来源只保存为描述性元数据，不建立订阅或更新关系。本文因此只定义本地调教留痕、变化回看和历史回退，不再定义来源检查、自动同步、合并或整支撤销。
>
> 范围：定义 Agent 的 `AGENT.md` 在本地被调教、被记录、被回看、被回退，以及安装来源如何在这些本地行为之外提供识别信息。页面内部的区域、控件与状态由各自页面 PRD 承接。

## 用户目标

用户希望自己对 Agent 的每一次本地调教都被记住、看得见、退得回；也希望清楚知道一支团队最初从哪里安装，但不需要把来源当作持续维护关系。

这条流程让 Agent 团队像一位有记忆的同事：你教过它的话它记得，之后可以回看这次变化并回到旧版本。来源仓库或安装包只解释内容的起点，不在后台改写本地团队。

## 开始条件

流程有一个主起点，并有一个不属于“进化”的安装起点：

- **本地调教**：用户在团队页修改某名成员的 `AGENT.md` 并保存成功，或在 Finder 中直接修改文件后被应用读取到。
- **安装团队**：官方 seed 或 GitHub 预览安装创建一支新的本地团队。安装内容是这支团队的本地起点，不产生修订同步批次。

来源仓库不会在安装后被应用自动检查、拉取或合并。用户想采用 GitHub 仓库的新内容时，重新打开预览并安装一支新的团队，或直接编辑当前本地团队。

## 参与者与职责

| 参与者 | 职责 | 明确不负责 |
| --- | --- | --- |
| 用户 | 调教 Agent、事后回看变化、不满意时回退 | 不需要处理来源更新，也不需要裁决远端合并 |
| 桌面应用 | 记录本地修订、呈现变化与来历、承接成员级回退、展示安装来源 | 不执行来源同步，不修改已安装团队的来源内容，不向上游推送本地改动 |
| 默认 Agent | 为本地修订写一句用日常语言表达的说明；服务于将来的本地自动进化 | 不参与来源导入或远端更新裁决 |
| 安装来源 | 在安装和团队页中提供来源识别信息 | 不获得访问本机内容的能力，不能修改用户本地团队 |

## 主流程

### 一、本地调教留痕

用户每一次成功保存 `AGENT.md`，应用记录一条修订。一条修订包含当时的完整内容、作者、发生时间，以及一句用日常语言说明这次改了什么的摘要。

- 作者是**你**或 **Agent**；当前产品版本不把来源仓库的后续内容自动写成本地修订。用户在 Finder 中的外部修改同样记为“你”，与在团队页里改没有区别。
- 摘要由默认 Agent 在保存完成后于后台撰写，不阻塞保存。摘要尚未产出或写不出来时，用中性说明占位，不留空白，也不编造内容。
- 修订记录保存在应用自己的数据目录，团队文件夹里始终只有当前内容。用户用 Finder 打开团队目录时看到的是一份干净的 `AGENT.md`。
- 修订史暂不设置数量或时间上限。

### 二、看见变化与来历

用户查看 `AGENT.md` 的位置只有一个：团队页里的 Markdown 编辑器。不存在独立的“变化查看模式”或历史对比页，编辑器本身就是阅读视图。

- 编辑器上方常驻一行最近变化的摘要，用户不展开全文也知道最近发生了什么。
- 正文中最近由本地保存产生的变动段落在左侧带标记，标记旁标明来历（“你 · 3 天前”或“Agent”）。
- 点击标记就地展开一小块，说明这里原来是什么，不跳转、不打开第二个界面。
- 从最近变化那一行可以展开完整时间线，按次列出每条本地修订的摘要与作者，并从任意一条回到那一版。
- 团队页另外展示 `installationSource`：GitHub 来源可打开仓库链接，Moebius 来源可显示来源标签；该信息不进入修订作者，也不触发来源访问。

这套呈现回答两个问题：“我刚说的它记住了吗”和“这条规矩是哪次本地修改留下的”。来源展示回答的是第三个问题：“这支团队最初从哪里安装”。三者互不替代。

### 三、来源内容不自动进入本地团队

- 官方安装与 GitHub 安装都写入普通本地团队目录、团队 record、显式运行绑定和 `installationSource`。
- 新安装不写 `official-state-v1.json`，也不创建用于来源更新的基线、订阅关系、检查任务或同步批次。
- 团队页不提供“重新检查”“同步更新”“撤销同步”或“停止接收更新”。来源仓库删除、改名、转私有或暂时不可访问，都不会改变已安装团队的内容、可用性或页面状态。
- GitHub 来源团队需要新内容时，用户重新预览并导入一支新的团队；新的导入是另一支本地团队，当前团队的本地修改不会被静默替换。

### 四、正在使用该团队的对话

本流程只承接本地已保存团队版本的既有会话语义，不新增来源同步提示。已经载入团队快照的会话继续遵守会话版本冻结规则；后续新会话使用当前可用的本地团队版本。

如果主对话页为本地团队变化提供查看、应用或关闭提示，三个动作沿主对话页的既有定义执行；本次变更不会把来源仓库更新混入这些提示。

### 五、回退

- 成员级时间线可以回到该成员的一条历史本地修订；回退本身也是一条新的本地修订，可以再次回退。
- 回退只作用于用户选定的成员和本地版本，不创建来源更新批次，也不提供整支团队的来源撤销。
- 回退失败时保留当前内容和原有修订记录，不留下半份成员文件；沿用团队文件修复与保存失败的既有错误处理。

## 分支与异常

- **摘要写不出来**：修订照常成立，摘要位置用中性说明占位。摘要缺失不影响本地内容、历史回退或变化提示。
- **保存过程中退出应用或崩溃**：沿用现有文件事务与恢复规则，不留下半写入的成员文件；已经成功保存的其他成员不被静默回滚。
- **团队处于需要修复状态**：沿用既有修复流程；修复完成后再按本地文件规则继续，不从来源仓库重建团队。
- **用户在 Finder 中编辑同一份 `AGENT.md`**：沿用外部修改与本地草稿的既有冲突语义，保存成功后作者记为“你”。
- **刚从 GitHub 装进来的团队**：安装本身不产生本地修订记录；首次内容来自预览快照，后续编辑才进入本地时间线。
- **来源仓库不可访问**：已安装团队照常使用，页面不产生失联状态或更新待办；来源链接打开失败沿用外部链接失败处理。
- **存量官方团队**：旧 `.system` 目录、历史会话/SQLite ownership、旧 revision 路径和 `official-state-v1.json` 只按兼容读取规则使用，不启动迁移、搬迁、覆盖、删除或同步。

## 等待与自动推进

本流程没有来源检查、同步或后台合并需要等待。用户保存本地内容后看到保存结果；摘要生成继续沿既有后台摘要规则推进，不改变本地内容的原子保存结果。

## 完成条件

一次本地调教的完成，表现为：保存成功反馈出现；编辑器上方最近变化那一行更新为这次的摘要；正文对应段落出现署名为“你”或“Agent”的标记；成员时间线可以回看这条修订。

一次官方或 GitHub 安装的完成，表现为：普通团队目录、团队 record、显式运行绑定和来源元数据全部写入；团队出现在团队页和选择器中；打开和新建对话可用；不产生来源更新任务或官方状态文件。

## 指标与验收

### 产品指标

- **本地调教留痕率**：成功保存的本地成员修改中，能在时间线回看的比例。
- **来源识别清晰度**：用户能从团队页区分 Moebius 来源、GitHub 来源和无来源本地团队的比例。
- **本地回退成功率**：用户从成员时间线发起回退后，目标本地修订成为当前内容的比例。
- **看懂成本**：用户在不打开完整历史的情况下，能从最近变化行说出最近一次本地变化的比例。

### 验收清单

1. 用户保存 `AGENT.md` 后能在成员时间线看到本地修订、作者和摘要。
2. 用户可以从成员时间线回到一条历史本地修订，回退失败不破坏当前内容。
3. 官方安装与 GitHub 安装都生成普通可编辑本地团队，并写入各自的 `installationSource`。
4. 新安装不依赖 `official-state-v1.json` 或打包 `official.json` 才能在团队页发现和打开。
5. GitHub 来源只提供仓库识别和打开链接，不提供检查、同步、撤销、停止接收更新或后台任务。
6. 来源仓库不可访问时，已安装团队照常可用，页面不产生失联状态或更新待办。
7. 已有 `.system` 官方团队、历史会话和旧状态按兼容读取继续可用，不发生启动迁移或自动同步。
8. 已载入团队快照的历史会话继续遵守既有冻结规则；来源元数据不会静默替换会话内容。

## 待讨论

- **时间线的呈现密度**：连续多次短时间内的本地修改是否合并成一条，避免噪音。
- **Agent 自动进化**：任务结束后由一个 Agent 分析对话、自动改进 `AGENT.md`。修订记录已为它预留作者维度，但触发时机、审阅方式与关闭开关尚未讨论。

## 非目标

- 不做产品自建的分发服务、订阅关系或注册中心。GitHub 仓库只是 GitHub 来源安装时的内容来源和识别信息。
- 不向来源仓库推送用户的本地修改；用户想把自己的改动发出去，走 GitHub 自己的路。
- 不提供来源检查、自动同步、远端合并、整支来源回滚或“停止接收更新”。
- 不做通用版本控制：没有分支、没有合并请求、没有多人协作、没有远程仓库概念。
- 不向用户展示增删行、差异格式或任何版本控制术语。`AGENT.md` 的历史以自然语言摘要、来历和成员时间线表达。
- 不做跨团队的规则共享或规则库。
- 不改变会话快照的既有冻结规则：本地团队后续保存不会改写任何已有会话当前载入的团队版本。
