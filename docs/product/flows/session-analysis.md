# 对话分析与优化

> 状态：直接父子归属、入口面板与 Markdown 来源导航已完成产品采访；文本片段采用“所见即所传”契约
>
> 关联页面：[主页面会话区](../pages/main-conversation.md)、[主页面右侧栏](../pages/main-right-sidebar.md)、[主页面侧边栏](../pages/main-left-sidebar.md)、[Agent 团队](../pages/agent-teams.md)
>
> 范围：定义用户从一段正在运行或已经结束的 Moebius 根对话，或任一对话中的 Agent 消息收集来源引用，在右侧栏开始一段可从直接父对话找回的分析对话，先确认优化方案、再由所选团队按正常权限修改本地文件的完整流程。根对话支持整段与消息级入口；分析对话只支持消息级入口，不提供“分析整段分析对话”。来源对象只决定发送前文本胶囊以及发送后的 Markdown 来源引用；胶囊中可读取的完整文本是唯一会插入消息并交给 Agent 的内容，应用不再根据引用后台展开消息、对话、运行记录或完整输出。标题、时间线、运行记录、输入框、附件和运行操作继续由页面 PRD 定义，本流程不另造一套分析专用布局或权限模型。

本文按用户可观察层级使用术语：

- **对话**：用户在主内容区或右侧栏中阅读、继续、查找和管理的完整对象，包括界面中的「新对话」。
- **消息**：对话时间线中的一条用户或 Agent 内容。
- **会话**：只用于会话记录文件、外部执行会话、provider session 等技术对象，以及关联文档的既有专名；不与「对话」交替指代同一个用户对象。

## 用户目标

用户在监督一支 Agent 团队时，希望不用离开 Moebius、复制日志或另开终端，就能针对当前对话继续追问：

- 团队运行是否符合这支 Agent 团队的设计预期；
- 一次运行为什么耗时很长，主要时间花在哪里；
- 团队、Agent 职责或本地文件是否需要调整；
- 确认优化方案后，由当前所选团队按普通对话权限修改工作空间、一个或多个团队配置，或方案涉及的其他本地文件。

这段分析本身是一段正常、持久、可继续的 Moebius 对话。它不依附于某一种诊断问题，也不把来源对话自动变成动态数据源。

## 开始条件

- 用户拥有一段归属于本地项目和工作空间的对话；来源对话可以仍在运行，也可以已经结束。
- 用户从任一根对话或分析对话的时间线中打开 Agent 消息菜单并选择「在右侧栏分析这条消息」，或从左侧栏根对话行打开菜单并选择「在右侧栏分析这段对话」。
- 分析对话没有左侧栏行，也不在标题区、分析面板或其他位置提供「在右侧栏分析这段对话」；需要继续下钻时，用户选择其中某条具体消息。
- 使用任一入口都不要求来源对话先停止或完成。
- 右侧栏原本关闭时，入口负责打开右侧栏；右侧栏已经打开时，入口直接在现有标签工作区继续。

## 参与者与职责

### 用户

- 决定从哪些消息或整段对话收集文本线索；
- 选择候选问题或自行输入分析目标；
- 阅读分析结论、修订优化方案并决定是否确认；
- 确认后继续监督修改与验证结果。

### 桌面应用

- 按入口对象生成消息级或对话级来源引用，并以可删除的文本胶囊放入尚未发送的新对话；
- 在首次发送前维护分析草稿，在首次发送成功后创建持久化对话；
- 为分析草稿预选来源对话的项目与工作空间，并把「通用助手」作为初始团队；
- 首次发送成功后，把文本胶囊按固定格式序列化为首条用户消息顶部的 Markdown 来源块，并把新对话登记到直接来源对话的分析面板；
- 从直接来源对话的分析面板打开或聚焦已创建分析对话的唯一右侧栏标签，不在左侧栏生成入口；
- 将 `moebius-ref:` 作为公开应用内导航文本解析；只按当前用户已有访问范围打开目标，不因引用存在而增加文件或对话权限；
- 把发送前胶囊中可读取的完整文本按顺序序列化到用户消息中，并保证同一片段只出现一次；`moebius-ref:` 只用于用户激活后的应用内导航，不触发后台来源读取；
- 保证方案获得用户确认前，分析对话不会修改工作空间、团队文件或其他本地状态；
- 在分析对话内部需要查看完整输出、文件或子任务时，把目标打开为同一外层右侧栏中的兄弟标签，不嵌套第二层右侧栏。

### 所选团队的主 Agent

- 新对话默认预选「通用助手」团队；用户发送前改选团队时，由最终所选团队的主 Agent 接收首条消息；
- 不从“分析入口”获得额外角色或文件权限，只依据用户正文、消息中可见的来源片段与普通附件理解本轮目标；
- 先分析并提出可讨论的优化方案，等待用户确认；
- 用户确认后，按普通对话已有权限修改已确认方案涉及的本地文件、验证并报告结果。

### 来源对话及其团队

- 不自动参与新的分析对话；
- 团队、成员职责、CLI、model 和 effort 不被分析对话继承；
- 来源对话继续按原节奏运行，不因用户开始分析而自动暂停或停止。

## 主流程

### 1. 从来源消息或根对话开始分析

用户从任一对话的时间线选择「在右侧栏分析这条消息」，或从左侧栏根对话行选择「在右侧栏分析这段对话」后，应用都在直接来源对话所属的外层右侧栏中查找同一初始工作空间下尚未发送的分析新对话：

- 已存在时，聚焦该标签并在原有文本胶囊之后追加一条与本次入口对象对应的文本片段；
- 不存在时，新建一个标签，显示与[主页面会话区的新对话](../pages/main-conversation.md#新对话从项目行进入项目已带上)相同的布局与样式。

消息入口位于根对话时，不改变左侧栏选中对象；位于右侧栏分析对话时，新草稿作为同一外层右侧栏中的兄弟标签打开，不嵌套第二层右侧栏。从左侧栏菜单对非当前根对话触发时，先原子地切换到该根对话及其自己的右侧栏标签组，再打开或聚焦分析草稿；任一步失败都保留进入前的主内容、右侧栏、选中态和阅读位置。

同一直接来源对话中的两种入口复用同一份分析草稿、同一套草稿归并规则和同一个右侧栏标签，不因来源是一条消息还是根对话整段而分裂成不同分析模式。分析对话中的消息入口也复用这套规则，但归并范围只属于该分析对话，不与根对话或其他分析对话的草稿混合。分析新对话不是专用面板。除下列增量外，标题、空态、上下文、输入框、附件入口和发送行为全部复用正常新对话：

```text
┌ 右侧栏 ─────────────────────────────────────┐
│ 新对话 ×                                  ＋ │
│──────────────────────────────────────────────│
│                                              │
│                    新对话                    │
│                                              │
│           Agent 运行不符合预期？             │
│           Agent 运行太长了？                 │
│                                              │
│ ┌──────────────────────────────────────────┐ │
│ │ [项目] [工作空间] [分支] [通用助手]      │ │
│ │ [文本片段 1 ×] [文本片段 2 ×] …          │ │
│ │ 描述你的目标…                      ＋  ↑ │ │
│ └──────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘
```

项目与工作空间来自来源对话；「通用助手」只是初始团队。它们都是正常新对话中的预选值，不是锁定值：首次发送前，用户可以按普通新对话规则改选项目、工作空间和团队，创建时以发送瞬间仍显示的选择为准。用户改选工作空间后，这份草稿不再接收来源对话原工作空间后续入口追加的文本；后续入口改为查找或建立与来源工作空间匹配的另一份草稿。

分析对话创建后，团队查看与切换继续沿用普通主对话规则，不把通用助手锁成不可更改的特殊模式。

### 2. 收集来源引用

每次入口追加一个发送前文本胶囊。胶囊只显示「文本片段 1」等短标签；悬浮、键盘聚焦和辅助技术读取该胶囊将插入消息的完整文本。入口对象决定来源类型：

- **消息级来源**：来自「在右侧栏分析这条消息」，记录来源对话与消息的稳定标识。发送后显示为成员、消息开头和应用内消息链接；激活时打开或聚焦来源对话，定位并短暂突出该消息。
- **对话级来源**：只来自根对话左侧栏的「在右侧栏分析这段对话」，记录根对话的稳定标识。发送后显示为对话标题和应用内对话链接；激活时打开或聚焦来源根对话，不伪造消息位置。

分析对话本身不提供整段分析入口；从分析对话继续下钻时只能生成消息级来源。公开的对话级 `moebius-ref:` 仍可指向可访问的分析对话，这项导航能力不等于产品提供了“分析整段分析对话”的创建动作。

来源引用只承担两项公开职责：把发送前胶囊的文本保存进历史，以及供用户激活后在应用内导航。传给 Agent 的内容遵守“所见即所传”：

- 胶囊的辅助说明、键盘聚焦文本与辅助技术可读取文本必须展示该胶囊将插入的完整 Markdown 文本；
- 首次发送时，每个仍保留胶囊的文本按用户排列顺序原样插入一次；运行时不得因为其中含有 `moebius-ref:` 再追加目标消息、目标对话、结构化 run 记录、stdout、stderr 或完整输出；
- 片段在发送成功后冻结在用户消息中。重试、重新运行、同一 run 恢复和恢复失败后的重新执行都只复用这份已持久化的可见文本，不刷新来源目标；
- 用户在正文中直接输入或粘贴合法 `moebius-ref:` 时，它只是普通的公开 Markdown 链接，不触发后台读取，也不授予额外来源权限；Agent 消息中的同格式链接同样只提供用户导航；
- 目标后来缺失、归档、无权访问或暂时不可打开，只影响用户点击链接后的导航反馈，不影响消息提交、排队或 Agent run；
- 时间线与实际 Agent 输入包含同一份来源块，不另存一份不可见来源正文。Agent 是否读取工作空间文件继续服从普通权限。

来源引用不充当文件附件，不把点击位置解释成固定分析范围，也不限制用户随后提出的问题。它不增加一般权限，也不形成跨项目、工作空间、团队或 provider 的隐式读取授权。

已创建分析对话中的普通后续消息，在主 Agent 忙碌时完全复用[主页面会话区的待发射队列](../pages/main-conversation.md#输入框)，包括持久化、顺序、失败恢复和用户操作；消息中的 `moebius-ref:` 不增加额外读取步骤或队首阻塞条件。

文本片段在输入框的附件区域占一行。每个胶囊右侧提供删除操作；空间不足时仍保持单行并允许横向查看，不展开完整来源挤压输入正文。

用户删除某个胶囊后，该段文本不进入首次消息。重复点击入口会继续追加新的胶囊，不新增标签，也不把内容写进正文输入框。

### 3. 选择问题

新对话空态在输入框上方提供候选提示词。候选项只帮助用户快速形成正文，不改变文本胶囊：

- 显示「Agent 运行不符合预期？」时，填入「分析这段对话是否符合这个 Agent 团队设计的预期」；
- 显示「Agent 运行太长了？」时，填入「分析这段对话为什么占用的时间那么长，主要耗时在哪一块，是否符合团队设计的预期，是否有优化空间」。

用户可以继续编辑候选内容，也可以完全不用候选提示词、自行输入问题。无论从哪种正文开始，分析对话都遵守先给方案、等待确认、再修改文件的共同规则。

### 4. 首次发送并创建对话

文本胶囊只提供上下文，不代替用户问题。正文为空时，即使已有一个或多个文本胶囊也不能发送；用户需要选择候选提示词或自行输入问题。对话标题因此继续按普通主对话规则取首条用户正文，不从来源标题、消息摘录、目标 ID 或「文本片段 1」生成。

首次发送先把仍保留的文本胶囊按用户排列顺序序列化为固定 Markdown 来源块，放在首条用户正文顶部，来源块与正文之间留一个空行；普通附件仍按正常消息规则提交。应用随后依次执行：

1. 把每个仍保留胶囊中可读取的完整文本按顺序各序列化一次，与正文组成首条用户消息。
2. 提交首条用户消息并创建分析对话，同时登记直接父面板入口。
3. 消息与对话创建成功后，再创建 run 并启动所选团队主 Agent；进程启动失败时保留已经创建的消息、对话和面板入口，按正常运行异常恢复。

创建成功后的用户可观察结果：

```markdown
> 来源：
> - [消息 · 开发 · “正在修改登录页空状态”](moebius-ref:message/<conversation-id>/<message-id>)
> - [对话 · “登录页运行分析”](moebius-ref:conversation/<conversation-id>)

分析这次运行为什么耗时过长。
```

- 当前标签原地从新对话切换为已创建对话，不另开标签；
- 对话标题按普通主对话规则从首条用户消息确定；
- 分析对话使用发送瞬间用户最终选择的项目与工作空间；
- 对话使用发送瞬间用户最终选择的团队；用户没有改选时就是「通用助手」，并载入这支团队自己的运行配置；
- 来源团队的成员、CLI、model 和 effort 不会仅因为来源关系自动进入分析对话；用户在发送前主动选择来源团队时，按普通新对话规则载入该选择；
- 分析对话成为直接来源对话的子对话，直接来源对话的分析面板新增一个可找回入口；左侧栏不新增普通根对话行；
- 候选提示词消失；
- 文本胶囊不再作为独立结构进入历史，时间线只渲染一份包含来源块的 Markdown 正文。
- 所选团队主 Agent 收到的来源内容与时间线中可见的来源块一致；应用不附加链接目标的消息、对话、运行记录或日志。

首次消息创建成功后，标签内容完整切换为 [main-conversation.md](../pages/main-conversation.md) 定义的已有对话布局。本流程不重新定义其标题、上下文顺序、时间线、运行记录、输入框、附件、停止、完整输出、重试、恢复或响应式表现。

这段分析对话仍位于外层右侧栏标签中。它内部的「完整输出」、结果卡片、子任务行、文件链接，以及从某条具体消息继续创建的下一层分析对话，都在当前外层标签条新建或聚焦兄弟标签；不得在分析对话内部再嵌套一层右侧栏，也不得错误使用来源对话的步骤或文件身份。关闭兄弟标签后仍可从直接父对话的分析面板再次打开。

首次提交尚未成功时，草稿仍是新对话，不在左侧栏或直接父对话的分析面板产生半成品入口；用户的正文、文本胶囊、普通附件和已预选上下文全部保留以供重试。

来源块中的消息标题、对话标题和摘录转义、长度截断、不可见字符清理及不可用降级，统一遵守[主页面会话区](../pages/main-conversation.md)的规则。`moebius-ref:` 是公开应用内文本协议：应用、用户、Agent 或复制粘贴生成的合法引用表现相同；未知自定义协议继续阻止。

### 5. 分析并确认方案

首次启动的主 Agent（默认是通用助手）收到包含可见来源片段的首条消息后先分析问题、说明判断依据并提出优化方案。存在多项来源时必须分别辨认；片段信息不足时明确指出判断缺口，不得假装已经读取链接目标。每次完整提出或实质修改方案都会形成一版新的当前方案；用户的确认只授权确认时那一版方案及其中明确覆盖的修改范围，不能沿用到后来改变的方案。

当前方案获得确认前，Agent 可以继续读取、搜索、解释和讨论，也可以运行明确不会留下持久变化的诊断；不得写入工作空间或团队文件，不得安装依赖、运行会生成或改写文件的命令，也不得执行其他可能改变本地状态的操作。

用户不需要输入固定口令，也不需要点击专用按钮：

- 用户在方案之后回复「可以，就按这个方案改」或语义等价的明确同意时，授权整版当前方案；
- 用户回复「只做第 2 项」时，只授权当前方案中被明确点名的范围；
- 用户提出疑问、否定或要求微调时，Agent 继续讨论；方案被实质修改后，旧确认失效，新的当前方案必须重新等待确认；
- 「为什么这样改」「再看看」「第 2 项方向不错」「先别改」、沉默、追问或只认可判断，都不构成修改授权；
- 用户切换团队不会扩大已有授权；新团队若改变方案或修改范围，必须重新等待确认。

如果 Agent 在未确认或超出已确认范围时尝试写入，操作不能执行；正常时间线中说明当前方案仍待确认或本次操作超出确认范围，并允许用户继续讨论。这里不增加专用状态条，但写入拦截必须是用户可见、可重复验证的事实。

候选提示词可以提醒用户这段对话会先给方案，但候选提示词不是唯一约束。用户自行输入问题时，同样必须等待确认。

### 6. 修改与收尾

用户确认后，当前主 Agent 恢复普通对话本来具有的写入能力，并只执行当前方案已经确认的范围。确认范围可以包含最终选择的工作空间、一个或多个团队的配置与 Agent 文件，或方案明确涉及的其他本地文件。

来源对话、被点击的 run、文本胶囊和“分析”命名都不授予、缩小或推断文件权限，也不把任何团队自动变成唯一修改目标。实际可读写范围继续由当前所选团队、Agent 配置与普通对话运行环境决定；超出正常权限的目标仍按不可访问处理。

任何团队配置修改都只影响以后重新载入该团队的对话与 run，不改写已经创建对话所冻结的团队快照。

来源对话是否仍在运行不构成等待条件；两段对话可以同时作用于同一个工作空间。Agent 在确认后的写入开始前必须重新检查目标文件现状：

- 如果并发变化不改变已确认方案，可以在确认范围内继续并说明发现了变化；
- 如果变化使方案或修改范围需要调整，先说明分歧并提出新版方案，重新等待用户确认；
- 如果无法安全合并，不得静默覆盖，必须停止对应写入并给出保留双方改动的恢复建议。

修改阶段完全复用普通主对话与[单 Agent 会话](../pages/agent-conversation.md)的运行记录、停止、完整输出、异常、重试和恢复规则。完成时，当前主 Agent 在正常时间线回复中说明：

- 实际修改了什么；
- 做了哪些验证；
- 哪些风险或问题仍未解决。

本流程不增加「分析中」「等待确认」「已进入修改」等专用状态标记。能够由对话内容本身表达的推进状态，继续由对话内容表达。

### 7. 再次开始分析

一旦首次消息成功创建对话，后续再次从直接来源对话的消息或根对话左侧栏入口开始分析时：

- 不向已经创建的分析对话静默追加文本；
- 若当前来源对话和来源初始工作空间已有另一份尚未发送且仍保持该工作空间的分析新对话，则聚焦并追加与本次入口对象对应的文本片段；
- 否则新建下一份分析新对话。

因此，同一直接来源对话和同一初始工作空间同时至多有一份仍保持该工作空间的未发送分析新对话，但可以存在用户改选了其他工作空间的草稿，以及多段已经创建、彼此独立的直接子分析对话。每段已创建分析对话都只登记在自己的直接父对话面板中；孙辈不向根对话或更早祖先重复汇总。

## 分支与异常

### 用户移除文本片段

删除只影响尚未发送草稿中的对应胶囊，不修改来源对话，也不影响其他文本片段、正文或普通附件。发送成功后胶囊已经转换为 Markdown 来源块，不再存在可单独删除的历史胶囊；用户使用「改一改重发」时编辑的是完整 Markdown，重发不得自动重复拼接来源块，后续 run 只使用编辑后消息中可见的文本。

### 用户离开或关闭右侧栏

尚未发送的分析新对话沿用普通新对话草稿的保留原则：切换对话、切换页面、窗口变化或重新启动应用后，已输入正文、文本胶囊、普通附件和预选上下文仍可恢复。草稿不会因为被隐藏而提前创建左侧栏行或父面板入口。

切换页面或隐藏右侧栏只是暂时离开，不等于丢弃。用户点击分析新对话标签上的关闭操作则是主动丢弃：

- 草稿只含系统预选上下文、没有正文、文本胶囊或普通附件时，直接关闭并丢弃；
- 草稿已有正文、文本胶囊或普通附件时，先明确询问是否丢弃；
- 用户确认丢弃后删除整份草稿，下一次入口创建全新草稿；
- 用户取消丢弃时保持原标签、内容和焦点不变。

关闭最后一个右侧栏标签时，右侧栏随之关闭。用户之后仅通过主内容区的显示按钮重新打开右侧栏时，先进入「这个标签要看什么」的内容选择状态，不自动伪造一个高亮的「新标签」。仍被保留而非主动丢弃的分析草稿，在用户再次从直接来源消息或根对话左侧栏入口开始分析时恢复并聚焦。

### 首次创建失败

文本片段序列化、消息提交或对话创建失败时，应用保留整份草稿并显示可理解原因，允许原地重试，不留下消息、对话与父面板入口彼此不一致的半成品状态。链接目标不可用不是创建失败条件。

### Agent 启动失败

只有首条消息和对话已经创建后，才会尝试启动所选团队主 Agent。此时进程没有成功启动属于已创建对话中的运行异常：消息、分析对话和父面板入口全部保留，不恢复成新对话草稿。用户按普通主对话规则查看原因、重试或继续说话；重试创建新 run 时仍使用已持久化的可见消息文本。

### 通用助手暂不可用

若内置「通用助手」团队当前不能用于创建对话，应用保留分析草稿并明确说明需要修复团队；不得静默改用来源团队、最近使用的团队或其他模型。用户仍可以通过正常团队选择器主动改选另一支可用团队。

### 来源引用不可用

来源引用不会带来额外读取权限。目标对话或消息缺失、不可访问或暂时无法打开时：

- 发送前胶囊与已发送 Markdown 都保留创建时生成的可读文本；
- 消息仍可提交、排队并启动 Agent，链接目标状态不会形成隐藏的发送前校验；
- 用户激活链接时显示可聚焦的「来源不可用」，不得当成外链打开；
- 应用不复制记录、猜测替代目标或提升权限。

来源目标后来新增、修改、归档或恢复，都不改写已经冻结在消息里的文本。重试、重新运行和恢复仍使用同一份可见消息；历史中的导航链接只按点击当时的目标可用性决定能否打开。

### 目标文件不可修改

已确认方案中的工作空间、团队文件或其他本地目标不可访问、已经移除、损坏或在确认后变得不可写时，其他彼此独立且仍在授权范围内的修改可以继续；不可写部分停止，并在正常回复中说明阻塞对象和恢复方式。不得因为某个目标不可写而把修改静默转移到同名文件、同名团队或其他位置。

### 来源对话继续运行

开始分析、确认方案和修改文件都不自动停止来源对话。Agent 在确认后写入前重新检查文件；发现并发变化时按本流程的方案版本规则继续、重取确认或停止冲突写入。本流程不承诺自动隔离、自动合并或回滚。

### 父对话或根对话不可用

已创建分析对话没有独立左侧栏入口，也不在父对话不可用时改挂到其他对话。标准找回路径始终从根对话开始，逐层通过直接父对话的分析面板打开：

- 归档根对话时，整棵直接父子树递归隐藏；恢复根对话时一起恢复；
- 任一后代仍有运行中或待接回控制工作时，根对话归档不可执行；
- 关闭分析对话右侧栏标签只关闭视图，不归档、不删除，也不改变父子归属；
- 项目移除与重新添加的可见性结果由项目流程和左侧栏统一定义，但不得重写父子关系、把分析对话变成根对话或生成独立左侧栏入口。

父对话暂时不可访问时，本流程不伪造主内容区降级入口；恢复条件满足后仍从原父面板找回。

分析面板中的已创建入口随对话树持久化；面板的开合状态只在当前应用进程内按具体对话记忆，软件重启后默认关闭。重启后的找回路径是打开根对话，再按需要逐层打开直接父面板和目标分析对话。

## 等待与自动推进

- 选择消息级或根对话级分析入口后，打开或聚焦直接来源对话所属的分析新对话并追加对应文本胶囊是自动动作。
- 首次发送后的片段序列化、消息与对话创建、父面板登记和 Agent 启动按本流程定义的顺序自动推进；前一步失败时不得越过边界执行后一步。
- 当前主 Agent 完成分析并提出方案后，流程必须等待用户确认。
- 用户继续讨论时，流程保持在方案阶段。
- 用户明确确认当前方案后，当前主 Agent 自动进入已授权范围的修改与验证，不再请求“继续”类二次确认。
- 来源对话仍在运行时，分析与修改不额外等待。
- 运行失败、停下、卡住与恢复入口全部沿用普通对话规则；所有恢复或新 run 都使用对应用户消息中已经持久化的可见文本，不刷新链接目标。本流程不增加自动重试。

## 完成条件

本流程在以下条件同时满足时完成：

- 所选 Agent 获得的每个来源片段都与用户发送前可读取、发送后可见的文本一致，且没有附加链接目标的隐藏内容；
- 当前主 Agent 已经按用户确认的方案完成约定范围内的修改；
- 必要验证已经实际运行，未验证部分被明确说明；
- 正常对话时间线中留下修改结果、验证结论和剩余风险；
- 用户可以从直接父对话的分析面板再次打开这段分析对话；更深层对话可以从根对话开始逐层找回，不需要也不产生独立左侧栏入口。

如果用户只需要分析而不确认修改，流程可以停留在方案阶段；这是一段有效、可继续的对话，不视为失败或半成品。

## 涉及页面

- [主页面会话区](../pages/main-conversation.md)：在任一对话的 Agent 消息菜单中提供「在右侧栏分析这条消息」，定义发送前胶囊、发送后 Markdown 来源块、直接子分析面板及复用的对话布局。
- [主页面右侧栏](../pages/main-right-sidebar.md)：承载分析草稿与已创建分析对话的唯一标签、兄弟标签、跨树工作现场、标签关闭和恢复。
- [主页面侧边栏](../pages/main-left-sidebar.md)：只在根对话行菜单中提供「在右侧栏分析这段对话」；已创建分析对话不进入左侧栏，也不独立归档。
- [Agent 团队](../pages/agent-teams.md)：提供正常可见、可编辑的内置单成员「通用助手」团队及其独立运行配置。
- [单 Agent 会话](../pages/agent-conversation.md)：提供当前主 Agent 每次运行的活动、耗时、停止、完整输出、异常、重试和恢复语义。

这些页面只维护各自范围内的入口和表现；跨页面的草稿、创建、确认、修改与找回顺序以本流程为准。

## 指标与验收

### 产品指标

- **复盘启动成功率**：用户不离开 Moebius、不手工复制路径或目标 ID，成功提交包含所选文本片段的首条分析问题并启动 Agent 的任务数 / 尝试任务数；首版目标为 100%。
- **片段交付正确率**：每个已发送文本片段单独计量；Agent 输入中该片段与发送前胶囊可读取文本完全一致、只出现一次，且没有追加链接目标隐藏内容的片段数 / 总片段数；目标为 100%。
- **上下文可预期率**：真实复盘任务中，用户仅凭发送前胶囊可读取文本即可准确预期 Agent 将获得哪些来源内容的任务数 / 对应总任务数；目标为 100%。
- **复盘启动成本**：从打开消息级或对话级分析入口到提交首条问题，不把阅读和输入时间计入时，用户只需完成入口选择、可选候选提示词和发送，不增加项目、工作空间或团队的必选设置步骤。
- **方案闸门越权率**：测试矩阵中，未确认、确认旧方案、只确认局部范围或明确拒绝时发生持久写入的用例数 / 对应总用例数；目标为 0。
- **对话找回成功率**：来源树可用时，已创建分析对话在切换页面与重启应用后能够从直接父面板重新打开并继续对话的用例数 / 总用例数；目标为 100%。
- **来源导航成功率**：每个被激活的来源项单独计量；消息级引用一次激活后到达对应对话与消息，对话级引用一次激活后到达对应对话，跨树时恢复正确根对话及其右侧栏工作现场；误定位目标为零。
- **产品内完成率**：真实复盘任务中，用户无需转到终端或外部聊天工具即可得到具体判断与可确认方案的任务占比；首轮内部试用记录基线，连续两版不得下降。

### 端到端验收

1. 用户可以从任一对话的 Agent 消息菜单选择「在右侧栏分析这条消息」，也可以从根对话左侧栏菜单选择「在右侧栏分析这段对话」，都不需要手工寻找或复制路径、目标 ID 或日志。
2. 分析对话没有左侧栏行，也不在标题区菜单、分析面板或其他位置提供「分析整段对话」；只能从其中某条具体消息创建下一层分析对话。
3. 同一直接来源对话和初始工作空间内，首次发送前多次进入只按点击顺序累积来源胶囊，不产生多个标签或持久化对话；分析对话与其根对话、父对话或兄弟对话的草稿不能混合。
4. 文本胶囊以短标签单行显示，每项均可在发送前移除，并能通过悬浮、键盘聚焦和辅助技术读取将插入消息的完整文本；这份文本就是 Agent 获得的全部片段内容。
5. 每个已保留片段的可读取文本按顺序原样插入一次。任何 Agent run 都不得因片段或正文中含有合法 `moebius-ref:` 而追加目标消息、完整对话、结构化运行记录或 stdout/stderr；引用不增加一般对话或文件权限。
6. 候选提示词与用户自由输入到达同一发送路径，不改变或替换文本胶囊；只有胶囊、正文为空时不能发送。
7. 分析新对话初始预选来源项目与工作空间及「通用助手」；用户可以在发送前改选，创建结果使用发送瞬间的最终选择。
8. 首次发送把保留胶囊按顺序转换为首条用户消息顶部的固定 Markdown 来源块，来源块与正文之间空一行；历史不再显示独立胶囊，对话标题只来自用户正文。
9. 首次发送成功后，原标签原地切换为普通已有对话视图；新对话成为直接来源对话的子分析对话，只在直接父面板增加入口，不在左侧栏新增根对话行。
10. 消息级来源一次激活后打开或聚焦目标对话、定位并短暂突出原消息；对话级来源只打开或聚焦目标对话，目标已经打开时保持原阅读位置。
11. 合法 `moebius-ref:` 不区分应用、用户、Agent 或复制文本的作者；格式非法、目标缺失或不可访问时保留原可读标签并显示可聚焦的「来源不可用」，不得进入外链流程或提升权限。
12. 来源标题和消息摘录经过确定的安全 Markdown 纯文本投影、空白与控制字符清理、特殊字符转义及 Unicode grapheme 截断；长文本、Emoji、代码、链接、图片、附件和嵌套来源块都不能破坏链接边界或串改正文。
13. 来源目标属于另一棵对话树时，一次激活原子地切换到目标根对话、恢复该根对话自己的右侧栏标签组并打开或聚焦目标；失败时保持原工作现场和阅读位置。
14. 从分析对话消息创建的下一层只进入该分析对话自己的面板；打开下一层时复用同一外层右侧栏的兄弟标签，不嵌套侧栏，也不向更早祖先面板重复汇总。
15. 已创建分析对话中的完整输出、结果卡片、子任务和文件链接同样在当前外层右侧栏打开或聚焦兄弟标签，不出现来源身份串线。
16. 新入口不会向已创建分析对话静默追加来源，而是创建或聚焦另一份尚未发送的新对话。
17. 未发送草稿在页面切换、隐藏右侧栏和应用重启后恢复；主动关闭有内容的草稿先确认，确认丢弃后不再复活。
18. 含来源块的消息执行「改一改重发」时回填完整公开 Markdown，不恢复胶囊；用户可以编辑目标 ID，重发不自动追加第二份来源块。复用原用户消息的重试、重新运行与恢复保持原 Markdown 不变，也不读取或刷新链接目标；新用户消息只按自身可见文本进入 Agent 输入。
19. 当前方案未获确认、用户只追问或拒绝、确认的是旧方案或操作超出局部授权时，任何正常可写的本地目标都不发生持久变化，任何会产生持久变化的命令都不能执行，并出现正常时间线说明。
20. 用户明确确认整版或指定范围后，只执行对应当前方案与范围；方案实质变化或新团队提出不同方案时重新等待确认。
21. 确认后，当前主 Agent 只按普通对话权限执行已确认方案；方案可以涉及工作空间、一个或多个团队文件及其他正常可写目标，来源关系和来源块既不授权也不限制。团队修改只影响未来载入，不改写任何已冻结团队快照。
22. 来源对话运行中仍可分析与修改；发现并发变化时先重检，方案变化则重新确认，无法安全合并时不静默覆盖。
23. 「通用助手」不可用时保留草稿并明确说明，不静默换团队或模型；用户可以主动选择其他团队。
24. 关闭分析对话标签只关闭视图，不归档、不删除；用户可以从直接父面板再次打开。归档根对话递归隐藏全部后代，恢复根对话时一起恢复，分析对话没有独立归档入口。任一后代仍有运行中或待接回控制工作时归档不可执行并显示可读原因；停止或等待全部后代结束后，归档入口恢复可用。
25. 首次发送严格按“序列化可见片段 → 提交首条消息并创建分析对话及父面板入口 → 创建 run 并启动 Agent”的顺序执行。序列化、消息或对话创建失败时完整保留草稿且不留下彼此不一致的半成品；Agent 进程启动失败则保留已经创建的消息、分析对话和父面板入口并走正常恢复。
26. 从左侧栏对非当前根对话选择分析入口后，该行成为唯一选中项，来源根对话显示在主内容区，对应分析草稿显示在它自己的右侧栏标签组；切回此前根对话时，其标签、草稿与阅读状态仍在。任一目标未成功呈现时，进入前的选中项、主内容、右侧栏和阅读位置保持不变。
27. 直接父对话暂时不可访问时，不在主内容区或左侧栏生成分析对话的孤立降级入口，也不改变直接父子归属；父对话恢复后，分析对话仍只从原父面板找回。
28. 对每个消息级或对话级胶囊，所选 Agent 获得的片段文本与胶囊通过悬浮、键盘聚焦和辅助技术公开的文本逐字一致；即使链接目标拥有大量消息与完整输出，也不能有任何目标内容被隐式附加。
29. 多项来源同时存在时，片段按用户排列顺序各出现一次；某项语法非法、目标缺失或无权访问都不改变其可见文本，也不影响其他片段、消息提交或 run 创建。
30. 合法 `moebius-ref:` 的目标读取失败或不可用不属于发送与运行前置条件；新消息和新 run 继续按普通流程创建，只有用户激活链接时才报告导航不可用。
31. 已创建分析对话中的普通用户或 Agent 消息即使包含合法 `moebius-ref:`，链接也只供用户导航，不向当前或下一次 Agent run 自动交付目标内容。
32. 文本片段可以随消息跨项目、工作空间、团队或 provider 使用，但传递的仍只有可见文本；链接不得形成读取来源对话、来源项目文件、运行记录或其他对象的隐式授权。
33. 来源对话在两次运行之间新增消息或运行输出时，复用原用户消息执行重试、重新运行或恢复都不能取得新增内容；只有用户重新创建片段或显式写入新消息的文字才进入后续 Agent 输入。
34. 已创建分析对话的主 Agent 忙碌时，用户连续发送两条普通后续消息，两项按发送顺序进入现有待发射区；切换对话或重启应用后，两项及其顺序不变。队首消息中的链接目标不可用不阻塞发射，第二项仍在队首完成后按顺序继续。

## 非目标

- 不把文本胶囊实现成文件附件、动态引用、自动刷新快照或可执行对象。
- 不把公开 `moebius-ref:` 当成作者身份、可信声明或额外权限。
- 不根据点击位置预先决定分析范围。
- 不因入口来自消息或根对话而创建两套分析草稿、标签、发送或后续对话行为；二者只改变来源类型。
- 不为分析对话增加「分析整段对话」入口，不把孙辈汇总到根对话或更早祖先面板。
- 不把已创建分析对话作为普通根对话放入左侧栏，也不提供独立归档入口或父对话不可用时的伪降级入口。
- 不继承来源团队、来源模型或来源 Agent 的 provider 会话。
- 不创建独立于现有对话运行时的「纯对话模式」或分析专用页面布局。
- 不要求来源对话结束后才能分析或修改。
- 不自动停止来源对话，不承诺并发修改的自动隔离、合并或回滚。
- 不自动判断团队设计一定正确，也不替用户确认优化方案。
- 不为已创建分析对话增加专用阶段标签、状态条或固定确认口令。
