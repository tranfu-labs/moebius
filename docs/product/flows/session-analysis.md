# 对话分析与优化

> 状态：消息级 / 对话级入口增量已完成产品采访，待用户视角复评
>
> 关联页面：[主页面会话区](../pages/main-conversation.md)、[主页面右侧栏](../pages/main-right-sidebar.md)、[主页面侧边栏](../pages/main-left-sidebar.md)、[Agent 团队](../pages/agent-teams.md)
>
> 范围：定义用户从一段正在运行或已经结束的 Moebius 对话或其中一条 Agent 消息收集静态文本线索，在右侧栏开始一段可找回的普通对话，先确认优化方案、再由所选团队按正常权限修改本地文件的完整流程。来源对象只决定插入消息级还是对话级文本片段，不改变分析草稿、标签、发送或后续对话行为。主对话的标题、时间线、运行记录、输入框、附件和运行操作继续由页面 PRD 定义，本流程不另造一套分析对话布局或权限模型。

本文按用户可观察层级使用术语：

- **对话**：用户在主内容区或右侧栏中阅读、继续、查找和管理的完整对象，包括界面中的「新对话」。
- **消息**：对话时间线中的一条用户或 Agent 内容。
- **会话**：只用于会话记录文件、外部执行会话、provider session 等技术对象，以及关联文档的既有专名；不与「对话」交替指代同一个用户对象。

## 用户目标

用户在监督一支 Agent 团队时，希望不用离开 Moebius、复制日志或另开终端，就能针对当前对话继续追问：

- 团队运行是否符合这支 Agent 团队的设计预期；
- 一次运行为什么耗时很长，主要时间花在哪里；
- 团队、Agent 职责或本地文件是否需要调整；
- 确认优化方案后，由当前所选团队按普通对话权限修改工作空间、一个或多个团队配置，或方案涉及的其他本地文件。

这段分析本身是一段正常、持久、可继续的 Moebius 对话。它不依附于某一种诊断问题，也不把来源对话自动变成动态数据源。

## 开始条件

- 用户拥有一段归属于本地项目和工作空间的对话；来源对话可以仍在运行，也可以已经结束。
- 用户从时间线中的 Agent 消息打开更多菜单并选择「在右侧栏分析这条消息」，或从左侧栏对话行打开对话菜单并选择「在右侧栏分析这段对话」。
- 使用任一入口都不要求来源对话先停止或完成。
- 右侧栏原本关闭时，入口负责打开右侧栏；右侧栏已经打开时，入口直接在现有标签工作区继续。

## 参与者与职责

### 用户

- 决定从哪些消息或整段对话收集文本线索；
- 选择候选问题或自行输入分析目标；
- 阅读分析结论、修订优化方案并决定是否确认；
- 确认后继续监督修改与验证结果。

### 桌面应用

- 按入口对象把携带的信息转成消息级或对话级静态文本，并以可删除的文本胶囊放入尚未发送的新对话；
- 在首次发送前维护分析草稿，在首次发送成功后创建持久化对话；
- 为分析草稿预选来源对话的项目与工作空间，并把「通用助手」作为初始团队；
- 在左侧栏提供已创建分析对话的找回入口，并恢复其来源对话和右侧栏标签；
- 不解析文本胶囊，不代替当前 Agent 读取其中的路径，也不因胶囊存在而增加文件读取权限；
- 保证方案获得用户确认前，分析对话不会修改工作空间、团队文件或其他本地状态；
- 在分析对话内部需要查看完整输出、文件或子任务时，把目标打开为同一外层右侧栏中的兄弟标签，不嵌套第二层右侧栏。

### 所选团队的主 Agent

- 新对话默认预选「通用助手」团队；用户发送前改选团队时，由最终所选团队的主 Agent 接收首条消息；
- 不从“分析入口”获得额外角色或权限，依据文本胶囊、候选提示词或用户正文理解本轮目标；
- 先分析并提出可讨论的优化方案，等待用户确认；
- 用户确认后，按普通对话已有权限修改已确认方案涉及的本地文件、验证并报告结果。

### 来源对话及其团队

- 不自动参与新的分析对话；
- 团队、成员职责、CLI、model 和 effort 不被分析对话继承；
- 来源对话继续按原节奏运行，不因用户开始分析而自动暂停或停止。

## 主流程

### 1. 从来源消息或对话开始分析

用户从时间线选择「在右侧栏分析这条消息」，或从左侧栏对话行选择「在右侧栏分析这段对话」后，应用都在来源对话的右侧栏中查找同一初始工作空间下尚未发送的分析新对话：

- 已存在时，聚焦该标签并在原有文本胶囊之后追加一条与本次入口对象对应的文本片段；
- 不存在时，新建一个标签，显示与[主页面会话区的新对话](../pages/main-conversation.md#新对话从项目行进入项目已带上)相同的布局与样式。

消息入口所在的对话已经显示在主内容区，不改变左侧栏选中对象。从左侧栏菜单对非当前对话触发时，复用同一条既有分析路由：先把该来源对话设为左侧栏唯一选中对象并显示在主内容区，再打开或聚焦它自己的右侧栏分析标签；原主内容对话的右侧栏标签、未发送草稿和阅读状态按原对话保留，切回时恢复。只有来源对话与目标分析草稿都成功呈现后才提交新的选中态；任一步失败都保留进入前的主内容、右侧栏和选中态，并显示可理解原因。

两种入口复用同一份分析草稿、同一套草稿归并规则和同一个右侧栏标签，不因来源是一条消息还是整段对话而分裂成不同分析模式。分析新对话不是专用面板。除下列增量外，标题、空态、上下文、输入框、附件入口和发送行为全部复用正常新对话：

```text
┌ 右侧栏 ─────────────────────────────────────┐
│ 新对话 ×                                  ＋ │
│──────────────────────────────────────────────│
│                                              │
│                    新对话                    │
│                                              │
│           Agent 运行不符合预期？             │
│           Agent 运行太长了？                 │
│                                              │
│ ┌──────────────────────────────────────────┐ │
│ │ [项目] [工作空间] [分支] [通用助手]      │ │
│ │ [文本片段 1 ×] [文本片段 2 ×] …          │ │
│ │ 描述你的目标…                      ＋  ↑ │ │
│ └──────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘
```

项目与工作空间来自来源对话；「通用助手」只是初始团队。它们都是正常新对话中的预选值，不是锁定值：首次发送前，用户可以按普通新对话规则改选项目、工作空间和团队，创建时以发送瞬间仍显示的选择为准。用户改选工作空间后，这份草稿不再接收来源对话原工作空间后续入口追加的文本；后续入口改为查找或建立与来源工作空间匹配的另一份草稿。

分析对话创建后，团队查看与切换继续沿用普通主对话规则，不把通用助手锁成不可更改的特殊模式。

### 2. 收集静态文本片段

每次入口只提供一段普通文本，入口对象只决定该段文本采用哪一种内容：

- **消息级文本片段**：来自「在右侧栏分析这条消息」，始终包含 Moebius 会话记录的绝对路径；该消息能够对应到一次外部执行时，同时写明执行 CLI 与外部会话标识。
  - Codex 示例：`Moebius 会话记录：<路径>；外部执行：Codex <session id>`；
  - Kimi 示例：`Moebius 会话记录：<路径>；外部执行：Kimi <session id>`；
  - 尚未建立外部会话时：`Moebius 会话记录：<路径>；外部执行：未建立`。
- **对话级文本片段**：来自「在右侧栏分析这段对话」，只写入 `Moebius 会话记录：<路径>`；左侧栏对话行不代表某一条消息或某一次外部执行，应用不得猜测最近一次 run 或外部会话标识补入片段。

路径和外部会话标识是用户主动进入本地分析流程后才显示的调试线索，是普通时间线平时不展示内部标识规则的局部例外；它们不能回流到普通时间线、侧边栏标题或可分享摘要。

文本与来源记录完全解耦：

- 不充当文件附件；
- 不在后台读取来源对话；
- 不随来源对话新增内容自动刷新；
- 不把点击位置解释成固定分析范围；
- 不限制用户随后提出的问题。

应用不解析路径或外部标识，也不据此增加读取权限。当前 Agent 只使用原本拥有的文件权限尝试读取；读取不到时必须在正常回复中说明无法访问的对象和影响，不能声称已经完成对应分析。

文本片段在输入框的附件区域占一行，以「文本片段 1」「文本片段 2」等短标签显示。每个胶囊右侧提供删除操作；悬浮或键盘聚焦时显示完整文本。空间不足时仍保持单行并允许横向查看，不展开完整文本挤压输入正文。

用户删除某个胶囊后，该段文本不进入首次消息。重复点击入口会继续追加新的胶囊，不新增标签，也不把内容写进正文输入框。

### 3. 选择问题

新对话空态在输入框上方提供候选提示词。候选项只帮助用户快速形成正文，不改变文本胶囊：

- 显示「Agent 运行不符合预期？」时，填入「分析这段对话是否符合这个 Agent 团队设计的预期」；
- 显示「Agent 运行太长了？」时，填入「分析这段对话为什么占用的时间那么长，主要耗时在哪一块，是否符合团队设计的预期，是否有优化空间」。

用户可以继续编辑候选内容，也可以完全不用候选提示词、自行输入问题。无论从哪种正文开始，分析对话都遵守先给方案、等待确认、再修改文件的共同规则。

### 4. 首次发送并创建对话

文本胶囊只提供上下文，不代替用户问题。正文为空时，即使已有一个或多个文本胶囊也不能发送；用户需要选择候选提示词或自行输入问题。对话标题因此继续按普通主对话规则取首条正文，不从路径、外部标识或「文本片段 1」生成。

首次发送把用户正文、仍保留的文本胶囊和普通附件作为同一条首条消息提交。成功后：

- 当前标签原地从新对话切换为已创建对话，不另开标签；
- 对话标题按普通主对话规则从首条用户消息确定；
- 分析对话使用发送瞬间用户最终选择的项目与工作空间；
- 对话使用发送瞬间用户最终选择的团队；用户没有改选时就是「通用助手」，并载入这支团队自己的运行配置；
- 来源团队的成员、CLI、model 和 effort 不会仅因为来源关系自动进入分析对话；用户在发送前主动选择来源团队时，按普通新对话规则载入该选择；
- 左侧栏出现一条可找回的对话入口；
- 候选提示词消失；
- 文本胶囊随首条用户消息进入历史，不再提供删除操作，悬浮或键盘聚焦仍可查看完整文本。

首次消息创建成功后，标签内容完整切换为 [main-conversation.md](../pages/main-conversation.md) 定义的已有对话布局。本流程不重新定义其标题、上下文顺序、时间线、运行记录、输入框、附件、停止、完整输出、重试、恢复或响应式表现。

这段主对话仍位于外层右侧栏标签中。它内部的「完整输出」、结果卡片、子任务行和文件链接如果需要打开右侧栏内容，统一在当前外层标签条新建或聚焦兄弟标签；不得在分析对话内部再嵌套一层右侧栏，也不得错误使用来源对话的步骤或文件身份。关闭兄弟标签后仍回到原分析对话标签。

首次提交尚未成功时，草稿仍是新对话，不在左侧栏产生半成品入口；用户的正文、文本胶囊、普通附件和已预选上下文全部保留以供重试。

### 5. 分析并确认方案

首次启动的主 Agent（默认是通用助手）收到首条消息后先分析问题、说明判断依据并提出优化方案。每次完整提出或实质修改方案都会形成一版新的当前方案；用户的确认只授权确认时那一版方案及其中明确覆盖的修改范围，不能沿用到后来改变的方案。

当前方案获得确认前，Agent 可以继续读取、搜索、解释和讨论，也可以运行明确不会留下持久变化的诊断；不得写入工作空间或团队文件，不得安装依赖、运行会生成或改写文件的命令，也不得执行其他可能改变本地状态的操作。

用户不需要输入固定口令，也不需要点击专用按钮：

- 用户在方案之后回复「可以，就按这个方案改」或语义等价的明确同意时，授权整版当前方案；
- 用户回复「只做第 2 项」时，只授权当前方案中被明确点名的范围；
- 用户提出疑问、否定或要求微调时，Agent 继续讨论；方案被实质修改后，旧确认失效，新的当前方案必须重新等待确认；
- 「为什么这样改」「再看看」「第 2 项方向不错」「先别改」、沉默、追问或只认可判断，都不构成修改授权；
- 用户切换团队不会扩大已有授权；新团队若改变方案或修改范围，必须重新等待确认。

如果 Agent 在未确认或超出已确认范围时尝试写入，操作不能执行；正常时间线中说明当前方案仍待确认或本次操作超出确认范围，并允许用户继续讨论。这里不增加专用状态条，但写入拦截必须是用户可见、可重复验证的事实。

候选提示词可以提醒用户这段对话会先给方案，但候选提示词不是唯一约束。用户自行输入问题时，同样必须等待确认。

### 6. 修改与收尾

用户确认后，当前主 Agent 恢复普通对话本来具有的写入能力，并只执行当前方案已经确认的范围。确认范围可以包含最终选择的工作空间、一个或多个团队的配置与 Agent 文件，或方案明确涉及的其他本地文件。

来源对话、被点击的 run、文本胶囊和“分析”命名都不授予、缩小或推断文件权限，也不把任何团队自动变成唯一修改目标。实际可读写范围继续由当前所选团队、Agent 配置与普通对话运行环境决定；超出正常权限的目标仍按不可访问处理。

任何团队配置修改都只影响以后重新载入该团队的对话与 run，不改写已经创建对话所冻结的团队快照。

来源对话是否仍在运行不构成等待条件；两段对话可以同时作用于同一个工作空间。Agent 在确认后的写入开始前必须重新检查目标文件现状：

- 如果并发变化不改变已确认方案，可以在确认范围内继续并说明发现了变化；
- 如果变化使方案或修改范围需要调整，先说明分歧并提出新版方案，重新等待用户确认；
- 如果无法安全合并，不得静默覆盖，必须停止对应写入并给出保留双方改动的恢复建议。

修改阶段完全复用普通主对话与[单 Agent 会话](../pages/agent-conversation.md)的运行记录、停止、完整输出、异常、重试和恢复规则。完成时，当前主 Agent 在正常时间线回复中说明：

- 实际修改了什么；
- 做了哪些验证；
- 哪些风险或问题仍未解决。

本流程不增加「分析中」「等待确认」「已进入修改」等专用状态标记。能够由对话内容本身表达的推进状态，继续由对话内容表达。

### 7. 再次开始分析

一旦首次消息成功创建对话，后续再次从来源消息或左侧栏来源对话选择分析入口时：

- 不向已经创建的分析对话静默追加文本；
- 若当前来源对话和来源初始工作空间已有另一份尚未发送且仍保持该工作空间的分析新对话，则聚焦并追加与本次入口对象对应的文本片段；
- 否则新建下一份分析新对话。

因此，同一来源对话和同一初始工作空间同时至多有一份仍保持该工作空间的未发送分析新对话，但可以存在用户改选了其他工作空间的草稿，以及多段已经创建、彼此独立的分析历史。

## 分支与异常

### 用户移除文本片段

删除只影响尚未发送草稿中的对应胶囊，不修改来源对话，也不影响其他文本片段、正文或普通附件。已经发送的历史文本胶囊不能单独删除。

### 用户离开或关闭右侧栏

尚未发送的分析新对话沿用普通新对话草稿的保留原则：切换对话、切换页面、窗口变化或重新启动应用后，已输入正文、文本胶囊、普通附件和预选上下文仍可恢复。草稿不会因为被隐藏而提前创建左侧栏对话。

切换页面或隐藏右侧栏只是暂时离开，不等于丢弃。用户点击分析新对话标签上的关闭操作则是主动丢弃：

- 草稿只含系统预选上下文、没有正文、文本胶囊或普通附件时，直接关闭并丢弃；
- 草稿已有正文、文本胶囊或普通附件时，先明确询问是否丢弃；
- 用户确认丢弃后删除整份草稿，下一次入口创建全新草稿；
- 用户取消丢弃时保持原标签、内容和焦点不变。

关闭最后一个右侧栏标签时，右侧栏随之关闭。用户之后仅通过主内容区的显示按钮重新打开右侧栏时，先进入「这个标签要看什么」的内容选择状态，不自动伪造一个高亮的「新标签」。仍被保留而非主动丢弃的分析草稿，在用户再次从来源消息或左侧栏来源对话选择分析入口时恢复并聚焦。

### 首次创建失败

应用保留整份草稿并显示可理解原因，允许原地重试。只有对话与首条消息成功创建后，草稿才被消费并出现在左侧栏。

### Agent 启动失败

首条消息和对话已经创建、但所选团队的主 Agent 没有成功启动时，这是一段已创建对话中的运行异常，不恢复成新对话草稿。用户按普通主对话规则查看原因、重试或继续说话。

### 通用助手暂不可用

若内置「通用助手」团队当前不能用于创建对话，应用保留分析草稿并明确说明需要修复团队；不得静默改用来源团队、最近使用的团队或其他模型。用户仍可以通过正常团队选择器主动改选另一支可用团队。

### 文本指向的记录不可读

文本胶囊不会带来额外读取权限。所选 Agent 无法读取其中写明的 Moebius 记录路径或外部会话时：

- 其余可访问信息仍可继续分析；
- 回复中明确指出哪一项不可读，以及哪些判断因此无法完成；
- 不要求应用回头解析胶囊、复制记录或提升权限；
- 用户可以自行调整权限、补充普通附件或删除对应胶囊后继续。

### 目标文件不可修改

已确认方案中的工作空间、团队文件或其他本地目标不可访问、已经移除、损坏或在确认后变得不可写时，其他彼此独立且仍在授权范围内的修改可以继续；不可写部分停止，并在正常回复中说明阻塞对象和恢复方式。不得因为某个目标不可写而把修改静默转移到同名文件、同名团队或其他位置。

### 来源对话继续运行

开始分析、确认方案和修改文件都不自动停止来源对话。Agent 在确认后写入前重新检查文件；发现并发变化时按本流程的方案版本规则继续、重取确认或停止冲突写入。本流程不承诺自动隔离、自动合并或回滚。

### 来源入口无法恢复

分析对话的聊天历史和工作空间归属不能因来源对话暂时不可打开而丢失。用户从左侧栏打开分析对话时：

- 来源对话仍可用，主内容区恢复来源对话，右侧栏聚焦分析对话标签；
- 来源对话已归档、移除、损坏或暂时不可用，分析对话降级为在主内容区按普通主对话布局打开，并说明暂时无法回到来源；
- 来源恢复可用后，再次从左侧栏进入时恢复并排打开方式。

来源失效只改变承载位置，不改变分析对话的消息历史、所选工作空间或继续对话能力。

## 等待与自动推进

- 选择消息级或对话级分析入口后，打开或聚焦同一分析新对话并追加对应文本胶囊是自动动作。
- 首次发送成功后，草稿转成持久化对话并启动所选团队的主 Agent 是自动动作。
- 当前主 Agent 完成分析并提出方案后，流程必须等待用户确认。
- 用户继续讨论时，流程保持在方案阶段。
- 用户明确确认当前方案后，当前主 Agent 自动进入已授权范围的修改与验证，不再请求“继续”类二次确认。
- 来源对话仍在运行时，分析与修改不额外等待。
- 运行失败、停下、卡住与恢复全部沿用普通对话规则，不在本流程增加自动重试。

## 完成条件

本流程在以下条件同时满足时完成：

- 当前主 Agent 已经按用户确认的方案完成约定范围内的修改；
- 必要验证已经实际运行，未验证部分被明确说明；
- 正常对话时间线中留下修改结果、验证结论和剩余风险；
- 用户可以从左侧栏再次进入这段对话；来源可用时恢复来源对话与右侧栏中的分析标签，来源失效时仍能在主内容区继续。

如果用户只需要分析而不确认修改，流程可以停留在方案阶段；这是一段有效、可继续的对话，不视为失败或半成品。

## 涉及页面

- [主页面会话区](../pages/main-conversation.md)：在 Agent 消息菜单中提供「在右侧栏分析这条消息」，并完整定义分析新对话与已创建对话复用的布局、时间线和操作。
- [主页面右侧栏](../pages/main-right-sidebar.md)：承载新对话与已创建对话标签、标签关闭、空白内容选择和恢复。
- [主页面侧边栏](../pages/main-left-sidebar.md)：在对话行菜单中提供「在右侧栏分析这段对话」，并提供已创建分析对话的找回入口；分析对话是用户主动管理的对话，不按内部子任务隐藏。
- [Agent 团队](../pages/agent-teams.md)：提供正常可见、可编辑的内置单成员「通用助手」团队及其独立运行配置。
- [单 Agent 会话](../pages/agent-conversation.md)：提供当前主 Agent 每次运行的活动、耗时、停止、完整输出、异常、重试和恢复语义。

这些页面只维护各自范围内的入口和表现；跨页面的草稿、创建、确认、修改与找回顺序以本流程为准。

## 指标与验收

### 产品指标

- **复盘启动成功率**：在来源对话有可用记录路径的任务中，用户不离开 Moebius、不手工复制路径或日志，成功提交首条分析问题的任务数 / 尝试任务数；首版目标为 100%。
- **复盘启动成本**：从打开消息级或对话级分析入口到提交首条问题，不把阅读和输入时间计入时，用户只需完成入口选择、可选候选提示词和发送，不增加项目、工作空间或团队的必选设置步骤。
- **方案闸门越权率**：测试矩阵中，未确认、确认旧方案、只确认局部范围或明确拒绝时发生持久写入的用例数 / 对应总用例数；目标为 0。
- **对话找回成功率**：已创建分析对话在切换页面、重启应用、来源可用和来源失效四类场景中能够重新打开并继续对话的用例数 / 总用例数；目标为 100%。
- **产品内完成率**：真实复盘任务中，用户无需转到终端或外部聊天工具即可得到具体判断与可确认方案的任务占比；首轮内部试用记录基线，连续两版不得下降。

### 端到端验收

1. 用户可以从 Agent 消息菜单选择「在右侧栏分析这条消息」，也可以从左侧栏对话菜单选择「在右侧栏分析这段对话」，都不需要手工寻找或复制会话记录文件。
2. 消息级入口按 Codex、Kimi 和尚未建立外部会话三种情况生成带来源记录与执行线索的静态文本；对话级入口只生成来源记录路径，不猜测某次 run 或外部会话标识。路径与外部标识只在用户主动进入的分析上下文中出现。
3. 应用不解析文本胶囊、不自动刷新来源内容，也不因胶囊存在增加读取权限；来源继续产生内容后，已添加胶囊保持原文。
4. 文本指向的记录不可读时，Agent 明确说明缺口，不伪造分析结果；其他可访问内容仍可继续分析。
5. 同一来源对话和初始工作空间内，首次发送前从消息或对话入口多次进入只按点击顺序累积对应文本胶囊，不产生多个标签或多个持久化对话；用户改选工作空间后，来源入口不再向该草稿追加。
6. 文本胶囊以短标签单行显示，每项均可在发送前移除，并能通过悬浮、键盘聚焦和辅助技术读取完整文本。
7. 候选提示词与用户自由输入到达同一发送路径，不改变或替换文本胶囊；只有胶囊、正文为空时不能发送。
8. 分析新对话初始预选来源项目与工作空间及「通用助手」；用户可以在发送前改选，创建结果使用发送瞬间的最终选择。
9. 首次发送后原标签原地切换为普通主对话，页面布局和运行交互不产生分析专用分叉。
10. 已创建分析对话中的完整输出、结果卡片、子任务和文件链接在同一外层右侧栏打开兄弟标签，不出现嵌套侧栏或来源身份串线。
11. 新入口不会向已创建分析对话追加文本，而是创建或聚焦另一份尚未发送的新对话。
12. 未发送草稿在页面切换、隐藏右侧栏和应用重启后恢复；主动关闭有内容的草稿先确认，确认丢弃后不再复活。
13. 当前方案未获确认、用户只追问或拒绝、确认的是旧方案或操作超出局部授权时，任何正常可写的本地目标都不发生持久变化，任何会产生持久变化的命令都不能执行，并出现正常时间线说明。
14. 用户明确确认整版或指定范围后，只执行对应当前方案与范围；方案实质变化或新团队提出不同方案时重新等待确认。
15. 确认后，当前主 Agent 只按普通对话权限执行已确认方案；方案可以涉及工作空间、一个或多个团队文件及其他正常可写目标，来源关系和文本胶囊既不授权也不限制。团队修改只影响未来载入，不改写任何已冻结团队快照。
16. 来源对话运行中仍可分析与修改；发现并发变化时先重检，方案变化则重新确认，无法安全合并时不静默覆盖。
17. 「通用助手」不可用时保留草稿并明确说明，不静默换团队或模型；用户可以主动选择其他团队。
18. 已创建分析对话可以从左侧栏找回；来源可用时恢复并排标签，来源失效时在主内容区降级打开且历史可继续。
19. 关闭最后一个右侧栏标签会关闭右侧栏；仅通过显示按钮重开时进入内容选择状态，不留下虚假的「新标签」。
20. 创建失败不会留下半条首条消息、空对话入口或丢失的分析草稿；Agent 启动失败则保留已经创建的对话并走正常恢复。
21. 从左侧栏对非当前对话选择分析入口后，该行成为唯一选中项，来源对话显示在主内容区，对应分析草稿显示在右侧栏；切回此前对话时，其右侧栏标签、未发送草稿与阅读状态仍在。任一目标未成功呈现时，进入前的选中项、主内容与右侧栏保持不变。

## 非目标

- 不把文本胶囊实现成文件附件、动态引用、自动刷新快照或可执行对象。
- 不解析胶囊中的路径或标识，不因胶囊存在自动读取记录或增加 Agent 的文件权限。
- 不根据点击位置预先决定分析范围。
- 不因入口来自消息或对话而创建两套分析草稿、标签、发送或后续对话行为；二者只改变插入的文本片段。
- 不继承来源团队、来源模型或来源 Agent 的 provider 会话。
- 不创建独立于现有对话运行时的「纯对话模式」或分析专用页面布局。
- 不要求来源对话结束后才能分析或修改。
- 不自动停止来源对话，不承诺并发修改的自动隔离、合并或回滚。
- 不自动判断团队设计一定正确，也不替用户确认优化方案。
- 不为已创建分析对话增加专用阶段标签、状态条或固定确认口令。
