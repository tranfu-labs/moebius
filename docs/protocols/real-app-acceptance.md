# 真机验收协议（用户动作的最终闸门）

本文件是「什么算验证过了」的唯一事实源。各团队角色（functional-qa、qa、delivery-reviewer 及对应闸门角色）引用本协议，NEVER 在角色文件里改写或复述细节。

## 为什么有这份协议

2026-07-30 `sidebar-conversation-management` 交付：全量 1632 项测试、typecheck、构建全绿，功能验收还真实打回过 4 个问题，但用户拿到手第一次点「置顶」就崩（`Illegal invocation`，fetch receiver 丢失，后由 `8d6406e` 修复）。当时「真实运行验证」规则已存在 4 天，被两个口子消解：

1. 「测试可断言的行为不重复搭真实环境」——写路径被归入可断言，真机验证被豁免；
2. 「真实运行的应用」没有定义——预置状态的 Electron fixture 也算数，四段证据字段被替身观察合法填满。

每层测试各自全绿推不出整体可用：mock 接缝处的缺陷恰好是这套矩阵系统性排除的类别。本协议把最终裁决权交给真机用户旅程。

## 定义：什么算「真实运行的应用」

MUST 同时满足：

- 真实构建或 dev 等价形态的完整应用（桌面形态即真实 Electron 窗口，CDP 通道见 ADR-0002）；
- 连接真实本地服务，走真实网络 / IPC / 持久化栈——fetch、SQLite、进程边界都是生产实现，无 mock、无 stub；
- 被验收的状态由真实用户操作产生，NEVER 预置注入。

以下一律**不算**真机，只能作辅助证据：Storybook / Page Story、预置状态的 fixture 页、替换或拦截网络栈的页面、绕过 UI 直接打 HTTP。

## 适用范围（不可豁免集）

本次交付**每个新增或变更的用户动作**（点击、输入、菜单项、快捷键），只要产生副作用（发请求、持久化、进程调用），MUST 在真机上从用户真实入口各做一遍。

- 豁免只适用于只读渲染态（静态展示、样式、文案），这些以自动化测试与 Story 为证据。
- 副作用动作 NEVER 豁免，无论自动化测试是否已断言同一行为——测试断言的是替身环境，豁免判断权不归实现者。
- 判断入口：PRD 用户旅程里出现的动作默认适用。

## 执行与记录

- 每个动作记四段：**入口 / 操作 / 屏幕观察 / 与承诺一致否**。只写亲眼观察到的事实。
- 涉及持久化的动作，重启应用后复查一次。
- 每条证据 MUST 带**环境**字段：`真机` 或 `替身＋不算数的理由`。缺环境字段的「通过」无效。
- 四段文字记录写入本次 change 的交付记录（如 `tasks.md` 交付记录节），随归档留存可审计；截图与长日志仍按仓库约定落系统临时目录，NEVER 进仓库。

## 不可抵扣

测试计数、typecheck、构建成功、Story 截图、fixture DOM 检查，NEVER 抵扣任何一个副作用动作的真机记录。某个动作真机做不了，就写「未验证」并阻断交付——写「未验证」不是失职，用替身证据冒充真机才是。

交付汇总 MUST 以真机行为证据开头；测试计数只出现在「回归保障」一节，NEVER 作为「功能可用」的论据。

## 演练：证明这道门是活的

一道从未拦下过任何东西的门，无法区分「一直没问题」和「门是装饰」。验收连续多轮全数通过时，视为需要演练的信号：挑一个历史真缺陷（首选 `8d6406e` 修复的置顶 fetch receiver bug）回退出复现构建，走一遍本协议，确认流程真的变红。演练由用户或主 Agent 显式发起，不自动执行。
