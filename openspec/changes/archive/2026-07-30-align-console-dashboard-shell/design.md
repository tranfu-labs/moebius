# 设计：align-console-dashboard-shell

## 方案

### 1. 参考优先级与映射原则

实现时按以下优先级消解冲突：

1. 本次用户限定的区域范围。
2. `docs/product/pages/main-left-sidebar.md`、`main-conversation.md` 与现行
   `openspec/specs/console-ui/spec.md` 的业务行为。
3. `dashboard.html` + `app.css` 在左侧栏和主会话区的视觉度量。
4. `packages/console-ui/DESIGN.md` 的既有 token、无阴影、字体、图标和状态语义。

参考稿只提供视觉目标，不复制 DOM、内联 SVG、假数据或脚本。参考稿与生产规则冲突时保留生产
规则：例如侧栏继续可拖动调宽、继续显示“重新查看引导”，右侧栏仍由既有实现独立承载。

### 2. 左侧栏

`OperatorConsole` 继续拥有窗口控制、品牌、应用级入口和底部固定操作；
`ConversationSidebar` 继续拥有项目与会话列表。两者使用同一组紧凑度量：

| 部位 | 目标 |
| --- | --- |
| 默认宽度 | 252px；保留现有最小 / 最大宽度与拖动分隔线 |
| 窗口控制行 | 46px；左侧保留 macOS 交通灯安全区，关闭按钮 28px |
| 品牌行 | 34px，左右 16px，Logo / 品牌名同轴 |
| 应用级导航 | 34px 行高、10px 图标文字间距、8px 圆角、行间 2px |
| 项目区标题 | 11.5px、上 18px / 下 6px、左右 20px |
| 项目行 | 32px 行高、8px 圆角、项目名 13.5px / 590 |
| 会话行 | 32px 行高、左缩进 28px、标题 13.5px、必要状态点 7px |
| 选中态 | `bg-sel` + 左侧 `»` 标记；不改变排序或状态点 |
| 底部操作 | 固定、顶部 1px 分隔线；“重新查看引导”和“设置”均复用 34px 导航行 |

项目行的拖动、展开、修复、加号和更多菜单保持独立命中。hover 才出现的动作不得挤压项目名
或让状态点跳动；键盘聚焦时动作仍可达。侧栏仍使用语义 token，不把参考稿的裸色复制进组件。

视觉层级统一落在本项：侧栏与主区使用同一 `bg-canvas`，选中与悬停分别使用 `bg-sel` /
`bg-hover`；右边界和底部固定区顶部使用 1px `border-line`，不增加阴影或渐变。品牌与页面标题
沿用 `font-display`，导航和列表沿用包内正文族及 510 / 590 字重。窗口控制、品牌、应用导航和
底部操作不滚动；只有项目 / 会话列表占据剩余高度并独立纵向滚动。

### 3. 主会话内容轴

把 `conversation-layout.ts` 的主会话列作为唯一度量入口：

- 最大宽度从 760px 调整为 840px。
- 宽窗口居中；窄窗口保持 32px 左右 gutter。
- sticky 标题、通知、空态、消息、活动 run、结果卡片、待发射区和 composer 全部复用该入口，
  不在各组件重复写第二套宽度。
- 顶部窗口拖拽行与 sticky 会话标题都保持 46px。
- 时间线消息间节奏以 24px 为基准；底部为固定 composer 留出空间的既有机制继续有效。

主区继续使用不透明 `bg-canvas`；顶部控制行底部使用 1px `border-line`，composer 使用
`bg-card` 与 `border-line`，不引入裸色、阴影或渐变。主区只有时间线滚动，顶部控制行、标题
和底部 composer 不随消息离开视口；时间线必须保留足够底部空间，使最后一条消息不被 composer
遮挡。这里约束的是固定的视觉关系，不限定必须使用 CSS `fixed`，可由现有 flex / sticky
布局实现。

目录轨仍相对当前主会话定位。840px 只改变正文列目标，不改变目录轨事件模型；现有窄容器避让
规则继续按主会话实际可用宽度工作。

### 4. 消息与活动记录

主会话使用参考稿的消息层级：

- 主会话身份头像为 24px 圆形，角色名为 12.5px / 590，时间保持 hover / focus 可见。
- Agent / system 正文从身份头像左缘向右缩进 32px；Agent 长正文最大 68ch。
- 用户身份行右对齐，用户气泡最大宽度 75%，内边距 8px × 12px，圆角 10px。
- 历史完整输出、分析入口、附件和 Markdown 继续使用现有能力，只调整其所在视觉轴。
- 活动 `RunBlock` 在主会话使用同样的 24px 身份头像、32px 正文缩进和正文列右边界；
  右侧子任务继续使用现有 embedded 密度。

`68ch` 直接对应参考 `app.css` 的 Agent 正文最大宽度，是长文本可读性的视觉目标，不改变
Markdown 或消息业务。时间 hover 来自参考视觉；focus 可见是现有键盘可访问性契约的等价保留，
不新增时间字段或交互状态。状态点聚合和目录轨均沿用现行 PRD / spec：本次只校验状态点的
尺寸与对齐、目录轨的归属与避让，不改写聚合优先级、事件模型或业务行为。

为避免改动 `RoleTag` / `RunBlock` 的所有消费者，优先增加窄的显式视觉变体或样式参数，
由主会话调用点选择；不得通过全局默认值连带修改排除范围。

### 5. Composer

主会话与新对话的 `RoleComposer` 使用 `main` 视觉变体：

- 外层与 840px 正文列同宽，宿主上下 padding 为 12px / 16px。
- composer box 为 1px `border-line`、14px 圆角、`bg-card`，内边距 10px 12px 12px。
- 上下文项为 28px 高、12px 圆角；已锁定项目 / 工作空间 / 分支保持文本态，团队仍可操作。
- textarea 单行起步、随内容增长，最大高度 120px；不再用固定 76px 高的空白面。
- 附件按钮、发送按钮和主理人停止按钮保持 32px 方形、10px 圆角。
- 运行中同时存在发送与停止、附件草稿、文本片段、禁用原因和待发射区时，继续使用既有业务状态，
  只按参考稿的内容轴与间距排列。

右侧子任务的 `RoleComposer` 继续使用 `embedded` 视觉变体及其可用宽度，不继承主会话 840px
或单行起步规则。

`120px` 直接对应参考 `app.css` 的 textarea 最大高度；`main` / `embedded` 仅是共享组件的
技术隔离参数，不成为产品状态、数据字段或运行时协议。composer 的“固定”同样只描述它相对
时间线停留在主区底部的可观察关系，不要求改用某一种定位原语。

### 6. Story 与测试职责

现有 `Page/Console/OperatorConsole` 是主要确定性入口，补充或调整 fixture 使一组 Page Story
同时覆盖：

- 侧栏展开、项目展开 / 折叠、选中会话和三种状态点。
- 用户消息、Agent 长消息、活动 run、历史操作与普通 composer。
- 新对话空态及其 composer。
- 右侧栏关闭的主范围基线；另保留右侧栏打开 Story 证明排除区域未被视觉变体污染。

自动测试只断言稳定契约，不逐个快照 Tailwind 字符串：

- `conversation-layout` 的 840px 单一宽度常量及各主会话消费者复用。
- 默认侧栏 252px、拖动边界仍生效；导航 / 项目 / 会话行的目标高度和选中标记。
- 主会话消息头像、32px 缩进、68ch Agent 正文与 75% 用户气泡。
- `RoleComposer` 的 main / embedded 变体互不串样，发送、停止、附件和输入法测试继续通过。
- 新对话、待发射区和已有会话 composer 共用 840px 内容轴。
- 侧栏与主区共用 canvas，语义分隔线、字体族 / 字重、选中 / hover / card token 正确，且
  没有新增阴影、渐变或裸色。
- 侧栏只有项目列表滚动，主区只有时间线滚动；短高度下底部操作与 composer 可达，最后一条
  消息不被 composer 遮挡。

真实桌面状态不依赖 Storybook fixture。新增验收脚本
`pnpm exec tsx scripts/acceptance/console-dashboard-ui.ts`，通过 Playwright Electron 启动真正的
`desktop/`：使用系统临时目录作为 `MOEBIUS_DATA_ROOT`，写入有效 onboarding marker 和临时附件，
并把临时 `codex` 可执行文件放在本次进程 PATH 最前。该可执行文件按测试消息生成生产适配器已经
支持的 JSONL：

- `FAIL`：发出 `thread.started` 后非零退出，生成失败红点。
- `SUCCESS`：延迟发出最终 Agent 消息后正常退出；脚本先切换会话，生成成功未读蓝点。
- `LIVE`：持续发出活动并保持运行，生成闪烁运行点和活动 run；此时再发送消息生成待发射区，
  通过真实文件输入加入附件，并保留草稿以同时观察发送与停止。

默认模式自动做 DOM / 几何断言并把截图与 evidence 写入系统临时目录后退出；`--hold` 在同样的
确定性状态停住，供 `@qa` 在真实应用中人工复核。夹具不修改 desktop IPC、local-console API、
SQLite schema 或 Codex 事件协议，也不把假数据写入仓库或生产种子。

### 7. 真实运行验收

实现阶段交给 `@qa` 的逐条入口和信号如下：

1. **左侧栏基线**
   - 入口：运行 `pnpm exec tsx scripts/acceptance/console-dashboard-ui.ts --hold`，进入脚本准备好的
     真实 Electron 主窗口并保持侧栏展开。
   - 操作：展开一个含多段会话的项目，选择其中一段会话，再折叠另一个有状态点的项目。
   - 信号：默认侧栏为 252px；46px 控制行、34px 品牌行和 34px 应用入口分层清楚；
     项目 / 会话行为 32px；选中行出现 `»` 与中性选中底；展开项目不重复聚合点，
     折叠项目只显示最高优先点；侧栏与主区同为 canvas、分隔线为 1px 语义线、品牌字体层级
     正确且无阴影 / 渐变；只有项目列表滚动，底部引导与设置始终可达。
   - 短窗回归：把窗口设为 Electron 允许的 900×480，并准备 15 个项目；根页面不得出现额外
     纵向滚动，项目列表可独立滚到底，侧栏 footer 底边不得超出 480px。

2. **主会话内容轴**
   - 入口：同一真实 Electron 主页面，打开脚本准备的 `LIVE` 会话。
   - 操作：把窗口调整到宽桌面尺寸，再缩窄到正文列开始收缩。
   - 信号：宽窗标题、Agent 正文、活动记录、待发射区和 composer 共用居中的 840px 轴；
     窄窗共同保留 32px gutter；sticky 标题与顶部控制行均为 46px，时间线滚动时标题和
     composer 固定在主区且目录轨不进入左侧栏；最后一条消息不被 composer 遮挡，页面根节点
     不产生横向滚动。

3. **消息层级**
   - 入口：切换脚本准备的已完成会话与 `LIVE` 会话。
   - 操作：悬停用户与 Agent 消息，并检查一条超过数行的 Agent 回复。
   - 信号：成员头像为 24px；Agent 正文相对身份行缩进 32px 且最长约 68ch；
     用户身份行与气泡右对齐、气泡不超过正文列 75%；时间只在 hover / focus 时出现；
     完整输出与分析入口仍可用，Markdown 和附件不溢出正文列。

4. **Composer 与行为保持**
   - 入口：在脚本准备的 `LIVE` 会话和侧栏“新建对话”之间切换。
   - 操作：输入多行文字、添加附件、输入 `@` 打开成员补全；在主理人运行时再输入一条消息。
   - 信号：两种主页面 composer 与 840px 内容轴一致，空输入从单行高度起步且最多增长到
     120px；上下文项、附件、发送 / 停止按钮保持可达；发送、停止、附件、补全、输入法和
     待发射行为未改变。
   - 动态高度回归：在 900×620 长时间线中同时保留 20 行草稿、附件和待发射区并滚到底；
     时间线底部留白、Relay Rail 和“回到底部”按钮必须跟随底部组合区实测高度，最后一项与
     按钮均不得进入组合区。

5. **排除区域**
   - 入口：在同一真实 Electron 窗口打开右侧栏中的过程标签；embedded composer 的细粒度
     尺寸以现有右栏 Story 作为补充证据，而不是替代桌面观察。
   - 操作：在主会话与右侧标签间切换、缩放窗口。
   - 信号：右侧栏内部布局与 embedded composer 保持原密度，不出现 840px 主会话宽度、
     24px 主会话头像或主会话 composer 间距；右侧栏开关、覆盖和滚动恢复继续工作。

## 权衡

1. **对齐视觉参数，不复制参考 DOM**：复制原型最快，但会形成第二套组件和假行为；选择在生产
   组件中收敛度量，成本稍高但保持单一事实与真实交互。
2. **840px 作为共享内容轴**：放弃继续维持 760px 的旧实现，以满足用户指定参考；宽度集中在
   `conversation-layout.ts`，避免标题、消息和 composer 再次漂移。
3. **保留可调侧栏**：参考稿固定 252px，但 PRD 要求可拖动；因此只把 252px 作为默认值，
   不删除最小 / 最大宽度与拖动能力。
4. **主区变体隔离共享组件**：不全局放大 `RoleTag` 或压缩所有 `RoleComposer`，避免右侧子任务
   被意外改版；代价是共享组件多一个显式布局参数。
5. **不修改 PRD**：页面职责和产品行为没有变化，精确像素本来就属于高保真设计与设计系统；
   本 change、spec delta 与实现阶段的 `DESIGN.md` 承接这些参数。
6. **真实 Electron 夹具而非只用 Storybook**：临时 fake codex 让运行态可重复，同时仍经过
   desktop、preload、local-console 与生产 renderer；代价是新增一个验收脚本及对应命令文档。

## 风险

- 840px 正文列在同时打开左右栏时可能压缩目录轨空间；通过容器宽度场景和左右栏组合 Story
  验证，窄时必须共同收缩而不是产生根级横滚。
- composer 从固定高面改为内容驱动后，附件、文本片段和运行中双按钮可能碰撞；必须覆盖空、
  多行、附件、待发射、运行中发送 + 停止和禁用态。
- 新增共享组件变体可能被调用方遗漏；用联合类型和 main / embedded 单测锁定所有生产调用点。
- 精确 class 断言容易脆弱；只对共享常量、关键几何和作用域变体做契约测试，视觉细节由
  Storybook 与桌面真实运行复核。
- 临时 fake codex 必须严格复用生产适配器已支持的 JSONL 事件；脚本测试其退出、清理和
  `--hold` 中断路径；必须按文档中的 `pnpm ... --hold` 启动并以 Ctrl+C 结束，命令正常退出，
  临时数据根被删除且不残留 Electron / fake Codex 子进程。
- 回滚时可恢复旧 760px 内容轴、248px 默认宽度和原 composer 变体；不涉及数据迁移、IPC
  或持久化回滚。

## 范围锁定

- `dashboard.html` / `app.css` 只读，不修改参考页或把参考假数据引入产品。
- 右侧栏视觉不在本 change 内；`main` / `embedded` 只用于阻止样式串入右侧栏。
- 不修改运行时协议、状态点规则、目录轨模型、发送 / 停止 / 附件行为或持久化数据。
- 不做清单外重构；只有实现上述度量、隔离与验证直接需要的最小修改可以进入 change。
