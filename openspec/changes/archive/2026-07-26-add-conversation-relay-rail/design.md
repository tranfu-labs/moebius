# 设计：add-conversation-relay-rail

## 方案

### 数据投影

`OperatorConsole` 直接从当前 `messages` 中选择 `speaker=user|agent` 的稳定可见消息，并结合现有 `memberIdentities` 解析可读名称。系统事实、运行中占位、子会话卡片和工具过程不会成为目录事件。目录事件使用真实 message id 定位，不复制正文事实或增加后端读取通道。

### 轨迹模型

- 固定事件行高 20px，容量由主时间线视口扣除标题与 composer 遮挡后的实测高度决定，最低 7 行。
- 未超容量时完整显示；超容量时保留阅读焦点、连续上下文和首尾边界，远端连续区间各用一个省略行表示。
- 收起与展开复用同一批行和焦点，只改变横向投影。
- 相邻真实行用首次引导同类三次贝塞尔 S 曲线连接；任一侧为省略行时断开，避免伪造隐藏事件的交接路径。
- 目录浏览游标与主时间线阅读焦点分离；滚轮或方向键只浏览，Enter / Space / 点击才定位正文。

### 组件交互

- 收起宽度 44px，展开宽度按主会话容器在 148–224px 内响应。
- 展开后按钮占满整条事件行，节点只作为该行的视觉标记；因此最左、最右泳道拥有相同命中面积。
- 预览使用现有 Radix Popover。因为 Trigger 是整行，Popover 的 side offset 相对面板边缘恒定，不随节点 lane x 漂移；碰撞时整卡翻转。
- Agent 卡只有成员色点、可读成员名、时间与回复开头；用户卡使用“你”、时间与原文开头，不展示内部 slug 或生成摘要。
- reduced-motion 分支禁用平滑滚动和位移类过渡，只保留信息等价的静态状态。

### 阅读位置

桌面 renderer 用版本化 localStorage map 保存 `sessionId -> messageId`。`OperatorConsole` 在会话切换后仅执行一次恢复；锚点不存在时聚焦最新稳定事件。用户离底阅读时刷新不跳底；位于底部时沿用现有跟随逻辑。

## 权衡

- 复用当前 state 的消息数组，放弃独立 rail API 和全会话批量缓存：当前页面只展示一条当前主会话目录，新增接口会重复读取同一事实。
- 不复用 onboarding 组件源码：两者行高、状态机和职责不同；只在独立纯函数中复刻已经验证的曲线几何语义。
- 不让连接线跨省略区：视觉连续性略弱，但不会把隐藏的多次往返伪造成一次直接交接。

## 风险

- 多成员导致泳道变密：通过 148–224px 响应宽度与等距 lane 降级，准确身份仍由预览承担。
- 消息 DOM 高度差异很大：阅读焦点按各消息可见矩形中心与时间线阅读中心的距离计算，不按消息索引估算。
- localStorage 损坏或锚点被删除：解析 fail-soft，丢弃无效项并回到最新事件，不阻塞会话读取。
