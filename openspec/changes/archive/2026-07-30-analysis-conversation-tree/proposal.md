## 背景

当前分析草稿在首次发送后创建普通根会话，因此进入左侧栏；分析来源仍以日志路径和 provider 执行标识的文本片段表达，既不能形成可导航的会话关系，也不能向 Agent 稳定交付来源内容。右侧栏虽已具备会话草稿提升与按宿主保存标签现场的能力，但缺少直接父子归属、父面板查询、跨树路由和归档事务契约。

## 提案

- 为分析会话持久化直接父会话关系和分析会话类型，根会话列表与团队子任务投影均不把它当作普通对象。
- 在每个可承载对话的内容区接入分析入口面板；面板只查询直接分析子项，点击后在根会话的同一外层右侧栏标签组打开或聚焦唯一会话标签。
- 以公开 `moebius-ref:` Markdown 语法序列化消息级与对话级来源，统一支持导航、目标不可用降级和新 run 开始前的最新只读来源交付。
- 让同一 run 的继续恢复沿用已取得来源上下文；重试、重新运行和重发创建新 run 并重新读取。
- 将带来源的待发射项、分析子树归档、项目移除、面板入口和右侧栏标签纳入确定的提交与回滚边界。
- 保留已确认的生产组件 Page Story 作为页面契约，不让 fixture 进入运行时。

## 影响

- 业务域：`local-console`、`console-ui`、`desktop-shell`。
- 运行时：会话 schema / JSONL 事实、会话创建与查询、消息提交与 run 上下文、归档和项目移除。
- 桌面编排：分析草稿创建、面板开合、右侧栏标签、跨树选择、Markdown 内部导航。
- 用户界面：左侧栏、主会话内容区、右侧栏分析会话、消息 Markdown 与失败反馈。
- 自动化：本地会话存储/运行时、renderer 状态编排、Markdown 引用、Page Story 与真实桌面观察。
