# 提案：控制台错误可见性

## 需求基线

本 change 修复已经写明但未被实现稳定满足的失败反馈契约；产品意图不变，PRD 不新增规则。

| 文件 | 小节 | 变更 | 状态 |
| --- | --- | --- | --- |
| `docs/product/pages/main-conversation.md` | `#操作与反馈` | 失败反馈保持可理解、可重试，不被后台刷新静默抹除 | 已有事实，不改 PRD |
| `docs/product/pages/new-conversation.md` | `#页面状态` | 创建失败保留输入并显示可理解错误 | 已有事实，不改 PRD |
| `docs/product/pages/agent-teams.md` | `#跨页面异常反馈` | 团队异常与恢复反馈持续可见 | 已有事实，不改 PRD |

需求输入来自 50 批 RA-16 的真实 Desktop 观察与主理人对共享槽写入面的复核；这里没有新增页面、
文案或交互选择，不存在需要用户补充的体验分叉。

## 问题

本地控制台的共享错误槽被每秒一次的状态轮询无条件清空，导致几乎所有用户可见错误的显示寿命不超过 1 秒。

根因（已在代码层坐实）：

- `desktop/src/console-page/use-console-state-sync.ts:81`
  `window.setInterval(..., 1_000)`——每秒触发一次 `refreshConsoleState`。
- `desktop/src/console-page/refresh-console-state.ts:51`
  刷新成功路径**无条件**执行 `options.setError(null)`。

即：一个周期性成功回调，无条件清除了一个它并不了解来源的错误。

## 影响范围

`desktop/src/console-page/` 下共 **53 处**非 null `setError(...)` 写入方，覆盖会话发送、项目变更、
分析、附件、团队保存等路径。**它们全部受影响，不限于附件失败。**

发现经过：50 批 RA-16 真机验收中，QA 需要挂 `MutationObserver` 才能捕获附件失败文案，正常用户读不到。
经复核，该现象并非附件专有，而是共享错误槽的通用行为。

性质：**既有缺陷，非四层架构系列引入**。四层系列六批均未改动该逻辑。但它使 50 批「16 条中文 fallback
迁入双语 locale」的用户可见价值大打折扣——文案翻译正确，用户却读不到。

## 目标

用户触发的错误与异步失败必须保持可读，直到被用户消解或被同源的新状态取代；周期性刷新成功
**不得**清除并非由它自己产生的错误。

## 方向与约束

1. **不接受只特例化附件路径。** 把附件失败挪到 composer 局部状态可解决 1/53，其余 52 个写入方仍然
   受同一缺陷影响。修复必须作用在共享错误槽的语义上。
2. **刷新只能清除自己产生的错误。** 需要区分「本次刷新自身失败产生的错误」与「其他来源的错误」；
   实现形态（错误带来源标记 / 显式消解 / 分槽）由 design 阶段权衡，本提案不预设。
3. **不得改成靠延时或 TTL 掩盖。** 加长显示时间只是把清除推后，不解决「无条件清除他人错误」这一根因。
4. **不得回退四层边界。** `refreshConsoleState` 当前是 adapter/application 接缝；错误来源判定若含业务
   规则，须落在 domain 纯函数，遵循 40 批已确立的口径与 193 条 permit 棘轮，不新增 condition permit。
5. 附件失败是否另外固定在 composer 区域（QA 在 RA-16 中的建议）可作为独立的呈现改进评估，
   但**不作为本 change 的替代方案**。

## 验收方向

- 构造真实失败后，错误在无用户操作的情况下持续可见超过若干个轮询周期，不被成功刷新清除。
- 刷新自身失败产生的错误，在下一次刷新成功后正常消失。
- 覆盖多来源并发：一处错误存在期间另一路径成功，不得清除前者。
- 53 个写入方按类别抽样验证，不只验附件。
- 真机验证中英文两种语言下的实际可读性。

## 不做

- 不重新设计控制台的整体通知/提示体系。
- 不改动错误文案本身（50 批已完成 locale 迁移）。
- 不处理 `tests/local-console-execution-runtime.test.ts` 的 8 秒等待阈值脆性（另一独立遗留项）。
