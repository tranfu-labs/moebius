# Wireframes：local-runtime-supervision-and-override-rerun

基线：`docs/wireframes/pages/console.md`。本 change 只调整主会话和 embedded 单 Agent 记录内部的运行活动、异常终局与操作，不增加页面、路由或新的侧栏容器。

## pages/agent-conversation.md

### 服务繁忙·运行中

```text
│ (开) 开发                                      已进行 03:18 │
│ 对方服务繁忙，正在第 3 次重试                               │
│                              完整输出不可用          [停下] │
```

- 重试行仍是同一个 run 的最新活动，不追加历史消息。
- 只有可靠 retry 事件才显示次数；没有次数时显示「对方服务繁忙，正在重试」。
- 到达 long-run report 只替换活动说明，不移除「停下」；到达 busy 闸才形成终局。

### 用户停止·保留半截正文

```text
│ (开) 开发                                       耗时 03:26 │
│ 已经定位到 Kimi ACP 的终局映射，下一步需要…                │
│ 内容不完整                                                   │
│ ⏹ 你让这一步停下了                                          │
│ [完整输出不可用] [重试] [换执行配置重跑…] [改一改重发]     │
```

- partial Markdown 继续使用正文渲染，终局事实使用结构化组件。
- 「内容不完整」不得使用成功或完成语义。
- 窄宽度下操作自然换行，正文和按钮都不造成页面级横向滚动。

### 引擎异常·原因置信度

```text
可靠机器信号
│ ⚠ Kimi 额度当前不可用                                       │
│ 已有内容不完整                                               │
│                         [重试] [换执行配置重跑…]             │

只有间接证据
│ ⚠ 当前执行引擎没有产出完整结果                              │
│ 可能是额度或服务问题。                                      │
│                         [重试] [换执行配置重跑…]             │
```

准确原因与保守原因共用同一结构，不能因为没有准确 quota code 就退化成“成功”或隐藏重跑入口。

### 换执行配置重跑

```text
│ 换执行配置重跑                                               │
│ CLI       [Codex ▾]                                         │
│ Model     [gpt-5.4 ▾]                                       │
│ Effort    [high ▾]                                          │
│ 只用于这一次重跑，不会修改团队成员设置。                    │
│                                      [取消] [开始重跑]       │
```

- loading 时保留原终局内容和取消操作；registry 失败时原位说明并允许重新加载。
- 首版没有「以后都使用」勾选。
- 键盘焦点打开后进入首个选择器，取消或完成后回到原终局操作。

## pages/main-conversation.md
