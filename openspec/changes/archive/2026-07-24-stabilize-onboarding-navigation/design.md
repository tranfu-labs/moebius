# 设计：stabilize-onboarding-navigation

## 方案

正式实现与原型都使用相同的三层布局概念，但保持源码隔离：

1. 页面滚动区负责窗口内居中和短窗口滚动。
2. `onboarding frame` 使用 `width: 100%` 与 `max-width: 780px`，提供四步不变的左右对齐边界。
3. 标题和普通步骤内容在 frame 内以 `max-width: 512px` 居中；AI 团队设计器与第 3 步接力舞台使用 frame 的完整可用宽度。
4. 全局 action row 是步骤内容之后的同级元素，`margin-top: 16px`、`justify-content: flex-end`、按钮间距 `8px`。主按钮最右边缘与 frame 的最右边缘重合。

全局 action row 使用正常文档流，不使用 absolute、fixed 或 sticky。短窗口时它与当前步骤内容一起滚动，不覆盖内容。AI 团队设计器打开时不渲染全局 action row，避免与子流程的返回、调整和创建操作竞争。

## 权衡

- 不把所有普通内容强行拉宽到 780px：稳定导航锚点不应牺牲普通步骤的阅读密度，因而保留 512px 内层内容。
- 不固定步骤高度：AI 团队设计器和接力舞台的内容量差异很大，固定高度会制造多余空白或裁切；本次只稳定水平位置，垂直位置继续与当前步骤内容保持 16px 的可理解关系。
- 不保留全局底部 footer：footer 的独立 640px 宽度是按钮跳动和重复进度的来源，继续维护它只会留下第二套对齐体系。
- 不使用绝对定位：正常文档流可自然支持短窗口、动态团队数量和错误态，不需要额外计算内容高度。

## 风险

- 第 3 步默认窗口高度可能因 action row 进入滚动区而减少可用空间。实现后必须在默认 `1180 × 760` 视口验证六棒完成态与操作可见性。
- 原型验证脚本可能仍查找旧 footer 进度 DOM。实施时同步调整结构断言，并通过完整原型门禁。
- 普通步骤的 512px 内容与 780px 右对齐按钮之间会形成有意留白；视觉截图需要确认这是稳定锚点而非误对齐。

## 实施校正

默认 `1180 × 760` 视觉验收显示，接力行沿用固定 `72px` 高度时会把外部 action row 推到视口之外。接力舞台因此把每拍行高改为 `clamp(60px, 8dvh, 72px)`：常规高度仍保留原有呼吸感，默认桌面高度可收紧到完整展示六棒与外部操作，短窗口和更长脚本继续只滚动时间线。该校正不固定步骤总高度，也不改变 `780 / 16 / 8` 布局契约。
