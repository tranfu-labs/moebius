# 设计：per-conversation-right-sidebar-visibility

## 本项目适用方案

### 方案来源判定

本 change 属于 C 型：现有 renderer 将一个应随工作现场变化的状态做成了全局偏好。解决成功的判据是：对话 A 已打开右侧栏、此前未打开过的对话 B 仍关闭；返回 A 或重启应用后，各自恢复自己的最后状态；失败导航、归档与项目移除不产生串线或残留。

### 模块划分与数据流

1. 产品与行为规格：页面 PRD 已写入新的用户语义；console-ui 规格增量把可判定的会话隔离、默认关闭、入口和重启场景写为 Requirement。
2. 右侧栏工作现场存储：将现有按 host 保存标签的文档升级为同一 host 下保存标签和开关状态的版本化文档。读取、快照、恢复、会话归档和项目移除继续由同一个 store 负责。
3. 当前 host 控制器：use-right-sidebar-tabs 在 host 改变时原子读取该 host 的标签和开关状态；显示或隐藏仅写当前 host；宽度仍使用全局偏好。
4. 导航与回滚：普通选择、搜索、分析路由、来源迁移和项目移除均通过既有 host 解析切换工作现场。导航快照同时包含开关状态，失败时恢复进入前的完整现场。
5. 视图与验收：operator-console-view 继续只接收当前 host 的布尔开关；单元、集成和真实 Electron 用例覆盖 A/B、重启、入口、失败回滚和清理。

数据流为：路由确定 host → store 读取该 host 工作现场 → controller 投影当前开关与标签 → 视图呈现 → 用户开关或入口写回同一 host → 导航快照在失败时整体恢复。

### 关键选型与结构决策

| 决策 | 本项目约束 | 采纳结论 |
| --- | --- | --- |
| 状态归属 | 页面 PRD 已规定一棵对话树只有根对话的一条外层标签组，用户要求每段对话独立开关 | 开关与该根对话的外层工作现场同归属；分析对话和其后代复用所属根对话的状态，不新增嵌套右侧栏。 |
| 持久化边界 | 现有 RightSidebarTabsStore 已按 host 保存标签，并提供快照、恢复、删除 host 的生命周期入口 | 以同一版本化 host 文档保存标签与开关，避免两个独立存储在导航回滚或归档时不同步。 |
| 宽度偏好 | PRD 和现有实现将宽度视为用户跨工作现场的布局偏好 | 宽度继续全局保存；本 change 只改变开关状态，不改变尺寸语义。 |
| 旧数据处理 | 旧版只有全局开关，不能推断它曾为哪些对话打开；新 PRD 要求未打开过的对话默认关闭 | 新版本优先读取新的 host 文档；首次迁移时仅可把旧的打开状态带给当时显示的 host，其他 host 默认关闭，并保留旧键供回退版本读取。 |
| 失败恢复与清理 | 现有导航已快照 tabs，归档和项目移除通过 clearHosts 清理工作现场 | 快照扩展为同一 host 的开关状态；清理 host 时同时删除该 host 开关状态，失败导航恢复进入前状态。 |

不新增 provider、IPC、数据根或外部依赖；现有 desktop renderer 与 console-ui 的分层边界不变。

## 现有方案调研

- 候选 1：维持全局开关偏好。代价是直接违反 A 打开、B 首次访问仍关闭的产品验收，不采用。
- 候选 2：新增一份独立的按 host 开关映射。它能满足隔离，但需要为归档、项目移除、导航快照和失败恢复额外维护第二条生命周期，不采用。
- 候选 3：扩展现有按 host 的右侧栏工作现场文档。它复用现成的快照、恢复和 clearHosts 生命周期，使标签与开关原子一致，采用。
- 基线候选：什么都不做。代价等同候选 1，继续产生跨对话串线。

## 测试策略

- 存储单测：覆盖新版本文档的缺失、损坏、未知字段、旧标签文档迁移、旧全局打开状态只迁移当前 host、快照恢复与 clearHosts 清理。
- controller 单测：覆盖 A 打开、切 B 关闭、返回 A 打开；B 自己打开后与 A 相互独立；重渲染不将旧 host 的开关写到新 host。
- 导航与集成测试：覆盖普通选择、搜索和分析入口只打开目标 host；导航失败时恢复原 host、标签和开关状态；归档或项目移除后不保留已删除 host 的状态。
- 真实应用验收：扩展既有 console-dashboard-ui，新增 right-sidebar-conversation-visibility 专项 case；在真实 Electron 中操作两段根对话，断言 A/B 切换和应用重启后的独立状态，同时保留既有 right-sidebar-responsive case 的响应式覆盖；证据继续写入系统临时目录。
- 验证门禁：依赖可用后先运行受影响范围的 scope 测试、typecheck、desktop build 与该真实应用验收；步骤 4 再重跑步骤 1 的两条基线命令并执行一次完整 pnpm test。

当前工作区缺少 node_modules，步骤 1 的测试与构建均未能启动；上述可执行验证均为未验证，不能以本方案替代运行证据。

## 风险与回滚

- 迁移错误可能让已有标签丢失或让一个旧全局状态扩散到多个对话；新文档必须防御性解析，并保留旧键，回滚版本仍可读取原值。
- 快速导航或异步加载可能以旧 host 覆盖新 host；controller 使用当前 host 输入，导航失败沿用完整场景快照恢复。
- 归档与项目移除遗漏开关会留下不可达状态；将其置于现有 clearHosts 生命周期内，并由单测覆盖。

## 方向性风险判定

无方向性风险。状态归属、持久化生命周期和回滚均有用户需求、现行 PRD 的外层工作现场规则以及现有按 host store 的直接依据；没有“无本项目依据，仅为惯例”的方向选择类条目，因此不需要 spike 或用户中段确认。

本方案经评审交接后自主定稿，按纪律第 3 条分级作为基准。
