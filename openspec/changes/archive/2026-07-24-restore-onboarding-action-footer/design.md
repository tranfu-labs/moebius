# 设计：restore-onboarding-action-footer

## 方案

正式实现与隔离原型采用相同的三段式页面结构：

```text
┌────────────────────── 应用标题栏 ──────────────────────┐
│                                                       │
│                  可滚动步骤主体                       │
│          512px 普通内容 / 780px 宽版内容              │
│                                                       │
├──────────────── 固定底部操作 footer ─────────────────┤
│              780px 响应式对齐框架                     │
│                                  [上一步]  [继续]      │
└───────────────────────────────────────────────────────┘
```

1. 根容器继续使用纵向 flex 和窗口高度约束。应用标题栏与操作 footer 都是 `shrink-0` 的兄弟区域，中间步骤主体使用 `min-height: 0`、`flex: 1` 与纵向滚动。
2. footer 全宽显示背景和顶部分割线，内部容器使用 `width: 100%`、`max-width: 780px` 与和主体一致的响应式水平页边距。
3. footer 内不渲染进度 DOM，只用右对齐 action group 承载现有主次按钮，按钮间距保持 8px。
4. footer 不使用 `position: fixed`、absolute 或 sticky；它通过页面 flex 布局稳定占据底边，因此不会覆盖可滚动主体。
5. AI 团队设计器打开时不渲染 footer，中间主体自动获得该高度，避免全局操作与设计器子流程竞争。
6. 第 3 步继续让接力时间线在高度不足时内部滚动；固定 footer 不参与时间线滚动，并始终可见。

## 测试设计

### 单元测试

- 四步常规状态都渲染独立于滚动主体的 footer，且 footer 内不出现步骤圆点或 `n / 4`。
- 第 1 步环境异常时 footer 显示“重新检查 / 继续”并保持继续禁用；环境就绪后只显示“继续”。
- 第 2–4 步 footer 显示“上一步”和对应主操作，按钮间距 8px。
- AI 团队设计器打开时全局 footer 不存在，关闭后恢复。
- 回看模式第 4 步继续显示“完成回看”。

### AI 验证流程

- 运行 console-ui onboarding 定向测试、console-ui 构建与类型检查。
- 重新构建并发布自包含 onboarding 原型，运行 `file://` 完整旅程门禁。
- 在默认 `1180 × 760`、窄窗口和最小支持高度下截图，核对 footer 始终贴住窗口底边、主体独立滚动、按钮右边缘与 780px 框架对齐且没有第二套进度。
- 打开 AI 团队设计器，核对全局 footer 隐藏、设计器操作完整可达。

## 权衡

- 不原样恢复旧 footer：旧版同时带有 640px 内层、步骤圆点和 `n / 4`，会重新引入横向对齐跳动与重复进度；本次只恢复稳定底栏。
- 不保留内容后的操作行：它无法满足操作始终位于窗口底部的目标，且短窗口可能需要额外滚动才能触达。
- 不用 CSS `position: fixed`：固定定位会覆盖主体并要求手工补偿 footer 高度；flex 末端区域能提供相同的可见结果和更可靠的响应式行为。
- footer 内层保留 780px 而不恢复旧 640px：它继续与普通步骤和宽版步骤共享右边缘，避免步骤切换时按钮横向跳动。

## 风险

- footer 会持续占用一段垂直高度，第 3 步和短窗口的主体空间减少；必须验证接力时间线内部滚动仍能容纳标准六棒和完成说明。
- footer 隐藏时根布局高度会变化；AI 团队设计器需验证不会产生页面级横向滚动或底部内容不可达。
- 原型验证脚本目前把 `.onboarding-footer` 当作遗留结构；实施时必须改为只拒绝 footer 内重复进度，并新增 footer 几何与滚动独立性断言。

## 实施校正

560px 高度验收首次发现原型根容器只有 `min-height`，会被接力内容撑到视口之外，导致 footer 跑到可视区下方。原型 onboarding 根容器因此增加明确的 `100dvh` 高度，中间 stage 继续使用 `min-height: 0` 和内部滚动。正式 `OnboardingShell` 原本已有 `h-screen`，无需额外改动。修正后低窗口滚动前后 footer 的顶部几何位置保持不变。
