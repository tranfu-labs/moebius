# wireframes：terminal-notification-delivery

> 基线：页面级结构以对应页面 PRD 与既有 `docs/wireframes/pages/*.md` 为准；本文件只记录本次页面/版式变化，供实现对照，不替代 PRD。

## pages/onboarding.md — 第 4 步 · 任务提醒（新步骤，就绪顺延第 5 步）

```text
第 4 步，共 5 步
任务结束时叫你回来
开启后不必盯着窗口；完成或等待你时，Moebius 会提醒你

┌──────────────────────────────────────────────┐
│ 任务提醒                          [已开启]   │
│ macOS 通知                        [尚未开启] │
│ 通知会显示提醒类别和应用内对话名称            │
└──────────────────────────────────────────────┘

暂时不要只跳过本步；第一次任务完成时仍可能显示应用内权限弹窗

                    [ 上一步 ] [ 暂时不要 ] [ 允许系统通知 ]
```

- 总开关关闭时标题改为「任务提醒当前已关闭」，副本指向设置恢复；「暂时不要」与「允许系统通知」不可见，主操作为「继续」。
- 回看模式读取真实开关与权限；第 5 步保持既有「准备就绪 / 开始使用」。

## pages/settings.md — 常规 · 任务提醒设置组

```text
任务提醒
任务完成或需要你处理时提醒你

┌──────────────────────────────────────────────┐
│ 任务提醒                        [开]         │
│ 正在改为关闭…  /  任务提醒已关闭             │
│ 通知设置未更改            [重试]              │
├──────────────────────────────────────────────┤
│ macOS 通知          [尚未开启]  [允许系统通知]│
│ 通知可能显示应用内对话名称；锁屏预览、声音、  │
│ 静音和专注模式由 macOS 控制。                 │
├──────────────────────────────────────────────┤
│ ⚠ 暂时无法发送系统通知                       │
│ 系统通知与声音暂时无法发送；Dock 与侧边栏仍   │
│ 可用。                                       │
│                              [重新检查] [反馈问题] │
└──────────────────────────────────────────────┘
```

- 总开关保存采用前台短事务：保存中锁定开关、分类、关闭与 `Esc`，失败恢复旧值并显示「通知设置未更改」。
- 权限已拒绝时显示「已拒绝」与「打开系统设置」；系统通知通道异常独立表达。

## 浮层：发送时权限弹窗（新）

```text
┌ 需要允许系统通知 ────────────────────┐
│ 任务提醒已开启，但 macOS 还不允许     │
│ 系统通知。                           │
│                                      │
│ ┌ 发布前检查          已完成        ┐ │
│ ├ 落地页文案          正在等待你    ┤ │
│ └ 导出功能重构        正在等待你    ┘ │
│                                      │
│ 关闭后，系统通知、声音和 Dock 提醒    │
│ 都会停用，侧边栏状态点保留。          │
│                                      │
│          [开启系统通知] [重新检测]    │
│          [关闭任务提醒]              │
└──────────────────────────────────────┘
```

- 无第四种静默关闭：标题栏关闭、`Escape` 与遮罩点击均不可用。
- 请求期间显示「等待 macOS 确认…」；请求结束显示「权限操作已完成，请重新检测」；打开系统设置期间持续显示「正在打开系统设置…」。

## pages/main-left-sidebar.md — 单点状态与 Dock

```text
│ ▾ 项目 A       │
│    发布前检查 ● │  红：需要你处理
│    落地页文案 ● │  蓝：未读
│    集成收尾 ● │  闪：正在推进
│    分享卡片     │  无点
│ ▸ 项目 B   ●   │  折叠项目：一个最高优先级代表点
└────────────────┘
Dock 角标：2 段对话（只计当前可见红点与蓝点）
```

- 每段对话与折叠项目始终只有一个状态点；Dock 只统计未归档对话当前可见红点与蓝点的去重数。
