# local-console delta：轮次收束与终局事实

## Requirement: 主理人收束成为一等持久化事实

Source: docs/product/pages/main-conversation.md#侧边栏状态点的触发

- MUST 让主理人在不继续交棒时留下「有新结果 / 需要用户处理 / 确认没有新增内容」之一的收束事实，绑定本轮与对应终局消息，持久化并跨刷新与重启保持。
- MUST NOT 让成员交棒、某名成员结束、当前没有活动成员或队列在调度缝隙中暂时为空产生收束事实。
- MUST 让一轮以一次需要团队推进的用户动作开始：新对话首次发送，以及上一轮已收束或终止后的首次发送、重试或重新运行；进行中追加的消息归入当前轮；「需要用户处理」收束后用户的回应开始新一轮。
- MUST 让每一轮只保留一个最终收束结论，后一轮不覆盖前一轮已留在时间线中的结论。

#### Scenario: 交棒缝隙不产生收束

- **GIVEN** 专业成员已回复、主理人尚未接回，调度缝隙中暂时没有活动 run
- **WHEN** 检查轮次状态
- **THEN** 该轮保持进行中（闪烁点）
- **AND** 不产生任何收束事实。

## Requirement: 连续 30 秒静默兜底

Source: docs/product/pages/main-conversation.md#侧边栏状态点的触发

- MUST 在主理人没有留下收束事实且会话没有活动工作、待发射内容或等待主理人接回的专业结果时，开始连续 30 秒静默确认；计时期间保持进行中状态且不显示倒计时。
- MUST 在计时期间出现新用户消息、Agent 可见活动、待发射项变化或待接回结果变化时取消本次计时，再次满足全部静默条件后重新计满 30 秒。
- MUST 让切换页面、刷新、休眠唤醒与重启不清零已经过的静默时间；恢复后按最后可见活动与当前真实工作状态继续判断，连续静默满 30 秒必须形成「本轮没有明确收尾」。
- MUST NOT 让「本轮没有明确收尾」冒充主理人结论；它作为需要用户处理的可见事实，用户主动停下或确认「结束并保留历史」是中性终止，不进入该兜底。

#### Scenario: 静默计时重置

- **GIVEN** 一轮已静默 20 秒
- **WHEN** 出现新的 Agent 可见活动
- **THEN** 本次计时取消
- **AND** 下一次全部静默时重新计满 30 秒后才形成「本轮没有明确收尾」。

## Requirement: 终局事件总线与去重

Source: docs/product/flows/state-change-delivery.md#只把本轮终局变成通知

- MUST 在收束事实成功落盘后发布 `session:round:terminal` 类型化事件（event_id/session_id/round_id/outcome/terminal_message_id/conversation_title/occurred_at），同一 event_id 最多投递一次。
- MUST NOT 从 Agent 正文、自然语言「完成/等待」措辞、工具输出或队列暂时为空推断终局事件。
- MUST 让事件消费失败不影响会话终局事实；通知、声音、Dock 与权限弹窗都是该事件的消费者。

#### Scenario: 同一轮不重复投递

- **GIVEN** 一轮终局事实已落盘并投递成功
- **WHEN** 刷新、休眠唤醒或重启后重新读取同一终局
- **THEN** 不产生第二条投递
- **AND** 新一轮再次终局时允许产生下一条。
