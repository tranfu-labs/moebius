# desktop-shell delta：任务提醒交付链路

## Requirement: 主理人收束事实驱动系统通知、声音与 Dock

Source: docs/product/flows/state-change-delivery.md#主流程、docs/product/pages/main-left-sidebar.md#Dock 角标与状态点一致性

- MUST 在会话页保存本轮终局事实后，由主进程消费内部类型化事件并提交一次 macOS 系统通知（标题 Moebius、对话名称、已完成/正在等待你）与系统通知声音。
- MUST 使用 `event_id` 持久化去重，让刷新、重渲染、休眠唤醒与重启不重复提交通知；同一对话同一轮最多一条通知。
- MUST 在运行、交棒、排队、短暂空闲或单个成员结束时不提交通知；用户自身的发送、已读、打开结果、停下不触发通知。
- MUST 让 Dock 数字等于未归档对话当前可见红点或蓝点的去重对话数，并在归档/恢复/项目移除时按侧边栏生命周期更新。

#### Scenario: 一轮只通知一次

- **GIVEN** 一段对话经历运行、交棒、短暂空队列后由主理人收束为有新结果
- **WHEN** 收束事实落盘并触发投递
- **THEN** 恰好提交一条「已完成」通知
- **AND** 刷新与重启后不重复提交。

## Requirement: 每次发送前读取真实 macOS 权限

Source: docs/product/flows/state-change-delivery.md#每次发送前检查权限，未通过时由弹窗承接本次终局

- MUST 在每次真正准备提交通知前读取 macOS 当前通知授权；任务提醒总开关关闭时不读取权限、不弹窗、不提交。
- MUST 在权限已允许时提交通知并请求系统声音；仅声音关闭或专注模式开启不算权限失败。
- MUST 在权限未通过时将本次终局放入唯一应用内权限弹窗（按形成顺序合并多段对话），授权通过后不补发已展示的终局。
- MUST 让弹窗的「开启系统通知」在尚未决定时发起一次原生授权请求，在已拒绝或暂时无法检测时只打开系统设置；「重新检测」每次读取当前真实状态；「关闭任务提醒」按设置原子保存规则持久化关闭总开关。
- MUST 在系统通知提交失败时保留终局、侧边栏与 Dock 事实，并让设置显示可理解的「暂时无法发送系统通知」通道状态，不得伪造送达成功。

#### Scenario: 权限未通过时弹窗承接

- **GIVEN** 总开关开启、macOS 权限未通过、一段对话形成终局
- **WHEN** 发送前权限检查执行
- **THEN** 不提交系统通知或声音
- **AND** 显示包含对话名称与终局类别的单一权限弹窗，用户开启并重新检测通过后只关闭弹窗，本次终局不补发。

## Requirement: 通知点击回流与生命周期边界

Source: docs/product/flows/state-change-delivery.md#点击通知回到对应对话

- MUST 让系统通知点击激活或恢复 Moebius 窗口，并打开产生终局的对话、定位对应收束记录；用户已位于目标记录时只聚焦，不创建重复标签或重复已读动作。
- MUST 在通知点击已由主进程接收、但页面定位前发生中断（崩溃或重启）时，让下次启动按持久化点击载荷继续定位；启动过程不重放通知。
- MUST 在用户 `Command+Q` 明确退出后接受「无通知冷启动」边界：Electron 38 会移除已提交通知，通知中心不存在可点击通知；普通重开通过持久化侧边栏红点或蓝点找回对应对话（仅限仍保留红点或蓝点的对话；「确认没有新增内容」等无点结论不保留提醒入口），不得伪造历史通知点击。
- MUST 在目标被普通归档时显示「恢复对话」入口并在恢复后定位；目标所属项目已移除时说明当前无法打开且不提供虚假恢复；目标记录不可用时保留原工作现场并说明对应对话不可用。

#### Scenario: 运行中点击直达

- **GIVEN** 一条终局通知已提交且 Moebius 正在运行（含关闭窗口、隐藏、失焦或最小化）
- **WHEN** 用户点击该通知
- **THEN** Moebius 激活窗口并进入目标对话的对应收束记录
- **AND** 该终局不重新产生通知。

#### Scenario: 点击已接收后中断，下次启动续定位

- **GIVEN** 用户点击通知且主进程已接收点击载荷，但页面定位完成前应用退出或崩溃
- **WHEN** 用户下次启动 Moebius
- **THEN** 应用按持久化点击载荷继续打开目标对话并定位
- **AND** 启动过程不重放通知、不伪造新的通知点击。

#### Scenario: 明确退出后通知移除，不承诺冷启动

- **GIVEN** 用户通过 `Command+Q` 明确退出 Moebius
- **WHEN** 用户检查通知中心或重新打开 Moebius
- **THEN** Electron 38 已移除该应用已提交的通知，通知中心不存在可点击通知
- **AND** 普通重开不读取、不消费不存在的通知点击；仅按侧边栏当前红点或蓝点（若有）找回对话，无点结论无找回入口。

（注：本 Requirement 按产品方 2026-08-10 裁决的三段生命周期书写；Electron 40+ 的 `Notification.getHistory()` 冷启动评估拆分为后续技术升级，不在本 delta 承诺范围内。四轮签名 spike 实测证据见 change design.md「冷启动 spike 实测」小节。）

## Requirement: 任务提醒总开关的原子保存与失败恢复

Source: docs/product/pages/settings.md#管理任务提醒

- MUST 让任务提醒总开关默认开启并跨关闭/重启保留最后完整保存值；保存采用前台短事务（最长 3 秒），保存中锁定开关、分类切换、关闭与 Esc，避免冲突提交。
- MUST 在保存超时或失败时恢复操作前生效值并显示「通知设置未更改」与重试；应用在保存完成前异常退出时只读取最后完整保存值。
- MUST 让总开关关闭后不提交新通知、不请求声音并隐藏 Dock 角标，同时保留侧边栏状态点、时间线事实与已进入通知中心的历史通知；重新开启后只处理之后形成的新终局并按未清可见提醒重建 Dock。

#### Scenario: 保存失败不冒充成功

- **GIVEN** 用户把任务提醒从开启切到关闭
- **WHEN** 保存失败
- **THEN** 开关保持开启并显示失败与重试
- **AND** 通知、声音与 Dock 行为保持关闭前状态。

## Requirement: Onboarding 任务提醒说明与授权

Source: docs/product/pages/onboarding.md#第 4 步 · 任务提醒

- MUST 让第 4 步分别展示任务提醒总开关与 macOS 通知权限的真实值；未授权显示「尚未开启」。
- MUST 让「暂时不要」只跳过本步授权、不关闭任务提醒，并说明总开关开启时第一次真实任务完成仍可能显示应用内权限弹窗。
- MUST 在回看模式读取当前真实开关与权限，不得把默认值当当前值，也不得自动开启或关闭总开关。
