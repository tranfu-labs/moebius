# console-ui delta：任务提醒界面与单点状态

## Requirement: 每段对话与折叠项目始终只显示一个状态点

Source: docs/product/pages/main-conversation.md#侧边栏状态点的触发、docs/product/pages/main-left-sidebar.md#对话状态点与顺序

- MUST 按会话页保存的轮次状态派生每段对话的最终可见点：红（需要你处理）、蓝（未读）、闪烁（正在推进）、无点，任何时刻同一对话只显示其中一个。
- MUST 在新一轮开始后结束旧蓝点并只显示闪烁点；本轮结束后才按结果显示红、蓝或无点。
- MUST 让折叠项目只显示一个最高优先级代表点，不得叠加次级点或其他第二状态信号。

#### Scenario: 新一轮开始后旧提醒结束

- **GIVEN** 一段对话已收束为有新结果且未读（蓝点）
- **WHEN** 用户发送新消息开始新一轮
- **THEN** 该对话只显示闪烁点
- **AND** 不再同时显示蓝点或任何次级提醒。

## Requirement: Dock 只统计未归档对话当前可见的红点与蓝点

Source: docs/product/pages/main-left-sidebar.md#Dock 角标与状态点一致性

- MUST 让 Dock 数字等于未归档对话中当前可见红点或蓝点的去重对话数；闪烁点与无点不计入。
- MUST 让被高优先级点遮挡的底层提醒不参与 Dock 计数；红点确认后若蓝点仍可见则继续计一次，全部清除才退出计数。
- MUST 让归档对话退出 Dock、恢复后按未清可见提醒重新计入；项目移除批量归档同样退出 Dock 且不得改写提醒事实。

#### Scenario: 当前可见点决定计数

- **GIVEN** 矩阵含 2 个红点、2 个蓝点、2 个闪烁点、2 个无点
- **WHEN** 计算 Dock 数字
- **THEN** 结果为 4
- **AND** 界面不出现「计入 Dock」等评审答案标签。

## Requirement: 用户界面统一使用「任务提醒」用户文案

Source: docs/product/pages/settings.md#管理任务提醒、docs/product/pages/onboarding.md#第 4 步 · 任务提醒

- MUST 在用户可见文案中使用「任务提醒」作为功能名，说明为「任务完成或需要你处理时提醒你」。
- MUST NOT 在用户可见文案中出现「终局」「投递」「通道」「应用总开关」等内部术语；系统通知通道异常显示为「暂时无法发送系统通知」。

#### Scenario: 设置与引导文案一致

- **GIVEN** 设置页与首次引导均展示任务提醒相关说明
- **WHEN** 检查全部静态文案与可访问名称
- **THEN** 两处使用一致的「任务提醒」用语
- **AND** 不出现被禁内部术语。

## Requirement: 发送时权限弹窗明确区分任务提醒与系统通知权限

Source: docs/product/flows/state-change-delivery.md#每次发送前检查权限，未通过时由弹窗承接本次终局

- MUST 让权限弹窗标题为「需要允许系统通知」，并说明「任务提醒已开启，但 macOS 还不允许系统通知」。
- MUST 提供「开启系统通知／重新检测／关闭任务提醒」三个操作；「关闭任务提醒」操作前说明系统通知、声音和 Dock 提醒都会停用，侧边栏状态点保留。
- MUST NOT 在弹窗中展示内部权限枚举或恢复「当前状态」式调试信息。

#### Scenario: 关闭任务提醒的影响说明

- **GIVEN** 权限弹窗显示中
- **WHEN** 用户查看「关闭任务提醒」操作
- **THEN** 操作前可见其将停用系统通知、声音与 Dock 提醒并保留侧边栏状态点
- **AND** 保存失败时不冒充关闭成功。
